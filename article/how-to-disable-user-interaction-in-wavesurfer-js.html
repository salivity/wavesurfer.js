How to Disable User Interaction in Wavesurfer.js

This guide explains how to control user interaction with an audio waveform using Wavesurfer.js. You will learn about the exact configuration parameter responsible for locking or unlocking seeking behavior, how to configure it during initialization, and how to toggle user interactivity dynamically at runtime.

The option that enables or disables user interaction with the waveform in Wavesurfer.js is interact.

By default, interact is set to true, which allows users to click or drag across the waveform to seek to different parts of the audio track. Setting this option to false makes the waveform completely non-interactive, turning it into a display-only visualization while playback continues normally.

Disabling Interaction at Initialization

To disable user interaction when creating your Wavesurfer instance, pass interact: false into the configuration object:

import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#violet',
  progressColor: '#purple',
  url: '/path/to/audio.mp3',
  interact: false, // Disables clicking and dragging on the waveform
});

Changing Interactivity Dynamically

If you need to enable or disable interaction after the waveform has already been initialized, use the setOptions method:

// Disable user interaction
wavesurfer.setOptions({ interact: false });

// Re-enable user interaction
wavesurfer.setOptions({ interact: true });

Common Use Cases

Setting interact: false is particularly useful in scenarios such as:

  • Read-only visualizers: Displaying audio progress without allowing the listener to jump ahead or rewind.
  • Mandatory audio playback: Preventing skipping in compliance training or instructional modules.
  • Synchronized playback: Ensuring multiple media players remain strictly in sync without user-driven offsets.
