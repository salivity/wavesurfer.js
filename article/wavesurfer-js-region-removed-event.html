Wavesurfer.js Region Removed Event

This article explains how to detect when a region is deleted in Wavesurfer.js, identifying the specific event triggered by the Regions plugin and demonstrating how to handle it in your code. By listening to this event, you can keep your application state synchronized, update user interfaces, and trigger backend updates whenever an audio selection is removed.

In Wavesurfer.js, the event that signals a region has been removed is region-removed. This event is emitted by the RegionsPlugin instance rather than the main WaveSurfer instance.

Listening to region-removed in Wavesurfer.js v7+

In modern versions of Wavesurfer.js (v7 and newer), the Regions plugin is instantiated and registered with the player. To listen for region deletions, attach an event listener directly to your Regions plugin instance using the .on() method:

import WaveSurfer from 'wavesurfer.js';
import RegionsPlugin from 'wavesurfer.js/dist/plugins/regions.esm.js';

// Initialize WaveSurfer
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#violet',
  progressColor: '#purple',
});

// Initialize the Regions plugin
const wsRegions = wavesurfer.registerPlugin(RegionsPlugin.create());

// Listen for the region-removed event
wsRegions.on('region-removed', (region) => {
  console.log(`Region removed: ${region.id}`);
  // Perform cleanup, update UI, or synchronize backend data
});

The callback function receives the removed region object as its argument, giving you access to properties such as region.id, region.start, and region.end before it is completely discarded.

Region-Level Removal Event

In addition to listening globally on the plugin instance, individual region instances emit a remove event directly before they are destroyed:

const region = wsRegions.addRegion({
  start: 10,
  end: 20,
  content: 'Sample Region',
});

region.on('remove', () => {
  console.log('This specific region is being removed');
});

Programmatic vs. User Removal

The region-removed event fires regardless of whether the region was removed programmatically via region.remove() or through user interaction (such as a custom delete button or shortcut). Handling this event centrally on the RegionsPlugin instance ensures your application state remains consistent no matter how the removal was initiated.
