Smooth Playhead Animation in Wavesurfer.js Overlays

This article covers how to achieve a smooth, 60+ frames-per-second playhead animation in custom Wavesurfer.js overlays. By default, Wavesurfer.js updates playhead positions based on audio decoding chunks and throttled time updates, which leads to noticeable visual stutter when rendering custom HTML or canvas overlays. Below, you will learn why this stutter occurs, how to decouple the visual rendering loop using requestAnimationFrame, and how to use hardware-accelerated CSS transforms or HTML5 Canvas rendering for fluid motion.

Why Default Wavesurfer.js Events Cause Stutter

Wavesurfer.js emits events like timeupdate or audioprocess as playback progresses. These events are bound to internal Web Audio API processing intervals or HTML5 Audio timeupdate cycles, which typically trigger only 4 to 10 times per second.

If you update a custom DOM element or canvas overlay using only these event callbacks:

// Creates a choppy, stuttering playhead
wavesurfer.on('timeupdate', (currentTime) => {
  updatePlayhead(currentTime);
});

The resulting movement will jump abruptly rather than sweep across the waveform.

The Solution: Decouple Rendering with requestAnimationFrame

To achieve fluid 60 FPS (or higher) animations, decouple your rendering pipeline from the audio timing events. You should run an independent requestAnimationFrame loop whenever audio is actively playing, while relying on wavesurfer.getCurrentTime() to query high-precision time values.

Step 1: Manage the Render Loop Lifecycle

Only run the visual loop when audio is active. Hook into Wavesurfer’s playback state events (play, pause, seeking, and finish) to start and stop the animation loop, preventing unnecessary CPU and GPU usage.

let animationFrameId = null;

function renderLoop() {
  if (!wavesurfer.isPlaying()) return;

  updatePlayheadPosition();
  animationFrameId = requestAnimationFrame(renderLoop);
}

wavesurfer.on('play', () => {
  cancelAnimationFrame(animationFrameId);
  animationFrameId = requestAnimationFrame(renderLoop);
});

wavesurfer.on('pause', () => {
  cancelAnimationFrame(animationFrameId);
});

wavesurfer.on('finish', () => {
  cancelAnimationFrame(animationFrameId);
  updatePlayheadPosition(); // Align to final position
});

wavesurfer.on('seeking', () => {
  updatePlayheadPosition(); // Instantly update when clicking the waveform
});

Step 2: Calculate Sub-Pixel Coordinates

Calculate progress by dividing the current time by the total duration, then multiply by the container's width. Handle division by zero when the track has not fully loaded.

function getPlayheadX() {
  const duration = wavesurfer.getDuration();
  if (!duration) return 0;

  const currentTime = wavesurfer.getCurrentTime();
  const containerWidth = wavesurfer.getWrapper().clientWidth;

  return (currentTime / duration) * containerWidth;
}

If you are using Wavesurfer's zooming functionality (wavesurfer.zoom(pxPerSec)), determine the position using the zoom scale and scroll offset:

function getZoomedPlayheadX() {
  const currentTime = wavesurfer.getCurrentTime();
  const wrapper = wavesurfer.getWrapper();
  
  // wavesurfer.options.minPxPerSec determines zoomed pixel width per second
  const pxPerSec = wavesurfer.options.minPxPerSec || 0;
  return currentTime * pxPerSec;
}

Step 3: Implement Hardware-Accelerated DOM Overlays

When using a standard HTML element (such as a <div>) as your custom playhead, avoid updating style.left. Modifying positional layout properties forces browser recalculations and repaints on every frame.

Instead, use transform: translate3d() to force GPU acceleration:

const playheadElement = document.getElementById('custom-playhead');

// CSS setup:
// #custom-playhead {
//   position: absolute;
//   top: 0;
//   left: 0;
//   will-change: transform;
//   pointer-events: none;
// }

function updatePlayheadPosition() {
  const x = getPlayheadX();
  playheadElement.style.transform = `translate3d(${x}px, 0, 0)`;
}

Step 4: Animating on a Custom Canvas Overlay

If your overlay is rendered via an HTML5 <canvas> element (such as a custom timeline, marker system, or playhead beam):

  1. Clear the canvas overlay.
  2. Fetch the precise playhead X position.
  3. Draw the playhead directly to the 2D context.
const canvas = document.getElementById('overlay-canvas');
const ctx = canvas.getContext('2d');

function updateCanvasPlayhead() {
  const x = getPlayheadX();

  // Clear previous frame
  ctx.clearRect(0, 0, canvas.width, canvas.height);

  // Draw smooth playhead
  ctx.beginPath();
  ctx.moveTo(x, 0);
  ctx.lineTo(x, canvas.height);
  ctx.lineWidth = 2;
  ctx.strokeStyle = '#ff0055';
  ctx.stroke();
}

Combine this canvas update function directly into the requestAnimationFrame loop defined in Step 1 to eliminate jitter and synchronize your custom overlays seamlessly with playback.
