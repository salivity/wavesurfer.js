How to Make Wavesurfer.js Full-Width with Flexbox

Embedding Wavesurfer.js inside a CSS Flexbox layout often causes waveform containers to collapse to zero width or overflow their parent elements due to intrinsic canvas sizing constraints. This article provides the exact Flexbox properties and container structures required to force Wavesurfer.js to stretch across the full width of its parent while remaining completely responsive across screen resize events.

The Underlying Flexbox Sizing Issue

Wavesurfer.js renders waveforms by calculating dynamic pixel dimensions and drawing directly onto HTML5 <canvas> elements. When placed inside a Flexbox parent:

  1. Flex items default to min-width: auto: Browsers will not shrink a flex item below the intrinsic content width of its children (in this case, the fixed-width canvas).
  2. Width calculations fail during resize: When resizing down, the container cannot shrink because the canvas forces the item to maintain its initial rendered width, leading to horizontal scrolling or container overflow.

The Optimal CSS Flexbox Structure

To solve this, the waveform wrapper must explicitly override the default min-width behavior and define clear flex-grow rules.

/* The parent layout */
.audio-player {
  display: flex;
  align-items: center;
  width: 100%;
  gap: 1rem;
}

/* Fixed controls (e.g., play/pause buttons) */
.player-controls {
  flex: 0 0 auto;
}

/* The Wavesurfer.js target container */
.waveform-container {
  flex: 1 1 0%;
  min-width: 0;
  width: 100%;
}

Why These Properties Matter:

  • flex: 1 1 0%: Instructs the container to expand and fill all remaining space along the flex axis while setting its flex base size to zero rather than relying on its intrinsic content size.
  • min-width: 0: Overrides the CSS specification's default min-width: auto for flex children. This allows the wrapper to shrink below the width of the nested canvas element during dynamic browser resizing.
  • width: 100%: Guarantees that the container occupies the full horizontal space allocated to it by the flex engine before the canvas is drawn.

HTML Implementation

Structure the markup so the waveform container is a direct flex child alongside any other player components:

<div class="audio-player">
  <button class="player-controls" id="playBtn">Play</button>
  <div id="waveform" class="waveform-container"></div>
  <span class="player-controls" id="duration">0:00</span>
</div>

Wavesurfer.js Initialization

When instantiating Wavesurfer.js, bind it directly to the flex-controlled container. Modern versions of Wavesurfer (v7+) use a built-in ResizeObserver to redraw the canvas automatically whenever the container width changes:

import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F46E5',
  progressColor: '#818CF8',
  height: 64,
  responsive: true, // For v6; v7 handles resizing natively via ResizeObserver
});

wavesurfer.load('/path-to-audio.mp3');

If using Wavesurfer v6 or earlier, ensure that window resize events explicitly trigger a redraw:

window.addEventListener('resize', () => {
  wavesurfer.drawer.fireEvent('redraw');
});

By setting flex: 1 1 0% and min-width: 0 on the direct waveform parent, the container cleanly absorbs layout changes without being constrained by the rendered canvas dimensions.
