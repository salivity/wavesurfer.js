Wavesurfer.js off Method for Event Cleanup

This guide explains how the off method works for event cleanup in Wavesurfer.js, why properly detaching event listeners is critical for preventing memory leaks in single-page applications, and how to implement it correctly using function references and modern unsubscribe patterns.

Understanding Event Listeners in Wavesurfer.js

Wavesurfer.js relies on an event-driven architecture. Developers subscribe to player lifecycle events—such as ready, timeupdate, seeking, and finish—using the wavesurfer.on() method.

When your application navigates between views or unmounts audio components, any active listener attached to the Wavesurfer instance remains in memory if not explicitly removed. This causes memory leaks, unexpected callbacks on destroyed DOM nodes, and degraded browser performance.

How the off Method Operates

The off method removes an active listener from Wavesurfer's internal event registry.

Syntax

wavesurfer.off(eventName, callback);
  • eventName (string): The name of the event to unsubscribe from (e.g., 'timeupdate').
  • callback (function): The exact function reference that was originally passed to wavesurfer.on().

Reference Equality Requirement

The most common mistake when using off is attempting to remove an anonymous function. The internal event system matches handlers by reference equality (===).

If you register an event with an anonymous function:

// Cannot be cleaned up with off()
wavesurfer.on('timeupdate', (currentTime) => {
  console.log(currentTime);
});

// This will fail silently because the function reference is different
wavesurfer.off('timeupdate', (currentTime) => {
  console.log(currentTime);
});

To clean up listeners effectively using off, you must define the handler as a named variable or function:

// Define a stable function reference
const handleTimeUpdate = (currentTime) => {
  console.log('Current time:', currentTime);
};

// Attach listener
wavesurfer.on('timeupdate', handleTimeUpdate);

// Clean up listener
wavesurfer.off('timeupdate', handleTimeUpdate);

Modern Alternative: The Unsubscribe Function

In Wavesurfer.js v7 and later, calling wavesurfer.on() returns an unsubscribe function directly. This eliminates the need to maintain separate named function references in your component scope.

// Subscribing returns an unsubscription handler
const unlistenTimeUpdate = wavesurfer.on('timeupdate', (time) => {
  console.log('Current time:', time);
});

// Calling the returned function triggers the cleanup internally
unlistenTimeUpdate();

Under the hood, this returned function calls the equivalent of off with the exact callback reference automatically.

Complete Component Cleanup Pattern

When destroying a component (such as in React useEffect, Vue beforeUnmount, or standard JavaScript lifecycle routines), combine event removal with instance destruction:

// Setup
const onReady = () => console.log('Audio is ready');
wavesurfer.on('ready', onReady);

// Cleanup routine
function cleanup() {
  // 1. Remove specific event listeners
  wavesurfer.off('ready', onReady);

  // 2. Destroy the entire Wavesurfer instance to clear all audio nodes and remaining events
  wavesurfer.destroy();
}

Calling wavesurfer.destroy() automatically unbinds all remaining events and cleans up Web Audio API nodes. However, selectively using off remains essential when swapping audio sources or toggling specific behaviors without re-instantiating the entire waveform player.
