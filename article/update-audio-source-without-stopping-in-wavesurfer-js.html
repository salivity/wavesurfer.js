Update Audio Source Without Stopping in Wavesurfer.js

Updating the audio source in Wavesurfer.js without pausing or interrupting active playback requires decoupling the audio playback mechanism from the waveform rendering cycle. Calling the native load() method halts the current audio thread, clears cached buffers, and resets the playback head. By pairing Wavesurfer with an external HTML5 <audio> element and pre-fetching the new media stream or pre-computed peaks, you can smoothly swap sources, synchronize playback timestamps, and re-render the waveform without cutting off audio output.

The Underlying Issue with Native load()

By default, calling wavesurfer.load(url) forces Wavesurfer to abort active playback, clear the internal Web Audio buffer or media element, fetch the new binary payload, and reset the playhead to 0. If your application streams dynamic segments, switches bitrates, or transitions tracks seamlessly, this default behavior introduces unwanted silence and latency.

Step 1: Decouple Audio from Wavesurfer

In Wavesurfer.js (v7+), the recommended approach is to pass an external HTML5 audio element into the initialization configuration via the media property. This gives you direct control over the media pipeline independently of the waveform UI.

import WaveSurfer from 'wavesurfer.js';

// Create and configure a dedicated audio element
const audioElement = new Audio();
audioElement.src = 'https://example.com/stream-part-1.mp3';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  media: audioElement, // Delegate playback control to your element
});

// Start playback
audioElement.play();

Step 2: Use Dual Audio Elements for Seamless Swapping

Because an individual HTML5 Audio element cannot seamlessly change its src without a brief rebuffering gap, the most reliable pattern is an audio-swapping pipeline (A/B buffering). You load the new URL in a secondary element, align the time, swap the active node, and then update Wavesurfer’s view.

let currentAudio = audioElement;
let nextAudio = new Audio();

async function switchAudioSource(newUrl, precomputedPeaks) {
  const currentTime = currentAudio.currentTime;
  const isPlaying = !currentAudio.paused;

  // Prepare the incoming media element
  nextAudio.src = newUrl;
  nextAudio.currentTime = currentTime;

  // Wait for the new audio element to buffer sufficiently
  await new Promise((resolve) => {
    nextAudio.addEventListener('canplaythrough', resolve, { once: true });
  });

  if (isPlaying) {
    await nextAudio.play();
  }

  // Stop previous playback smoothly
  currentAudio.pause();

  // Re-bind Wavesurfer to the new media element
  wavesurfer.setOptions({
    media: nextAudio,
  });

  // Re-render waveform using precomputed peaks to avoid decode delays
  if (precomputedPeaks) {
    wavesurfer.load(newUrl, precomputedPeaks, nextAudio.duration);
  } else {
    wavesurfer.load(newUrl);
  }

  // Swap element references for future switches
  const temp = currentAudio;
  currentAudio = nextAudio;
  nextAudio = temp;
}

Step 3: Prevent Rendering Freezes with Precomputed Peaks

If the client has to fetch and decode the entire audio file via AudioContext.decodeAudioData while audio is actively playing, the main thread can stutter.

To eliminate decoding lag during a live source swap:

  1. Generate the peak data on your server or build step (e.g., using audiowaveform).
  2. Supply the peak array directly to wavesurfer.load(newUrl, peaks, duration).
  3. Wavesurfer draws the updated canvas immediately, while the secondary audio element handles playback without dropouts.

Handling Continuous Live Streams (HLS/MSE)

For dynamic streaming architectures like HLS or DASH, use hls.js directly on the audio element:

import Hls from 'hls.js';

if (Hls.isSupported()) {
  const hls = new Hls();
  hls.loadSource('https://example.com/playlist.m3u8');
  hls.attachMedia(audioElement);
  
  // Update playlist sources dynamically via Hls instance
  // Playback continues uninterrupted through HLS buffer management
  function updateStreamManifest(newManifestUrl) {
    hls.loadSource(newManifestUrl);
  }
}

Attaching an MSE-managed stream to the media element allows source updates to occur transparently inside the media buffer, keeping Wavesurfer in sync without tearing down the visual waveform.
