Wavesurfer.js Peak Calculation Progress Event

Tracking waveform rendering and decoding is essential for creating responsive audio interfaces. This article explains which event signals peak calculation and audio loading progress in Wavesurfer.js, how it functions under the hood, and how to implement it to display a custom loading indicator.

In Wavesurfer.js, progress during audio fetching, decoding, and peak calculation is signaled by the loading event. As the audio file downloads and its waveform peaks are computed, this event fires continuously, providing an integer representing the completion percentage from 0 to 100.

Using the loading Event

To track the progress of peak generation, attach a listener to the loading event on your Wavesurfer instance:

import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F46E5',
  progressColor: '#312E81',
  url: '/audio/track.mp3',
});

// Listen for peak calculation and download progress
wavesurfer.on('loading', (percent) => {
  console.log(`Peak calculation progress: ${percent}%`);
  
  const progressBar = document.getElementById('progress-bar');
  if (progressBar) {
    progressBar.style.width = `${percent}%`;
  }
});

Event Lifecycle: From Loading to Ready

Understanding the sequence of events helps in managing UI state effectively:

  1. loading: Fires repeatedly while audio data is retrieved and peaks are calculated, emitting progress percentages.
  2. decode: Fires once the audio data has been fully decoded into an AudioBuffer and peak data is prepared.
  3. ready: Emitted when the waveform is fully drawn and the audio is ready for playback.

By subscribing to loading, you ensure users receive continuous visual feedback while heavy audio files are processed into visual peaks.
