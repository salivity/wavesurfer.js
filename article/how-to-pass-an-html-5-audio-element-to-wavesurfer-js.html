How to Pass an HTML5 Audio Element to Wavesurfer.js

This article explains how to connect an existing HTML5 <audio> element to Wavesurfer.js instead of letting the library create its own audio context. By leveraging the media configuration option, you can visualize waveforms for preloaded audio, preserve native streaming capabilities, and synchronize custom playback controls with Wavesurfer's interactive UI.

Step 1: Set Up the HTML Markup

Define both your existing <audio> element and the target container <div> where the waveform will render. If the audio is hosted on a different domain, include the crossorigin="anonymous" attribute to allow Wavesurfer to read the audio data for waveform generation.

<div id="waveform"></div>

<audio id="my-audio" controls crossorigin="anonymous">
  <source src="path/to/your-audio.mp3" type="audio/mpeg" />
  Your browser does not support the audio element.
</audio>

Step 2: Initialize Wavesurfer.js with the media Option

In modern versions of Wavesurfer.js (v7 and newer), you pass an existing HTMLMediaElement directly to the media parameter inside WaveSurfer.create().

import WaveSurfer from 'wavesurfer.js';

// Select the existing audio element
const audioElement = document.getElementById('my-audio');

// Initialize WaveSurfer
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  media: audioElement, // Pass the HTML5 audio element here
});

Legacy Wavesurfer.js (v6 and Earlier)

If you are using an older version of Wavesurfer.js (v6 or lower), passing an existing audio element requires selecting the MediaElement backend and passing the element to the load method or backend settings:

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  backend: 'MediaElement',
});

// Load the element directly
wavesurfer.load(audioElement);

Key Considerations

  • Synchronized State: When the media element is passed, Wavesurfer does not duplicate playback logic. Pausing, playing, or seeking via native controls, custom buttons, or clicking the waveform will keep both the audio element and the waveform in sync automatically.
  • CORS Restrictions: Web Audio API requires permissive Cross-Origin Resource Sharing (CORS) headers on the server serving the audio file. Without proper headers, the visual waveform cannot be decoded, even if the <audio> element can play the file natively.
  • Pre-computed Peaks: For long audio files streamed through an HTML5 audio tag, consider passing pre-computed peaks to WaveSurfer.create(). This avoids having to fetch the entire audio file into memory upfront just to draw the waveform.
