Update Wavesurfer.js Colors with CSS Variables

Using CSS custom properties (variables) alongside Wavesurfer.js allows developers to synchronize waveform styling with a centralized web application theme. Because Wavesurfer.js renders audio visualizations on an HTML5 <canvas> element rather than standard DOM nodes, it cannot automatically inherit CSS cascade rules. Instead, developers can read CSS custom properties via JavaScript and apply them dynamically to the waveColor and progressColor options, enabling seamless, runtime theme transitions such as dark mode toggles.

The Rendering Challenge with Canvas

Standard HTML elements update their appearance instantly when CSS variables change because the browser engine recalculates the DOM styles automatically. Wavesurfer.js, however, relies primarily on an HTML5 Canvas context. Pixels drawn to a canvas do not listen to CSS style updates directly. To apply colors defined in CSS stylesheets (such as --wave-color or --progress-color) to an audio track, JavaScript must act as the bridge between your CSS stylesheets and the Wavesurfer rendering engine.

Reading CSS Variables with JavaScript

To extract the current value of a CSS custom property, use the native getComputedStyle() method against the root element (document.documentElement) or the specific container housing the waveform:

:root {
  --waveform-background: #e2e8f0;
  --waveform-progress: #3b82f6;
}

[data-theme="dark"] {
  --waveform-background: #334155;
  --waveform-progress: #60a5fa;
}
const styles = getComputedStyle(document.documentElement);
const waveColor = styles.getPropertyValue('--waveform-background').trim();
const progressColor = styles.getPropertyValue('--waveform-progress').trim();

Trimming whitespace is essential because getPropertyValue() often returns strings with leading or trailing spaces, which can invalidate color parsing inside canvas contexts.

Initializing Wavesurfer with CSS Variables

Once read, pass these values into the initial Wavesurfer instance configuration:

import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: waveColor,
  progressColor: progressColor,
  url: '/audio-sample.mp3',
});

Driving Dynamic Theme Updates at Runtime

When a user switches themes, your application typically updates a class or data attribute on the <html> or <body> element. When this change occurs, retrieve the new variable values and pass them into the setOptions method provided by modern Wavesurfer.js:

function updateWaveformTheme() {
  const updatedStyles = getComputedStyle(document.documentElement);
  const newWaveColor = updatedStyles.getPropertyValue('--waveform-background').trim();
  const newProgressColor = updatedStyles.getPropertyValue('--waveform-progress').trim();

  wavesurfer.setOptions({
    waveColor: newWaveColor,
    progressColor: newProgressColor,
  });
}

Calling setOptions updates the instance configuration and triggers an internal redraw of the canvas elements, immediately reflecting the new colors without interrupting audio playback or requiring a complete reload of the waveform data.

Automating Updates with MutationObserver or System Preferences

To automate this synchronization without tightly coupling it to every theme toggle button, attach a MutationObserver to watch for attribute changes on the root element:

const observer = new MutationObserver((mutations) => {
  for (const mutation of mutations) {
    if (mutation.attributeName === 'data-theme' || mutation.attributeName === 'class') {
      updateWaveformTheme();
    }
  }
});

observer.observe(document.documentElement, { attributes: true });

If your application responds directly to system-level dark mode settings, you can also bind the update function to a media query listener:

window.matchMedia('(prefers-color-scheme: dark)').addEventListener('change', () => {
  updateWaveformTheme();
});

By abstracting your palette into CSS custom properties and using JavaScript to propagate values into setOptions, you maintain a single source of truth for all UI colors while keeping canvas-based audio components fully responsive to design changes.
