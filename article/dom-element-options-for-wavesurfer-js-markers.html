DOM Element Options for Wavesurfer.js Markers

This article explores the various DOM element rendering options available for markers in Wavesurfer.js. It details how the library generates visual indicators along the audio timeline, covering default DOM structures, custom HTML element injection, styling hooks, and structural configurations across both modern and legacy implementations of the library.

Built-In Marker DOM Elements

By default, Wavesurfer.js renders markers using standard HTML <div> elements injected directly into the waveform wrapper. When a marker is declared without custom templates, the library creates a container element that holds two primary sub-elements:

  • Marker Line: A vertical line element spanning the height of the waveform (or anchored to the top or bottom) to denote the precise point in time.
  • Marker Label/Visual: A wrapper element containing the text label, icon, or visual handle representing the marker point.

These elements are rendered inside the waveform's overlay container, positioned absolutely based on the calculated pixel offset corresponding to the marker's timestamp.

Custom HTML Element Injection

Developers are not limited to the default marker representations. Wavesurfer.js provides options to render fully custom DOM nodes:

  • Custom DOM Nodes: You can create an HTMLElement in JavaScript (such as an SVG icon, button, or complex card) and assign it directly to the marker configuration. In legacy versions via the Markers plugin, this is done via the markerElement property. In modern versions utilizing the Regions plugin for point markers, the content property accepts a raw HTMLElement.
  • HTML String Rendering: Modern Wavesurfer.js allows passing standard HTML markup as a string to the marker or point-region content. The library parses this string into standard DOM elements inside the marker’s container.

Positioning and Structural Placement

The rendering behavior of the DOM node can be altered structurally to fit different user interface needs:

  • Top vs. Bottom Anchoring: Markers can be aligned to render their handles or labels at the 'top' or 'bottom' edge of the waveform canvas. This changes the CSS positioning properties of the generated DOM nodes.
  • Full-Height Overlays: By configuring the marker line to span 100% of the canvas height, the DOM element functions as a full-height divider across the waveform tracks.
  • Drag Handles: If dragging is enabled, dedicated handle elements are appended to the DOM hierarchy, allowing user-driven timeline updates via mouse and touch events.

Class-Based CSS Customization

Every marker generated by Wavesurfer.js receives predefined CSS classes applied directly to its DOM container and child nodes. This architecture enables rendering modifications via external stylesheets without replacing the underlying nodes:

  • Custom Class Names: Custom class properties can be passed into the marker configuration, allowing scoped styles for specific marker types (such as loop points, cue points, or commentary markers).
  • Pseudo-Elements (::before / ::after): Because the markers are standard DOM nodes, CSS pseudo-elements can be used to inject custom tooltips, icons, or directional arrows without altering the JavaScript configuration.
