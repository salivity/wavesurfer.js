Wavesurfer.js Frequency Domain Data Array Lengths

This article provides an overview of the array length options available for frequency domain data when working with Wavesurfer.js. Because Wavesurfer.js relies on the Web Audio API to analyze audio signals, frequency data arrays are directly governed by the Fast Fourier Transform (FFT) configuration. Understanding the relationship between the FFT size and the resulting frequency bins allows developers to choose the optimal array length for their specific visualization and performance requirements.

Understanding Frequency Bin Count

When extracting frequency domain data in Wavesurfer.js (such as when building real-time visualizers or rendering spectrograms), data is processed using an AnalyserNode. Frequency domain data is written to a Uint8Array via getByteFrequencyData() or a Float32Array via getFloatFrequencyData().

The length of these typed arrays is strictly dictated by the analyzer's frequencyBinCount property. The frequencyBinCount is always exactly half of the configured fftSize:

\[\text{Array Length} = \frac{\text{fftSize}}{2}\]

Available Array Length Options

According to the Web Audio API specification, fftSize must be a power of two between \(2^5\) (32) and \(2^{15}\) (32768). Consequently, the array length options for frequency domain data are:

  • 16 (from fftSize: 32)
  • 32 (from fftSize: 64)
  • 64 (from fftSize: 128)
  • 128 (from fftSize: 256)
  • 256 (from fftSize: 512)
  • 512 (from fftSize: 1024)
  • 1024 (from fftSize: 2048, standard default)
  • 2048 (from fftSize: 4096)
  • 4096 (from fftSize: 8192)
  • 8192 (from fftSize: 16384)
  • 16384 (from fftSize: 32768)

The default array length is typically 1024 because standard Web Audio nodes default to an fftSize of 2048.

Configuring Array Length in Wavesurfer.js

Depending on how Wavesurfer.js is implemented, the frequency array length can be set in two primary ways:

  1. Using the Spectrogram Plugin:
    When configuring the Spectrogram plugin, you pass the fftSamples parameter. The value of fftSamples represents the fftSize. Setting fftSamples: 1024 generates frequency data with an array length of 512.

  2. Custom Web Audio Nodes:
    If you tap into the audio context using custom analyzer nodes connected to the Wavesurfer audio output or media element, you define analyser.fftSize. Allocating your data array should match this size:

    const analyser = wavesurfer.backend.analyser; // or custom audioContext AnalyserNode
analyser.fftSize = 512; // Must be power of 2 between 32 and 32768

// Array length will be 256
const frequencyData = new Uint8Array(analyser.frequencyBinCount);
analyser.getByteFrequencyData(frequencyData);

Choosing the Right Length

  • Smaller arrays (16 to 256 bins): Ideal for low-resolution, high-performance UI elements such as standard graphic equalizers or responsive bar visualizers where CPU usage must remain minimal.
  • Medium arrays (512 to 2048 bins): The standard range for general audio visualizers and waveform representations, providing a balanced trade-off between spectral detail and rendering frame rates.
  • Larger arrays (4096 to 16384 bins): Best suited for high-precision scientific analysis, detailed spectrogram views, or pitch detection, though they introduce higher processing overhead and temporal smearing.
