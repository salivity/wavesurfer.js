How to Track Playback Progress in Wavesurfer.js

Tracking playback progress as a percentage in Wavesurfer.js is a common requirement for displaying custom progress bars, updating numerical indicators, or syncing UI elements with audio. This guide demonstrates how to capture playback events, calculate the elapsed percentage using the current time and total duration, and handle user seeking to keep your interface accurate.

Listening to the Time Update Event

Wavesurfer.js provides built-in event listeners to monitor audio state changes. The primary event for tracking continuous playback is timeupdate. This event fires continuously as the audio plays, passing the current playback time in seconds to the callback function.

To calculate the percentage:

  1. Retrieve the current playback time from the event or via wavesurfer.getCurrentTime().
  2. Retrieve the total track length using wavesurfer.getDuration().
  3. Divide the current time by the total duration and multiply by 100.

Code Implementation

Here is a straightforward implementation using modern Wavesurfer.js (v7+):

import WaveSurfer from 'wavesurfer.js';

// Initialize WaveSurfer
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#violet',
  progressColor: '#purple',
  url: '/path/to/audio.mp3',
});

// Function to calculate and update progress
function updateProgress(currentTime) {
  const duration = wavesurfer.getDuration();
  
  if (duration > 0) {
    const percentage = (currentTime / duration) * 100;
    console.log(`Progress: ${percentage.toFixed(2)}%`);
    
    // Example: update a custom DOM progress element
    // document.getElementById('progress-bar').style.width = `${percentage}%`;
  }
}

// Track progress during regular playback
wavesurfer.on('timeupdate', (currentTime) => {
  updateProgress(currentTime);
});

// Track progress when the user seeks or clicks the waveform
wavesurfer.on('seeking', (currentTime) => {
  updateProgress(currentTime);
});

Handling Seeking and Edge Cases

The timeupdate event handles active playback, but users frequently click or drag across the waveform to seek to a specific position. Listening to the seeking event ensures your UI updates immediately when the position changes manually, even while playback is paused.

Additionally, always verify that wavesurfer.getDuration() returns a value greater than zero before performing the division to prevent NaN or Infinity errors before the audio metadata finishes loading. If you need to initialize the display before playback starts, listen to the ready event to safely access the track's total duration.
