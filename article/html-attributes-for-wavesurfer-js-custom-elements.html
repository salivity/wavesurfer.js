HTML Attributes for Wavesurfer.js Custom Elements

Wrapping Wavesurfer.js inside a custom HTML element (Web Component) allows developers to encapsulate audio playback logic and bind player state directly to the DOM. By mapping Wavesurfer's internal events to standard or custom HTML attributes, the component provides a declarative interface that can be easily styled using CSS selectors like :host([playing]) or queried using standard JavaScript DOM methods. This article covers the essential HTML attributes used to reflect the playback, loading, and configuration states of a Wavesurfer.js custom element wrapper.

Playback State Attributes

Playback states inform both the DOM and CSS whether audio is currently active. These are typically implemented as boolean attributes:

  • playing: Present when the audio is actively playing. It is typically added when Wavesurfer fires the play event and removed on pause or finish.
  • paused: Often toggled inversely to playing. While omitting playing implies a paused state, explicitly reflecting paused provides an intuitive selector for styling pause buttons or dimmed visualizations.
  • ended: Added when the playback reaches the end of the track (via the finish event). It is removed if playback restarts or if the user seeks to an earlier time.

Lifecycle and Loading Attributes

Wavesurfer.js must fetch, decode, and render the audio waveform before full interaction is possible. Lifecycle attributes signal these background processes:

  • loading: Added as soon as a source file begins downloading and decoding (often listening to load or loading events). It is removed once the audio is ready for interaction.
  • ready: Added when Wavesurfer fires the ready event, indicating that the audio buffer has been decoded and the waveform is fully drawn. This is ideal for enabling transport controls.
  • error: Added if the audio source fails to fetch or decode via the error event. It can be paired with an attribute like error-message to expose human-readable debugging details to the DOM.

Audio Configuration Attributes

Certain attributes reflect the runtime settings applied to the audio pipeline:

  • muted: A boolean attribute that reflects whether the audio output is currently muted, mapped to the ws.setMuted() method or volume change events.
  • volume: A numeric string attribute (e.g., volume="0.8") reflecting the current volume level between 0 and 1.
  • loop: A boolean attribute indicating whether the audio will automatically replay once it reaches the end.
  • src: A standard attribute defining the audio track URL. Changing this attribute via attributeChangedCallback typically triggers Wavesurfer's load() method to swap the active track.

Time Tracking Attributes

While high-frequency updates can cause DOM thrashing if not managed carefully, custom elements often reflect high-level time data:

  • duration: A numeric string representing the total track length in seconds, populated once the decode or ready event resolves.
  • current-time: Frequently throttled (e.g., updating once per second via the timeupdate event) to reflect current playback progress in seconds for CSS counters or external bindings.

Implementation Pattern

To keep attributes synchronized without performance bottlenecks, custom element wrappers use standard element methods inside Wavesurfer event listeners:

// Synchronizing playing state
wavesurfer.on('play', () => this.toggleAttribute('playing', true));
wavesurfer.on('pause', () => this.removeAttribute('playing'));

// Synchronizing readiness
wavesurfer.on('ready', () => {
  this.removeAttribute('loading');
  this.toggleAttribute('ready', true);
});

Using toggleAttribute() within event callbacks ensures the host element accurately mirrors the internal state of Wavesurfer.js, simplifying integration across modern web applications.
