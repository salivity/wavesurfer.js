Support High-DPI Retina Displays in Wavesurfer.js

Rendering crisp audio waveforms on high-DPI and Retina displays requires configuring the HTML5 canvas to account for higher pixel densities. This article explains why default canvas waveforms appear blurry on modern screens, how Wavesurfer.js manages high-DPI rendering internally, and how to implement canvas pixel-ratio scaling manually when building custom plugins or working with older versions of the library.

Understanding the High-DPI Canvas Problem

Standard HTML5 <canvas> elements use a default 1:1 pixel mapping. On high-DPI displays (such as Apple Retina screens or 4K monitors), the operating system uses a higher physical pixel density, indicated by window.devicePixelRatio (often 2 or 3).

If a canvas with a width of 800 CSS pixels has its internal bitmap dimensions also set to 800 pixels, a Retina display with a devicePixelRatio of 2 stretches that 800-pixel bitmap across 1600 physical hardware pixels. This interpolation causes lines, text, and audio waveform peaks to look soft, fuzzy, or visibly pixelated.

Default Behavior in Wavesurfer.js v7+

Recent versions of Wavesurfer.js automatically query window.devicePixelRatio during waveform initialization and resize events. When rendering waveforms with the standard Web Audio or Canvas renderer, the library scales the internal drawing buffer to match the device's hardware pixels while constraining the layout size with CSS.

If your waveform appears sharp out of the box in Wavesurfer.js v7+, no additional configuration is required unless you are bypassing the core renderer.

Manual High-DPI Scaling for Custom Renderers and Plugins

If you are developing a custom Wavesurfer.js drawer, extending an existing plugin, or utilizing an older version of the library (v6 or earlier), you must explicitly synchronize the canvas drawing buffer with the screen's pixel ratio.

High-DPI canvas correction requires three steps:

  1. Increase the internal canvas width and height by the devicePixelRatio.
  2. Lock the visual canvas width and height using inline CSS to the original logical size.
  3. Scale the 2D rendering context so drawing coordinates remain unchanged.

Here is the implementation:

function setupHighDPICanvas(canvas, width, height) {
  const ctx = canvas.getContext('2d');
  const dpr = window.devicePixelRatio || 1;

  // Set visual dimensions via CSS
  canvas.style.width = `${width}px`;
  canvas.style.height = `${height}px`;

  // Scale internal bitmap dimensions by pixel ratio
  canvas.width = Math.floor(width * dpr);
  canvas.height = Math.floor(height * dpr);

  // Normalize coordinate system so drawing logic uses CSS pixels
  ctx.scale(dpr, dpr);

  return ctx;
}

Implementing in Wavesurfer.js Custom Draw Loops

When overriding wavesurfer.drawer or creating custom canvas overlays, apply the scaling factor directly to peak measurements and canvas operations:

const dpr = window.devicePixelRatio || 1;
const container = document.querySelector('#waveform');
const width = container.clientWidth;
const height = 128; // Desired height in CSS pixels

const canvas = document.createElement('canvas');
const ctx = canvas.getContext('2d');

canvas.width = width * dpr;
canvas.height = height * dpr;
canvas.style.width = `${width}px`;
canvas.style.height = `${height}px`;

ctx.scale(dpr, dpr);

// Render waveform peaks using standard coordinates
peaks.forEach((peak, index) => {
  const x = index;
  const y = (height / 2) - (peak * (height / 2));
  const barHeight = peak * height;

  ctx.fillStyle = '#4a90e2';
  ctx.fillRect(x, y, 1, barHeight);
});

Handling Multi-Monitor DPI Changes

Users frequently drag browser windows between standard-DPI and high-DPI monitors. To prevent the waveform from degrading when moved across screens with different pixel densities, listen for resolution changes using window.matchMedia:

function monitorDpiChanges(wavesurfer) {
  const mediaQuery = window.matchMedia(`(resolution: ${window.devicePixelRatio}dppx)`);

  mediaQuery.addEventListener('change', () => {
    // Force Wavesurfer.js to recompute dimensions and redraw
    wavesurfer.drawer.recalculateWidth();
    wavesurfer.drawBuffer();
    
    // Rebind listener for the new pixel ratio
    monitorDpiChanges(wavesurfer);
  }, { once: true });
}

Using this approach guarantees that waveform visuals remain crisp across all display densities, window resizes, and multi-monitor setups.
