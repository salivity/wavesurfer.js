Save and Load Wavesurfer.js Regions with a Database

This article explains how to persist audio annotations and segment markers created with the Wavesurfer.js Regions plugin to a backend database. You will learn how to extract region coordinates from the client-side instance, serialize and transmit the data via a REST API, and fetch and re-render the saved regions when the audio waveform loads.

Initializing Wavesurfer and the Regions Plugin

To work with regions in modern Wavesurfer.js (version 7+), register the RegionsPlugin during initialization.

import WaveSurfer from 'wavesurfer.js';
import RegionsPlugin from 'wavesurfer.js/dist/plugins/regions.esm.js';

const wsRegions = RegionsPlugin.create();

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: '/path/to/audio.mp3',
  plugins: [wsRegions],
});

Formatting the Region Data

A region is defined by key properties such as id, start, end, color, and optional metadata like content (labels) or custom data objects. Before sending data to the server, extract these values into a JSON-friendly array:

function getSerializedRegions() {
  return wsRegions.getRegions().map(region => ({
    id: region.id,
    start: region.start,
    end: region.end,
    content: region.content?.innerText || '',
    color: region.color
  }));
}

Saving Regions to the Backend

You can trigger a save operation either via explicit user action (like a "Save" button) or automatically by listening to plugin lifecycle events such as region-created, region-updated, and region-removed.

Here is an implementation using a dedicated save function:

async function saveRegionsToDatabase(audioId) {
  const payload = getSerializedRegions();

  try {
    const response = await fetch(`/api/audio/${audioId}/regions`, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({ regions: payload }),
    });

    if (!response.ok) {
      throw new Error(`Server error: ${response.statusText}`);
    }

    const result = await response.json();
    console.log('Regions saved successfully:', result);
  } catch (error) {
    console.error('Failed to save regions:', error);
  }
}

If you prefer auto-saving after a user drags or resizes a region, attach the request to the region-updated event:

wsRegions.on('region-updated', (region) => {
  // Update a single region in the database
  fetch(`/api/regions/${region.id}`, {
    method: 'PUT',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      start: region.start,
      end: region.end,
    }),
  });
});

Loading Regions from the Backend

Regions should only be added once the audio file metadata has loaded, ensuring time durations are valid. Use the Wavesurfer ready or decode event to trigger the database fetch.

wavesurfer.on('ready', async () => {
  const audioId = '123'; // Dynamic audio identifier
  await loadRegionsFromDatabase(audioId);
});

async function loadRegionsFromDatabase(audioId) {
  try {
    const response = await fetch(`/api/audio/${audioId}/regions`);
    const data = await response.json();

    // Clear any existing client-side regions before populating
    wsRegions.clearRegions();

    // Iterate through fetched records and render
    data.regions.forEach(regionData => {
      wsRegions.addRegion({
        id: regionData.id,
        start: regionData.start,
        end: regionData.end,
        content: regionData.content,
        color: regionData.color || 'rgba(0, 123, 255, 0.3)',
        drag: true,
        resize: true,
      });
    });
  } catch (error) {
    console.error('Failed to load regions:', error);
  }
}

Handling Deletions

When a region is removed in the UI, ensure that removal is reflected in the database. Listen for the region-removed event:

wsRegions.on('region-removed', (region) => {
  fetch(`/api/regions/${region.id}`, {
    method: 'DELETE',
  }).catch(err => console.error('Failed to delete region:', err));
});

Database Schema Considerations

When designing your backend schema (SQL or NoSQL), store the following fields at minimum:

  • id: String or UUID to match Wavesurfer's internal identifiers.
  • audio_id: Foreign key mapping the region to a specific audio track.
  • start: Float representing the start time in seconds.
  • end: Float representing the end time in seconds.
  • content: Text column for transcripts, tags, or notes.
  • color: String representing the CSS RGBA/HEX color.
