Compute Wavesurfer.js Peaks with Web Workers

This article explains how to offload audio peak computation to a background Web Worker to enhance performance when using Wavesurfer.js. Processing raw audio buffers directly on the browser's main thread causes frame drops and interface freezing, particularly with long audio tracks. By delegating downsampling and amplitude peak extraction to a dedicated Web Worker and passing the resulting array to Wavesurfer.js, you maintain a fluid user interface while accelerating waveform rendering.

The Problem with Main-Thread Peak Calculation

When Wavesurfer.js renders a waveform, it must analyze the decoded audio channel data, slice it into segments corresponding to pixel widths, and extract the minimum and maximum amplitude values (peaks) for each segment. Because JavaScript on the main thread shares execution time with user interactions, animations, and DOM rendering, performing millions of array operations blocks the browser. Moving this mathematical downsampling to a Web Worker keeps the main thread responsive.

Step 1: Create the Web Worker (peak-worker.js)

The Web Worker receives the raw channel data (or an ArrayBuffer) and the target number of peaks to generate. It slices the sample array into evenly spaced chunks and determines the peak values for each chunk.

// peak-worker.js
self.onmessage = function (e) {
  const { channelData, targetLength } = e.data;
  const sampleSize = channelData.length / targetLength;
  const peaks = [];

  for (let i = 0; i < targetLength; i++) {
    const start = Math.floor(i * sampleSize);
    const end = Math.floor((i + 1) * sampleSize);
    let min = 0;
    let max = 0;

    for (let j = start; j < end; j++) {
      const value = channelData[j];
      if (value > max) {
        max = value;
      } else if (value < min) {
        min = value;
      }
    }

    // Wavesurfer.js accepts alternating [min, max, min, max] or separate channels
    peaks.push(max);
  }

  // Return computed peaks back to the main thread
  self.postMessage({ peaks });
};

Step 2: Decode Audio and Delegate to the Worker

On the main thread, fetch the audio file and decode it into an AudioBuffer using the browser's native AudioContext. Once decoded, extract the channel data and send it to the worker.

const audioContext = new (window.AudioContext || window.webkitAudioContext)();
const worker = new Worker('peak-worker.js');

async function processAudioPeaks(audioUrl, targetPeaksCount) {
  // Fetch audio file
  const response = await fetch(audioUrl);
  const arrayBuffer = await response.arrayBuffer();

  // Decode audio data
  const audioBuffer = await audioContext.decodeAudioData(arrayBuffer);
  const channelData = audioBuffer.getChannelData(0); // Primary channel

  return new Promise((resolve) => {
    worker.onmessage = (event) => {
      resolve(event.data.peaks);
    };

    // Transfer the channel data to the worker
    worker.postMessage({
      channelData: channelData,
      targetLength: targetPeaksCount
    });
  });
}

Step 3: Render Waveform with Precomputed Peaks

Wavesurfer.js provides a peaks parameter in its initialization and .load() methods. When precomputed peaks are provided, Wavesurfer skips internal peak computation entirely and draws the waveform immediately.

import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F46E5',
  progressColor: '#818CF8',
});

async function init() {
  const audioUrl = '/path/to/audio.mp3';
  const containerWidth = document.querySelector('#waveform').clientWidth;

  // Compute peaks using the worker (e.g., 1 peak per 2 pixels)
  const targetPeaksCount = Math.floor(containerWidth / 2);
  const peaks = await processAudioPeaks(audioUrl, targetPeaksCount);

  // Load into Wavesurfer with precalculated peaks
  wavesurfer.load(audioUrl, [peaks]);
}

init();

Optimizations and Best Practices

  • Transferable Objects: If decoding raw byte streams within the worker, pass ArrayBuffer instances using transfer lists (worker.postMessage(buffer, [buffer])) to avoid memory duplication.
  • Server-Side Fallbacks: For static audio libraries, consider running peak calculation workers once on the server or storing the generated peaks in a database. When peaks are fetched alongside track metadata as a JSON array, the client completely bypasses both decoding and calculation.
  • Worker Termination: Once peak extraction is complete, call worker.terminate() if the worker is no longer needed, freeing up system resources.
