Cache Audio and Peaks for Offline Wavesurfer.js

Progressive Web Apps (PWAs) deliver seamless offline audio playback and waveform visualization by coupling Service Worker caching strategies with Wavesurfer.js precomputed peak rendering. By storing both the raw audio file and its corresponding peak JSON data in browser storage—such as the Cache Storage API or IndexedDB—a PWA eliminates network dependency and bypasses the CPU-heavy decoding process required to draw waveforms on constrained devices.

Precomputing Peaks to Eliminate Offline Overhead

By default, Wavesurfer.js downloads an entire audio file and decodes it using the browser's Web Audio API (AudioContext.decodeAudioData) to calculate waveform peaks. In an offline environment, especially on mobile devices, this decoding process consumes significant battery, memory, and CPU resources.

To optimize performance, generate peak data on the server during ingestion using tools like audiowaveform. Export the peaks as a JSON array containing normalized floating-point or integer min/max points. This lightweight JSON file can be fetched and cached independently, allowing Wavesurfer.js to draw the visual waveform instantly offline before or even without decoding the full audio track.

Caching Assets via the Service Worker

A Service Worker acts as a network proxy that intercepts requests and serves cached responses when the app is offline. Both the audio file and the peak JSON should be handled through a Cache-First or Stale-While-Revalidate strategy using the Cache Storage API.

self.addEventListener('fetch', (event) => {
  const url = new URL(event.request.url);

  // Match audio files and peak JSON endpoints
  if (url.pathname.endsWith('.json') || url.pathname.endsWith('.mp3')) {
    event.respondWith(
      caches.match(event.request).then((cachedResponse) => {
        if (cachedResponse) {
          return cachedResponse;
        }
        return fetch(event.request).then((networkResponse) => {
          return caches.open('audio-cache-v1').then((cache) => {
            cache.put(event.request, networkResponse.clone());
            return networkResponse;
          });
        });
      })
    );
  }
});

Handling Audio HTTP Range Requests

A major obstacle when caching media files in PWAs is that modern browsers use HTTP Range requests (206 Partial Content) to stream audio. The native Cache API does not automatically resolve range requests against a cached 200 OK full-file response.

To resolve this issue, implement an explicit range request handler inside the Service Worker. When an event.request.headers.get('range') is detected, retrieve the complete cached audio ArrayBuffer, slice the specified byte range, and return a custom Response with status 206 along with the appropriate Content-Range and Content-Length headers. Alternatively, utilizing Workbox and its workbox-range-requests plugin automates this logic entirely.

Storing Data in IndexedDB

An alternative or complementary approach to the Cache API is storing audio files and peak data directly in IndexedDB. IndexedDB is structured, supports large binary data via Blob objects, and works natively within both window and worker scopes.

  1. Fetch the peak JSON and save it as an object or parsed array under a unique track ID.
  2. Fetch the audio file as a Blob and save it directly in the same record.
  3. When offline, retrieve the record directly from IndexedDB without going through the Service Worker fetch pipeline.

Loading Cached Data into Wavesurfer.js

Once the peak JSON and the audio file are retrieved from either storage mechanism, pass them into Wavesurfer.js. When using precomputed peaks, supply the peaks directly to the load method alongside the audio URL or Object URL:

async function initOfflinePlayer(audioKey) {
  // Retrieve peak JSON and Audio Blob from cache or IndexedDB
  const peakResponse = await caches.match(`/data/${audioKey}-peaks.json`);
  const peakData = await peakResponse.json();

  const audioResponse = await caches.match(`/media/${audioKey}.mp3`);
  const audioBlob = await audioResponse.blob();
  const audioUrl = URL.createObjectURL(audioBlob);

  const wavesurfer = WaveSurfer.create({
    container: '#waveform',
    waveColor: '#4F4A85',
    progressColor: '#383351',
    backend: 'MediaElement' // Uses HTML5 Audio element for efficient streaming
  });

  // Render the precomputed peaks immediately
  wavesurfer.load(audioUrl, peakData.data);
}

By decoupling waveform visualization from raw audio decoding and configuring resilient offline storage, PWAs provide immediate rendering and uninterrupted audio playback regardless of network availability.
