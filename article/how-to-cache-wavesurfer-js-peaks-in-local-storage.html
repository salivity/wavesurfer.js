How to Cache Wavesurfer.js Peaks in LocalStorage

Generating audio waveforms dynamically on the client side requires decoding the entire audio file, which consumes significant CPU and memory. This guide explains how to extract exported peak data from Wavesurfer.js, serialize it, and store it directly inside the browser's localStorage. By checking for cached peaks before rendering, your web application can bypass the expensive decoding phase and display interactive audio waveforms almost instantly on subsequent page visits.

Extracting and Storing Peak Data

Wavesurfer.js provides an exportPeaks() method that returns an array of floating-point numbers representing the minimum and maximum audio amplitudes. Because localStorage only accepts strings, this array must be serialized using JSON.stringify() before storage.

To avoid redundant computations, save the peaks immediately after the initial audio decoding event:

// Initialize Wavesurfer without peaks on first load
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F46E5',
  progressColor: '#818CF8',
  url: '/path/to/audio.mp3'
});

// Once audio is decoded, export and cache the peaks
wavesurfer.on('decode', () => {
  const peaks = wavesurfer.exportPeaks();
  try {
    localStorage.setItem('audio_peaks_track_1', JSON.stringify(peaks));
  } catch (error) {
    console.error('Failed to save peaks to localStorage:', error);
  }
});

Retrieving and Rendering from the Cache

When the user returns to the page, check if the peaks exist in localStorage. If found, parse the JSON data and pass it directly to the peaks configuration property during the WaveSurfer.create() initialization. When the peaks option is provided alongside the url, Wavesurfer renders the waveform immediately without waiting to fetch and decode the entire audio file.

const storageKey = 'audio_peaks_track_1';
const cachedData = localStorage.getItem(storageKey);
let cachedPeaks = null;

if (cachedData) {
  try {
    cachedPeaks = JSON.parse(cachedData);
  } catch (error) {
    console.error('Failed to parse cached peaks:', error);
    localStorage.removeItem(storageKey);
  }
}

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F46E5',
  progressColor: '#818CF8',
  url: '/path/to/audio.mp3',
  peaks: cachedPeaks // Wavesurfer uses these peaks directly
});

// Only bind the caching event if peaks were not already cached
if (!cachedPeaks) {
  wavesurfer.on('decode', () => {
    const peaks = wavesurfer.exportPeaks();
    try {
      localStorage.setItem(storageKey, JSON.stringify(peaks));
    } catch (error) {
      console.warn('Storage limit exceeded or unavailable:', error);
    }
  });
}

Key Considerations

  • Storage Limits: Standard localStorage is restricted to roughly 5MB per origin. For long audio files or multiple tracks, an array of high-precision floats can quickly consume this quota. If peak data causes quota errors, consider rounding the float values to two decimal places before stringifying, or switch to IndexedDB for larger datasets.
  • Cache Invalidation: Always tie the storage key to a version or hash of the source audio file (for example, audio_peaks_track_1_v2). If the underlying audio file is replaced or edited, the stored peaks must be invalidated to prevent rendering mismatched waveforms.
