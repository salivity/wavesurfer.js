Understanding the Wavesurfer.js seekTo Method

This guide provides a focused breakdown of the seekTo method in Wavesurfer.js, explaining its core purpose, parameter requirements, and internal behavior. You will learn how the method translates relative values into audio playback positions, how it synchronizes the visual waveform canvas, and how to properly implement it in your web audio projects.

The seekTo method is a built-in function of the Wavesurfer.js audio visualization library used to move the playback position to a specific point along an audio track. Unlike methods that accept direct timestamps in seconds, seekTo strictly requires a normalized floating-point number between 0 and 1. In this scale, 0 represents the start of the audio file, 0.5 represents the exact midpoint, and 1 represents the end of the track.

When seekTo(progress) is executed, Wavesurfer.js performs several synchronous operations:

  1. Calculates Target Time: The library multiplies the passed float by the total audio duration (targetTime = progress * duration) to derive the exact playback time in seconds.
  2. Updates the Audio Engine: The underlying audio playback source—whether utilizing the HTML5 MediaElement or Web Audio API context—updates its currentTime to match the calculated target time.
  3. Redraws the Waveform: The visual playhead, progress bar overlay, and cursor are redrawn instantly to reflect the new position on the canvas. If horizontal scrolling is enabled, the container automatically scrolls to bring the current playhead into view.
  4. Dispatches Events: The method fires relevant event listeners, primarily the seek event (passing the normalized progress), allowing other UI elements to respond to the manual navigation.
// Seek directly to 25% of the total audio duration
wavesurfer.seekTo(0.25);

// Seek to a specific timestamp in seconds (e.g., 30 seconds)
const targetSeconds = 30;
const totalDuration = wavesurfer.getDuration();
wavesurfer.seekTo(targetSeconds / totalDuration);

The method maintains the existing playback state. If the audio is actively playing when seekTo is called, playback continues immediately from the new position. If the audio is paused, the playhead moves to the target point while remaining paused, displaying the updated frame to the user without generating unwanted audio output.
