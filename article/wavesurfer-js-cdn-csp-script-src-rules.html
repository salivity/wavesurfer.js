Wavesurfer.js CDN CSP script-src Rules

Configuring Content Security Policy (CSP) headers for Content Delivery Network (CDN) builds of Wavesurfer.js requires permitting external script sources while handling audio decoding and web worker operations. This guide details the exact script-src directives, hash or nonce alternatives, and related policy requirements necessary to run CDN-hosted Wavesurfer.js securely without triggering console violations.

Direct Domain Allowlisting

If you load Wavesurfer.js directly from a public CDN via a <script> tag, the primary CDN host must be explicitly allowed in the script-src directive.

Depending on your CDN of choice, use one of the following domain patterns:

  • cdnjs: script-src 'self' https://cdnjs.cloudflare.com;
  • unpkg: script-src 'self' https://unpkg.com;
  • jsDelivr: script-src 'self' https://cdn.jsdelivr.net;

To support versioned subpaths or multiple CDNs, you can combine origins:

Content-Security-Policy: script-src 'self' https://unpkg.com https://cdnjs.cloudflare.com;

Using Nonces or Hashes for Stricter Security

For environments implementing strict CSP without broad domain wildcards, employ a cryptographic nonce or an integrity hash.

Nonce-Based Policy

Generate a random, base64-encoded nonce per request on your server, apply it to the header, and add it to the CDN script tag.

  • Header:

    Content-Security-Policy: script-src 'self' 'nonce-rAnd0m12345';

  • HTML:

    <script src="https://unpkg.com/wavesurfer.js@7/dist/wavesurfer.min.js" nonce="rAnd0m12345"></script>

Hash-Based Policy

Calculate the SHA-256, SHA-384, or SHA-512 hash of the exact CDN file contents:

Content-Security-Policy: script-src 'self' 'sha256-abcdef...';

Handling Web Workers and Blob URLs

Wavesurfer.js utilizes Web Workers for decoding audio files and rendering waveforms off the main thread. In many CDN bundles, workers are instantiated using inline Blob URLs (URL.createObjectURL(blob)).

When using Blob-based workers, modern browsers check the worker-src directive, falling back to script-src if worker-src is omitted. To avoid execution errors, ensure blob: is included:

Content-Security-Policy: script-src 'self' https://unpkg.com blob:; worker-src 'self' blob:;

If your configuration does not define worker-src, blob: must be present in script-src:

Content-Security-Policy: script-src 'self' https://unpkg.com blob:;

Supporting Directives for Wavesurfer.js

While not part of script-src, Wavesurfer.js requires the following directives to function when fetching audio and running across domains:

  • connect-src: Wavesurfer fetches remote audio files via fetch or XMLHttpRequest. Add your audio host and CDN (if fetching source maps):

    connect-src 'self' https://your-audio-bucket.example.com;

  • media-src: Required if using the MediaElement backend (wavesurfer.create({ backend: 'MediaElement' })):

    media-src 'self' https://your-audio-bucket.example.com blob:;

Recommended Production Configuration

A comprehensive CSP configuration accommodating modern Wavesurfer.js (v7+) loaded via unpkg looks like:

Content-Security-Policy: default-src 'self'; script-src 'self' https://unpkg.com blob:; worker-src 'self' blob:; connect-src 'self' https://your-audio-bucket.example.com; media-src 'self' https://your-audio-bucket.example.com blob:; style-src 'self' 'unsafe-inline';
