How to Add ARIA Attributes to Wavesurfer.js

Wavesurfer.js creates customizable, interactive audio waveforms using the HTML5 Canvas or Web Audio API, but it does not include accessible Rich Internet Applications (ARIA) attributes by default. This guide explains how to add essential ARIA roles, static labels, and dynamic states to your Wavesurfer.js container so screen readers and other assistive technologies can interpret and interact with the audio waveform.

1. Set Up Initial Container Attributes

Because a waveform serves both as an audio visualizer and an interactive scrubber, the container element should typically be designated with role="slider" or role="region". If users can click or drag across the waveform to seek audio, treating it as a slider is best for accessibility.

You can declare static ARIA attributes directly in your HTML container:

<div 
  id="waveform" 
  role="slider" 
  tabindex="0"
  aria-label="Audio scrubber"
  aria-valuemin="0" 
  aria-valuenow="0" 
  aria-valuetext="0 seconds">
</div>

Alternatively, you can attach these attributes programmatically via JavaScript using setAttribute:

const container = document.querySelector('#waveform');

container.setAttribute('role', 'slider');
container.setAttribute('tabindex', '0');
container.setAttribute('aria-label', 'Audio scrubber');
container.setAttribute('aria-valuemin', '0');
container.setAttribute('aria-valuenow', '0');

2. Update Dynamic Values with Wavesurfer Events

For an interactive scrubber, screen readers require dynamic updates to aria-valuemax, aria-valuenow, and human-readable formats via aria-valuetext. Listen to Wavesurfer.js lifecycle events—specifically ready and timeupdate (or audioprocess in older versions)—to update these values.

import WaveSurfer from 'wavesurfer.js';

const container = document.getElementById('waveform');

const wavesurfer = WaveSurfer.create({
  container: container,
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: '/path/to/audio.mp3',
});

// Update maximum value once the audio file metadata is loaded
wavesurfer.on('ready', () => {
  const duration = Math.round(wavesurfer.getDuration());
  container.setAttribute('aria-valuemax', duration);
});

// Update current progress during playback or seeking
wavesurfer.on('timeupdate', (currentTime) => {
  const currentSeconds = Math.round(currentTime);
  container.setAttribute('aria-valuenow', currentSeconds);
  container.setAttribute('aria-valuetext', `${currentSeconds} seconds`);
});

3. Add Keyboard Navigation Support

Adding ARIA roles such as role="slider" creates an expectation that the element can be manipulated via keyboard inputs (such as the Left and Right Arrow keys). Add a standard keyboard event listener to the container to alter audio playback position accordingly:

container.addEventListener('keydown', (event) => {
  const step = 5; // Skip duration in seconds
  const currentTime = wavesurfer.getCurrentTime();
  const duration = wavesurfer.getDuration();

  if (event.key === 'ArrowRight') {
    event.preventDefault();
    wavesurfer.setTime(Math.min(currentTime + step, duration));
  } else if (event.key === 'ArrowLeft') {
    event.preventDefault();
    wavesurfer.setTime(Math.max(currentTime - step, 0));
  } else if (event.key === ' ') {
    event.preventDefault();
    wavesurfer.playPause();
  }
});

4. Hide Generated Canvas Elements from Assistive Tech

Wavesurfer.js automatically injects shadow DOM elements, wrappers, or <canvas> elements into the designated container. Because these elements are purely visual representations of the audio signal, they can confuse screen readers. Set aria-hidden="true" on internal canvas elements once initialized:

wavesurfer.on('ready', () => {
  const visualElements = container.querySelectorAll('canvas');
  visualElements.forEach((el) => {
    el.setAttribute('aria-hidden', 'true');
  });
});
