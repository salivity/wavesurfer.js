Responsive Wavesurfer.js Waveforms for Mobile

Wavesurfer.js generates audio visualizers using HTML5 Canvas elements, which means standard CSS media queries cannot alter internal waveform dimensions like bar widths and heights directly. To create a responsive waveform that adapts to mobile screens, developers must bridge CSS viewport detection with JavaScript by using window.matchMedia or the ResizeObserver API. This guide explains how to listen for mobile breakpoints and dynamically update Wavesurfer.js parameters such as height, barWidth, and barGap to maintain clarity and usability on smaller screens.

Why Standard CSS Media Queries Are Insufficient

Wavesurfer.js draws waveforms onto an HTML5 <canvas> element using a fixed pixel density. Applying CSS rules like height: 50px or scaling the canvas via CSS stretches or squishes the rendered audio bars, leading to blurry, distorted visuals.

To properly scale the waveform without distortion, the canvas must be redrawn using updated configuration properties. This requires passing new numeric values for the height and bar dimensions directly to the Wavesurfer instance whenever the screen size crosses a designated threshold.

Implementing JavaScript Media Queries with window.matchMedia

The most direct way to replicate CSS media queries in JavaScript is the window.matchMedia() API. This method allows you to evaluate media query strings—such as (max-width: 768px)—and attach event listeners that fire whenever the viewport crosses that boundary.

When a mobile breakpoint is matched, you adjust specific Wavesurfer configuration options:

  • height: Reduced for mobile screens to conserve limited vertical space.
  • barWidth: Set to a smaller value (or omitted for a continuous line) to ensure fine audio details fit within a narrow horizontal viewport.
  • barGap: Scaled down proportionally to avoid excessive whitespace between audio bars.

Dynamic Reconfiguration Using setOptions

In modern versions of Wavesurfer.js (v7+), the setOptions() method allows you to alter configuration properties at runtime and automatically trigger a re-render:

// Define the mobile media query
const mobileQuery = window.matchMedia('(max-width: 768px)');

// Function to determine settings based on viewport size
function getResponsiveOptions(isMobile) {
  return {
    height: isMobile ? 60 : 128,
    barWidth: isMobile ? 2 : 4,
    barGap: isMobile ? 1 : 3,
  };
}

// Initialize Wavesurfer with the initial viewport configuration
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F46E5',
  progressColor: '#818CF8',
  url: '/audio-sample.mp3',
  ...getResponsiveOptions(mobileQuery.matches),
});

// Listen for viewport changes (orientation shifts, window resizing)
mobileQuery.addEventListener('change', (e) => {
  wavesurfer.setOptions(getResponsiveOptions(e.matches));
});

Handling Continuous Container Resizing

While window.matchMedia works well for distinct mobile and desktop breakpoints, modern responsive layouts often use fluid grids or split views where container widths change incrementally.

To adapt the waveform dimensions dynamically to the container rather than just the window:

  1. Use ResizeObserver: Monitor the parent container of the waveform.
  2. Debounce Updates: Re-rendering canvas elements can be computationally expensive. Debouncing resize events ensures that setOptions() is not called on every single pixel adjustment during a window drag.
  3. Calculate Proportional Bar Widths: Calculate barWidth and barGap programmatically based on the measured clientWidth of the container to maintain a consistent number of bars regardless of screen size.
