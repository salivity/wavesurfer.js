Word Alignment Data Structures for Wavesurfer.js

Integrating word-level alignment timestamps with Wavesurfer.js requires a data structure that balances rapid lookup performance during playback, low memory overhead, and efficient scrubbing response. Because the audio player frequently fires update events, the chosen structure must quickly map a floating-point playback timestamp to a specific word or span of words without dropping frames. This guide analyzes the most effective data structures for organizing timestamped words, their trade-offs, and how to apply them for synchronized text rendering in Wavesurfer.js.

1. Sorted Array with a Moving Cursor (Optimal for Standard Playback)

The most memory-efficient and straightforward data structure is a flat array of word objects sorted strictly by their start times:

[
  { "word": "Welcome", "start": 0.12, "end": 0.54 },
  { "word": "to",      "start": 0.56, "end": 0.68 },
  { "word": "the",     "start": 0.70, "end": 0.81 },
  { "word": "demo",    "start": 0.83, "end": 1.25 }
]

Performance Characteristics

  • Sequential Playback: \(O(1)\). By tracking an active word pointer index, checking if the current time still falls within the active word—or moving to the immediate next index—requires constant time during standard audioprocess or timeupdate events.
  • Random Access (Seeking): \(O(\log n)\). When a user clicks a new position on the waveform, a standard binary search (bisection) quickly identifies the word matching the target timestamp.
  • Memory Overhead: Negligible. Flat arrays minimize pointer dereferencing and optimize CPU cache locality.

2. Interval Tree (Best for Overlapping Words and Multi-Speaker Audio)

Standard sorted arrays struggle when audio features multiple speakers speaking simultaneously, where words overlap in time. An Interval Tree stores temporal intervals [start, end] in a balanced search tree.

Performance Characteristics

  • Query Time: \(O(\log n + k)\), where \(k\) is the number of overlapping words returned for a given timestamp.
  • Space Complexity: \(O(n)\).
  • Use Case: Multi-track transcription, speaker diarization overlays, and conversational audio where timestamps are not strictly monotonic.

3. Time-Bucketed Hash Map (Best for Long-Form Audio)

For extremely long audio files containing tens of thousands of words, iterating through arrays or trees can introduce micro-delays. A time-bucketed map divides the timeline into fixed segments (such as 1-second or 5-second intervals).

const buckets = {
  0: [ /* words starting between 0.00s and 0.99s */ ],
  1: [ /* words starting between 1.00s and 1.99s */ ],
  2: [ /* words starting between 2.00s and 2.99s */ ]
};

Performance Characteristics

  • Lookup Time: \(O(1)\) to find the bucket via Math.floor(currentTime), followed by a brief scan of the tiny subset array containing only the words within that second.
  • Space Complexity: \(O(n)\), with minor overhead for bucket key references.
  • Use Case: Transcripts exceeding one hour, podcast transcription, or audiobooks where avoiding binary search tree traversal yields a consistent response budget.

Direct Wavesurfer.js Regions Integration

Wavesurfer.js provides a Regions plugin that can represent each word visually. While you can feed word intervals directly into regions.addRegion(), rendering thousands of DOM elements simultaneously degrades browser rendering performance.

To maintain 60 FPS playback:

  1. Store words in a flat sorted array.
  2. Track the active index using the audioprocess event.
  3. Virtualize the DOM/Regions: Only create Wavesurfer regions for words currently within the visible zoom viewport, dynamically adding and removing them as the viewport shifts.
