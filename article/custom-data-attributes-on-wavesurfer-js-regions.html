Custom Data Attributes on Wavesurfer.js Regions

This article explains how custom data attributes function on Wavesurfer.js region DOM elements, outlining built-in identifiers and demonstrating how any standard HTML5 data-* attribute can be dynamically attached to store metadata, enhance CSS styling, and streamline event handling.

Default Region Data Attributes

When using the Wavesurfer.js Regions plugin, the library automatically renders a container element (typically an HTMLDivElement) for each segment created on the waveform.

By default, the plugin assigns:

  • data-id: Stores the unique string identifier assigned to or generated for that specific region. Wavesurfer.js relies on this attribute internally to track mouse interactions, dragging, and resizing operations.

Attaching Custom data-* Attributes

Because region elements are standard DOM nodes exposed via the Wavesurfer API, you can attach any valid HTML5 custom data attribute to them. HTML5 specifications permit any attribute name starting with data- followed by lowercase characters, hyphens, or underscores (for example, data-speaker-id, data-label, or data-category).

Custom attributes are not automatically mapped from the configuration object in regions.addRegion(). Instead, you attach them directly to the region's DOM element using the region.element reference.

Using the region-created Event

The cleanest method to bind custom attributes is listening to the region lifecycle events:

const wsRegions = wavesurfer.registerPlugin(WaveSurfer.Regions.create());

wsRegions.on('region-created', (region) => {
  // Using the dataset API
  region.element.dataset.category = 'vocals';
  region.element.dataset.timestamp = Date.now().toString();

  // Or using setAttribute
  region.element.setAttribute('data-speaker-id', 'speaker_01');
  region.element.setAttribute('data-verified', 'true');
});

Attaching Attributes During Direct Creation

When creating regions programmatically, you can immediately access the created instance and mutate its element:

const region = wsRegions.addRegion({
  start: 2,
  end: 6,
  content: 'Chorus',
  color: 'rgba(0, 255, 0, 0.2)'
});

region.element.dataset.type = 'chorus';
region.element.dataset.trackIndex = '3';

Practical Applications for Custom Attributes

  • CSS Attribute Selectors: Target and style specific regions using CSS without managing extra utility classes (e.g., .wavesurfer-region[data-type="chorus"] { border-top: 2px solid green; }).
  • Database Synchronisation: Store external database IDs directly on the element (data-db-id="12345") to make CRUD updates straightforward during user edits.
  • Delegated Event Handling: Inspect target attributes when listening to global DOM events without maintaining parallel lookup arrays in memory.
