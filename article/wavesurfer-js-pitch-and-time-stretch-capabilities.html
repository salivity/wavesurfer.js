Wavesurfer.js Pitch and Time Stretch Capabilities

This article explores the pitch-shifting and time-stretching capabilities of Wavesurfer.js when integrated with the Web Audio API. While Wavesurfer.js is primarily an audio waveform visualizer and playback controller, manipulating pitch and duration independently depends on whether you rely on native browser APIs, standard media elements, or specialized Digital Signal Processing (DSP) libraries integrated through custom Web Audio nodes.

Default Playback Speed vs. Pitch Shifting

By default, altering the playback speed in Wavesurfer.js affects audio differently depending on the configured backend:

  1. HTMLMediaElement Backend: Modern browsers support the preservesPitch attribute on audio elements. When using Wavesurfer.js with a standard media element backend, setting the playback rate (wavesurfer.setPlaybackRate(n)) will time-stretch the audio while automatically preserving the original pitch. However, this is handled entirely by the browser’s internal resampler and offers limited fine-grained control over the pitch itself.
  2. Web Audio API Backend: When using native Web Audio components like the AudioBufferSourceNode, changing the playbackRate.value resamples the audio buffer directly. This causes the classic "tape-stop" or "vinyl" effect: speeding up the audio raises the pitch, and slowing it down lowers the pitch. The Web Audio API does not have a native, built-in node for independent pitch shifting or phase vocoding.

Independent Time-Stretching and Pitch Modification

To achieve independent pitch shifting (changing pitch without altering tempo) or advanced time-stretching (changing tempo without altering pitch) within the Web Audio API pipeline, external DSP algorithms are required.

The standard Web Audio API does not feature a native PitchShiftNode. Consequently, developers utilizing Wavesurfer.js must implement one of the following approaches:

  • AudioWorklet Integration: You can build a custom AudioWorkletNode that runs algorithms such as WSOLA (Waveform Similarity Overlap-Add) or a Phase Vocoder on a separate audio rendering thread. Wavesurfer.js can then route its audio output through this custom node.
  • SoundTouchJS: A common solution in the Wavesurfer.js ecosystem is integrating libraries like SoundTouchJS. SoundTouch provides tempo and pitch controls independently. Audio frames are processed through a custom script processor or AudioWorklet and fed into the Web Audio context managed by Wavesurfer.js.
  • Tone.js Integration: Tone.js provides high-level abstractions like Tone.PitchShift and Tone.GrainPlayer. Developers often connect Wavesurfer’s underlying audio nodes or audio buffers directly to Tone.js effects chains to manipulate pitch in real time without impacting track playback duration.

Latency and Quality Considerations

When stretching audio or shifting pitch in real time using the Web Audio API alongside Wavesurfer.js, several trade-offs emerge:

  • Transient Smearing: Phase vocoders often soften sharp transients (like drum hits), making percussive sounds feel muddy.
  • Phasing Artifacts: Granular-based methods (such as WSOLA or grain players) can introduce robotic or metallic phasing artifacts if the grain size is not properly tuned to the source material.
  • CPU Overhead: Running complex pitch and stretch DSP algorithms in JavaScript or WebAssembly within an AudioWorklet demands significant CPU resources, which can impact visualization rendering performance in Wavesurfer.js on lower-end devices.
