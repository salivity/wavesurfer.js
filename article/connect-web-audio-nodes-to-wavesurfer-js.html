Connect Web Audio Nodes to Wavesurfer.js

Integrating external Web Audio API nodes into Wavesurfer.js allows developers to apply custom effects, dynamic equalizers, and real-time audio manipulation directly to waveform visualizations. This article explains how to route audio nodes through Wavesurfer.js, identifying the core method used for filter integration and providing practical implementation steps to connect custom nodes into the playback pipeline.

The Core Method: setFilters()

The primary method used to insert and connect external Web Audio nodes into the Wavesurfer.js processing chain is setFilters().

In Wavesurfer.js instances running the Web Audio backend, wavesurfer.setFilters() accepts an array of Web Audio AudioNode objects. The library automatically disconnects the default internal routing and splices your array of filter nodes sequentially between the source node and the final destination (or analyser node).

// Example: Inserting BiquadFilterNodes using setFilters
const lowpass = wavesurfer.backend.ac.createBiquadFilter();
lowpass.type = 'lowpass';
lowpass.frequency.setValueAtTime(1000, wavesurfer.backend.ac.currentTime);

const gainNode = wavesurfer.backend.ac.createGain();
gainNode.gain.setValueAtTime(0.8, wavesurfer.backend.ac.currentTime);

// Connect the nodes into the Wavesurfer audio pipeline
wavesurfer.setFilters([lowpass, gainNode]);

When setFilters() is invoked, Wavesurfer.js chains the nodes in the exact order they appear in the array: Source -> lowpass -> gainNode -> Analyser/Destination.

Connecting External Sources with Native Web Audio

If you are working with an external audio source—such as a microphone stream (MediaStreamAudioSourceNode) or an external synthesizer node—rather than an audio file loaded directly through Wavesurfer, you must bridge the external node using the native Web Audio .connect() method alongside Wavesurfer's internal context.

1. Access the Audio Context

Wavesurfer exposes its internal AudioContext via the backend:

const audioContext = wavesurfer.backend.getAudioContext();

Always create your external nodes using this shared context to prevent errors caused by routing nodes across mismatched audio contexts.

2. Route External Nodes Manually

To direct an external source through a filter chain and into Wavesurfer's visualizer without using the built-in loader:

// Create an external source (e.g., from an HTML5 Audio element or stream)
const externalSource = audioContext.createMediaElementSource(audioElement);

// Create your custom filter
const filterNode = audioContext.createBiquadFilter();
filterNode.type = 'peaking';
filterNode.frequency.value = 1000;

// Connect external source -> filter -> Wavesurfer's analyser -> destination
externalSource.connect(filterNode);
filterNode.connect(wavesurfer.backend.analyser);
wavesurfer.backend.analyser.connect(audioContext.destination);

Working with Wavesurfer.js v7

In Wavesurfer.js version 7, playback defaults to an HTML5 Media Element rather than a pure Web Audio buffer backend. To connect Web Audio filters in version 7:

  1. Retrieve the media element using wavesurfer.getMediaElement().
  2. Create an AudioContext and instantiate a source via createMediaElementSource().
  3. Connect your custom nodes directly using native Web Audio API methods.
const audioContext = new AudioContext();
const mediaElement = wavesurfer.getMediaElement();
const source = audioContext.createMediaElementSource(mediaElement);

const filter = audioContext.createBiquadFilter();
filter.type = 'highpass';
filter.frequency.value = 500;

// Complete the audio graph
source.connect(filter);
filter.connect(audioContext.destination);

By leveraging setFilters() for legacy and buffer-based pipelines, or native node chaining via createMediaElementSource() in modern versions, you can insert any custom Web Audio processing node directly into the Wavesurfer.js workflow.
