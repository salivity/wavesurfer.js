How to Use Wavesurfer.js in React with Hooks

Managing Wavesurfer.js in React is best achieved by encapsulating its initialization, event listeners, and cleanup inside a custom useWavesurfer hook. This article explains the recommended hook pattern for integrating Wavesurfer.js into functional components, detailing how to bind DOM containers, manage instance lifecycles with useEffect, prevent memory leaks through proper teardown, and synchronize audio state reactively.

The Custom Hook Pattern

The recommended approach to managing Wavesurfer.js in React is building a custom hook that accepts a container ref and Wavesurfer configuration options. Because Wavesurfer directly manipulates the DOM and maintains its own internal audio context, wrapping this logic in a hook isolates imperative third-party API calls from declarative React UI rendering.

Core Responsibilities of the Hook

A well-designed useWavesurfer hook handles four main tasks:

  1. DOM Attachment: Binds Wavesurfer to a stable DOM node reference via useRef.
  2. Lifecycle Management: Instantiates Wavesurfer on mount and destroys it on unmount using useEffect.
  3. Reactive State: Subscribes to Wavesurfer events (such as play, pause, and timeupdate) and exposes them as native React state.
  4. Cleanup: Invokes wavesurfer.destroy() to cancel audio contexts and eliminate memory leaks when parameters change or the component unmounts.

Hook Implementation

Below is the standard custom hook pattern for managing Wavesurfer.js (v7+):

import { useState, useEffect } from 'react';
import WaveSurfer from 'wavesurfer.js';

export const useWavesurfer = (containerRef, options) => {
  const [wavesurfer, setWavesurfer] = useState(null);
  const [isPlaying, setIsPlaying] = useState(false);
  const [currentTime, setCurrentTime] = useState(0);

  useEffect(() => {
    if (!containerRef.current) return;

    // 1. Create the instance
    const ws = WaveSurfer.create({
      ...options,
      container: containerRef.current,
    });

    setWavesurfer(ws);

    // 2. Register event listeners
    const subscriptions = [
      ws.on('play', () => setIsPlaying(true)),
      ws.on('pause', () => setIsPlaying(false)),
      ws.on('timeupdate', (time) => setCurrentTime(time)),
      ws.on('destroy', () => setIsPlaying(false)),
    ];

    // 3. Cleanup on unmount or options change
    return () => {
      subscriptions.forEach((unsub) => unsub());
      ws.destroy();
    };
  }, [containerRef, options.url]);

  return { wavesurfer, isPlaying, currentTime };
};

Using the Hook in a Component

To consume the hook, pass a container reference and audio configuration from your component.

import React, { useRef } from 'react';
import { useWavesurfer } from './useWavesurfer';

export const AudioPlayer = ({ audioUrl }) => {
  const containerRef = useRef(null);

  const { wavesurfer, isPlaying, currentTime } = useWavesurfer(containerRef, {
    url: audioUrl,
    waveColor: '#4F46E5',
    progressColor: '#818CF8',
    height: 80,
  });

  const handlePlayPause = () => {
    if (wavesurfer) {
      wavesurfer.playPause();
    }
  };

  return (
    <div>
      <div ref={containerRef} />
      <button onClick={handlePlayPause}>
        {isPlaying ? 'Pause' : 'Play'}
      </button>
      <span>Time: {currentTime.toFixed(2)}s</span>
    </div>
  );
};

Key Best Practices

  • Avoid Direct Instance Storage in Component State: Only store the Wavesurfer instance in the custom hook or expose control handlers (play, pause) to prevent unnecessary component re-renders.
  • Always Run Destruction Logic: Omitting ws.destroy() causes duplicated audio nodes and overlapping waveform canvases when React components remount or dependencies change under Strict Mode.
  • Memoize Configuration Objects: Pass primitive values or memoize configuration objects using useMemo so that new object references do not trigger unintended re-instantiation loops inside the hook.
