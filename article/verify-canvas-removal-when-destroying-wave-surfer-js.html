Verify Canvas Removal When Destroying WaveSurfer.js

This article explains how to verify that canvas elements are completely removed from the Document Object Model (DOM) when terminating a WaveSurfer.js instance. It covers the proper execution of the destruction lifecycle, manual inspection using browser developer tools, programmatic assertions for automated tests, and memory heap profiling to ensure no detached canvas nodes remain in memory.

Executing the Destruction Lifecycle

WaveSurfer.js provides a built-in method designed to unmount its rendered nodes, clear event listeners, and clean up audio contexts. To initiate the cleanup process, call the destroy() method on your active instance:

wavesurfer.destroy();

Depending on the version of WaveSurfer.js you use, this method targets either the direct child nodes inside your container element or elements mounted within a Shadow Root (common in WaveSurfer v7).

Programmatic Verification in JavaScript

To confirm programmatically that canvas elements have been unmounted from the DOM, query the host container immediately after calling destroy().

const container = document.querySelector('#waveform');

// Ensure the instance exists and canvas is rendered
console.log('Canvases before destroy:', container.querySelectorAll('canvas').length);

// Destroy the instance
wavesurfer.destroy();

// Verify canvas removal
const remainingCanvases = container.querySelectorAll('canvas');
const isCanvasRemoved = remainingCanvases.length === 0;

console.log('Are canvases removed?', isCanvasRemoved);

If you are using WaveSurfer.js v7 with the default Shadow DOM implementation, the wrapper element hosts a shadow root. Verify that the shadow root or wrapper is cleared:

// Check for any remaining child elements or shadow hosts inside the container
const hasRemainingChildren = container.children.length === 0;
console.log('Container is completely empty:', hasRemainingChildren);

Automated Testing Assertions

When running component or integration tests using frameworks such as Jest, Vitest, Playwright, or Cypress, assert the absence of the canvas element from the DOM:

Jest / Testing Library

test('removes canvas elements on destroy', () => {
  const container = document.createElement('div');
  container.id = 'waveform';
  document.body.appendChild(container);

  const ws = WaveSurfer.create({ container: '#waveform' });
  
  // Teardown
  ws.destroy();

  // Assertion
  expect(container.querySelector('canvas')).toBeNull();
  expect(container.innerHTML).toBe('');
});

Playwright

await page.evaluate(() => window.wavesurfer.destroy());
const canvasCount = await page.locator('#waveform canvas').count();
expect(canvasCount).toBe(0);

Manual Inspection via Browser DevTools

  1. Open your browser's Developer Tools (F12 or right-click and select Inspect).
  2. Navigate to the Elements panel.
  3. Locate the container element assigned to WaveSurfer.js.
  4. Expand the container to view the rendered <canvas> tags or wrapper divs.
  5. Trigger your application's destroy logic.
  6. Verify that the container's contents collapse and the <canvas> tags are deleted from the DOM tree.

Checking for Detached Canvas Nodes in Memory

Elements can be removed from the visible DOM tree but still retained in memory due to dangling JavaScript references. To verify that canvas references are fully cleared:

  1. Open the Memory tab in Chrome DevTools.
  2. Select Heap snapshot and click Take snapshot.
  3. Trigger the wavesurfer.destroy() action in your application.
  4. Click the trash can icon in DevTools to force garbage collection.
  5. Take a second Heap snapshot.
  6. In the Class filter input, type Detached HTMLCanvasElement or HTMLCanvasElement.

If the count displays 0 (or does not show "Detached"), the canvas elements have been successfully dereferenced and garbage collected.
