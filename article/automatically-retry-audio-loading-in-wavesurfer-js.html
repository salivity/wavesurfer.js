Automatically Retry Audio Loading in Wavesurfer.js

Handling transient network drops when loading audio into Wavesurfer.js is essential for delivering a resilient web audio player. When an audio file fails to load due to network instability, Wavesurfer emits an error event. By capturing this event, tracking attempt counts, and re-triggering the load method with an optional delay or exponential backoff, you can automatically recover from network failures without requiring the user to refresh the page.

Listening to Error Events

Wavesurfer provides event subscriptions through its .on() method. When an audio URL cannot be fetched or decoded, Wavesurfer emits the 'error' event and passes the corresponding error object to your callback.

To prevent endless loops when a file is permanently missing (like an HTTP 404), you should establish a maximum retry threshold alongside a delay before each attempt. Additionally, you should reset the retry counter when the audio successfully decodes or becomes ready.

Implementation Example

Below is a complete implementation using Wavesurfer.js v7 that automatically retries loading with an exponential backoff strategy:

import WaveSurfer from 'wavesurfer.js';

const audioUrl = 'https://example.com/audio/track.mp3';
const maxRetries = 3;
let retryCount = 0;
const baseDelay = 1000; // 1 second

// Initialize WaveSurfer
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: audioUrl,
});

// Reset the retry counter once the audio is ready
wavesurfer.on('ready', () => {
  retryCount = 0;
  console.log('Audio loaded successfully.');
});

// Handle errors and retry loading
wavesurfer.on('error', (error) => {
  console.warn(`Audio load failed: ${error.message || error}`);

  if (retryCount < maxRetries) {
    retryCount++;
    // Calculate backoff delay (1s, 2s, 4s...)
    const delay = baseDelay * Math.pow(2, retryCount - 1);

    console.log(`Retrying in ${delay / 1000}s (Attempt ${retryCount} of ${maxRetries})...`);

    setTimeout(() => {
      // Re-attempt loading the audio file
      wavesurfer.load(audioUrl);
    }, delay);
  } else {
    console.error('Max retry attempts reached. Please check your network connection.');
  }
});

Best Practices for Network Retries

  • Distinguish Errors: Not all errors warrant a retry. While fetch failures or timeouts should trigger a reload, decoding errors often mean the audio format is corrupt or unsupported, making retries futile.
  • Exponential Backoff: Avoid hammering the server immediately after a drop. Using exponential backoff (delay = baseDelay * 2^(attempt - 1)) prevents overwhelming the server or the client during prolonged outages.
  • UI Feedback: Provide visual feedback in your interface to inform the user that a reconnection attempt is occurring, rather than leaving the player in an empty or broken state.
