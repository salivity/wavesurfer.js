How to Publish a Wavesurfer.js Plugin on NPM

This guide provides a comprehensive walkthrough for developing, configuring, and publishing a third-party Wavesurfer.js plugin to the NPM registry. You will learn how to design a plugin compatible with Wavesurfer.js architecture, configure package.json with appropriate peer dependencies, bundle code for modern module formats, and execute the publication process so other developers can install and integrate your package.

1. Understand the Plugin Architecture

Wavesurfer.js (version 7 and above) relies on a modular architecture where plugins extend the core BasePlugin class.

At a minimum, your plugin class should implement the required lifecycle methods:

import { BasePlugin } from 'wavesurfer.js/dist/base-plugin.js';

export interface MyPluginOptions {
  customOption?: boolean;
}

export class MyPlugin extends BasePlugin<MyPluginOptions> {
  protected options: MyPluginOptions;

  constructor(options?: MyPluginOptions) {
    super(options);
    this.options = options || {};
  }

  public static create(options?: MyPluginOptions) {
    return new MyPlugin(options);
  }

  onInit() {
    if (!this.wavesurfer) {
      throw Error('WaveSurfer is not initialized');
    }
    // Plugin logic and event subscriptions
  }

  destroy() {
    // Unsubscribe from events and cleanup DOM elements
    super.destroy();
  }
}

2. Configure package.json

A reliable plugin must properly declare module entry points, types, and dependencies to prevent version conflicts in consuming projects.

Run npm init -y in your repository and update package.json with the following configuration:

{
  "name": "wavesurfer.js-plugin-example",
  "version": "1.0.0",
  "description": "A custom third-party plugin for Wavesurfer.js",
  "main": "./dist/index.cjs",
  "module": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "import": "./dist/index.js",
      "require": "./dist/index.cjs",
      "types": "./dist/index.d.ts"
    }
  },
  "files": [
    "dist"
  ],
  "scripts": {
    "build": "tsup src/index.ts --format cjs,esm --dts --clean",
    "prepublishOnly": "npm run build"
  },
  "peerDependencies": {
    "wavesurfer.js": ">=7.0.0"
  },
  "devDependencies": {
    "tsup": "^8.0.0",
    "typescript": "^5.0.0",
    "wavesurfer.js": "^7.0.0"
  },
  "keywords": [
    "wavesurfer",
    "wavesurfer.js",
    "plugin",
    "audio"
  ],
  "license": "MIT"
}

Key Fields Explained:

  • peerDependencies: Declares that your plugin requires wavesurfer.js without bundling a separate copy into your distributed code.
  • exports: Provides modern dual-package support for both CommonJS (require) and ES Modules (import).
  • files: Restricts the published artifacts exclusively to the dist folder.
  • keywords: Ensures your package is discoverable when users search for Wavesurfer plugins on NPM.

3. Build and Bundle the Plugin

Modern JavaScript libraries should ship lightweight, pre-bundled files containing ESM, CommonJS, and TypeScript definitions.

Tools such as tsup, Rollup, or Vite handle this efficiently. Using tsup, the build script runs:

npm run build

Verify that the output directory (dist/) contains:

  • index.js (ES Module)
  • index.cjs (CommonJS)
  • index.d.ts (Type declarations)

4. Test the Package Locally

Before pushing to the registry, verify the package in an external project:

  1. In the plugin project directory, run:

    npm link

  2. In a test application where wavesurfer.js is installed, run:

    npm link wavesurfer.js-plugin-example

  3. Import the plugin and confirm that registration works properly:

    import WaveSurfer from 'wavesurfer.js';
import { MyPlugin } from 'wavesurfer.js-plugin-example';

const ws = WaveSurfer.create({
  container: '#waveform',
  plugins: [
    MyPlugin.create({ customOption: true })
  ]
});

5. Publish to NPM

Once local testing confirms stability, publish your plugin to the public registry.

  1. Log in to NPM:

    npm login

    Follow the CLI prompts to authenticate with your credentials.

  2. Verify Package Contents: Inspect what will be included in the tarball:

    npm pack --dry-run

  3. Publish the Package: If using an unscoped package name:

    npm publish

    If using a scoped package name (e.g., @organization/wavesurfer-plugin-example):

    npm publish --access public

6. Maintenance and Versioning

Whenever you introduce bug fixes or new features, update your version according to Semantic Versioning (SemVer) before republishing:

npm version patch  # For backwards-compatible bug fixes
npm version minor  # For new, backwards-compatible features
npm version major  # For breaking changes
npm publish
