Wavesurfer.js Event Fired When Seeking Completes

This article explains the specific events triggered when seeking finishes in Wavesurfer.js. It covers the primary built-in seek event provided by the library's API, the underlying HTML5 seeked event accessible through the media element, and how to implement both in your application.

The Built-in seek Event

In Wavesurfer.js, the primary event fired when a user completes a seek action is the seek event. This event triggers whenever the playback position changes due to user interaction, such as clicking or dragging on the waveform.

Depending on the version of Wavesurfer.js you are using, the callback provides the target position:

  • Wavesurfer.js v7: The seek event callback receives the new time position (or relative progress depending on the method called).
  • Wavesurfer.js v6 and earlier: The event emits a single float value representing the progress as a percentage between 0 and 1.

Example (Wavesurfer.js v7)

import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#violet',
  progressColor: '#purple',
  url: '/audio.mp3',
});

// Fired when the user seeks on the waveform
wavesurfer.on('seek', (relativeX) => {
  console.log('Seeking completed at relative position:', relativeX);
});

The Native seeked Event

Wavesurfer.js uses an underlying HTML5 <audio> or <video> element to handle media playback. The browser's native media engine fires two seeking-related events:

  1. seeking: Dispatched when a seek operation starts.
  2. seeked: Dispatched when the media player has finished repositioning to the new timestamp and is ready to resume or display the new frame.

If you need to guarantee that the underlying audio buffer has resolved and the audio hardware is aligned with the new position, you can attach an event listener to the media element directly.

Example Using the Media Element

// Access the native HTMLMediaElement
const mediaElement = wavesurfer.getMediaElement();

mediaElement.addEventListener('seeked', () => {
  console.log('Audio element completed seeking to:', mediaElement.currentTime);
});

Which Event Should You Use?

  • Use wavesurfer.on('seek') if your goal is to react to user interactions specifically on the waveform, such as updating external UI indicators, markers, or display timestamps immediately.
  • Use mediaElement.addEventListener('seeked') if your logic relies on the browser audio buffer being fully updated and ready for synchronized playback or complex media operations.
