How to Add Plugins Dynamically to Wavesurfer.js

This article explains how to dynamically attach a plugin to an existing Wavesurfer.js instance after initialization. It covers the specific methods used across different versions of the library, provides straightforward code examples for registering a plugin at runtime, and details how to properly handle plugin instances when they are no longer needed.

The Method: registerPlugin()

In the modern version of Wavesurfer.js (version 7 and later), the method used to dynamically attach and initialize a plugin on an already existing instance is registerPlugin().

When called on your Wavesurfer instance, registerPlugin() immediately initializes the plugin and binds it to the current audio waveform:

import WaveSurfer from 'wavesurfer.js';
import RegionsPlugin from 'wavesurfer.js/dist/plugins/regions.esm.js';

// Create the Wavesurfer instance
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: '/audio.mp3',
});

// Dynamically attach the plugin later
const regions = wavesurfer.registerPlugin(
  RegionsPlugin.create({
    dragSelection: true,
  })
);

The registerPlugin() method accepts the initialized plugin instance as its argument and returns that same instance, allowing you to interact with the plugin’s API directly.

Legacy Wavesurfer.js: addPlugin()

If you are using Wavesurfer.js version 6 or older, the dynamic method was named addPlugin().

In legacy versions, calling addPlugin() adds the plugin definition, and you must call initPlugin(name) afterward to activate it if it does not initialize automatically:

// Wavesurfer.js v6 and earlier
const wsRegions = wavesurfer.addPlugin(
  WaveSurfer.regions.create({
    dragSelection: true,
  })
);

wsRegions.init();

Removing Dynamically Attached Plugins

To detach or clean up a plugin that was added dynamically, call the destroy() method directly on the plugin instance. In Wavesurfer.js v7+, this unbinds all attached DOM elements and event listeners:

// Destroy the dynamically added plugin
regions.destroy();

This ensures proper memory management by preventing memory leaks when toggling features like minimaps, timelines, or region selectors dynamically in your application.
