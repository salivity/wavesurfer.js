Map Wavesurfer Byte Data to Canvas Scope Lines

Visualizing audio as an oscilloscope trace requires capturing time-domain waveform data and transforming it into two-dimensional canvas coordinates. This guide covers the essential HTML5 Canvas 2D drawing routines and mathematical mapping techniques needed to convert raw 8-bit time-domain byte data from Wavesurfer.js (or its underlying Web Audio AnalyserNode) into continuous scope lines.

Capturing the Byte Data

Wavesurfer.js exposes its underlying Web Audio API context. An AnalyserNode connected to the audio pipeline produces time-domain byte data through a Uint8Array. The values in this array range from 0 to 255, where 128 represents the zero-crossing (silence), 0 represents the minimum negative amplitude, and 255 represents the maximum positive amplitude.

const analyser = wavesurfer.backend.analyser;
const bufferLength = analyser.frequencyBinCount;
const dataArray = new Uint8Array(bufferLength);

analyser.getByteTimeDomainData(dataArray);

Canvas Coordinate Mapping Routines

To render these bytes as an oscilloscope line, use the standard 2D rendering context (CanvasRenderingContext2D). The mapping translates array indices to the horizontal \(X\) axis and byte values to the vertical \(Y\) axis.

1. Clearing the Canvas

Before drawing each frame, clear previous artifacts or apply a semi-transparent fill to create an analog phosphor decay effect:

  • ctx.clearRect(0, 0, width, height): Erases previous frames entirely for a clean, sharp trace.
  • ctx.fillRect(0, 0, width, height) (with an alpha fillStyle): Retains faint trails of past frames for a classic CRT oscilloscope look.

2. Defining Path Geometry

  • ctx.beginPath(): Initializes a new path for the waveform trace, clearing any sub-paths remaining from previous renders.
  • ctx.moveTo(x, y): Sets the starting point of the trace using the first data byte.
  • ctx.lineTo(x, y): Appends line segments from the previous coordinate to each successive sample point across the canvas.

3. Stroking the Vector

  • ctx.lineWidth: Controls trace thickness.
  • ctx.strokeStyle: Sets the trace color (such as an oscilloscope green or cyan).
  • ctx.stroke(): Rasterizes the continuous path onto the canvas surface.

Implementation Routine

The following routine demonstrates how to map the array buffer into pixel coordinates inside an animation loop:

function drawScope(canvas, ctx, analyser, dataArray, bufferLength) {
  requestAnimationFrame(() => drawScope(canvas, ctx, analyser, dataArray, bufferLength));

  analyser.getByteTimeDomainData(dataArray);

  // Clear frame
  ctx.fillStyle = 'rgb(10, 10, 10)';
  ctx.fillRect(0, 0, canvas.width, canvas.height);

  // Configure trace appearance
  ctx.lineWidth = 2;
  ctx.strokeStyle = '#00ff66';
  ctx.beginPath();

  const sliceWidth = canvas.width / bufferLength;
  let x = 0;

  for (let i = 0; i < bufferLength; i++) {
    // Normalize byte (0-255) to 0.0 - 1.0 range
    const v = dataArray[i] / 255.0;
    
    // Scale normalized value to canvas height
    const y = v * canvas.height;

    if (i === 0) {
      ctx.moveTo(x, y);
    } else {
      ctx.lineTo(x, y);
    }

    x += sliceWidth;
  }

  // Draw the full path across the width
  ctx.lineTo(canvas.width, canvas.height / 2);
  ctx.stroke();
}

Performance Considerations

  • Avoid Sub-pixel Path Overload: If bufferLength exceeds the pixel width of the canvas, step through the array using increments larger than 1 (i += Math.ceil(bufferLength / canvas.width)) to prevent unnecessary line segments.
  • Path Batching: Keep all segments within a single beginPath() and stroke() sequence per frame. Invoking stroke() inside the loop introduces significant CPU overhead.
