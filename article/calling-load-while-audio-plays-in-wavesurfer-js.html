Calling load() While Audio Plays in Wavesurfer.js

Calling the load() method while audio is actively playing in Wavesurfer.js immediately halts playback, clears the current audio buffer, resets the waveform display, and initiates the process of fetching and decoding the new track. This article explains the technical sequence of events triggered by this action, including how the underlying media element behaves, which lifecycle events are fired, and how to avoid common race conditions or unhandled promise rejections.

Immediate Playback Halt and State Reset

When load() is executed during playback, Wavesurfer.js immediately pauses the internal audio engine—whether using the standard HTML5 HTMLMediaElement (default in v7) or a Web Audio API backend. The current playback position is discarded, the active audio stream is detached, and the internal time counter resets to 0.

The current waveform visuals are cleared from the canvas. Depending on your configuration and the version of Wavesurfer.js, the container will either render an empty canvas, display a loading progress bar, or hold until the new audio peaks are ready to be drawn.

Event Lifecycle Changes

Calling load() interrupts the normal flow of the currently playing track and triggers a distinct sequence of events:

  1. Pause Event: A pause event is dispatched as the playing track is forced to stop.
  2. Loading Events: The library emits loading (or load in v7), signaling the start of the HTTP request and the decoding process for the new audio source.
  3. Ready Event: Once the new audio data is completely fetched and the waveform peaks are calculated, the ready event fires.

Because playback was aborted by loading a new resource, the finish event for the original track will not fire.

Playback Does Not Automatically Resume

Calling load() does not preserve the playback state across tracks. Once the new file finishes loading and rendering, Wavesurfer.js remains in a paused state at time 0. If continuous playback is required, you must explicitly listen for the ready event and call play() programmatically:

wavesurfer.load('new-audio.mp3');
wavesurfer.once('ready', () => {
    wavesurfer.play();
});

Potential Promise Rejections and Race Conditions

Modern browsers return a Promise when initiating playback via the HTML5 audio element's .play() method. If load() is invoked immediately after a .play() call while that promise is still pending, the browser may throw an AbortError with the message: "The play() request was interrupted by a call to pause() or load()".

To avoid unhandled rejection warnings in your application, ensure that any manual .play() calls gracefully handle promise rejections before triggering subsequent load() operations:

wavesurfer.play().catch((error) => {
    if (error.name !== 'AbortError') {
        console.error(error);
    }
});
