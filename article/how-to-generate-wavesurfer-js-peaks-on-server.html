How to Generate Wavesurfer.js Peaks on Server

Generating waveform peaks on the server dramatically reduces client-side CPU usage and bandwidth when loading audio in Wavesurfer.js. This article details the primary tools and server scripts used to pre-compute audio data into compatible JSON peak arrays, covering the industry-standard BBC audiowaveform CLI, FFmpeg-based scripting pipelines, and native Node.js solutions.

BBC's audiowaveform

The fastest and most widely adopted tool for generating Wavesurfer.js-compatible peaks is audiowaveform, an open-source C++ command-line utility created by the BBC. It reads audio formats like MP3, WAV, FLAC, and Ogg, and directly outputs peak data in either JSON or binary .dat formats.

To generate a JSON file compatible with Wavesurfer.js, run:

audiowaveform -i input.mp3 -o output.json --pixels-per-second 20 --bits 8

The resulting JSON output contains metadata along with a data array containing alternating minimum and maximum amplitude integers. Wavesurfer.js natively reads this format when passed to the backend.load() or peaks parameter:

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: 'violet',
  progressColor: 'purple'
});

fetch('output.json')
  .then(response => response.json())
  .then(peaksData => {
    wavesurfer.load('input.mp3', peaksData.data);
  });

FFmpeg with Custom Server Scripts

If installing custom C++ binaries is not feasible, standard server setups running FFmpeg can extract raw pulse-code modulation (PCM) audio, which a server script in Python, Node.js, or PHP can downsample into a JSON array of floating-point values between -1 and 1.

Using FFmpeg to extract 8-bit mono raw audio:

ffmpeg -i input.mp3 -ac 1 -filter:a aresample=8000 -map 0:a -c:a pcm_s8 -f data -

In a Node.js script, stream the stdout of that FFmpeg command into chunks, calculate the maximum peak per chunk block, and write the output array to JSON:

const { spawn } = require('child_process');

function generatePeaks(audioPath, totalSamples = 1000) {
  const ffmpeg = spawn('ffmpeg', [
    '-i', audioPath,
    '-ac', '1',
    '-f', 's8',
    '-'
  ]);

  let rawBuffer = Buffer.alloc(0);

  ffmpeg.stdout.on('data', chunk => {
    rawBuffer = Buffer.concat([rawBuffer, chunk]);
  });

  ffmpeg.stdout.on('end', () => {
    const blockSize = Math.floor(rawBuffer.length / totalSamples);
    const peaks = [];

    for (let i = 0; i < totalSamples; i++) {
      let max = 0;
      for (let j = 0; j < blockSize; j++) {
        const val = Math.abs(rawBuffer[i * blockSize + j]);
        if (val > max) max = val;
      }
      peaks.push(parseFloat((max / 128).toFixed(2)));
    }

    process.stdout.write(JSON.stringify(peaks));
  });
}

Node.js Wrappers and Libraries

For Node.js backends that prefer library integrations over direct shell commands, several packages streamline this process:

  • node-audiowaveform: A Node.js wrapper around the BBC audiowaveform binary that lets you process buffers or file paths within an async Promise workflow.
  • waveform-data: A companion JavaScript library by BBC that parses .dat and .json outputs from audiowaveform, allowing dynamic reslicing and downsampling of peak data before sending it to the client.

Peak Formatting Requirements

Wavesurfer.js accepts pre-rendered peaks in two primary structural formats:

  1. A simple array of floats: An array of values representing normalized maximum amplitudes, such as [0.02, 0.45, 0.89, 0.12].
  2. An array of alternating min/max values: Arrays containing paired low and high values, such as [-5, 5, -12, 14], typical of audiowaveform JSON output.

Using either approach bypasses client-side audio decoding via the Web Audio API, allowing waveforms to render immediately upon page load.
