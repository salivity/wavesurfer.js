Wavesurfer.js Community Plugin Naming Conventions

This article explores the standard naming conventions used to identify community-developed plugins for the Wavesurfer.js audio visualization library. By understanding the standard prefixes, repository naming practices, and JavaScript class conventions, developers can easily discover, identify, and publish third-party extensions within the broader Wavesurfer.js ecosystem.

NPM Package Conventions

The primary indicator of a community-created plugin is its package name on package managers such as npm. While official plugins are bundled directly inside the core wavesurfer.js package (imported via paths like wavesurfer.js/dist/plugins/...), community plugins are distributed as standalone packages.

Community plugins generally adopt one of the following patterns:

  • Prefix-based naming: wavesurfer-plugin-[feature] or wavesurfer.js-plugin-[feature] (for example, wavesurfer-plugin-record or wavesurfer.js-plugin-cursor).
  • Scoped packages: @username/wavesurfer-plugin-[feature] or @organization/wavesurfer-[feature], which clearly identifies the third-party maintainer while keeping the library relationship explicit.

Repository and Topic Tagging

On code hosting platforms like GitHub, open-source community plugins follow identical repository naming structures as their npm counterparts to maintain consistency:

  • Repository Names: Typically named using the pattern wavesurfer.js-[plugin-name] or wavesurfer-plugin-[plugin-name].
  • Topics and Keywords: Maintainers use search tags such as wavesurfer, wavesurferjs, wavesurfer-plugin, and audio-visualization in repository topics and npm package.json keywords to improve discoverability.

JavaScript Class and Object Naming

Within application code, community plugins adhere to Wavesurfer's internal architecture conventions to ensure compatibility with plugin loader mechanisms:

  • PascalCase with "Plugin" Suffix: The main export or factory class is consistently named in PascalCase and ends with the word Plugin (for example, SpectrogramPlugin, RegionsPlugin, or CustomMarkerPlugin).
  • Factory Function Syntax: In modern Wavesurfer.js (v7 and newer), plugins often export a static create() method on the plugin class or a camelCase factory function, following the pattern create[PluginName] or simply PluginClass.create(options).
