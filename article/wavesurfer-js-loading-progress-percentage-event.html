Wavesurfer.js Loading Progress Percentage Event

Tracking file download and decoding status is essential for delivering smooth user feedback when handling large media files. This article details the specific Wavesurfer.js event used to monitor audio loading progress percentage, how to implement its listener, and practical code examples to build a responsive progress indicator.

The loading Event

In Wavesurfer.js, the event that reports file loading progress percentage is the loading event.

Whenever audio data is fetched via the load or loadAudio methods, Wavesurfer emits this event continuously until the entire media file has been downloaded into the browser.

Syntax and Implementation

To listen for loading progress, register a listener on your Wavesurfer instance using the .on() method. The event callback receives a single argument representing the current progress as a number from 0 to 100.

import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: '/path/to/audio.mp3',
});

// Listen for the loading progress percentage
wavesurfer.on('loading', (percent) => {
  console.log(`Loading: ${percent}%`);
});

Updating a Progress Bar

The value provided by the loading event can be mapped directly to an HTML <progress> element or a custom progress bar style:

const progressBar = document.querySelector('#loading-bar');
const progressText = document.querySelector('#loading-text');

wavesurfer.on('loading', (percent) => {
  progressBar.style.width = `${percent}%`;
  progressText.innerText = `${percent}%`;

  if (percent === 100) {
    progressText.innerText = 'Decoding audio...';
  }
});

wavesurfer.on('ready', () => {
  // Hide loading indicators when decoding finishes and the waveform is drawn
  progressBar.parentElement.style.display = 'none';
});

Important Considerations

  • Loading vs. Decoding: The loading event tracks the HTTP retrieval progress of the audio file. Once it reaches 100%, Wavesurfer decodes the audio data before rendering the waveform. Use the decode or ready events to detect when rendering and audio decoding are fully complete.
  • Cached Audio: If an audio file is cached locally by the browser, the loading event may jump straight to 100% almost instantaneously.
  • Pre-decoded Peaks: If pre-computed peaks are passed into the configuration, Wavesurfer may skip audio file downloading entirely until playback is initiated, altering when the loading event triggers.
