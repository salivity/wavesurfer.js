Normalize Audio in Wavesurfer.js with Compressor

This article explains how to achieve consistent, normalized audio output in Wavesurfer.js using the Web Audio API's DynamicsCompressorNode. By dynamically leveling transient spikes and boosting quieter segments, a properly configured compressor prevents clipping and maintains an even perceived loudness across diverse audio tracks. Below are the optimal compressor parameter settings and the implementation steps needed to route Wavesurfer.js through an audio compression node.

Optimal DynamicsCompressorNode Settings for Normalization

To normalize dynamic audio without introducing unnatural artifacts like "pumping" or distortion, configure the DynamicsCompressorNode parameters as follows:

  • threshold (-24 to -18 dB): Sets the decibel level at which compression begins. Setting this around -20 dB ensures that louder passages are controlled while preserving standard quieter audio.
  • knee (20 to 30 dB): Provides a soft transition curve around the threshold. A broader knee (e.g., 25 dB) smooths the onset of compression, making the volume leveling sound transparent rather than abrupt.
  • ratio (3:1 to 5:1): Dictates how aggressively signal above the threshold is attenuated. A moderate ratio of 4:1 balances dynamics by lowering excessive peaks without flattening the sound into a lifeless block.
  • attack (0.003 to 0.01 seconds): Controls how quickly compression engages once the threshold is exceeded. A fast attack of 0.005 seconds (5ms) suppresses sudden transients and peaks immediately, preventing digital clipping.
  • release (0.2 to 0.3 seconds): Dictates how quickly the compressor returns to baseline once the input drops below the threshold. A setting around 0.25 seconds prevents audible pumping while quickly restoring headroom for subsequent sounds.

Implementing the Compressor in Wavesurfer.js

To apply these settings, create the node within your application's AudioContext and insert it into the audio processing chain before the destination output.

import WaveSurfer from 'wavesurfer.js';

// 1. Initialize AudioContext and DynamicsCompressorNode
const audioContext = new (window.AudioContext || window.webkitAudioContext)();
const compressor = audioContext.createDynamicsCompressor();

// 2. Apply normalization parameters
compressor.threshold.setValueAtTime(-20, audioContext.currentTime);
compressor.knee.setValueAtTime(25, audioContext.currentTime);
compressor.ratio.setValueAtTime(4, audioContext.currentTime);
compressor.attack.setValueAtTime(0.005, audioContext.currentTime);
compressor.release.setValueAtTime(0.25, audioContext.currentTime);

// 3. Connect the compressor to the speakers
compressor.connect(audioContext.destination);

// 4. Initialize Wavesurfer with the audio context and media element
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F46E5',
  progressColor: '#818CF8',
  url: '/path/to/audio.mp3',
  renderFunction: (peaks, ctx) => {
    // Optional custom rendering logic
  }
});

// 5. Route the audio element into the compressor node upon readiness
wavesurfer.on('ready', () => {
  const mediaElement = wavesurfer.getMediaElement();
  const source = audioContext.createMediaElementSource(mediaElement);
  
  // Route: MediaElement -> Compressor -> Destination
  source.connect(compressor);
});

Post-Compression Gain Compensation

Compression naturally lowers the overall energy of peaks, which can reduce total perceived volume. If your source audio is quiet overall, chain a GainNode after the DynamicsCompressorNode to apply makeup gain:

const makeUpGain = audioContext.createGain();
makeUpGain.gain.setValueAtTime(1.5, audioContext.currentTime); // Boost signal by ~3.5 dB

// Updated Route: Source -> Compressor -> Gain -> Destination
source.connect(compressor);
compressor.connect(makeUpGain);
makeUpGain.connect(audioContext.destination);

This arrangement levels loud and soft passages dynamically while maintaining an elevated, broadcast-ready output volume across any playback media.
