Prevent Wavesurfer.js Memory Leaks in React useEffect

Integrating Wavesurfer.js into a React application frequently leads to memory leaks due to orphaned Web Audio API contexts, lingering DOM nodes, and detached event listeners. This article explains the underlying causes of these leaks when using the useEffect hook and demonstrates how to properly destroy instances, handle React 18's strict mode remounting, and manage references cleanly.

Why Memory Leaks Occur with Wavesurfer.js

Wavesurfer.js relies on the browser's Web Audio API (AudioContext) and registers multiple event listeners on window and DOM objects to render interactive waveforms. When a component re-renders or unmounts, React discards the component's DOM nodes. However, unless Wavesurfer.js is explicitly instructed to clean up, its underlying AudioContext remains active in browser memory, and event listeners continue to hold references to discarded elements.

In React 18, components mount, unmount, and remount immediately in development mode (Strict Mode). If initialization code does not include an explicit teardown mechanism, multiple duplicate instances of Wavesurfer and audio contexts will be created simultaneously, rapidly consuming system RAM.

The Core Solution: The destroy() Method

The definitive method to prevent leaks is invoking the native destroy() method provided by Wavesurfer.js within the cleanup function returned by useEffect. The destroy() method tears down canvas nodes, cancels ongoing audio decode operations, removes DOM event listeners, and closes the associated AudioContext.

Implementation Example

The following pattern ensures that the Wavesurfer instance is created only once per target configuration and is completely scrubbed from memory when the component unmounts:

import React, { useEffect, useRef } from 'react';
import WaveSurfer from 'wavesurfer.js';

const AudioPlayer = ({ audioUrl }) => {
  const containerRef = useRef(null);
  const waveSurferRef = useRef(null);

  useEffect(() => {
    // Ensure the container element is rendered
    if (!containerRef.current) return;

    // Initialize the Wavesurfer instance
    const ws = WaveSurfer.create({
      container: containerRef.current,
      waveColor: '#4F46E5',
      progressColor: '#818CF8',
      url: audioUrl,
    });

    waveSurferRef.current = ws;

    // Cleanup function executed on unmount or before dependency changes
    return () => {
      ws.destroy();
      waveSurferRef.current = null;
    };
  }, [audioUrl]);

  return <div ref={containerRef} />;
};

export default AudioPlayer;

Critical Practices for Leak Prevention

  1. Avoid Storing Instances in State: Do not save the Wavesurfer instance into React state via useState. Setting state triggers an additional render pass. Instead, store the active instance in a useRef to maintain a mutable reference that persists across renders without triggering layout updates.

  2. Clean Up Custom Event Listeners: If custom listeners are added manually via ws.on('event', callback), verify whether they need explicit removal. While ws.destroy() unbinds default internal listeners, unregistering custom subscriptions prevents closure-related memory retention.

  3. Handle Fast Prop Changes and Race Conditions: If the audioUrl changes before Wavesurfer finishes loading or decoding an existing file, calling ws.destroy() inside the cleanup phase will abort ongoing asynchronous decoding operations cleanly, preventing background promises from resolving on detached components.
