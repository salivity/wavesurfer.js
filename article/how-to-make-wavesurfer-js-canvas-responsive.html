How to Make Wavesurfer.js Canvas Responsive

This guide explains how to ensure the Wavesurfer.js audio visualization dynamically adapts to changing container sizes and browser viewports. It covers the native responsiveness built into modern versions of the library, how to handle edge cases using the modern ResizeObserver API, debouncing techniques to preserve performance, and strategies for redrawing waveforms inside dynamic layouts like tabs or accordions.

1. Ensure the Container Uses Responsive CSS

Wavesurfer.js generates a <canvas> element that matches the dimensions of its parent container. If the container cannot shrink or expand, the canvas will remain static. Ensure the host element uses fluid sizing:

#waveform {
  width: 100%;
  max-width: 100%;
  overflow: hidden;
}

2. Built-in Behavior in Wavesurfer.js v7

In Wavesurfer.js version 7 and above, responsive handling is largely automated. The library internally uses a ResizeObserver on the target container. When the container dimensions change, Wavesurfer automatically redraws the waveform to fit the new width.

For standard responsive websites, creating an instance with a percentage-based container is often all that is required:

import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F46E5',
  progressColor: '#818CF8',
  url: '/audio.mp3',
});

3. Handling Dynamic Container Changes with ResizeObserver

While window resizing is handled out-of-the-box in newer versions, programmatic layout shifts—such as toggling sidebars, expanding accordions, or switching tabs—can cause the canvas to clip or stay stretched. You can manually observe the container and force a redraw.

Because continuous resizing events can cause performance degradation, use a debouncing utility:

const container = document.querySelector('#waveform');

let resizeTimer;
const observer = new ResizeObserver(() => {
  clearTimeout(resizeTimer);
  resizeTimer = setTimeout(() => {
    // In Wavesurfer v7, internal methods redraw automatically, 
    // but hidden-to-visible containers may require an explicit redraw.
    if (wavesurfer) {
      wavesurfer.renderer.recenter(wavesurfer.getCurrentTime() / wavesurfer.getDuration());
    }
  }, 100);
});

observer.observe(container);

4. Handling Legacy Wavesurfer.js (Version 6 and Below)

If you are maintaining an older project using Wavesurfer.js v6 or earlier, the library does not automatically listen to container adjustments. You must attach an event listener to the window and trigger a redraw:

// Wavesurfer.js v6 manual resize pattern
let resizeTimeout;

window.addEventListener('resize', () => {
  clearTimeout(resizeTimeout);
  resizeTimeout = setTimeout(() => {
    if (wavesurfer) {
      // Empty and redraw the waveform buffer to the new width
      wavesurfer.drawer.containerWidth = wavesurfer.drawer.container.clientWidth;
      wavesurfer.drawBuffer();
    }
  }, 150);
});

5. Fixing Issues with Initially Hidden Containers

When a waveform initializes inside a hidden element (e.g., display: none in a modal or inactive tab), clientWidth evaluates to 0, resulting in a blank or deformed canvas when revealed.

To resolve this:

  1. Initialize Wavesurfer only when the tab or modal becomes active.
  2. Alternatively, observe visibility changes and call a redraw once rendered:
function onTabActivated() {
  if (wavesurfer && container.clientWidth > 0) {
    // Redraw the waveform with the now-available container width
    wavesurfer.load(wavesurfer.getMediaElement().src);
  }
}
