Pause Wavesurfer.js Canvas with IntersectionObserver

Rendering interactive audio waveforms with Wavesurfer.js relies heavily on the HTML5 Canvas API, which can rapidly consume CPU and GPU resources when multiple instances run or animate simultaneously. By integrating the native IntersectionObserver API, web applications can monitor the visibility of each waveform container in real time and temporarily suspend rendering loops or canvas redraws whenever a player leaves the viewport, dramatically improving page scrolling performance and battery life.

The Performance Cost of Off-Screen Waveforms

Wavesurfer.js draws audio peaks and playback progress onto an HTML <canvas> element. During active audio playback or UI resizing, the library recalculates positions and redraws the canvas continuously using requestAnimationFrame.

When a user scrolls down a long page containing multiple audio clips—such as a podcast directory, sound library, or social feed—off-screen players continue executing these redraw instructions unless explicitly instructed to stop. This leads to unnecessary paint cycles, higher thread contention, and noticeable frame drops.

How IntersectionObserver Solves the Problem

The IntersectionObserver API provides an asynchronous way to observe changes in the intersection of a target element with an ancestor element or the top-level document viewport. Unlike traditional scroll event listeners, IntersectionObserver does not run on the main thread during scroll events, eliminating layout thrashing.

By attaching an observer to the DOM element holding the Wavesurfer instance, the browser automatically notifies your code when the element enters or exits the screen through the isIntersecting property.

Implementing the Pause Logic

To prevent unnecessary canvas updates, you can use the observer to toggle rendering behavior or manage playback state when an instance goes off-screen.

1. Initialize Wavesurfer

First, instantiate Wavesurfer normally on a target DOM node:

import WaveSurfer from 'wavesurfer.js';

const container = document.querySelector('#waveform');
const wavesurfer = WaveSurfer.create({
  container: container,
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: '/path/to/audio.mp3',
});

2. Create the IntersectionObserver

Configure an observer to watch the player's container element. When the element is not visible, canvas redrawing can be suspended:

const observer = new IntersectionObserver((entries) => {
  entries.forEach((entry) => {
    if (!entry.isIntersecting) {
      // Element is off-screen: pause playback or mute rendering
      if (wavesurfer.isPlaying()) {
        wavesurfer.pause();
      }
    }
  });
}, {
  root: null, // Tracks relative to the device viewport
  threshold: 0.0 // Fires as soon as a single pixel enters or exits
});

observer.observe(container);

3. Decoupling Audio Playback from Canvas Updates

In scenarios where audio must continue playing in the background while the user scrolls, pausing the entire player is not desirable. In this case, you can temporarily suppress the visual rendering pipeline.

Wavesurfer.js redraws the progress indicator on every timeupdate. When entry.isIntersecting is false, you can disconnect the visual update listeners or alter the internal renderer:

let isVisible = true;

const observer = new IntersectionObserver((entries) => {
  entries.forEach((entry) => {
    isVisible = entry.isIntersecting;
  });
}, { threshold: 0.1 });

observer.observe(container);

// Intercept time updates to avoid visual repaints when off-screen
wavesurfer.on('audioprocess', () => {
  if (!isVisible) {
    // Skip manual canvas rerenders or custom visualizer hooks
    return;
  }
});

When the player re-enters the viewport (isIntersecting: true), trigger a single update or seek event (e.g., wavesurfer.setTime(wavesurfer.getCurrentTime())) to instantly sync the waveform display to the current audio position without having processed every intermediate frame off-screen.

Key Benefits

  • Reduced GPU Overhead: Stops costly canvas clear and repaint cycles when the waveform cannot be seen.
  • Lower CPU Usage: Eliminates unneeded requestAnimationFrame ticks, freeing the main thread for smooth scrolling.
  • Scalability: Enables pages to safely embed dozens or hundreds of Wavesurfer players without degrading browser responsiveness.
