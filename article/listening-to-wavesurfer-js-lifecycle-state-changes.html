Listening to Wavesurfer.js Lifecycle State Changes

This article provides a practical guide on monitoring and handling state changes throughout the entire lifecycle of a Wavesurfer.js instance. You will learn the primary lifecycle events exposed by the library, how to capture playback and decoding milestones, and how to implement a unified listener pattern to track state transitions smoothly across modern Wavesurfer.js (v7+) implementations.

Core Wavesurfer.js Lifecycle Events

Wavesurfer.js uses an event emitter pattern via the wavesurfer.on(eventName, callback) method. Lifecycle events fall into three main categories: loading/decoding, playback/interaction, and teardown.

1. Loading and Decoding

  • load: Emitted when the audio source URL or blob starts loading.
  • loading: Emitted continuously during the download process, providing the download percentage (0–100).
  • decode: Emitted when audio decoding starts.
  • ready: Emitted when audio decoding and waveform rendering are complete, meaning the instance is ready for playback.

2. Playback and Interaction

  • play: Fired immediately when audio playback begins.
  • pause: Fired when audio playback is paused.
  • timeupdate: Emitted continuously as the playhead advances, passing the current time in seconds.
  • seeking: Emitted when the user scrubs or jumps to a new position.
  • finish: Emitted when playback reaches the end of the audio track.

3. Teardown and Errors

  • destroy: Fired when wavesurfer.destroy() is called to clean up DOM elements and audio contexts.
  • error: Fired whenever an error occurs during loading, decoding, or playback.

Implementing Individual Lifecycle Listeners

To listen to specific events, attach callbacks directly to the created instance:

import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F46E5',
  progressColor: '#818CF8',
  url: '/audio/sample.mp3',
});

// Track loading progress
wavesurfer.on('loading', (percent) => {
  console.log(`Loading: ${percent}%`);
});

// Track when audio is ready to play
wavesurfer.on('ready', (duration) => {
  console.log(`Audio is ready. Duration: ${duration}s`);
});

// Track playback state
wavesurfer.on('play', () => console.log('State: Playing'));
wavesurfer.on('pause', () => console.log('State: Paused'));
wavesurfer.on('finish', () => console.log('State: Finished'));

// Handle errors
wavesurfer.on('error', (err) => console.error('Wavesurfer Error:', err));

Creating a Unified State Change Dispatcher

Wavesurfer.js does not provide a single statechange hook by default. To monitor general state changes centrally, map the distinct lifecycle events into a unified state dispatcher:

const AudioState = {
  IDLE: 'idle',
  LOADING: 'loading',
  READY: 'ready',
  PLAYING: 'playing',
  PAUSED: 'paused',
  FINISHED: 'finished',
  DESTROYED: 'destroyed',
  ERROR: 'error',
};

function trackWavesurferLifecycle(ws, onStateChange) {
  let currentState = AudioState.IDLE;

  const setState = (newState, payload = null) => {
    if (currentState !== newState) {
      currentState = newState;
      onStateChange(currentState, payload);
    }
  };

  const subscriptions = [
    ws.on('load', () => setState(AudioState.LOADING)),
    ws.on('ready', () => setState(AudioState.READY)),
    ws.on('play', () => setState(AudioState.PLAYING)),
    ws.on('pause', () => setState(AudioState.PAUSED)),
    ws.on('finish', () => setState(AudioState.FINISHED)),
    ws.on('destroy', () => setState(AudioState.DESTROYED)),
    ws.on('error', (error) => setState(AudioState.ERROR, error)),
  ];

  // Return a cleanup function to unsubscribe listeners
  return () => {
    subscriptions.forEach((unsub) => unsub());
  };
}

// Usage:
const cleanupListeners = trackWavesurferLifecycle(wavesurfer, (state, payload) => {
  console.log(`Current Player State: ${state}`, payload || '');
});

Removing Event Listeners

In Wavesurfer.js v7+, calling .on() returns an unsubscribe function. Always invoke these functions when unmounting components in single-page applications (such as React, Vue, or Svelte) to prevent memory leaks:

// Register and capture the cleanup function
const unlistenPlay = wavesurfer.on('play', () => {
  console.log('Playing');
});

// Later, when tearing down
unlistenPlay();

Alternatively, use wavesurfer.unAll() before destroying the instance to remove all registered event listeners at once.
