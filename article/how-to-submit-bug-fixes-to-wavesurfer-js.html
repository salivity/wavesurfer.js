How to Submit Bug Fixes to Wavesurfer.js

This guide outlines the step-by-step process for contributing bug fixes to the official Wavesurfer.js open-source repository on GitHub. It covers everything from locating existing issues and configuring your local development environment to writing tests, conforming to project standards, and submitting a pull request that maintainers can easily review and merge.

1. Verify or Report the Bug

Before writing code, verify that the bug has not already been addressed:

  • Search the open and closed issues in the official katspaugh/wavesurfer.js GitHub repository.
  • If an issue does not already exist for the bug, open a new issue describing the bug, including reproducible steps, the browser environment, and the specific version of Wavesurfer.js you are using.
  • Comment on the issue to let maintainers know you are working on a fix to prevent duplicate efforts.

2. Fork and Clone the Repository

  1. Navigate to the Wavesurfer.js repository on GitHub and click the Fork button to create a copy under your personal GitHub account.

  2. Clone your fork locally using Git:

    git clone https://github.com/<your-username>/wavesurfer.js.git
cd wavesurfer.js

  3. Add the original repository as an upstream remote to keep your fork updated:

    git remote add upstream https://github.com/katspaugh/wavesurfer.js.git

3. Set Up the Development Environment

Wavesurfer.js is written in TypeScript and uses standard Node.js tooling.

  1. Ensure you have a recent LTS version of Node.js installed.

  2. Install the project dependencies:

    npm install

  3. Start the local development server to test examples and verify functionality:

    npm run start

4. Create a Dedicated Branch

Never commit bug fixes directly to the main branch. Create a new branch with a descriptive name representing the fix:

git checkout -b fix/issue-description

(e.g., git checkout -b fix/safari-audio-context-unlock)

5. Implement the Bug Fix

  • Locate the relevant source files in the src/ directory or corresponding plugin directory.
  • Apply the minimal code changes necessary to fix the reported issue.
  • Maintain consistent coding standards matching the existing codebase (formatting, naming conventions, and TypeScript type annotations).

6. Test and Lint Your Code

To ensure the bug fix does not cause regressions or violate style rules:

  1. Add or Update Tests: If applicable, write automated unit tests reproducing the issue to ensure future releases do not reintroduce the bug.

  2. Run Linting: Verify that code style and TypeScript rules pass without errors:

    npm run lint

  3. Run Tests: Execute the test suite:

    npm test

  4. Build the Project: Verify that the project compiles cleanly:

    npm run build

7. Commit Your Changes

Commit your changes with a clear, conventional commit message:

git add .
git commit -m "fix: resolve audio decoding failure in Safari (fixes #1234)"

Reference the original issue number in the commit message or description to automatically link the fix.

8. Push and Open a Pull Request

  1. Push your branch to your forked repository:

    git push origin fix/issue-description

  2. Navigate to the original katspaugh/wavesurfer.js GitHub repository. You will see a prompt to open a pull request from your recently pushed branch.

  3. Fill out the pull request template:

    • Provide a clear summary of the bug and how your changes resolve it.
    • Reference the issue being fixed (e.g., Closes #1234).
    • Confirm that all tests and lint checks pass.

9. Address Review Feedback

Once the pull request is submitted, maintainers and continuous integration (CI) bots will run automated tests. Monitor the pull request for comments, requested changes, or questions from the maintainers, and push any necessary updates directly to your branch to update the pull request automatically.
