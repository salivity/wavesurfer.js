Smooth Mobile Scrolling in Wavesurfer.js

Integrating smooth mobile scrolling with Wavesurfer.js requires properly balancing user touch gestures between native page scrolling and interactive waveform scrubbing. This guide details how utilizing the standard touch event handlers—touchstart, touchmove, and touchend—combined with passive listener configurations and CSS touch properties, allows developers to achieve fluid, performant scrolling on touch-enabled devices without interfering with waveform interactions.

Core Touch Handlers for Mobile Interaction

Achieving responsive mobile scrolling in Wavesurfer.js relies primarily on three standard DOM touch event handlers applied to the waveform's container element:

  • touchstart: Captures the initial contact coordinates (e.touches[0].clientX and clientY). It establishes the starting point for horizontal dragging and determines whether the user intended to tap or initiate a scroll gesture.
  • touchmove: Tracks the finger displacement in real time. By calculating the delta between the current touch position and the initial touchstart coordinates, the handler updates the container's horizontal scrollLeft property or shifts the audio playback position smoothly.
  • touchend (and touchcancel): Concludes the gesture lifecycle, firing momentum-based inertia scrolling logic if implemented and resetting stored coordinate variables to prepare for the next user interaction.

The Role of Passive Event Listeners

By default, touch listeners can introduce perceptible input lag on mobile devices because the browser's main thread waits to see if event.preventDefault() is invoked before executing scroll animations.

To eliminate stutter and maintain a consistent 60 frames per second during mobile dragging:

const container = document.querySelector('#waveform');

container.addEventListener('touchstart', handleTouchStart, { passive: true });
container.addEventListener('touchmove', handleTouchMove, { passive: true });
container.addEventListener('touchend', handleTouchEnd, { passive: true });

Setting { passive: true } informs the browser that the touch handlers will not cancel the scroll, allowing the compositor thread to render scrolling gestures immediately and smoothly.

Resolving Vertical vs. Horizontal Scroll Conflicts

A common issue in mobile web audio players occurs when horizontal waveform dragging accidentally traps vertical page navigation. To prevent Wavesurfer.js from hijacking vertical touch gestures, CSS touch-action must be paired with event handler logic:

#waveform {
  touch-action: pan-y;
}

Applying touch-action: pan-y allows native vertical scrolling to occur without hindrance, while reserving horizontal movements for touch handlers. Within the touchmove handler, calculating whether horizontal movement exceeds vertical movement allows you to update the waveform scroll position only when horizontal intent is clear, ensuring effortless navigation across both the audio timeline and the mobile document.
