Wavesurfer.js Dark and Light Mode Toggle Patterns

Dynamically toggling between dark and light modes in an application requires synchronizing canvas-based elements like Wavesurfer.js with standard DOM styles. Because Wavesurfer renders audio data directly to HTML5 Canvas contexts, standard CSS cascade rules do not automatically restyle the waveform. This guide outlines the core design patterns used to dynamically refresh Wavesurfer.js visual color schemes in real time without interrupting playback or reloading the audio buffer.

The Core Challenge of Canvas Re-theming

Unlike SVG or HTML-based UI components, Wavesurfer.js compiles colors directly into canvas pixel data. Simply toggling a CSS class on the <body> element will update the surrounding interface, but the waveform remains rendered with its initial initialization colors. To update the waveform, developers must explicitly pass new color properties to the Wavesurfer instance and trigger a redraw.

Pattern 1: The Native setOptions() Method

In modern Wavesurfer.js (v7+), the primary mechanism for updating styles is the setOptions() method. Calling this method with updated color values immediately updates the canvas rendering without losing track of current audio playback, buffer state, or cursor position.

function applyTheme(isDark) {
  const themeColors = isDark ? {
    waveColor: '#4A5568',
    progressColor: '#63B3ED',
    cursorColor: '#E2E8F0'
  } : {
    waveColor: '#CBD5E0',
    progressColor: '#3182CE',
    cursorColor: '#2D3748'
  };

  wavesurfer.setOptions({
    waveColor: themeColors.waveColor,
    progressColor: themeColors.progressColor,
    cursorColor: themeColors.cursorColor
  });
}

Pattern 2: CSS Custom Properties via getComputedStyle

To maintain a single source of truth for application theming, avoid hardcoding hex values in JavaScript. Instead, define design tokens using CSS variables and retrieve them dynamically before applying them to Wavesurfer.

CSS:

:root {
  --waveform-bg: #cbd5e1;
  --waveform-progress: #2563eb;
}

[data-theme="dark"] {
  --waveform-bg: #334155;
  --waveform-progress: #60a5fa;
}

JavaScript:

function syncWaveformWithCSS() {
  const styles = getComputedStyle(document.documentElement);
  
  wavesurfer.setOptions({
    waveColor: styles.getPropertyValue('--waveform-bg').trim(),
    progressColor: styles.getPropertyValue('--waveform-progress').trim()
  });
}

Pattern 3: Automated DOM Mutation Observers

When using third-party theme switchers or utility frameworks like Tailwind CSS, theme changes are often triggered by modifying an attribute or class on the <html> or <body> element. A MutationObserver allows Wavesurfer to respond automatically to global theme switches without requiring tight coupling between the toggle button and the audio player component.

const observer = new MutationObserver((mutations) => {
  for (const mutation of mutations) {
    if (mutation.type === 'attributes' && mutation.attributeName === 'class') {
      const isDark = document.documentElement.classList.contains('dark');
      applyTheme(isDark);
    }
  }
});

observer.observe(document.documentElement, {
  attributes: true,
  attributeFilter: ['class', 'data-theme']
});

Pattern 4: System Color Scheme Listeners

To support automatic matching of OS-level preferences, register an event listener on the prefers-color-scheme media query. This ensures that if a user changes their operating system appearance from light to dark, the waveform refreshes instantly.

const mediaQuery = window.matchMedia('(prefers-color-scheme: dark)');

function handleSystemThemeChange(e) {
  applyTheme(e.matches);
}

mediaQuery.addEventListener('change', handleSystemThemeChange);

Best Practices for Seamless Transitions

  1. Avoid Re-instantiation: Never call WaveSurfer.create() or wavesurfer.load() solely to change colors. Re-creating the instance causes audio stutter, memory leaks, and unnecessary recalculation of audio peaks.
  2. Update Associated Plugins: Remember to update any installed plugins that render their own canvas or DOM layers, such as TimelinePlugin or RegionsPlugin, using their respective update methods.
  3. Throttle Theme Changes: If themes are toggled via rapid interactions (such as automated testing or rapid user clicking), debounce or throttle the setOptions execution to prevent redundant canvas redraws.
