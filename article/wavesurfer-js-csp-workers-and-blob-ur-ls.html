Wavesurfer.js CSP: Workers and Blob URLs

Wavesurfer.js commonly uses inline Web Workers generated from Blob URLs to decode audio and render waveform peaks without freezing the browser's main thread. However, strict browser security policies—primarily Content Security Policy (CSP)—frequently block these mechanisms by default, leading to broken audio rendering and console security errors. This guide outlines which specific security directives restrict Wavesurfer.js, why these violations occur, and how to configure your security headers to resolve them.

Why Wavesurfer.js Triggers CSP Violations

To process audio buffers asynchronously, Wavesurfer.js (or its audio-decoding plugins) often packages worker script code into an in-memory Blob and initializes a worker using URL.createObjectURL(blob). While this avoids the need to host separate JavaScript files for worker threads, browsers treat Blob URLs as distinct origin targets that require explicit permission under modern security standards.

Key Policies and Directives That Restrict Wavesurfer.js

1. worker-src

The worker-src directive governs the sources that may be instantiated as Web Workers, Shared Workers, or Service Workers.

  • The Problem: By default, policies restricted to worker-src 'self' will reject workers created with a blob: scheme.

  • The Error: Refused to create a worker from 'blob:...' because it violates the following Content Security Policy directive: "worker-src 'self'".

  • The Fix: Add the blob: scheme to worker-src:

    Content-Security-Policy: worker-src 'self' blob:;

2. child-src (Fallback)

Under CSP Level 2 and in older browsers, worker-src was not supported. Instead, worker execution fell under the child-src directive (and originally script-src).

  • The Problem: If worker-src is omitted, the browser falls back to child-src. If child-src only allows 'self', the Blob Worker will fail.

  • The Fix: Provide blob: in both worker-src and child-src for backward compatibility:

    Content-Security-Policy: worker-src 'self' blob:; child-src 'self' blob:;

3. script-src

Some browsers or strict CSP implementations treat the script content executed inside an inline worker as falling under the main script evaluation rules.

  • The Problem: If a CSP does not permit the worker to execute, or if the initialization script relies on eval-like dynamic evaluation, the browser may enforce restrictions via script-src.

  • The Fix: Ensure script-src includes blob: if your target browsers do not fully isolate worker-src:

    Content-Security-Policy: script-src 'self' blob:;

4. media-src and connect-src

Wavesurfer.js requires access to the raw audio source data to draw waveforms.

  • connect-src: Wavesurfer uses fetch or XMLHttpRequest with responseType: 'arraybuffer' to load audio files. If your audio files are hosted on an external CDN, S3 bucket, or use blob: endpoints, your connect-src must whitelist those origins:

    connect-src 'self' blob: https://cdn.example.com;

  • media-src: If using HTML5 audio playback (backend: 'MediaElement'), the <audio> element loading the track will be evaluated against media-src. Ensure blob: and your media domains are allowed:

    media-src 'self' blob: data: https://cdn.example.com;

Cross-Origin Isolation (COOP and COEP)

If your application enables high-performance features like SharedArrayBuffer, you may have the following headers enabled:

  • Cross-Origin-Opener-Policy: same-origin
  • Cross-Origin-Embedder-Policy: require-corp

Under these conditions, any media or worker created from a Blob URL must either be same-origin or configured properly with appropriate Cross-Origin Resource Sharing (CORS) headers, or the browser will block access to the audio buffer.

Alternative Solution: External Workers

If your organization completely disallows blob: in your CSP for security reasons, you cannot rely on inline worker generation. In this scenario, you must:

  1. Extract the Wavesurfer worker script into a static file hosted directly on your domain (e.g., /js/wavesurfer-worker.js).
  2. Pass the external worker URL into Wavesurfer's configuration, allowing it to satisfy standard 'self' security constraints without requiring blob:.
