Update Wavesurfer.js Regions with Numeric Inputs

Integrating numeric input fields to control region boundaries in Wavesurfer.js allows users to fine-tune audio segments with millisecond-level precision. This guide covers how to bind HTML numeric inputs directly to a Wavesurfer.js region, dynamically update start and end timestamps via code, establish two-way synchronization between the visual waveform handles and input fields, and enforce boundary validation.

Prerequisites and Setup

To manipulate regions, Wavesurfer.js requires the official Regions plugin. Start by including the core library and the Regions plugin in your project:

<div id="waveform"></div>

<div class="controls">
  <label>
    Start Time (s):
    <input type="number" id="start-input" step="0.1" min="0" value="0" />
  </label>
  <label>
    End Time (s):
    <input type="number" id="end-input" step="0.1" min="0" value="5" />
  </label>
</div>

Initializing Wavesurfer and the Region

Instantiate Wavesurfer, register the Regions plugin, and define an active region once the audio decodes:

import WaveSurfer from 'wavesurfer.js';
import RegionsPlugin from 'wavesurfer.js/dist/plugins/regions.esm.js';

// Initialize the plugin instance
const wsRegions = RegionsPlugin.create();

// Initialize Wavesurfer
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: '/path-to-audio.mp3',
  plugins: [wsRegions],
});

let activeRegion = null;
const startInput = document.getElementById('start-input');
const endInput = document.getElementById('end-input');

wavesurfer.on('ready', () => {
  // Create an initial region
  activeRegion = wsRegions.addRegion({
    start: 0,
    end: 5,
    color: 'rgba(0, 123, 255, 0.3)',
    drag: true,
    resize: true,
  });

  // Set boundary limits on inputs
  const duration = wavesurfer.getDuration();
  startInput.max = duration;
  endInput.max = duration;
  
  // Set initial input values
  startInput.value = activeRegion.start.toFixed(2);
  endInput.value = activeRegion.end.toFixed(2);
});

Updating Regions from Numeric Inputs

To alter the region programmatically when a user changes input values, attach input or change listeners to the numeric fields. Use the region's setOptions() method to apply the new values:

function updateRegionFromInputs() {
  if (!activeRegion) return;

  let newStart = parseFloat(startInput.value) || 0;
  let newEnd = parseFloat(endInput.value) || 0;
  const duration = wavesurfer.getDuration();

  // Enforce boundary constraints
  if (newStart < 0) newStart = 0;
  if (newEnd > duration) newEnd = duration;
  if (newStart >= newEnd) {
    newStart = Math.max(0, newEnd - 0.1);
  }

  // Apply updates to the region
  activeRegion.setOptions({
    start: newStart,
    end: newEnd,
  });
}

startInput.addEventListener('input', updateRegionFromInputs);
endInput.addEventListener('input', updateRegionFromInputs);

Enabling Two-Way Synchronization

When a user drags or resizes the region directly on the waveform, the numeric inputs should reflect those changes immediately. Listen to the region-updated event exposed by the Regions plugin:

wsRegions.on('region-updated', (region) => {
  if (region === activeRegion) {
    // Avoid triggering input loops by writing directly to values
    startInput.value = region.start.toFixed(2);
    endInput.value = region.end.toFixed(2);
  }
});

Handling Edge Cases

  • Overlapping Points: Ensure start is always strictly less than end. If the start input exceeds the end input, either auto-advance the end input or clamp the start input.
  • Duration Limits: Disable or set input fields to readonly until the ready event fires so that wavesurfer.getDuration() returns a valid numeric length.
  • Decimal Precision: Use .toFixed(2) or .toFixed(3) when transferring values from the waveform to the input elements to avoid floating-point display issues.
