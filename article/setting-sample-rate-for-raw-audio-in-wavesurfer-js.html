Setting Sample Rate for Raw Audio in Wavesurfer.js

This article explains how to define the sample rate when loading raw array audio data into Wavesurfer.js. When working with pre-decoded PCM arrays, Float32Arrays, or custom audio buffers, setting the sample rate correctly is required to ensure accurate waveform rendering, proper playback speed, and precise duration calculation. The following sections outline the specific configuration option, how it interacts with the Web Audio API, and practical code implementation.

The sampleRate Option

In Wavesurfer.js, the option that explicitly defines the sample rate is sampleRate.

When configuring a Wavesurfer instance or processing raw audio data, sampleRate dictates how many audio samples represent one second of sound (commonly 44100 or 48000 Hz).

You can define this option directly during Wavesurfer initialization:

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F46E5',
  progressColor: '#818CF8',
  sampleRate: 44100, // Defines the sample rate
});

Loading Raw Array Data

When you have raw PCM audio data (such as a Float32Array), Wavesurfer.js needs to know both the channel data and how that data maps to time. The sample rate is essential for calculating the correct duration:

\[\text{Duration (seconds)} = \frac{\text{Array Length}}{\text{Sample Rate}}\]

Method 1: Using an AudioBuffer

The most reliable way to pass raw array data into Wavesurfer.js is to wrap your array inside a standard Web Audio API AudioBuffer. The sampleRate is defined during buffer creation:

const sampleRate = 44100;
const numberOfChannels = 1;
const rawData = new Float32Array([...]); // Your raw PCM sample values

// 1. Create an AudioContext with the target sample rate
const audioContext = new (window.AudioContext || window.webkitAudioContext)({
  sampleRate: sampleRate,
});

// 2. Create the AudioBuffer using the sampleRate
const audioBuffer = audioContext.createBuffer(
  numberOfChannels,
  rawData.length,
  sampleRate
);

// 3. Copy your raw array into the AudioBuffer channel
audioBuffer.copyToChannel(rawData, 0);

// 4. Initialize Wavesurfer with the matching sampleRate
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  sampleRate: sampleRate,
});

// 5. Load the buffer directly
wavesurfer.loadAudio('', audioBuffer);

Method 2: Passing Precomputed Peaks and Duration

If you are loading raw array data purely to visualize the waveform without decoding on the fly, you can provide the raw array as channel data alongside the calculated duration derived from your sample rate:

const sampleRate = 48000;
const channelData = new Float32Array([...]); // Raw audio samples
const duration = channelData.length / sampleRate;

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  sampleRate: sampleRate,
});

// Load using empty URL, channel arrays, and calculated duration
wavesurfer.load('', [channelData], duration);

Why Defining sampleRate Matters

  • Playback Pitch and Speed: If the sample rate set in the AudioContext or buffer does not match the original sample rate of the raw data, audio will play back either too fast (high-pitched) or too slow (low-pitched).
  • Accurate Timelines: Plugins such as the Timeline plugin rely on the calculated duration. A mismatch in sample rate stretches or compresses the timeline markers relative to the visual peaks.
