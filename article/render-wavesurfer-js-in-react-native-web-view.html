Render Wavesurfer.js in React Native WebView

This article explains how React Native applications render Wavesurfer.js by utilizing the react-native-webview component. Because Wavesurfer.js relies heavily on browser-specific APIs such as the HTML5 Canvas, SVG, and the Web Audio API, it cannot run directly within React Native’s native JavaScript thread. By encapsulating Wavesurfer.js inside an embedded WebView and orchestrating bidirectional communication via message passing, developers can render dynamic audio waveforms and handle playback smoothly on mobile devices.

Why Wavesurfer.js Requires a WebView

Wavesurfer.js is engineered explicitly for the web platform. It requires direct access to:

  • DOM Elements: To mount container <div> tags and manipulate elements.
  • HTML5 Canvas / SVG: To draw audio peaks and interactive timelines.
  • Web Audio API / HTMLAudioElement: To decode audio buffers and manage playback events.

React Native operates without a DOM, using native components (like UIView on iOS and android.view.View on Android) rather than HTML elements. The standard approach to run DOM-dependent JavaScript libraries like Wavesurfer.js in React Native is embedding them within a headless or styled WebView instance using react-native-webview.

Architecture of the Integration

The implementation consists of three primary components:

  1. The HTML/JS Shell: An HTML page (either loaded via an inline string or a bundled local asset) that imports the Wavesurfer.js library, defines a container element, and initializes the player.
  2. The WebView Container: The React Native WebView component that renders the HTML shell and handles layout on the screen.
  3. The Message Bridge: A communication channel between the React Native thread and the WebView environment to sync playback state, trigger actions, and relay audio metadata.

Step-by-Step Implementation

1. Preparing the HTML Bundle

Create an HTML string or an HTML file that includes the Wavesurfer.js script via CDN or an inlined script tag. The page initializes the waveform and sets up listeners for incoming post messages.

<!DOCTYPE html>
<html>
  <head>
    <meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no" />
    <script src="https://unpkg.com/wavesurfer.js"></script>
    <style>
      body { margin: 0; padding: 0; background-color: transparent; }
      #waveform { width: 100%; height: 100vh; }
    </style>
  </head>
  <body>
    <div id="waveform"></div>
    <script>
      const wavesurfer = WaveSurfer.create({
        container: '#waveform',
        waveColor: '#4F46E5',
        progressColor: '#818CF8',
        responsive: true,
        height: 80
      });

      // Listen for commands from React Native
      window.addEventListener('message', (event) => {
        try {
          const data = JSON.parse(event.data);
          if (data.type === 'LOAD_AUDIO') {
            wavesurfer.load(data.url);
          } else if (data.type === 'PLAY_PAUSE') {
            wavesurfer.playPause();
          }
        } catch (e) {
          console.error(e);
        }
      });

      // Send events back to React Native
      wavesurfer.on('ready', () => {
        window.ReactNativeWebView.postMessage(JSON.stringify({ type: 'READY' }));
      });

      wavesurfer.on('audioprocess', (currentTime) => {
        window.ReactNativeWebView.postMessage(JSON.stringify({ type: 'TIME_UPDATE', currentTime }));
      });
    </script>
  </body>
</html>

2. Rendering the WebView in React Native

Import WebView from react-native-webview and supply the HTML content via the source prop. Enable JavaScript execution and configure permissions to handle audio playback.

import React, { useRef } from 'react';
import { StyleSheet, View } from 'react-native';
import { WebView } from 'react-native-webview';

const WaveformPlayer = ({ audioUrl }) => {
  const webViewRef = useRef(null);

  const handleMessage = (event) => {
    const data = JSON.parse(event.nativeEvent.data);
    switch (data.type) {
      case 'READY':
        console.log('Waveform ready');
        break;
      case 'TIME_UPDATE':
        console.log('Current time:', data.currentTime);
        break;
      default:
        break;
    }
  };

  const onLoadEnd = () => {
    // Send audio URL once the WebView finishes loading
    const message = JSON.stringify({ type: 'LOAD_AUDIO', url: audioUrl });
    webViewRef.current.postMessage(message);
  };

  return (
    <View style={styles.container}>
      <WebView
        ref={webViewRef}
        originWhitelist={['*']}
        source={{ html: HTML_STRING }} // Pass the HTML string defined earlier
        onMessage={handleMessage}
        onLoadEnd={onLoadEnd}
        allowsInlineMediaPlayback={true}
        mediaPlaybackRequiresUserAction={false}
        javaScriptEnabled={true}
        style={styles.webview}
      />
    </View>
  );
};

const styles = StyleSheet.create({
  container: {
    height: 100,
    width: '100%',
  },
  webview: {
    backgroundColor: 'transparent',
  },
});

export default WaveformPlayer;

Essential WebView Configuration Settings

To ensure smooth rendering and proper playback, specific props must be passed to the WebView component:

  • allowsInlineMediaPlayback={true}: Essential for iOS to play audio directly within the page instead of opening the system's full-screen media player.
  • mediaPlaybackRequiresUserAction={false}: Permits playback to be triggered programmatically from React Native without requiring a direct user tap inside the WebView.
  • originWhitelist={['*']}: Allows the WebView to load scripts, remote audio URLs, or data streams without security blocks.
  • mixedContentMode="always": Required on Android if loading remote audio assets over insecure (http) endpoints within a secure bundle.

Best Practices for Performance

  • Precomputed Peaks: Generating audio waveforms directly from raw audio files inside a WebView can cause performance bottlenecks on low-end mobile devices. Where possible, precompute peaks on the server and pass the JSON array of peaks directly to wavesurfer.load(url, peaks) to skip audio decoding entirely.
  • Local Assets: Bundle the Wavesurfer.js library locally within the application assets rather than pulling it from a CDN to eliminate network latency and enable offline functionality.
  • Memory Management: Destroy the Wavesurfer instance via wavesurfer.destroy() during the WebView component unmount lifecycle to prevent audio buffer memory leaks.
