Streaming HLS Audio with Wavesurfer.js

This article explains how to integrate HTTP Live Streaming (HLS) audio streams with the Wavesurfer.js visualization library. Because Wavesurfer.js natively relies on the Web Audio API to decode complete audio files, streaming segmented protocols like HLS requires a hybrid approach using an external HLS client, an HTML5 media element, and precomputed waveform data.

The Underlying Challenge

Wavesurfer.js typically fetches an entire audio file as an ArrayBuffer and decodes it using the browser's AudioContext.decodeAudioData(). This approach does not work with HLS streams (.m3u8 manifests with split .ts or .aac segments) because the audio is split into small chunks delivered sequentially. Attempting to decode the manifest directly through Web Audio fails, and loading every chunk into memory simultaneously defeats the purpose of streaming.

The Integration Architecture

To integrate HLS with Wavesurfer.js, you must decouple audio playback from waveform rendering:

  1. Playback via Hls.js and HTML5 Audio: The browser uses Hls.js (or native Safari HLS support) to fetch and feed media segments into a standard HTML5 <audio> element.
  2. Wavesurfer Media Element Mode: Wavesurfer.js attaches directly to this <audio> element using its media configuration option, synchronizing its playback controls and cursor with the audio stream.
  3. Precomputed Waveform Data: Because Wavesurfer cannot analyze the unbuffered future segments of the stream, you must supply pre-generated waveform peak data (JSON) directly during initialization.

Step-by-Step Implementation

1. Precompute Waveform Peaks

Before streaming, extract peak data on your backend using tools like audiowaveform or FFmpeg. Export the peaks as an array of floating-point numbers or integers representing min/max amplitudes across the track duration.

2. Initialize Hls.js with the Media Element

Create an HTML5 audio element and bind Hls.js to it:

import Hls from 'hls.js';
import WaveSurfer from 'wavesurfer.js';

const audioElement = document.createElement('audio');
const streamUrl = 'https://example.com/audio/playlist.m3u8';

if (Hls.isSupported()) {
  const hls = new Hls();
  hls.loadSource(streamUrl);
  hls.attachMedia(audioElement);
} else if (audioElement.canPlayType('application/vnd.apple.mpegurl')) {
  // Native Safari HLS support
  audioElement.src = streamUrl;
}

3. Mount Wavesurfer.js to the Media Element

Initialize Wavesurfer, pass the existing audioElement, and provide the precomputed peaks along with the track duration:

fetch('https://example.com/audio/peaks.json')
  .then((response) => response.json())
  .then((peaksData) => {
    const wavesurfer = WaveSurfer.create({
      container: '#waveform',
      waveColor: '#4F4A85',
      progressColor: '#383351',
      media: audioElement,      // Link directly to the HLS audio element
      peaks: [peaksData.data],  // Pass precomputed waveform peaks
      duration: peaksData.duration // Total length in seconds
    });

    wavesurfer.on('ready', () => {
      console.log('Waveform ready for HLS playback');
    });
  });

Seeking and Playback Behavior

When a user clicks on the waveform to seek, Wavesurfer updates audioElement.currentTime. In turn, Hls.js identifies the corresponding segment from the manifest, buffers that specific chunk, and begins playback immediately without needing to load earlier segments. This combination ensures instant visual representation, low memory usage, and efficient bandwidth consumption for long-form audio.
