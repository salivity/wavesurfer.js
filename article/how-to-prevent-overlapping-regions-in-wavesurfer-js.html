How to Prevent Overlapping Regions in Wavesurfer.js

Managing audio segments often requires strict boundaries where no two segments occupy the same temporal space. This guide provides a straightforward method to prevent overlapping regions in the Wavesurfer.js Regions plugin by tracking boundary changes in real time and clamping them against neighboring regions during creation, dragging, and resizing.

The Overlap Prevention Strategy

By default, the Wavesurfer.js Regions plugin allows regions to freely intersect. To enforce non-overlapping behavior, you must listen to region modification events, determine the immediate preceding and succeeding regions, and clamp the active region’s start and end timestamps so they cannot cross adjacent boundaries.

Implementing Boundary Clamping

The most effective way to prevent overlaps is by binding an event handler to the region-update event. This event triggers continuously while a region is being moved or resized, allowing you to restrict movement before it renders past a valid boundary.

Here is the implementation using Wavesurfer.js v7:

import WaveSurfer from 'wavesurfer.js';
import RegionsPlugin from 'wavesurfer.js/dist/plugins/regions.esm.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#violet',
  progressColor: '#purple',
});

const wsRegions = wavesurfer.registerPlugin(RegionsPlugin.create());

wsRegions.on('region-update', (currentRegion) => {
  const otherRegions = wsRegions
    .getRegions()
    .filter((r) => r.id !== currentRegion.id)
    .sort((a, b) => a.start - b.start);

  // Find the immediate predecessor and successor
  let previousRegion = null;
  let nextRegion = null;

  for (const r of otherRegions) {
    if (r.end <= currentRegion.start) {
      previousRegion = r;
    } else if (r.start >= currentRegion.end && !nextRegion) {
      nextRegion = r;
    }
  }

  const minStart = previousRegion ? previousRegion.end : 0;
  const maxEnd = nextRegion ? nextRegion.start : wavesurfer.getDuration();

  // Enforce boundary constraints
  if (currentRegion.start < minStart) {
    const duration = currentRegion.end - currentRegion.start;
    currentRegion.start = minStart;
    
    // If the region was dragged into the boundary, preserve its duration
    if (currentRegion.end < minStart + duration) {
      currentRegion.end = Math.min(minStart + duration, maxEnd);
    }
  }

  if (currentRegion.end > maxEnd) {
    const duration = currentRegion.end - currentRegion.start;
    currentRegion.end = maxEnd;

    // If dragged into the boundary, preserve its duration if possible
    if (currentRegion.start > maxEnd - duration) {
      currentRegion.start = Math.max(maxEnd - duration, minStart);
    }
  }
});

Validating New Regions on Creation

If you allow users to add regions by clicking and dragging on the waveform (e.g., using wsRegions.enableDragSelection()), you must validate the new region when it is created.

Add a listener to the region-created event to inspect whether the new selection collides with any pre-existing segment:

wsRegions.on('region-created', (newRegion) => {
  const hasOverlap = wsRegions.getRegions().some((existing) => {
    if (existing.id === newRegion.id) return false;
    return newRegion.start < existing.end && newRegion.end > existing.start;
  });

  if (hasOverlap) {
    // Remove the newly created region immediately if it overlaps
    newRegion.remove();
  }
});

Key Considerations

  • Minimum Region Size: Ensure that clamping does not reduce a region's duration to zero. Enforce a minimum duration check (e.g., Math.max(currentRegion.start, minStart)) to prevent regions from collapsing.
  • Event Selection: Always use region-update for active visual restriction. Using region-updated (with a past-tense "d") only fires after the user releases the mouse, leading to abrupt snapping rather than a smooth, blocked drag motion.
