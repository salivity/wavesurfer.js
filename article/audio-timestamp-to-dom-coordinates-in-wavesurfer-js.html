Audio Timestamp to DOM Coordinates in Wavesurfer.js

This article explains the mathematical transformation mechanism used to translate temporal audio positions into Document Object Model (DOM) pixel coordinates in Wavesurfer.js. It details the underlying affine transformation matrix, the roles of sample rate, duration, and viewport scaling, and provides the direct formulas required to map between audio seconds and screen pixels accurately.

The Mathematical Transformation Model

Wavesurfer.js maps audio timestamps to horizontal DOM coordinates via a one-dimensional affine transformation. Because audio timelines represent a single continuous temporal dimension (\(t\)) rendered along the horizontal Cartesian axis (\(x\)), the translation can be modeled mathematically in 2D homogeneous coordinates using the following affine transformation matrix:

\[\begin{bmatrix} x \\ y \\ 1 \end{bmatrix} = \begin{bmatrix} S_x & 0 & T_x \\ 0 & 1 & T_y \\ 0 & 0 & 1 \end{bmatrix} \begin{bmatrix} t \\ 0 \\ 1 \end{bmatrix}\]

In this matrix:

  • \(S_x\) (Horizontal Scale Factor): Represents the temporal scale in pixels per second.
  • \(T_x\) (Translation Offset): Accounts for horizontal viewport offsets, such as container scrolling (scrollLeft) and the element's bounding client rect.
  • \(y\) and \(T_y\): Kept constant or set to \(0\), as timestamp mapping operates exclusively along the horizontal axis.

In CSS matrix syntax (matrix(a, b, c, d, tx, ty)), this corresponds to:

\[\text{matrix}(S_x, 0, 0, 1, T_x, 0)\]

Calculating the Scale Factor (\(S_x\))

The horizontal scale factor \(S_x\) determines how many physical CSS pixels represent one second of audio. Wavesurfer.js calculates this factor depending on whether fixed zoom is applied or the waveform is stretched to fill the container:

  1. Auto-fit Mode (Default): When minPxPerSec is not explicitly set, the waveform stretches to the width of the container. \[S_x = \frac{\text{containerWidth}}{\text{duration}}\]

  2. Zoomed Mode (minPxPerSec): When zoom(pxPerSec) or minPxPerSec is specified, the scale factor is defined explicitly: \[S_x = \text{pixelsPerSecond}\] The total canvas width becomes: \[\text{totalWidth} = \text{duration} \times S_x\]

Calculating Translation and DOM Offsets (\(T_x\))

To project an audio timestamp into absolute screen or client coordinates, the translation component \(T_x\) must resolve both local scrolling and the canvas position inside the browser viewport.

Given an audio timestamp \(t\) in seconds:

  1. Relative Waveform Coordinate (\(x_{\text{canvas}}\)): \[x_{\text{canvas}} = t \times S_x\]

  2. Viewport-Relative DOM Coordinate (\(x_{\text{client}}\)): To find the \(X\) position relative to the browser viewport (equivalent to clientX in pointer events): \[x_{\text{client}} = (t \times S_x) - \text{scrollLeft} + \text{containerRect.left}\]

  3. Container-Relative Coordinate (\(x_{\text{local}}\)): To position an overlay element (such as a marker or playhead) inside the Wavesurfer scroll wrapper: \[x_{\text{local}} = t \times S_x\] In this case, the parent container handles viewport clipping natively via CSS overflow: auto.

High-DPI and Canvas Pixel Scaling

Wavesurfer.js renders waveforms onto HTML5 <canvas> elements and accounts for high-density displays using window.devicePixelRatio (DPR).

The internal canvas pixel grid is multiplied by DPR:

\[\text{canvas.width} = \text{containerWidth} \times \text{DPR}\]

To prevent visual distortion, the 2D rendering context applies a native canvas transformation:

\[\text{ctx.scale}(\text{DPR}, 1)\]

Because the canvas element's CSS width remains sized to standard DOM pixels (e.g., width: 100% or styled in CSS pixels), DOM interactions, event coordinate listeners, and UI overlays bypass the DPR scaling factor entirely and rely directly on CSS pixel space.

Inverse Transformation: DOM Coordinate to Timestamp

To convert a click or drag event on the DOM back to an audio timestamp, apply the inverse transformation matrix:

\[\begin{bmatrix} t \\ 0 \\ 1 \end{bmatrix} = \begin{bmatrix} \frac{1}{S_x} & 0 & -\frac{T_x}{S_x} \\ 0 & 1 & 0 \\ 0 & 0 & 1 \end{bmatrix} \begin{bmatrix} x \\ y \\ 1 \end{bmatrix}\]

Expressed as a direct programmatic formula:

\[t = \frac{x_{\text{client}} - \text{containerRect.left} + \text{scrollLeft}}{S_x}\]

Where:

  • \(x_{\text{client}}\) is event.clientX from a mouse or touch event.
  • \(\text{containerRect.left}\) is obtained via wavesurfer.getWrapper().getBoundingClientRect().left.
  • \(\text{scrollLeft}\) is the scroll offset of the waveform scroll container.
  • \(S_x\) is the calculated pixels-per-second scale factor.
