Wavesurfer.js Keyboard Focus Outlines on Regions

Interactive regions in Wavesurfer.js rely on DOM elements layered on top of the audio waveform canvas, allowing developers to implement standard web accessibility practices for keyboard users. Because regions are HTML elements rather than flat pixel renderings, they can receive visual focus outlines through native browser styling or custom CSS. This guide explains how focus outlines function on interactive Wavesurfer.js regions, how keyboard navigation reaches them, and how to style these indicators to avoid common display issues like container clipping.

DOM Representation and Focusability

Wavesurfer.js renders the overall waveform using HTML5 Canvas, but its Regions plugin renders individual audio selections as standard <div> elements positioned over the track.

By default, an HTML <div> cannot receive keyboard focus. For a focus outline to appear when a user tabs through the interface, the region element must possess a tabindex attribute. When creating or configuring regions:

  • Setting tabindex="0" ensures the region is inserted into the natural tab sequence of the page.
  • Setting tabindex="-1" allows the region to receive programmatic focus (via JavaScript .focus()), displaying the outline only when targeted by code.

Once an interactive region element is focusable, keyboard users navigating with the Tab key will cycle directly to the region, triggering the browser's focus behavior.

Native Browser Focus Indicators

When an interactive region receives keyboard focus, modern browsers trigger the :focus-visible pseudo-class.

  • Default Appearance: Browsers render their standard focus ring around the bounding box of the region's <div>. In Chromium-based browsers, this is typically a high-contrast double outline (black and white or solid blue). In Safari and Firefox, it manifests as a distinct accent-colored ring.
  • Scope of the Outline: The outline wraps the full perimeter of the region's start and end boundaries on the time axis. If the region includes resize handles on the edges, those handles may either share the primary region's focus boundary or maintain their own focus rings if implemented as separate focusable elements.

Styling Focus Outlines with CSS

Default browser outlines can conflict with audio interface aesthetics or fail contrast requirements against complex waveform visuals. You can customize the focus outline using the region's class selector (commonly .wavesurfer-region):

/* Custom focus outline for keyboard navigation */
.wavesurfer-region:focus-visible {
  outline: 2px solid #005fcc;
  outline-offset: 2px;
  border-radius: 4px;
}

Using :focus-visible instead of :focus ensures that mouse users clicking to seek or drag a region do not trigger an unwanted focus ring, preserving the visual cue exclusively for keyboard and assistive technology users.

Handling Visual Clipping

A common issue in Wavesurfer.js implementations is focus outline clipping. Audio waveform wrappers frequently utilize overflow: hidden to keep playheads and peak data strictly contained within the player bounds.

When a standard CSS outline extends outward, it can be cut off at the top, bottom, or player edges. To resolve this:

  1. Negative Outline Offset: Use outline-offset: -2px to draw the ring just inside the region's boundaries rather than outside.
  2. Inset Box Shadow: Use box-shadow: inset 0 0 0 2px #005fcc as an alternative to outline. Inset shadows render fully within the element, ensuring the visual indicator remains visible even in tight, overflow-restricted player containers.
