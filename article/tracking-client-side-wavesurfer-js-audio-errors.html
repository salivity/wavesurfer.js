Tracking Client-Side Wavesurfer.js Audio Errors

Monitoring client-side audio failures in Wavesurfer.js requires capturing low-level decoding and media playback issues and transmitting those diagnostics to an Application Performance Monitoring (APM) or telemetry platform. This guide outlines how to hook into Wavesurfer.js event listeners, monitor underlying HTML5 audio and Web Audio API failures, and route these runtime metrics into modern telemetry tools like Sentry, Datadog, LogRocket, or custom beacon endpoints.

Listening to Wavesurfer.js Event Hooks

Wavesurfer.js exposes lifecycle events that serve as the primary entry point for capturing playback and loading failures.

  • wavesurfer.on('error', (error) => { ... }): The primary event for general exceptions. It catches failures occurring during audio source fetching, decoding, or waveform rendering.
  • Promise Rejections: When using asynchronous methods like wavesurfer.load(url) or wavesurfer.loadBlob(blob), always append a .catch() block. Unhandled rejections during audio initialization can bypass standard event listeners in modern versions (v7+).

Monitoring Underlying Audio Components

Wavesurfer.js relies on either an HTML5 <audio> element (MediaElement backend) or the Web Audio API (WebAudio backend). Monitoring these underlying engines provides granular failure data.

1. HTML5 Media Element Errors

When utilizing the default or media element backend, attach a listener directly to the media element:

const media = wavesurfer.getMediaElement();

media.addEventListener('error', () => {
  const mediaError = media.error;
  // mediaError.code returns:
  // 1: MEDIA_ERR_ABORTED
  // 2: MEDIA_ERR_NETWORK
  // 3: MEDIA_ERR_DECODE
  // 4: MEDIA_ERR_SRC_NOT_SUPPORTED
  sendTelemetry('audio_media_error', {
    code: mediaError.code,
    message: mediaError.message,
    currentSrc: media.currentSrc,
  });
});

Track playback stall conditions by monitoring stalled, waiting, and suspend events to detect buffering problems caused by network throttling or stream interruption.

2. Web Audio API Context Telemetry

When using raw Web Audio:

  • Monitor AudioContext.state transitions (running, suspended, interrupted, or closed).
  • Capture failures returned by AudioContext.decodeAudioData(), which frequently fail on malformed audio headers or unsupported sample rates across different mobile browsers.

Telemetry and Error Logging Integrations

Sentry

Sentry captures detailed stack traces and allows breadcrumb tracking for audio playback sessions.

  • Record audio lifecycle events as breadcrumbs (wavesurfer.on('ready'), wavesurfer.on('play'), wavesurfer.on('pause')).
  • Use Sentry.captureException(error) inside the Wavesurfer error callback.
  • Attach custom tags such as audio_format, audio_backend, and browser_audio_support.

Datadog RUM (Real User Monitoring)

Datadog RUM allows you to track audio loading as custom user actions and log failures as custom errors:

  • Track total load duration from load() invocation to the ready event using custom performance timings.
  • Send datadogRum.addError(error, { source: 'wavesurfer', url: audioUrl }) to correlate playback failures with user session recordings and network traces.

LogRocket or Session Replay Tools

Visual session replays show whether an audio failure was accompanied by user interactions (such as rapid scrubbing or volume changes). LogRocket captures console errors and allows custom event dispatching (LogRocket.track('Audio Playback Failed')) to flag sessions with broken audio states.

Custom Beacon Telemetry

For internal logging pipelines, use the navigator.sendBeacon() API to send telemetry data asynchronously without blocking the user interface or failing during page navigation:

wavesurfer.on('error', (err) => {
  const payload = JSON.stringify({
    event: 'wavesurfer_error',
    message: err.message || err,
    userAgent: navigator.userAgent,
    timestamp: Date.now(),
  });
  navigator.sendBeacon('/api/telemetry/audio-errors', payload);
});

Contextual Data to Include in Error Payloads

To diagnose audio errors effectively, ensure telemetry payloads include:

  • Audio URL and MIME Type: Helps identify missing files, broken redirects, or misconfigured content-type headers.
  • CORS Configuration: Missing Access-Control-Allow-Origin headers are a leading cause of decoding failures in canvas rendering.
  • Audio Backend: Identifies whether the failure occurred via MediaElement or WebAudio.
  • Hardware and Browser State: Includes browser version, OS, audio output device changes, and whether autoplay policies restricted playback.
