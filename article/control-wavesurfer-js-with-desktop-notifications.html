Control Wavesurfer.js with Desktop Notifications

Integrating desktop notification controls with an active Wavesurfer.js instance allows users to control audio playback directly from operating system media widgets, lock screens, and custom notification banners. This interface is primarily established using the browser's Media Session API and the Web Notifications API, which act as communication layers between the operating system's native notification dispatchers and the Wavesurfer.js JavaScript methods.

The Role of the Media Session API

Modern desktop operating systems (including Windows, macOS, and Linux desktop environments) display audio control overlays in their notification centers when media plays inside a browser. The browser exposes these system-level interfaces via the navigator.mediaSession interface.

Because Wavesurfer.js operates as an abstraction over either the HTML5 Audio element or the Web Audio API (AudioContext), it does not automatically hook into OS-level media notifications unless configured to do so. The Media Session API provides the bridge by translating OS events (such as pressing the play/pause button on a notification) into function calls that direct the Wavesurfer.js instance.

Binding System Controls to Wavesurfer Methods

To receive input from desktop notification controls, you attach action listeners to navigator.mediaSession that invoke the corresponding methods on your Wavesurfer instance:

if ('mediaSession' in navigator) {
  navigator.mediaSession.setActionHandler('play', () => {
    wavesurfer.play();
  });

  navigator.mediaSession.setActionHandler('pause', () => {
    wavesurfer.pause();
  });

  navigator.mediaSession.setActionHandler('seekbackward', (details) => {
    const skipTime = details.seekOffset || 10;
    wavesurfer.setTime(Math.max(wavesurfer.getCurrentTime() - skipTime, 0));
  });

  navigator.mediaSession.setActionHandler('seekforward', (details) => {
    const skipTime = details.seekOffset || 10;
    wavesurfer.setTime(Math.min(wavesurfer.getCurrentTime() + skipTime, wavesurfer.getDuration()));
  });

  navigator.mediaSession.setActionHandler('stop', () => {
    wavesurfer.stop();
  });
}

Synchronizing State Back to the System

Communication must be bidirectional. When audio is altered directly within the Wavesurfer.js waveform (such as user clicks or automatic track endings), the desktop notification needs to reflect the current state. Wavesurfer's event listeners synchronize this state back to the operating system:

wavesurfer.on('play', () => {
  navigator.mediaSession.playbackState = 'playing';
});

wavesurfer.on('pause', () => {
  navigator.mediaSession.playbackState = 'paused';
});

wavesurfer.on('ready', () => {
  navigator.mediaSession.metadata = new MediaMetadata({
    title: 'Track Title',
    artist: 'Artist Name',
    album: 'Album Name',
    artwork: [
      { src: '/path/to/cover.png', sizes: '512x512', type: 'image/png' }
    ]
  });
});

Updating playbackState prevents the notification control widget from falling out of sync, ensuring play and pause icons toggle correctly.

Interfacing Through the Web Notifications API

When using explicit desktop pop-ups via the Web Notifications API rather than native media overlays, control buttons are created using notification actions:

  1. Creating Actions: An interactive notification is spawned with action identifiers such as play or pause.
  2. Handling Service Worker Events: Clicks on notification buttons fire notificationclick events inside the registered Service Worker.
  3. Broadcasting to the Client: The Service Worker sends a message to the active client window using postMessage().
  4. Targeting Wavesurfer: The window listens via navigator.serviceWorker.onmessage and invokes the matching Wavesurfer call (e.g., wavesurfer.playPause()).

Using either the Media Session API for native system media widgets or the Notifications API for discrete push-style banners provides complete desktop control over a running Wavesurfer.js playback session.
