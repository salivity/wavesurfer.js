CacheStorage API for Wavesurfer.js AudioBuffers

Caching audio data using the browser's CacheStorage API significantly improves web application performance by eliminating repeated network requests and expensive decoding cycles in Wavesurfer.js. Because CacheStorage operates strictly with standard HTTP Request and Response interfaces, binary AudioBuffer instances cannot be stored directly. Instead, they must be converted into binary payloads—such as raw binary Blobs, ArrayBuffer arrays, or custom PCM data structures—wrapped in a synthetic Response object, and stored for instant retrieval during waveform rendering and audio playback.

The Storage Architecture Constraint

The Web Audio API represents fully decoded, uncompressed PCM audio as an in-memory AudioBuffer object. In contrast, the CacheStorage API is designed around the Service Worker specification, meaning it can only store pairs of Request and Response objects.

To bridge this gap, an application cannot write an AudioBuffer directly to disk or cache. You must either:

  1. Store the original encoded binary audio file (MP3, WAV, OGG) as a cached Response.
  2. Serialize the uncompressed channel data from the AudioBuffer into a raw binary format (ArrayBuffer or a WAV Blob) before caching.
  3. Cache the precomputed peak data (the visual amplitude points) alongside the audio to bypass both downloading and audio decoding entirely in Wavesurfer.js.

Serializing and Storing Binary Audio

To store binary audio inside CacheStorage, you must wrap the binary data in an HTTP Response object. If you have fetched an audio file as an ArrayBuffer or generated a Blob from an AudioBuffer, you instantiate a new Response with the appropriate headers:

async function cacheAudioBuffer(cacheName, url, audioData) {
  const cache = await caches.open(cacheName);
  
  // audioData can be an ArrayBuffer or Blob
  const response = new Response(audioData, {
    headers: {
      'Content-Type': 'audio/wav',
      'Content-Length': audioData.byteLength.toString(),
      'X-Cached-Date': new Date().toISOString()
    }
  });

  await cache.put(new Request(url), response);
}

If you are starting from an existing decoded AudioBuffer in memory and need to cache its exact PCM state to avoid future decodeAudioData processing overhead, you must extract its Float32 channel data using audioBuffer.getChannelData(channelIndex) and merge them into an uncompressed binary ArrayBuffer (typically formatted with a 44-byte standard WAV header).

Retrieving and Passing Audio to Wavesurfer.js

When a user requests a track, check the CacheStorage container before falling back to a network request. Wavesurfer.js accepts both direct URLs and binary inputs (such as Blobs or Web Audio API primitives) via its configuration and loading methods.

To retrieve the cached binary data:

async function getCachedAudio(cacheName, url) {
  const cache = await caches.open(cacheName);
  const cachedResponse = await cache.match(url);

  if (!cachedResponse) {
    return null;
  }

  // Convert the response back into an ArrayBuffer or Blob
  return await cachedResponse.arrayBuffer();
}

Once the ArrayBuffer is retrieved from the cache, load it directly into your Wavesurfer.js instance using a Blob:

const cachedData = await getCachedAudio('audio-cache-v1', '/media/track.wav');

if (cachedData) {
  const audioBlob = new Blob([cachedData], { type: 'audio/wav' });
  wavesurfer.loadBlob(audioBlob);
} else {
  // Fall back to fetching from network and caching for next time
  wavesurfer.load('/media/track.wav');
}

Optimizing Waveform Rendering with Peaks Caching

While caching the raw binary audio eliminates network latency, the browser must still execute AudioContext.decodeAudioData() to process the audio and render the waveform canvas in Wavesurfer.js. For large files, this causes noticeable main-thread CPU latency.

To achieve maximum performance, pair CacheStorage of the binary audio with an indexed storage structure (or structured JSON response stored in CacheStorage) containing the precomputed peaks array:

// Render instantly without re-decoding the entire binary audio buffer
wavesurfer.load(audioUrl, precomputedPeaksArray);

By storing the raw audio response in CacheStorage and feeding pre-extracted peaks to Wavesurfer.js, the player instantiates immediately while retaining offline availability and high-performance playback.
