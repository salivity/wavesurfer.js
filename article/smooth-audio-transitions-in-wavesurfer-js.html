Smooth Audio Transitions in Wavesurfer.js

Transitioning smoothly between two audio tracks in Wavesurfer.js requires blending the end of one track into the beginning of another using audio fading techniques. Because a single Wavesurfer instance cannot play two audio files simultaneously, the most reliable method involves running two separate instances concurrently and manipulating their volume levels using the Web Audio API or built-in volume controls. This guide outlines how to configure dual instances, trigger automated crossfades, and achieve seamless playback transitions.

The Dual-Instance Approach

To create a crossfade, you need an overlapping period where the outgoing track gradually lowers its volume (fade-out) while the incoming track increases its volume (fade-in). The simplest architectural pattern is to create two Wavesurfer instances—Instance A and Instance B—and toggle between them.

Step 1: Initialize the Instances

Set up two separate containers in your HTML and instantiate two Wavesurfer players in your JavaScript:

import WaveSurfer from 'wavesurfer.js';

const wsA = WaveSurfer.create({
  container: '#waveform-a',
  waveColor: '#4F4A85',
  progressColor: '#383351',
});

const wsB = WaveSurfer.create({
  container: '#waveform-b',
  waveColor: '#A8B3C5',
  progressColor: '#4F4A85',
});

Step 2: Implement the Fade Logic

Wavesurfer.js provides the setVolume(value) method, accepting a float between 0 (silent) and 1 (full volume). You can implement a linear or exponential crossfade function using requestAnimationFrame or setInterval.

function crossfade(outgoingWs, incomingWs, durationMs = 2000) {
  const stepTime = 50; // Interval in milliseconds
  const steps = durationMs / stepTime;
  let currentStep = 0;

  // Prepare incoming track
  incomingWs.setVolume(0);
  incomingWs.play();

  const fadeInterval = setInterval(() => {
    currentStep++;
    const progress = currentStep / steps;

    // Linear fade calculations
    const outgoingVol = Math.max(0, 1 - progress);
    const incomingVol = Math.min(1, progress);

    outgoingWs.setVolume(outgoingVol);
    incomingWs.setVolume(incomingVol);

    if (currentStep >= steps) {
      clearInterval(fadeInterval);
      outgoingWs.pause();
      outgoingWs.setVolume(1); // Reset volume for future playback
    }
  }, stepTime);
}

Step 3: Trigger the Transition Automatically

To transition smoothly before the active track finishes, listen to the audioprocess or timeupdate event on the active player. Calculate the remaining time by comparing the current playback time with the total track duration:

const FADE_DURATION = 3; // Fade duration in seconds

wsA.on('timeupdate', (currentTime) => {
  const duration = wsA.getDuration();
  
  // Trigger crossfade when remaining time matches the fade duration
  if (duration > 0 && duration - currentTime <= FADE_DURATION) {
    // Ensure the event only fires once per transition
    wsA.un('timeupdate');
    
    crossfade(wsA, wsB, FADE_DURATION * 1000);
  }
});

Using Web Audio API Gain Nodes (Advanced)

For professional-grade transitions, linear volume changes can cause a noticeable drop in perceived loudness midway through the transition. You can achieve an equal-power crossfade by connecting Wavesurfer's internal audio context to custom Web Audio GainNode instances.

  1. Obtain the AudioContext from Wavesurfer or route each instance's media element to separate gain nodes.
  2. Use gainNode.gain.setValueCurveAtTime() or gainNode.gain.linearRampToValueAtTime() to schedule high-precision, hardware-accelerated fades natively.
  3. An equal-power curve ensures that volumeA^2 + volumeB^2 = 1, maintaining constant perceived acoustic energy throughout the transition.

Best Practices

  • Preload Next Tracks: Always load the second track (wsB.load('url')) well in advance of the transition to ensure decoding finishes before playback begins.
  • UI Management: If your design only displays a single waveform, hide the inactive instance's container with CSS (display: none) and swap visibility once the transition is complete.
  • Cleanup: Destroy unused instances with ws.destroy() if your application plays an open-ended playlist, preventing Web Audio context and memory leaks.
