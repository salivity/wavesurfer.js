Loading Corrupt Audio Files in Wavesurfer.js

Passing corrupt or truncated audio files to Wavesurfer.js load methods triggers a failure in the browser's underlying decoding engine, preventing waveform rendering and halting audio playback. Because Wavesurfer.js relies on the Web Audio API to process raw audio data, corrupt files disrupt the decoding pipeline, dispatching error events that must be caught and handled in your application to avoid silent crashes and broken user interfaces.

The Underlying Decoding Process

When you invoke methods such as wavesurfer.load(url) or wavesurfer.loadBlob(blob), the library fetches the audio file as an ArrayBuffer and passes it directly to the browser's native AudioContext.decodeAudioData() method. Wavesurfer.js does not parse audio bytes directly; it relies on the browser to decompress and decode the file into an AudioBuffer containing raw PCM channel data.

What Happens with Corrupt Audio

If an audio file contains malformed headers, invalid byte streams, or missing frame markers, the browser's AudioContext.decodeAudioData() cannot process the buffer.

  1. Decoding Rejection: The decodeAudioData promise rejects with a DOMException (typically an EncodingError stating that the media resource could not be decoded).
  2. Error Emission: Wavesurfer.js catches this rejection internally and emits its own error event, passing the decoding error object to any registered listeners.
  3. Canvas State: The waveform canvas remains empty, unrendered, or displays a flat, zero-amplitude line depending on the version and custom rendering configuration.
  4. Playback State: The player fails to enter the ready state. Attempting to call wavesurfer.play() will either throw an unhandled exception or fail silently because no valid AudioBuffer exists to attach to an AudioBufferSourceNode.

What Happens with Truncated Audio

The behavior of truncated audio depends entirely on the file format and where the cutoff occurs:

  • Header-Strict Formats (WAV, MP4): Formats like WAV explicitly define byte lengths in their headers, while MP4/M4A containers often place critical index information (the moov atom) at the end of the file. If these files are truncated, decodeAudioData() treats the missing data as structural corruption and fails completely, triggering the standard EncodingError.
  • Stream-Based Formats (MP3, OGG): MP3 files are organized in independent audio frames. If an MP3 is cleanly cut off after valid header and initial frames, many modern browsers will decode whatever valid frames are present. In this scenario, Wavesurfer.js renders a shorter waveform corresponding only to the intact portion, adjusts the duration accordingly, and plays only up to the point of truncation without throwing an explicit error.

Proper Error Handling

To handle corrupt or severely truncated files gracefully, applications must listen to the error event provided by the Wavesurfer instance:

wavesurfer.on('error', (error) => {
  console.error('Wavesurfer decoding error:', error);
  // Update UI to notify user of corrupt media
});

Without an error listener, corrupt files can result in an unhandled promise rejection in the console, leaving the UI in an indeterminate loading state. Always clear loading spinners and notify users of invalid media within this callback.
