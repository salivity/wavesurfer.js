Detect Wavesurfer.js Media Stalling Events

Detecting network stalling events in Wavesurfer.js requires monitoring the native HTML5 audio element running beneath the visualization layer. When streaming audio over unstable connections, playback frequently freezes due to empty buffer queues rather than user-initiated pauses. This guide explains how to extract the underlying media backend from a Wavesurfer.js instance, listen for native buffering and stalling events, and handle playback recovery in your application.

Accessing the Underlying Media Element

Wavesurfer.js relies on an HTMLMediaElement (<audio> or <video>) for its MediaElement backend. Native network events do not bubble directly through custom Wavesurfer wrappers in all versions, so you must target the media element directly.

You can retrieve the media element using the getMediaElement() method:

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: '/path/to/audio/stream.mp3',
});

// Retrieve the native HTMLAudioElement
const audioElement = wavesurfer.getMediaElement();

In older versions (Wavesurfer v6 and earlier), if getMediaElement() is unavailable, the element can be referenced directly through the backend object:

const audioElement = wavesurfer.backend.media;

Key HTML5 Network and Buffering Events

To capture all aspects of media stalling, you must monitor several complementary events dispatched by the HTMLMediaElement:

  • waiting: Dispatched when playback stops because the next frame or audio chunk is not yet available, typically due to buffer underruns.
  • stalled: Dispatched when the browser attempts to fetch media data from the server, but no data has been received within an expected threshold.
  • playing: Dispatched when playback starts or resumes after being paused or delayed by buffering.
  • canplay: Dispatched when the browser has loaded enough data to begin playback, though further buffering may still occur.

Implementing the Event Listeners

Attach listeners directly to the retrieved media element to manage UI state, such as displaying a buffering spinner or executing fallback logic:

function setupStallDetection(audioElement) {
  let isStalled = false;

  // Triggered when data fetching stops unexpectedly
  audioElement.addEventListener('stalled', () => {
    isStalled = true;
    console.warn('Network stalled: Data transfer has stopped unexpectedly.');
    showLoadingIndicator(true);
  });

  // Triggered when playback pauses because buffer is empty
  audioElement.addEventListener('waiting', () => {
    isStalled = true;
    console.warn('Buffering: Waiting for data before resuming playback.');
    showLoadingIndicator(true);
  });

  // Triggered when sufficient data has loaded to resume
  audioElement.addEventListener('playing', () => {
    if (isStalled) {
      isStalled = false;
      console.log('Playback resumed.');
      showLoadingIndicator(false);
    }
  });

  audioElement.addEventListener('canplay', () => {
    if (isStalled) {
      showLoadingIndicator(false);
    }
  });
}

function showLoadingIndicator(isLoading) {
  const spinner = document.getElementById('audio-spinner');
  if (spinner) {
    spinner.style.display = isLoading ? 'block' : 'none';
  }
}

// Attach listeners once Wavesurfer is ready
wavesurfer.on('ready', () => {
  const mediaElement = wavesurfer.getMediaElement();
  setupStallDetection(mediaElement);
});

Handling Timeouts and Recovery

Browsers do not always recover cleanly from a stalled state if a network connection drops completely. To ensure stability, implement a timeout mechanism during stall events:

let stallTimeout = null;
const STALL_TIMEOUT_MS = 10000;

function handleStallWithTimeout(audioElement) {
  audioElement.addEventListener('waiting', () => {
    clearTimeout(stallTimeout);
    
    stallTimeout = setTimeout(() => {
      console.error('Network timeout: Audio stream could not recover.');
      // Attempt manual recovery or notify user
      audioElement.load();
    }, STALL_TIMEOUT_MS);
  });

  audioElement.addEventListener('playing', () => {
    clearTimeout(stallTimeout);
  });
}

By tapping directly into the HTMLMediaElement's waiting and stalled APIs, you gain immediate, reliable insight into network interruptions without relying on polling playback timestamps.
