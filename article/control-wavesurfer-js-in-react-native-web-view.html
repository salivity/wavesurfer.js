Control Wavesurfer.js in React Native WebView

Controlling audio playback with Wavesurfer.js inside a React Native application requires a bi-directional bridge between the React Native thread and the react-native-webview component. Because the audio engine runs within the web context, play and pause commands must be serialized as stringified JSON messages sent through the WebView's communication APIs, while Wavesurfer.js event listeners dispatch state updates back to React Native to keep the native UI synchronized.

Sending Play and Pause Commands from React Native

React Native sends playback commands to the WebView using either the postMessage method on the WebView reference or by evaluating JavaScript directly via injectJavaScript. The postMessage approach is the standard pattern for declarative messaging.

To trigger playback actions, define a structured JSON payload:

// Example commands from React Native
const sendPlayCommand = () => {
  webViewRef.current?.postMessage(JSON.stringify({ type: 'WAVESURFER_PLAY' }));
};

const sendPauseCommand = () => {
  webViewRef.current?.postMessage(JSON.stringify({ type: 'WAVESURFER_PAUSE' }));
};

const sendToggleCommand = () => {
  webViewRef.current?.postMessage(JSON.stringify({ type: 'WAVESURFER_PLAY_PAUSE' }));
};

Alternatively, direct execution can be achieved via injectJavaScript:

webViewRef.current?.injectJavaScript(`
  if (window.wavesurfer) {
    window.wavesurfer.playPause();
  }
  true;
`);

Receiving Commands and Triggering Wavesurfer.js

Inside the HTML/JavaScript code loaded by the WebView, an event listener intercepts messages posted by React Native. Once parsed, these messages trigger the corresponding Wavesurfer.js API methods: wavesurfer.play(), wavesurfer.pause(), or wavesurfer.playPause().

// Inside the WebView HTML script
window.addEventListener('message', (event) => {
  handleBridgeMessage(event.data);
});

// Fallback for Android environments
document.addEventListener('message', (event) => {
  handleBridgeMessage(event.data);
});

function handleBridgeMessage(data) {
  try {
    const payload = JSON.parse(data);

    if (!window.wavesurfer) return;

    switch (payload.type) {
      case 'WAVESURFER_PLAY':
        window.wavesurfer.play();
        break;
      case 'WAVESURFER_PAUSE':
        window.wavesurfer.pause();
        break;
      case 'WAVESURFER_PLAY_PAUSE':
        window.wavesurfer.playPause();
        break;
      default:
        break;
    }
  } catch (error) {
    console.error('Failed to parse bridge message:', error);
  }
}

Passing State Back to React Native

To keep the native playback button state in sync with the audio state, the WebView dispatches messages back to React Native using window.ReactNativeWebView.postMessage(). Wavesurfer.js provides lifecycle events (play, pause, and finish) that should trigger these bridge messages.

// Register Wavesurfer event listeners inside the WebView
window.wavesurfer.on('play', () => {
  window.ReactNativeWebView.postMessage(
    JSON.stringify({ event: 'ON_PLAY', isPlaying: true })
  );
});

window.wavesurfer.on('pause', () => {
  window.ReactNativeWebView.postMessage(
    JSON.stringify({ event: 'ON_PAUSE', isPlaying: false })
  );
});

window.wavesurfer.on('finish', () => {
  window.ReactNativeWebView.postMessage(
    JSON.stringify({ event: 'ON_FINISH', isPlaying: false })
  );
});

Handling State Updates in React Native

React Native captures these incoming bridge messages using the onMessage prop on the WebView component.

<WebView
  ref={webViewRef}
  source={{ html: htmlContent }}
  onMessage={(event) => {
    try {
      const data = JSON.parse(event.nativeEvent.data);
      if (data.event === 'ON_PLAY') {
        setIsPlaying(true);
      } else if (data.event === 'ON_PAUSE' || data.event === 'ON_FINISH') {
        setIsPlaying(false);
      }
    } catch (err) {
      console.warn('Error reading WebView message', err);
    }
  }}
/>

This communication loop ensures commands sent from native buttons update the audio instance reliably, while user interactions or end-of-track events occurring directly inside the canvas surface immediately update the React Native UI state.
