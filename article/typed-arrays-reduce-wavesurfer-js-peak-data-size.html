Typed Arrays Reduce Wavesurfer.js Peak Data Size

This article explains how using Int8Array and Int16Array binary typed arrays significantly decreases the data payload size of precomputed waveform peaks in Wavesurfer.js. By quantizing floating-point audio data into compact integer representations and bypassing JSON serialization, these typed arrays eliminate overhead, decrease network bandwidth requirements, and accelerate rendering performance in web applications.

The Overhead of Standard Peak Data

Wavesurfer.js renders visual audio waveforms by plotting arrays of minimum and maximum amplitude values across an audio track. A common approach involves exporting these peaks on a server and sending them to the client as a JSON array of floating-point numbers.

This approach creates substantial network overhead:

  • JSON Serialization: In JSON, a float like -0.852341 is stored as an ASCII string taking 9 to 10 bytes, plus additional bytes for punctuation (commas and brackets).
  • High Precision Waste: Visual waveform rendering requires only enough vertical resolution to map to screen pixels. Storing full 32-bit or 64-bit floating-point precision provides far more fidelity than a browser canvas can visually represent.

How Int8Array and Int16Array Reduce Payload Size

Binary typed arrays replace text-based JSON floats with dense, fixed-width binary representations.

1. Quantization to Lower Bit Depths

Before transmission, normalized floating-point peaks (which range from -1.0 to 1.0) are quantized into integers:

  • Int8Array (8-bit signed): Audio peaks are multiplied by 127 and rounded, fitting values within the -128 to 127 range. This represents 256 discrete vertical levels, which is often sufficient for standard waveform displays.
  • Int16Array (16-bit signed): Peaks are multiplied by 32767 and rounded, fitting values within the -32768 to 32767 range. This provides over 65,000 discrete steps, suitable for high-resolution displays or zoomed-in waveform visualizers.

2. Fixed Byte Allocations

Typed arrays operate directly on raw binary memory (ArrayBuffer):

  • An Int8Array consumes exactly 1 byte per value.
  • An Int16Array consumes exactly 2 bytes per value.

For a track requiring 20,000 peak points:

  • Standard JSON float array: ~140 KB to 200 KB
  • Raw Float32Array: 80 KB
  • Int16Array: 40 KB
  • Int8Array: 20 KB

Switching to Int8Array yields an approximate 85% to 90% reduction in raw payload size compared to standard JSON representations.

Network and Parsing Efficiency

Aside from raw byte reduction, typed arrays improve performance through modern transport and decoding mechanisms:

  • Direct Binary Fetching: The client can fetch the peak data as an arraybuffer via fetch() or XMLHttpRequest. This bypasses HTTP text-encoding overhead and gzip decompression limitations on structured text.
  • Instant In-Memory Instantiation: Unlike JSON, which requires the browser to parse strings into JavaScript numbers (a CPU-heavy task for large arrays), typed arrays can be instantiated directly over the received ArrayBuffer without memory reallocation.
  • Native Wavesurfer.js Ingestion: Wavesurfer.js can accept these arrays directly into its peaks option. If normalized ranges (-1.0 to 1.0) are required by specific internal renderers, the typed array elements can be scaled back through a single linear operation, or the canvas coordinate mapping can be adjusted to scale directly from the integer range.
