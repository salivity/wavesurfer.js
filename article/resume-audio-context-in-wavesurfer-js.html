Resume AudioContext in Wavesurfer.js

Modern web browsers enforce strict autoplay policies that automatically suspend the Web Audio API's AudioContext until a user interacts with the webpage. When using Wavesurfer.js, this can lead to silent playback or console warnings stating that the AudioContext was not allowed to start. This guide outlines why this happens and provides straightforward solutions to resume the AudioContext seamlessly using user-triggered events.

Why AudioContext Suspends

Browsers like Google Chrome, Safari, and Firefox automatically initialize an AudioContext in a "suspended" state if it is instantiated before an explicit user action (such as a click, tap, or keypress). To restore normal audio functionality, the context must be transitioned to the "running" state by invoking its .resume() method within an event listener.

Method 1: Resuming via a Play Button (Recommended)

The most reliable approach is to bind the resume operation directly to your playback trigger. Wavesurfer.js v7 and earlier versions allow direct access to the underlying AudioContext.

Wavesurfer.js v7+ Implementation

In Wavesurfer.js v7, you can access the context via wavesurfer.getAudioContext().

import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#violet',
  progressColor: '#purple',
  url: '/path/to/audio.mp3',
});

const playButton = document.querySelector('#play-btn');

playButton.addEventListener('click', async () => {
  const audioContext = wavesurfer.getAudioContext();

  // Check if context is suspended and resume it
  if (audioContext && audioContext.state === 'suspended') {
    await audioContext.resume();
  }

  // Toggle playback
  wavesurfer.playPause();
});

Wavesurfer.js v6 and Earlier

In older versions, the AudioContext resides within the backend instance:

playButton.addEventListener('click', () => {
  const audioContext = wavesurfer.backend.getAudioContext();

  if (audioContext && audioContext.state === 'suspended') {
    audioContext.resume().then(() => {
      wavesurfer.playPause();
    });
  } else {
    wavesurfer.playPause();
  }
});

Method 2: Global First-Interaction Listener

If you want the audio to be ready prior to the user pressing a dedicated play button, you can attach a one-time global event listener to the document.

const unlockAudioContext = async () => {
  const audioContext = wavesurfer.getAudioContext();

  if (audioContext && audioContext.state === 'suspended') {
    await audioContext.resume();
  }

  // Remove listeners once unlocked
  document.removeEventListener('click', unlockAudioContext);
  document.removeEventListener('keydown', unlockAudioContext);
  document.removeEventListener('touchstart', unlockAudioContext);
};

// Add listeners for any initial interaction
document.addEventListener('click', unlockAudioContext);
document.addEventListener('keydown', unlockAudioContext);
document.addEventListener('touchstart', unlockAudioContext);

Method 3: Using Wavesurfer's Built-in Events

You can also hook directly into the Wavesurfer event lifecycle by listening for the interaction event, which fires whenever a user clicks anywhere on the waveform.

wavesurfer.on('interaction', async () => {
  const audioContext = wavesurfer.getAudioContext();
  if (audioContext && audioContext.state === 'suspended') {
    await audioContext.resume();
  }
});

Summary Checklist

  • Always check whether audioContext.state === 'suspended' before attempting playback.
  • Ensure the .resume() method is called directly inside a synchronous execution block triggered by a trusted user event (click, touchend, or keydown).
  • Use wavesurfer.getAudioContext() for modern versions (v7+) and wavesurfer.backend.getAudioContext() for legacy versions.
