Sync Multiple Wavesurfer.js Players with Event Bus

Managing multiple independent Wavesurfer.js instances on a single webpage frequently leads to overlapping audio unless a centralized coordination layer is introduced. This article examines global event bus architectures—including the native EventTarget interface, lightweight publish/subscribe (pub/sub) libraries, and framework-level reactive stores—designed to broadcast play/pause toggles across isolated Wavesurfer components, ensuring only one audio track plays at any given time.

The Multi-Instance Synchronization Challenge

When multiple Wavesurfer.js instances exist simultaneously—such as in an audio catalog, playlist, or soundboard—each instance operates within its own encapsulated lifecycle. Without an external messaging layer, starting playback on one waveform does not automatically pause the others. Solving this requires an architectural pattern where an active instance can signal its state change globally, allowing sibling components to respond by pausing their respective audio graphs.

Native DOM and EventTarget Bus

The simplest zero-dependency pattern utilizes the browser's built-in event system. By relying on window or a dedicated native EventTarget instance, you can dispatch and listen for custom events.

// bus.js - Dedicated event target
export const audioBus = new EventTarget();

// Component integration
export function setupWavesurfer(container, url, id) {
  const ws = WaveSurfer.create({ container, url });

  // Pause when another instance claims the bus
  const handleGlobalPlay = (e) => {
    if (e.detail.activeId !== id && ws.isPlaying()) {
      ws.pause();
    }
  };

  audioBus.addEventListener('audio:play', handleGlobalPlay);

  // Broadcast when this instance plays
  ws.on('play', () => {
    audioBus.dispatchEvent(
      new CustomEvent('audio:play', { detail: { activeId: id } })
    );
  });

  // Cleanup to prevent memory leaks
  ws.on('destroy', () => {
    audioBus.removeEventListener('audio:play', handleGlobalPlay);
  });

  return ws;
}

This pattern keeps bundle sizes minimal, prevents direct component-to-component coupling, and works universally across modern browsers.

Pub/Sub Pattern via Micro-Libraries

For modular applications that run outside standard DOM constraints or require strictly typed event payloads, micro pub/sub libraries like mitt or nanoevents offer a decoupled alternative.

  1. Centralized Topics: A shared emitter defines an event such as track:activated carrying the unique identifier of the currently playing track.
  2. Subscriber Reaction: Each component subscribes on mount. When the event fires, the subscriber checks whether the broadcasted identifier matches its own. If it does not, it triggers .pause().
  3. Loop Prevention: Because Wavesurfer's .pause() method emits a pause event, your bus should avoid rebroadcasting pause states globally to eliminate recursive broadcast loops. Only play events should trigger cross-component muting.

Reactive State Bus in Modern Frameworks

In frameworks like React, Vue, or Svelte, an event bus can be replaced or augmented with a centralized reactive state store (such as Zustand, Pinia, or Svelte stores).

Instead of broadcasting commands, the architecture manages a single source of truth: activeAudioId.

  • When a Wavesurfer component begins playback, it sets activeAudioId to its own ID.
  • Sibling components observe changes to activeAudioId. If the observed ID does not match their local ID, an effect hook invokes .pause() on their local Wavesurfer instance.
  • This paradigm provides greater predictability in complex user interfaces, supports UI synchronization (such as displaying global playback status bars), and natively integrates with component lifecycle mounts and unmounts.

Lifecycle and Cleanup Considerations

Regardless of the messaging architecture chosen, every Wavesurfer component must unregister its event listeners when destroyed or unmounted. Failing to remove listeners causes orphaned references to discarded audio nodes, producing memory leaks and errors when non-existent components attempt to execute playback methods. Additionally, event payloads must uniquely identify the triggering instance using a UUID or index to ensure components do not inadvertently pause themselves upon emitting a play signal.
