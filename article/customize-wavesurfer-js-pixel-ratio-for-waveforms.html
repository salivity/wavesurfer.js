Customize Wavesurfer.js pixelRatio for Waveforms

This guide explains how to use the pixelRatio parameter in Wavesurfer.js to control waveform rendering density and canvas resolution. By adjusting this setting, you can optimize visual clarity on high-resolution displays or reduce rendering overhead to improve playback and drawing performance on lower-end hardware.

Understanding pixelRatio in Wavesurfer.js

Wavesurfer.js renders audio waveforms onto an HTML5 <canvas> element. By default, Wavesurfer.js sets its rendering density using the browser's native window.devicePixelRatio.

On modern high-DPI (Retina) screens, window.devicePixelRatio is typically 2 or higher. While this produces crisp lines, it forces the browser to render twice or three times as many pixels horizontally and vertically, multiplying memory consumption and rendering time. Customizing pixelRatio allows you to override this behavior explicitly.

Basic Configuration

You can define pixelRatio directly inside the WaveSurfer.create() configuration object during initialization:

import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F46E5',
  progressColor: '#818CF8',
  url: '/path/to/audio.mp3',
  pixelRatio: 1 // Explicitly set rendering density
});

When to Adjust pixelRatio

1. Boosting Performance (pixelRatio: 1)

Rendering long audio tracks (e.g., full podcasts or hour-long mixes) on high-DPI screens can cause frame drops, stuttering during scrolling, and high CPU/GPU usage. Setting pixelRatio: 1 disables Retina scaling:

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  pixelRatio: 1, // Prioritize speed and lower memory usage
});

This reduces canvas memory usage by up to 75% compared to a standard 2x Retina canvas, making zooming and panning significantly smoother.

2. Enhancing Visual Quality

If you want to ensure the sharpest possible waveform on high-resolution displays regardless of the device's native setting, you can set a higher value:

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  pixelRatio: 2, // Force high-resolution rendering
});

3. Capping Maximum Density Dynamically

A common best practice is clamping the pixel ratio. Some mobile devices have a devicePixelRatio of 3 or 4, which provides negligible visual improvement while heavily taxing mobile processors. You can limit the density using Math.min():

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  // Cap the ratio at 2 to balance quality and performance
  pixelRatio: Math.min(window.devicePixelRatio || 1, 2),
});

Runtime Updates

If your application dynamically detects performance constraints or window resizes across different monitors, you can update the option dynamically using the setOptions method:

// Switch to low-density rendering on the fly
wavesurfer.setOptions({
  pixelRatio: 1
});

Changing this setting triggers Wavesurfer.js to resize the underlying canvas and redraw the waveform data using the newly assigned pixel density.
