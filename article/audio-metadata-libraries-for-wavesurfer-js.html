Audio Metadata Libraries for Wavesurfer.js

While Wavesurfer.js is the standard tool for rendering interactive waveforms in web applications, it does not extract embedded audio metadata like ID3 tags, cover art, or track titles on its own. To display track information and album artwork alongside a waveform, developers must pair Wavesurfer.js with client-side or server-side metadata parsing libraries. This guide outlines the best JavaScript libraries for extracting cover art and track details, along with how to integrate them into a Wavesurfer.js player interface.

Top Libraries for Audio Metadata Extraction

1. music-metadata-browser

music-metadata-browser is the browser-compatible build of the comprehensive music-metadata package. It is widely considered the most robust option for modern web applications.

  • Supported Formats: MP3 (ID3v1, ID3v2.2, ID3v2.3, ID3v2.4), M4A/AAC, FLAC, OGG, WAV, WebM, and more.
  • Cover Art Handling: Automatically extracts image format (e.g., image/jpeg, image/png) and binary buffer data, which can easily be converted into a Blob URL for display.
  • Why Use It: It offers first-class TypeScript support, is actively maintained, and handles modern audio containers better than older alternatives.
import * as mm from 'music-metadata-browser';

async function parseAudio(file) {
  const metadata = await mm.parseBlob(file);
  const { title, artist } = metadata.common;
  
  let coverUrl = '';
  if (metadata.common.picture && metadata.common.picture.length > 0) {
    const picture = metadata.common.picture[0];
    const blob = new Blob([picture.data], { type: picture.format });
    coverUrl = URL.createObjectURL(blob);
  }

  return { title, artist, coverUrl };
}

2. jsmediatags

jsmediatags is a lightweight, widely-used library that supports reading tags from local File objects, Blobs, and remote URLs via HTTP range requests.

  • Supported Formats: MP3 (ID3v1, ID3v2), MP4, and FLAC.
  • Cover Art Handling: Returns the raw byte array of the picture tag, which must be converted to base64 or a Blob before setting it as the src of an HTML <img> element.
  • Why Use It: It supports reading metadata over HTTP without downloading the entire audio file first, making it efficient for remote streams.
import jsmediatags from 'jsmediatags';

function getTags(file) {
  jsmediatags.read(file, {
    onSuccess: (tag) => {
      const { title, artist } = tag.tags;
      const picture = tag.tags.picture;
      let coverUrl = '';

      if (picture) {
        const base64String = picture.data.reduce(
          (acc, byte) => acc + String.fromCharCode(byte),
          ''
        );
        coverUrl = `data:${picture.format};base64,${btoa(base64String)}`;
      }

      updateUI({ title, artist, coverUrl });
    },
    onError: (error) => {
      console.error(error);
    }
  });
}

3. id3js

id3js is a focused, Promise-based ID3 tag parser designed specifically for MP3 files.

  • Supported Formats: Exclusively MP3 (ID3v1.x and ID3v2.x).
  • Cover Art Handling: Extracts image types, descriptions, and array buffers directly into an image object.
  • Why Use It: It has a very small footprint and a modern Promise-based API if your application only serves MP3 files.

Implementation Workflow with Wavesurfer.js

To build a cohesive UI containing album art, track details, and the waveform:

  1. Capture the File: Receive the audio input via an <input type="file"> element, drag-and-drop listener, or network URL.
  2. Extract Metadata: Pass the file or Blob to your chosen parser (music-metadata-browser or jsmediatags) to resolve the title, artist, and picture data.
  3. Render Track Details: Insert the track title and artist into your UI's text elements. Convert the parsed image binary into an Object URL (URL.createObjectURL(blob)) and apply it to an <img> tag next to the waveform.
  4. Initialize Wavesurfer: Concurrently pass the file Blob or URL to Wavesurfer's loadBlob() or load() method to render the waveform.
  5. Clean Up: Call URL.revokeObjectURL() on any created cover art URLs when a track is replaced or destroyed to prevent browser memory leaks.
