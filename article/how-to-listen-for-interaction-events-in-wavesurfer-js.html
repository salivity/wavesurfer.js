How to Listen for Interaction Events in Wavesurfer.js

This guide explains how to detect and handle user interactions on an audio waveform using the Wavesurfer.js library. You will learn how to attach an event listener to the interaction event, access relevant callback parameters such as the new playback position, and apply this listener to trigger custom application logic whenever a user manually seeks or clicks the waveform.

Using the interaction Event

In Wavesurfer.js (version 7 and newer), the interaction event fires whenever a user manually interacts with the waveform to navigate the audio. This encompasses actions such as clicking on a specific point in the track or dragging across the timeline to seek.

To listen for this event, use the standard .on() method on your initialized Wavesurfer instance:

import WaveSurfer from 'wavesurfer.js';

// Initialize Wavesurfer
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: '/path/to/audio.mp3',
});

// Listen for the interaction event
wavesurfer.on('interaction', (newTime) => {
  console.log(`User interacted with the waveform. New time: ${newTime}s`);
});

Understanding the Event Callback

When the interaction event triggers, Wavesurfer.js passes a single argument to your callback function:

  • newTime (number): The calculated audio position in seconds corresponding to where the user clicked or released their drag on the waveform.

This allows you to execute immediate state updates, such as updating an external progress slider, syncing UI elements, or sending telemetry events to your analytics service without relying on standard playback progression events.

Differences from Other Events

It is important to distinguish the interaction event from other common Wavesurfer.js events:

  • timeupdate / audioprocess: These events trigger continuously while the audio plays normally. In contrast, interaction only fires when a human explicitly changes the track position via input devices.
  • seeking: The seeking event fires whenever the playback head moves to a new position, regardless of whether it was triggered by user input or programmatically via methods like wavesurfer.setTime(). The interaction event is restricted purely to direct user manipulation of the waveform canvas.

Removing the Listener

If you dynamically create or destroy instances of Wavesurfer, remove the event listener using the .un() method or by calling the unsubscribe function returned by .on() in modern versions:

// Unsubscribe pattern
const unsubscribe = wavesurfer.on('interaction', (newTime) => {
  // Handle interaction
});

// Later, when cleaning up:
unsubscribe();
