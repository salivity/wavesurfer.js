Wavesurfer.js Event That Fires Continuously

This article explains the specific events in Wavesurfer.js that trigger continuously during audio playback. It covers the primary event used in the modern version of the library (v7+), the legacy equivalent used in older releases (v6 and earlier), and how to implement these listeners to track playback time in real time.

The Continuous Event in Modern Wavesurfer.js (v7+)

In modern versions of Wavesurfer.js (version 7 and later), the event that fires continuously as audio plays is timeupdate.

Wavesurfer.js v7 restructured its event system to closely align with the native HTML5 <audio> element API. As audio plays, the timeupdate event emits continuously, passing the current playback time (in seconds) directly to the callback function.

import WaveSurfer from 'wavesurfer.js'

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#violet',
  progressColor: '#purple',
  url: '/audio.mp3',
})

// Fires continuously as the audio plays
wavesurfer.on('timeupdate', (currentTime) => {
  console.log('Current time:', currentTime)
})

The Continuous Event in Legacy Wavesurfer.js (v6 and Earlier)

In Wavesurfer.js version 6 and older, the event that fires continuously during playback is audioprocess.

Like timeupdate, the audioprocess event fires repeatedly while the audio is actively playing and provides the current timestamp in seconds.

// Wavesurfer.js v6 syntax
wavesurfer.on('audioprocess', (currentTime) => {
  console.log('Playback position:', currentTime)
})

Common Use Cases

Listening to continuous playback events is essential for tasks such as:

  • Updating Time Displays: Updating real-time playback counters, showing current time alongside the total duration.
  • Synchronizing Transcripts: Highlighting lyrics, subtitles, or text transcripts corresponding to the current audio timestamp.
  • Custom UI Updates: Driving custom playheads, animations, or external progress bars that run parallel to the waveform.
