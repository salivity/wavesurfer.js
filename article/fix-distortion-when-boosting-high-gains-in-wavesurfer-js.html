Fix Distortion When Boosting High Gains in Wavesurfer.js

Boosting high-gain frequencies using Web Audio API nodes in Wavesurfer.js frequently causes harsh digital clipping and distortion. When an equalizer node pushes audio amplitudes beyond the standard 0 dBFS (decibels relative to full scale) threshold, the browser clips the output waveform. To prevent this, developers must implement proper gain staging, employ dynamic range compression, and practice subtractive equalization within the Web Audio processing chain.

Understand the Cause: Web Audio Headroom and Clipping

The Web Audio API processes internal audio buffers using 32-bit floating-point numbers, allowing virtually unlimited headroom between nodes. However, when the signal reaches the final output (AudioDestinationNode), the browser hardware converts the signal back to fixed-point audio, hard-clamping any sample values exceeding the range of -1.0 to +1.0. Applying significant positive gain via a BiquadFilterNode pushes peaks past this boundary, resulting in digital distortion.

Implement Negative Pre-Gain

The most effective way to prevent clipping when boosting frequencies is negative pre-gain attenuation. If you need to boost a high-shelf or peaking filter by +6 dB, you should attenuate the overall signal before or after the filter chain by a corresponding margin.

Create a GainNode and place it immediately prior to your filter bank:

const audioContext = wavesurfer.backend.getAudioContext();
const preGainNode = audioContext.createGain();

// Reduce gain by 6 dB to accommodate the upcoming high-frequency boost
preGainNode.gain.value = Math.pow(10, -6 / 20); // approximately 0.501

By reducing the overall input level, the filter's high-gain peak has the required headroom to expand without crossing the 1.0 threshold at the destination.

Insert a DynamicsCompressorNode as a Limiter

To catch unpredictable transient spikes caused by high-gain resonance, insert a DynamicsCompressorNode at the end of the custom node graph, right before audioContext.destination. Configuring this node with a high ratio and fast attack turns it into a transparent brickwall limiter.

const limiter = audioContext.createDynamicsCompressor();
limiter.threshold.setValueAtTime(-0.5, audioContext.currentTime); // Engage just below 0 dBFS
limiter.knee.setValueAtTime(0, audioContext.currentTime);          // Hard knee
limiter.ratio.setValueAtTime(20, audioContext.currentTime);        // High compression ratio
limiter.attack.setValueAtTime(0.001, audioContext.currentTime);    // 1ms fast attack
limiter.release.setValueAtTime(0.1, audioContext.currentTime);     // 100ms release

Establish the Correct Node Pipeline in Wavesurfer.js

To ensure audio flows correctly through the safety stages, chain your nodes sequentially. Instead of relying solely on default routing, connect Wavesurfer’s media source through your pre-gain, your equalization filters, your limiter, and finally to the destination:

// Disconnect default routing
wavesurfer.backend.disconnectFilters();

// Create nodes
const filter = audioContext.createBiquadFilter();
filter.type = 'peaking';
filter.frequency.value = 8000;
filter.gain.value = 8; // High gain boost
filter.Q.value = 1.0;

// Chain: Source -> PreGain -> Filter -> Limiter -> Destination
const mediaElementSource = wavesurfer.backend.media;
mediaElementSource.disconnect();

mediaElementSource.connect(preGainNode);
preGainNode.connect(filter);
filter.connect(limiter);
limiter.connect(audioContext.destination);

Use Subtractive Equalization

Instead of applying large positive gain to high frequencies, achieve the desired tonal balance through subtractive equalization. Lowering the bass and midrange frequencies using negative gain creates the same relative acoustic presence for the high frequencies without consuming dynamic headroom or risking distortion.
