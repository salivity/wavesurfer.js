Wavesurfer.js: Web Audio API vs MediaElement Backend

Choosing between the Web Audio API and the HTML5 MediaElement in Wavesurfer.js determines how your audio is decoded, rendered, and played back in the browser. This article explains the specific configuration option used to switch between these rendering engines, how the behavior differs across Wavesurfer.js versions, and how to select the right approach for your project's performance and streaming requirements.

The Backend Option

In Wavesurfer.js (specifically v6 and earlier), the option that controls this behavior is backend.

When initializing a Wavesurfer instance, you pass the backend property inside the configuration object. The two primary choices are:

  • backend: 'WebAudio' (Default in v6 and earlier)
  • backend: 'MediaElement'

There is also a hybrid option, backend: 'MediaElementWebAudio', which plays media using the HTML5 audio element while routing the output through the Web Audio API graph to allow real-time audio manipulation and visualization.

// Example using the Web Audio API
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: 'violet',
  progressColor: 'purple',
  backend: 'WebAudio'
});

// Example using HTML5 MediaElement
const wavesurferMedia = WaveSurfer.create({
  container: '#waveform',
  waveColor: 'violet',
  progressColor: 'purple',
  backend: 'MediaElement'
});

Differences Between WebAudio and MediaElement

1. WebAudio Backend

  • Full File Loading: Downloads the entire audio file into memory as an ArrayBuffer before decoding it via AudioContext.decodeAudioData().
  • Precision: Offers sample-accurate playback, visual sync, and the ability to apply real-time DSP effects, filters, and audio manipulation.
  • Limitations: Memory-intensive. Large files (e.g., long podcasts or high-resolution tracks) can crash the browser tab on mobile devices.

2. MediaElement Backend

  • Progressive Streaming: Utilizes a native HTML5 <audio> element. Audio starts playing as soon as the first chunks are buffered without loading the whole file into RAM.
  • CORS Friendly: Simpler handling of Cross-Origin Resource Sharing (CORS) when loading tracks from external CDNs.
  • Limitations: Requires pre-computed peaks or separate audio analysis to render the waveform without downloading the whole file first.

Changes in Wavesurfer.js v7

In Wavesurfer.js version 7, the architecture was rewritten to be more lightweight and modular:

  • Default HTML5 Audio: Version 7 uses an HTML5 MediaElement by default for playback. You pass an existing audio element via the media parameter, or Wavesurfer creates one internally.
  • Rendering Without Web Audio: Waveforms are drawn using pre-computed peaks or by fetching audio data via fetch independent of the audio playback engine.
  • Web Audio Nodes: If you need Web Audio API functionality in v7, you connect the internal media element to an external AudioContext using createMediaElementSource() rather than setting a single backend string option.
