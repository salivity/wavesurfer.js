Integrating WebVTT and SRT with Wavesurfer.js

Integrating timed cues into Wavesurfer.js allows developers to display synchronized text, markers, and audio segments directly on top of an interactive waveform. This guide outlines how standard subtitle formats like WebVTT and SRT integrate with the Wavesurfer.js Regions plugin, highlighting their parsing mechanics, standard timecode conversions, and practical steps to map cue data directly into interactive regions.

WebVTT (.vtt)

WebVTT (Web Video Text Tracks) is the most natural fit for browser-based audio applications. Because it is the HTML5 standard for timed text tracks, it integrates seamlessly into web environments.

  • Timecode Syntax: Hours, minutes, seconds, and milliseconds separated by periods (e.g., 00:01:23.456).
  • Ease of Integration: High. Modern browsers can parse WebVTT natively using the native VTTCue and TextTrack interfaces, or you can use lightweight utility parsers without loading heavy third-party dependencies.
  • Region Mapping: The startTime and endTime values from a parsed WebVTT cue are already represented as floating-point numbers in seconds, which is the exact format required by the Wavesurfer.js Regions plugin.

SubRip (.srt)

SRT is one of the most widely available subtitle formats in media production. While it does not have native browser parsing support, it is simple to load into Wavesurfer.js using small parsing libraries.

  • Timecode Syntax: Hours, minutes, seconds, and milliseconds separated by a comma (e.g., 00:01:23,456).
  • Ease of Integration: Moderate. SRT files require converting the millisecond separator from a comma to a period, or running the text through an external parser such as srt-parser-2 or subtitles-parser.
  • Region Mapping: Once parsed, timecodes must be converted into total seconds (e.g., (hours * 3600) + (minutes * 60) + seconds + (milliseconds / 1000)) before passing them to the region configuration.

Direct JSON Timestamps

If you have control over the data pipeline, JSON is the most efficient data format for Wavesurfer.js. It avoids the need to parse raw string-based timing files entirely.

  • Structure: An array of objects specifying start, end, and optional metadata such as content, id, or color.
  • Ease of Integration: Highest. Requires zero text parsing or timecode conversion because the values are already native numbers.

How to Convert Timing Cues to Wavesurfer Regions

Wavesurfer.js handles visual cues via its Regions plugin (wavesurfer.js/dist/plugins/regions.esm.js). The plugin exposes an addRegion method that accepts start and end points in seconds.

Implementation Workflow

  1. Initialize Wavesurfer and the Regions Plugin: Create the Wavesurfer instance and register the Regions plugin to manage cue overlays.

  2. Fetch and Parse the File: Load the .vtt or .srt file using standard asynchronous fetch requests. Pass the resulting text into your parser of choice.

  3. Loop Over Parsed Cues: Extract the cue start time, end time, and cue text.

  4. Instantiate Regions: Call wsRegions.addRegion() for every cue in the file:

// Example: Mapping parsed cue objects to Wavesurfer regions
parsedCues.forEach(cue => {
  wsRegions.addRegion({
    start: cue.startTime, // in seconds
    end: cue.endTime,     // in seconds
    content: cue.text,    // cue caption or label
    color: 'rgba(0, 123, 255, 0.2)',
    drag: false,
    resize: false
  });
});

Summary Recommendation

  • Choose WebVTT if you are delivering text over standard web protocols and want compatibility with native HTML5 media elements.
  • Choose SRT if you are working with legacy video workflows or desktop tools, paired with a small client-side parser.
  • Choose JSON if you generate cue points from an API or database, as it eliminates parsing overhead completely.
