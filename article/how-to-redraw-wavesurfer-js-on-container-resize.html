How to Redraw Wavesurfer.js on Container Resize

This guide explains how to properly handle redrawing a Wavesurfer.js waveform when its container changes dimensions. It details the dedicated methods available across different library versions—specifically the modern redraw() method and the legacy drawBuffer() method—while providing practical examples using the ResizeObserver API for responsive, high-performance layouts.

The Modern Solution: wavesurfer.redraw()

In Wavesurfer.js version 7 and later, the primary method used to update the waveform after a container resize is wavesurfer.redraw().

Calling redraw() forces the instance to recalculate the canvas width and height based on the current dimensions of its parent container. It repaints the existing waveform peaks immediately without fetching, reloading, or re-decoding the audio data.

// Trigger a redraw manually
wavesurfer.redraw();

Automatic Handling vs. Manual Observation

Wavesurfer.js v7 includes built-in container tracking, meaning the waveform automatically adjusts to standard browser resizing events in most setups. However, automatic detection may fail if:

  • The container resizes due to CSS animations or flexbox/grid adjustments without a window resize event.
  • The container transitions from display: none to visible (e.g., inside tabs or modals).
  • Dynamic split-panes or sidebars alter container dimensions.

In these situations, use a ResizeObserver to detect size changes on the wrapper element and invoke redraw() directly:

const container = document.querySelector('#waveform-container');

const resizeObserver = new ResizeObserver(() => {
  wavesurfer.redraw();
});

resizeObserver.observe(container);

To prevent excessive repainting during continuous user interaction (such as dragging a layout divider), wrap the call in a debounce function or use requestAnimationFrame:

let resizeTimeout;

const resizeObserver = new ResizeObserver(() => {
  clearTimeout(resizeTimeout);
  resizeTimeout = setTimeout(() => {
    wavesurfer.redraw();
  }, 100);
});

resizeObserver.observe(container);

The Legacy Solution: wavesurfer.drawBuffer() (v6 and Older)

For projects using Wavesurfer.js v6 or older, the method to redraw the waveform without re-decoding the audio is wavesurfer.drawBuffer().

In these older versions, responsiveness had to be manually declared via the responsive: true configuration flag upon initialization. If manual re-rendering was needed, developers invoked drawBuffer() alongside a window resize event listener:

// Legacy (v6 and below)
window.addEventListener('resize', () => {
  wavesurfer.drawBuffer();
});

Using wavesurfer.redraw() in current implementations ensures waveforms remain crisp, accurately proportioned, and responsive across all layout changes.
