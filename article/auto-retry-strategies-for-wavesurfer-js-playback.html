Auto-Retry Strategies for Wavesurfer.js Playback

Network interruptions during mid-track streaming can abruptly halt audio playback in Wavesurfer.js, frustrating end users and breaking UI state. When network connectivity drops, standard HTML5 audio elements and Web Audio buffers typically fail to resume on their own. This article explores effective auto-retry strategies—including connection monitoring, exponential backoff algorithms, and playback position persistence—to seamlessly recover audio streams in Wavesurfer.js without forcing users to manually restart their track.

1. Configure the MediaElement Backend

By default, Wavesurfer.js can decode full audio files into Web Audio memory buffers, which fails entirely if a download breaks mid-stream. To handle network recovery efficiently, configure Wavesurfer.js to use the HTML5 MediaElement backend. This allows progressive streaming via native audio tags and enables byte-range recovery.

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#violet',
  progressColor: '#purple',
  backend: 'MediaElement'
});

Using the MediaElement backend ensures that the underlying browser media engine manages buffering and fires standard media events.

2. Detect Network Drops with Event Listeners

To implement auto-retry logic, you must detect precisely when a drop occurs. Wavesurfer.js provides lifecycle hooks, while its underlying media element exposes low-level network states:

  • error: Triggered when the media fails to load due to network disconnection or decoding issues.
  • stalled: Fired when the browser attempts to fetch media data, but the data is unexpectedly unavailable.
  • waiting: Triggered when playback halts due to a temporary lack of data.
const media = wavesurfer.getMediaElement();

media.addEventListener('stalled', () => handleNetworkDrop());
media.addEventListener('error', () => handleNetworkDrop());
window.addEventListener('offline', () => handleNetworkDrop());

3. Implement Exponential Backoff with Position Preservation

Immediate and continuous retry attempts can overwhelm mobile clients and servers. A robust recovery pattern saves the user's current playback position, tracks retry counts, and schedules retries with an exponential delay.

let retryCount = 0;
const MAX_RETRIES = 5;
const BASE_DELAY = 1000; // 1 second

function handleNetworkDrop() {
  const currentTime = wavesurfer.getCurrentTime();
  const wasPlaying = wavesurfer.isPlaying();

  if (retryCount >= MAX_RETRIES) {
    console.error("Playback recovery failed: Max retries exceeded.");
    return;
  }

  const delay = BASE_DELAY * Math.pow(2, retryCount);
  retryCount++;

  setTimeout(() => {
    attemptReconnection(currentTime, wasPlaying);
  }, delay);
}

4. Reconnect and Restore Playback State

Recovering the session involves reloading the media URL and seeking back to the timestamp where the stream stopped. Appending a cache-busting parameter or relying on HTTP Range headers allows the browser to re-request the audio stream from the server.

function attemptReconnection(resumeTime, shouldPlay) {
  const currentSrc = wavesurfer.getMediaElement().src;
  
  // Re-load the current track
  wavesurfer.load(currentSrc);

  wavesurfer.once('ready', () => {
    wavesurfer.setTime(resumeTime);
    retryCount = 0; // Reset counter on successful load

    if (shouldPlay) {
      wavesurfer.play().catch(err => {
        console.warn("Autoplay blocked or playback interrupted:", err);
      });
    }
  });
}

5. Listen for Online Recovery Events

In mobile environments where devices frequently switch between Wi-Fi and cellular networks, the browser may report an offline state. Instead of relying purely on timers, tie the retry mechanism to the browser's online event.

window.addEventListener('online', () => {
  if (wavesurfer.getMediaElement().networkState === HTMLMediaElement.NETWORK_NO_SOURCE ||
      wavesurfer.getMediaElement().error) {
    retryCount = 0; // Reset counter to prioritize immediate recovery
    attemptReconnection(wavesurfer.getCurrentTime(), true);
  }
});

Combining automated backoff logic with network state listeners ensures that transient drops, interface switches, and extended disconnects are handled smoothly, maintaining uninterrupted playback for the user.
