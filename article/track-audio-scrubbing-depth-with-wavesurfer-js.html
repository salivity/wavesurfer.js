Track Audio Scrubbing Depth with Wavesurfer.js

This article explains how to measure audio scrubbing engagement depth using Wavesurfer.js event listeners and analytics tracking parameters. Monitoring how users seek through audio reveals which segments capture interest, which are skipped, and how thoroughly content is consumed. Below is a breakdown of the critical Wavesurfer.js events and the precise parameters required to record accurate scrubbing engagement metrics.

Key Wavesurfer.js Events for Scrubbing

To capture scrubbing actions accurately, monitor these native Wavesurfer.js events:

  • interaction: Fires whenever a user interacts with the waveform (clicking or dragging).
  • seeking: Emits the relative target position (a float between 0 and 1) while or immediately after the user seeks.
  • timeupdate: Continuously fires during regular playback. Tracking the last known timestamp before a seek event allows you to determine where the scrub originated.

Essential Tracking Parameters

When a scrub interaction occurs, collect the following parameters in your event payload:

  1. seek_origin_time (seconds): The timestamp where the user was listening before initiating the scrub. Recorded from the most recent timeupdate timestamp.
  2. seek_destination_time (seconds): The timestamp where the scrub landed. Calculated by multiplying the seek relative value (0 to 1) by wavesurfer.getDuration().
  3. scrub_direction (string): The direction of the jump (forward or backward). Determined by comparing seek_destination_time to seek_origin_time.
  4. scrub_distance (seconds): The absolute magnitude of the jump (Math.abs(seek_destination_time - seek_origin_time)).
  5. engagement_depth_percentage (percentage): The destination position normalized against total length ((seek_destination_time / total_duration) * 100). This indicates how deep into the file the user navigated.
  6. scrub_type (string): Categorization of the interaction, differentiating between a single click jump (click) or an active waveform drag (drag).
  7. total_duration (seconds): The complete length of the audio track (wavesurfer.getDuration()), used as a baseline to normalize engagement depth across tracks of varying lengths.
  8. interaction_count (integer): A session-based counter tracking how many seek operations have occurred during the playback session to measure user restlessness or search behavior.

Implementation Logic

To record these parameters effectively, store the current playback position in a local variable via the timeupdate event. When the seeking or seek event triggers, compare the new position against the stored position.

Once the destination timestamp is resolved, calculate the delta, direction, and depth percentage, then dispatch the combined payload to your analytics platform before updating the stored position with the new destination timestamp.
