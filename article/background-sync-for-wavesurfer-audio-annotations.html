Background Sync for Wavesurfer Audio Annotations

This article explores how web applications can reliably sync audio annotations created with Wavesurfer.js to a server when recovering from an offline state. By combining the Service Worker Background Sync API, local client-side storage via IndexedDB, and fallback network status listeners, developers can create a resilient system that captures user markers, regions, and comments offline and automatically pushes them the moment network connectivity is re-established.

Local Persistence with IndexedDB

Wavesurfer.js handles audio visualization and annotation on the client side using plugins like the Regions Plugin. When a user creates or modifies an annotation while offline, the data cannot reach the server immediately.

To prevent data loss, the application must intercept the annotation events (such as region-created, region-updated, or region-removed) and store the serialized annotation payload—including start and end timestamps, labels, IDs, and metadata—directly into IndexedDB. Storing these objects locally guarantees that the data persists across page refreshes and browser restarts until an active network connection is confirmed.

The Service Worker Background Sync API

The primary feature used to push data automatically when returning online is the Background Sync API (SyncManager), integrated via a Service Worker.

When an annotation is saved to IndexedDB, the application registers a synchronization event with the Service Worker using:

navigator.serviceWorker.ready.then((registration) => {
  return registration.sync.register('sync-audio-annotations');
});

The Service Worker listens for the sync event:

self.addEventListener('sync', (event) => {
  if (event.tag === 'sync-audio-annotations') {
    event.waitUntil(pushPendingAnnotations());
  }
});

The key benefits of this background sync feature include:

  • Deferred Execution: If the user is currently offline, the browser delays firing the event until the connection is restored.
  • Resilience: The sync operation can run even if the user has navigated away from the page or closed the browser tab.
  • Automatic Retries: If the server returns an error or the network drops during transmission, the browser will automatically reschedule the sync attempt.

Periodic Background Sync

For non-critical annotations or batch operations, the Periodic Background Sync API allows web applications to register tasks to sync data periodically in the background. While standard Background Sync triggers immediately upon network reconnection, Periodic Background Sync is ideal for synchronizing large datasets, aggregated annotation analytics, or fetching updated remote annotations at set intervals when the user has a stable connection.

Fallbacks: Online Event Listeners

Because the Background Sync API is not supported in all browsers (such as Apple Safari), a complete implementation requires a client-side fallback using standard DOM events:

  • window.addEventListener('online', callback): Fired immediately when the browser gains network access while the page is still open.
  • navigator.onLine: A boolean property checked during user interaction to determine whether to attempt a direct HTTP request or immediately divert the payload to IndexedDB.

When the online event fires in browsers lacking SyncManager, a client script reads pending annotations from IndexedDB, dispatches the HTTP POST or PUT requests to the server, and purges the synced entries from the local database upon a successful 200 OK response.
