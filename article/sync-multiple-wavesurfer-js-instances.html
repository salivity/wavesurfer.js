Sync Multiple Wavesurfer.js Instances

Synchronizing multiple Wavesurfer.js instances is essential for building web-based digital audio workstations, multi-track audio players, and comparative listening tools. This guide explains how to initialize multiple waveform instances, link playback controls, synchronize user-driven seeking without triggering recursive event loops, and maintain timing alignment across all audio tracks.

1. Set Up the HTML Containers

Create distinct DOM elements for each track you intend to render.

<div id="controls">
  <button id="playBtn">Play / Pause</button>
</div>

<div id="track-1"></div>
<div id="track-2"></div>
<div id="track-3"></div>

2. Initialize the Wavesurfer Instances

Initialize each track using WaveSurfer.create() and store them in an array to manage them programmatically.

const tracks = [
  { container: '#track-1', url: 'audio/vocals.mp3' },
  { container: '#track-2', url: 'audio/bass.mp3' },
  { container: '#track-3', url: 'audio/drums.mp3' }
];

const instances = tracks.map(track => {
  return WaveSurfer.create({
    container: track.container,
    url: track.url,
    waveColor: '#4F4A85',
    progressColor: '#383351',
    height: 80
  });
});

3. Implement Unified Playback Controls

Avoid using built-in track clicks to control playback directly. Instead, control play and pause states through a centralized master action that iterates over all instances simultaneously.

const playBtn = document.getElementById('playBtn');

playBtn.addEventListener('click', () => {
  const isPlaying = instances[0].isPlaying();
  
  instances.forEach(ws => {
    if (isPlaying) {
      ws.pause();
    } else {
      ws.play();
    }
  });
});

4. Synchronize Seeking Without Infinite Loops

When a user clicks on one waveform to seek, the other waveforms must seek to the exact same position. Listening to standard seek events on all tracks can trigger an infinite event loop where instance A updates instance B, which updates instance A again.

Prevent this by setting an update lock flag while dispatching seek events.

let isSeeking = false;

instances.forEach(sourceWs => {
  // Use the 'interaction' event triggered by user input
  sourceWs.on('interaction', (newProgress) => {
    if (isSeeking) return;
    isSeeking = true;

    // Get current time position relative to duration
    const currentTime = sourceWs.getCurrentTime();

    instances.forEach(targetWs => {
      if (targetWs !== sourceWs) {
        targetWs.setTime(currentTime);
      }
    });

    isSeeking = false;
  });
});

5. Prevent Playback Drift

Browser audio rendering and processing delays can cause individual tracks to drift slightly out of phase over extended playback periods. To resolve drift, designate the first instance as the master clock and periodically align the slave instances if they deviate beyond an acceptable threshold (e.g., 20 milliseconds).

const masterInstance = instances[0];
const SLAVE_DRIFT_THRESHOLD = 0.02; // 20 milliseconds

masterInstance.on('timeupdate', (masterTime) => {
  if (!masterInstance.isPlaying()) return;

  for (let i = 1; i < instances.length; i++) {
    const slaveWs = instances[i];
    const diff = Math.abs(slaveWs.getCurrentTime() - masterTime);

    // Realign slave if drift exceeds the threshold
    if (diff > SLAVE_DRIFT_THRESHOLD) {
      slaveWs.setTime(masterTime);
    }
  }
});

6. Synchronize Zoom and Scroll

If your implementation includes zoom functionality, keep the visual zoom level and horizontal scrolling aligned across all tracks.

function setZoom(pxPerSec) {
  instances.forEach(ws => {
    ws.zoom(pxPerSec);
  });
}

// Synchronize scroll containers
instances.forEach(sourceWs => {
  const wrapper = sourceWs.getWrapper();
  
  wrapper.addEventListener('scroll', () => {
    const scrollLeft = wrapper.scrollLeft;

    instances.forEach(targetWs => {
      const targetWrapper = targetWs.getWrapper();
      if (targetWrapper !== wrapper) {
        targetWrapper.scrollLeft = scrollLeft;
      }
    });
  });
});
