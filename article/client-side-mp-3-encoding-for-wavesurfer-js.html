Client-Side MP3 Encoding for Wavesurfer.js

Wavesurfer.js excels at client-side audio visualization and manipulation, but it natively outputs raw audio formats such as PCM or uncompressed WAV. To convert this exported audio to an MP3 format directly inside the user's browser without server-side processing, developers rely on WebAssembly (Wasm) ports of established audio encoding libraries. This guide outlines the best WebAssembly libraries for client-side MP3 encoding, how to extract audio from Wavesurfer.js for processing, and the primary technical considerations for implementation.

Extracting Audio from Wavesurfer.js

Before encoding to MP3, you must access the raw audio data stored within Wavesurfer.js. Wavesurfer processes audio through the Web Audio API using an AudioBuffer.

You can extract this data using the getDecodedData() method:

const audioBuffer = wavesurfer.getDecodedData();

An AudioBuffer provides:

  • Sample Rate: audioBuffer.sampleRate (typically 44100 or 48000 Hz)
  • Channel Count: audioBuffer.numberOfChannels (1 for mono, 2 for stereo)
  • PCM Data: audioBuffer.getChannelData(channelIndex) which returns a Float32Array of audio samples ranging between -1.0 and 1.0.

WebAssembly encoders typically require this PCM data to be passed as either Float32Array or interleaved Int16Array buffers.

Top WebAssembly Libraries for MP3 Encoding

1. vmsg

vmsg is a lightweight library built specifically for encoding MP3 audio in the browser using the LAME encoder compiled to WebAssembly. While originally designed for microphone recording, its underlying Wasm core can process raw PCM chunks directly.

  • Underlying Engine: LAME
  • Strengths: Extremely small binary size (~80KB Wasm file), fast execution, and zero native browser dependencies.
  • Usage Context: Ideal for voice recordings, podcasts, and simple audio exports where bundle size is a priority.

2. @ffmpeg/ffmpeg (FFmpeg.wasm)

@ffmpeg/ffmpeg is a complete port of FFmpeg to WebAssembly. It contains libmp3lame alongside extensive audio manipulation filters, format converters, and multiplexers.

  • Underlying Engine: FFmpeg with libmp3lame
  • Strengths: Maximum flexibility. In addition to MP3 encoding, it can resample audio, adjust bitrates, normalize loudness, and handle multi-track audio.
  • Trade-offs: Large bundle size (multi-megabyte download) and requires specific HTTP response headers (Cross-Origin-Opener-Policy: same-origin and Cross-Origin-Embedder-Policy: require-corp) to enable SharedArrayBuffer multithreading.
  • Usage Context: Best when you need full audio processing pipelines, sample rate conversion, and complex filtering alongside MP3 encoding.

3. wasm-lame / lame-wasm

Several standalone open-source ports compile the C implementation of LAME directly to WebAssembly using Emscripten. Packages such as @breezystack/lamejs offer pure JavaScript implementations, while packages like wasm-lame or customized Emscripten wrappers expose the raw lame_encode_buffer functions.

  • Underlying Engine: LAME C codebase compiled via Emscripten
  • Strengths: Much faster execution than pure JavaScript alternatives (such as legacy lamejs), lower memory consumption, and predictable CPU usage on long tracks.
  • Usage Context: Best for standard stereo or mono track exports when you do not need the full overhead of FFmpeg.

General Implementation Workflow

Regardless of the selected library, the client-side pipeline follows four consistent steps:

  1. Obtain the Buffer: Call wavesurfer.getDecodedData() to retrieve the AudioBuffer.

  2. Format Conversion: Most LAME-based Wasm ports expect 16-bit signed integers (Int16Array). Convert the Float32Array values:

    function floatToInt16(float32Array) {
  const int16Array = new Int16Array(float32Array.length);
  for (let i = 0; i < float32Array.length; i++) {
    const s = Math.max(-1, Math.min(1, float32Array[i]));
    int16Array[i] = s < 0 ? s * 0x8000 : s * 0x7FFF;
  }
  return int16Array;
}

  3. Encode via Web Worker: Push the PCM data to a Web Worker running your WebAssembly module to prevent the encoding process from freezing the browser UI and Wavesurfer waveform rendering.

  4. Generate File Blob: Collect the output bytes from the encoder, create an MP3 Blob, and trigger a download or upload:

    const mp3Blob = new Blob([encodedBuffer], { type: 'audio/mp3' });
const url = URL.createObjectURL(mp3Blob);

Technical Considerations

  • Thread Blocking: MP3 encoding is computationally intensive. Always run your WebAssembly module inside a dedicated Web Worker to maintain 60 FPS UI performance in Wavesurfer.js.
  • Interleaving Stereo Channels: If the AudioBuffer has two channels, most Wasm encoders require interleaved samples (Left, Right, Left, Right) rather than two separate arrays. Ensure your conversion step interleaves the channels if the library does not provide dedicated multi-channel parameters.
  • Sample Rate Matching: Ensure the target encoder configuration matches the audioBuffer.sampleRate of your Wavesurfer instance to prevent pitch and playback speed distortion.
