How to Send Custom Headers in Wavesurfer.js

Sending custom HTTP headers—such as authentication tokens or API keys—when loading audio files in Wavesurfer.js depends on the version you are using. This guide explains how to fetch protected audio files using the native Fetch API combined with loadBlob() in modern Wavesurfer.js (version 7+), as well as how to configure the built-in XHR options in legacy versions.

Modern Wavesurfer.js (v7+): Fetch API and loadBlob()

In Wavesurfer.js v7 and newer, audio playback relies on the HTML5 MediaElement by default, which does not allow custom request headers when setting a direct URL. To bypass this limitation, you must fetch the audio data manually using the native JavaScript fetch() API and pass the resulting file to Wavesurfer using loadBlob().

import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
});

async function loadProtectedAudio(url, token) {
  try {
    const response = await fetch(url, {
      method: 'GET',
      headers: {
        'Authorization': `Bearer ${token}`,
        'X-Custom-Header': 'CustomValue',
      },
    });

    if (!response.ok) {
      throw new Error(`HTTP error! Status: ${response.status}`);
    }

    const audioBlob = await response.blob();
    wavesurfer.loadBlob(audioBlob);
  } catch (error) {
    console.error('Failed to load audio file:', error);
  }
}

loadProtectedAudio('https://example.com/api/audio/sample.mp3', 'YOUR_AUTH_TOKEN');

Alternatively, you can convert the blob into an object URL and pass it directly to wavesurfer.load():

const audioBlob = await response.blob();
const objectUrl = URL.createObjectURL(audioBlob);
wavesurfer.load(objectUrl);

Legacy Wavesurfer.js (v6 and Earlier): Using XHR Options

In Wavesurfer.js version 6 and older, network requests were handled via XMLHttpRequest (xhr). You can supply custom request headers either during initialization or directly inside the load() method.

Option 1: During Initialization

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: 'violet',
  progressColor: 'purple',
  xhr: {
    requestHeaders: [
      {
        key: 'Authorization',
        value: 'Bearer YOUR_AUTH_TOKEN',
      },
      {
        key: 'X-Custom-Header',
        value: 'CustomValue',
      },
    ],
  },
});

wavesurfer.load('https://example.com/api/audio/sample.mp3');

Option 2: Inside the load() Method

You can also pass XHR configuration as the fourth argument of the load() function to specify headers on a per-request basis:

wavesurfer.load(
  'https://example.com/api/audio/sample.mp3', // Audio URL
  null,                                       // Peaks array (optional)
  null,                                       // Preload attribute (optional)
  {
    requestHeaders: [
      {
        key: 'Authorization',
        value: 'Bearer YOUR_AUTH_TOKEN',
      },
    ],
  }
);

Server-Side CORS Requirements

When sending custom headers from a browser, the server hosting the audio files must explicitly permit them through Cross-Origin Resource Sharing (CORS). Ensure your server includes the following headers in its response:

  • Access-Control-Allow-Origin: Must specify your domain or *.
  • Access-Control-Allow-Headers: Must list all custom headers sent in the request (e.g., Authorization, X-Custom-Header).
  • Access-Control-Allow-Methods: Must allow GET, OPTIONS.
