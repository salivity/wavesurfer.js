Wavesurfer.js Plugin Lifecycle Hooks Guide

Creating custom plugins for modern Wavesurfer.js (version 7 and above) requires extending the official base plugin class to interact smoothly with the audio engine and DOM. This article covers the essential lifecycle hooks that custom plugins must implement, specifically focusing on onInit() for initialization and destroy() for teardown, along with standard patterns for managing configuration and event subscriptions.

The BasePlugin Architecture

In modern Wavesurfer.js, all plugins inherit from the BasePlugin class. Unlike older versions that relied on loosely coupled helper methods, the modern architecture uses a defined class structure where the core instance is injected into the plugin upon registration.

A plugin must implement or override two primary lifecycle hooks:

  1. onInit()
  2. destroy()

Additionally, standard constructor handling and a static factory method are standard conventions for instantiating and configuring the plugin.

1. The constructor Hook

While technically a class constructor rather than a Wavesurfer-specific lifecycle hook, handling configuration options here is mandatory for proper initialization.

  • Purpose: Sets default options, merges user configuration, and defines any local state properties.
  • Usage: Pass the options object to super(options). At this stage, the this.wavesurfer reference is not yet available.
constructor(options) {
  super(options);
  this.options = { ...defaultOptions, ...options };
}

2. The onInit() Lifecycle Hook

The onInit() method is the most critical lifecycle hook in a custom plugin. It is triggered automatically by Wavesurfer.js when the plugin is registered via wavesurfer.registerPlugin(...) or passed directly to the WaveSurfer.create() configuration array.

  • Purpose: Initializing plugin logic, creating DOM wrappers, accessing the audio element, and attaching event listeners.
  • Instance Access: When onInit() executes, this.wavesurfer is fully initialized and accessible.
  • Subscription Management: Custom plugins should store all event listeners inside the inherited this.subscriptions array to enable automated cleanup, or manage them manually.

Common actions inside onInit() include:

  • Listening to Wavesurfer events like ready, audioprocess, seeking, and destroy.
  • Querying or mutating the container via this.wavesurfer.getWrapper().
  • Accessing media controls through this.wavesurfer.getMediaElement().

3. The destroy() Lifecycle Hook

The destroy() method is executed when the plugin is manually destroyed via plugin.destroy() or automatically when the parent Wavesurfer instance is terminated via wavesurfer.destroy().

  • Purpose: Preventing memory leaks by tearing down DOM elements, aborting network requests, clearing timers, and detaching event listeners.
  • Implementation Requirement: You must call super.destroy() inside your custom destroy() implementation to ensure internal listeners in this.subscriptions are completely flushed.

Common cleanup tasks inside destroy() include:

  • Removing custom DOM nodes from the container.
  • Unbinding native DOM event listeners (e.g., window.addEventListener('resize')).
  • Clearing active setInterval or requestAnimationFrame instances.

Practical Plugin Implementation Example

Below is a complete implementation of a custom modern Wavesurfer.js plugin showcasing the full lifecycle flow:

import { BasePlugin } from 'wavesurfer.js/dist/base-plugin.js';

export class CustomMarkerPlugin extends BasePlugin {
  // Static factory pattern standard in Wavesurfer.js
  static create(options) {
    return new CustomMarkerPlugin(options);
  }

  constructor(options) {
    super(options);
    this.markerElement = null;
  }

  // 1. Initialization Hook
  onInit() {
    if (!this.wavesurfer) {
      throw new Error('WaveSurfer instance not found');
    }

    // Create custom DOM elements
    const wrapper = this.wavesurfer.getWrapper();
    this.markerElement = document.createElement('div');
    this.markerElement.className = 'custom-marker';
    wrapper.appendChild(this.markerElement);

    // Register listeners using this.subscriptions for tracking
    this.subscriptions.push(
      this.wavesurfer.on('ready', () => {
        this.renderMarker();
      }),
      this.wavesurfer.on('audioprocess', (currentTime) => {
        this.updatePosition(currentTime);
      })
    );
  }

  renderMarker() {
    // Custom UI setup logic
  }

  updatePosition(currentTime) {
    // Logic triggered by audio playback
  }

  // 2. Destruction Hook
  destroy() {
    // Clean up custom DOM nodes
    if (this.markerElement) {
      this.markerElement.remove();
      this.markerElement = null;
    }

    // Call super.destroy() to unsubscribe all events in this.subscriptions
    super.destroy();
  }
}

By correctly implementing onInit() for resource allocation and destroy() for resource deallocation, custom plugins remain fully compatible with Wavesurfer's modular ecosystem and prevent memory leaks during component re-renders.
