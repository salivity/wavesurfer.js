Handling Token Expiration Mid-Playback in Wavesurfer.js

Managing secure, long-duration audio playback in Wavesurfer.js introduces a common failure point: authentication tokens or signed URLs expiring mid-session. When playing extended recordings, the browser's underlying media engine frequently issues HTTP range requests for upcoming audio chunks; if an access token or signed query string expires while listening, subsequent range requests fail with HTTP 401 or 403 errors, terminating playback. To maintain seamless, uninterrupted playback, developers must implement an architectural pattern that abstracts request authentication away from the core media player, either through a client-side Service Worker interceptor, an MSE-based streaming protocol with lifecycle hooks, or proactive buffer management.

The Underlying Problem with MediaElement Range Requests

Wavesurfer.js relies heavily on the HTML5 <audio> element (backend: 'MediaElement') for long audio files to avoid decoding giant audio files entirely into memory with the Web Audio API.

When using an <audio> tag, the browser manages playback buffering natively through HTTP Range requests. If the source URL uses a short-lived signed token (such as AWS S3 pre-signed URLs or Google Cloud Storage signed URLs), that token is evaluated on every new range request. Once the TTL (Time To Live) passes:

  1. The user pauses, seeks, or naturally reaches unbuffered audio.
  2. The browser attempts a Range: bytes=X-Y request using the original, now-expired URL.
  3. The server responds with an authentication error.
  4. The media element fires a fatal MediaError, halting playback and leaving Wavesurfer out of sync.

Simply updating the src attribute of the audio element with a newly generated URL causes the browser to dump its current playback buffer, leading to audible stutter, lost playback positions, and broken waveform states.

Pattern 1: Service Worker Request Interception (Recommended)

The most resilient pattern for monolithic audio files (MP3, WAV, AAC) is the Service Worker Interceptor Pattern. This pattern leaves Wavesurfer.js completely untouched while intercepting outgoing network requests at the browser transport layer.

Implementation Workflow:

  1. Route Matching: The Service Worker listens to the fetch event and filters for requests targeted at the protected audio domain.
  2. TTL Tracking: The Service Worker tracks token expiration times stored in IndexedDB or received via client messaging (postMessage).
  3. Transparent Refresh: If the current token is expired or within a safety margin (e.g., 30 seconds before expiration), the Service Worker pauses the fetch event, requests a refreshed token or pre-signed URL from your authentication API, and rewrites the pending HTTP Range request with the new credentials.
  4. Pass-Through: The modified range request proceeds to the CDN/storage bucket.
// service-worker.js
self.addEventListener('fetch', (event) => {
  const url = new URL(event.request.url);

  if (url.pathname.startsWith('/secure-audio/')) {
    event.respondWith(
      (async () => {
        let validToken = await getValidTokenOrRefresh();
        
        // Clone request with new authorization headers or query parameters
        const modifiedHeaders = new Headers(event.request.headers);
        modifiedHeaders.set('Authorization', `Bearer ${validToken}`);

        const authenticatedRequest = new Request(event.request, {
          headers: modifiedHeaders,
          mode: 'cors',
          credentials: 'same-origin'
        });

        return fetch(authenticatedRequest);
      })()
    );
  }
});

Because the audio element’s original connection remains active and the Service Worker transparently updates the authentication headers, the browser's media pipeline never resets, and Wavesurfer continues tracking without interruption.

Pattern 2: HLS/DASH Streaming with Custom Fragment Loaders

For production architectures handling massive audio sessions (e.g., multi-hour podcasts or surveillance recordings), monolithic files should be converted into an adaptive streaming format like HLS or MPEG-DASH.

Wavesurfer.js can bind to an HTML5 media element driven by external streaming libraries like hls.js. This enables the Segment-Level Token Injection Pattern, where every audio fragment (.ts or .m4s) is authenticated independently.

Implementation Workflow:

  1. Initialize hls.js and hook it into Wavesurfer using the media configuration option.
  2. Intercept fragment loading within the hls.js configuration using xhrSetup or a custom pLoader (playlist loader) and fLoader (fragment loader).
  3. Evaluate the token's validity before every chunk fetch.
import Hls from 'hls.js';
import WaveSurfer from 'wavesurfer.js';

let currentAuthToken = 'initial-token';

const hls = new Hls({
  xhrSetup: (xhr, url) => {
    // Check if token needs refresh before dispatching segment request
    if (isTokenExpiringSoon()) {
      currentAuthToken = await fetchNewToken();
    }
    xhr.setRequestHeader('Authorization', `Bearer ${currentAuthToken}`);
  }
});

const audio = document.createElement('audio');
hls.attachMedia(audio);
hls.loadSource('https://cdn.example.com/audio/master.m3u8');

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  media: audio, // Pass the HLS-controlled element to Wavesurfer
});

Because HLS splits audio into small chunks (typically 2 to 6 seconds each), token expiration is mitigated at the network layer on a per-segment basis without disrupting the continuous playback timeline of the player.

Pattern 3: Dual-Element Seamless Swapping (Fallback)

If Service Workers and HLS are not viable options, you can implement the Dual-Element Swapping Pattern directly in the DOM.

Implementation Workflow:

  1. Set a background timer that triggers before the current signed URL expires.
  2. When the timer fires, instantiate a hidden second <audio> element in the background with a newly generated URL.
  3. Preload the new element and synchronize its currentTime with the active element.
  4. Once the secondary element has buffered, execute a synchronized pause-and-play handoff:
    • Call .play() on the secondary element.
    • Immediately call .pause() on the primary element.
    • Rebind Wavesurfer to the new media element via internal APIs or by reassigning the media property.
  5. Dispose of the old audio element and reset the lifecycle timer.

While effective, this pattern requires precise handling of audio volume cross-fades to prevent audible pops or micro-stutters during the transition.

Architectural Recommendation

  • Choose the Service Worker Interceptor if you are streaming raw audio files (MP3/WAV) directly from cloud storage (e.g., Amazon S3, Google Cloud Storage) and need to maintain a single URL contract.
  • Choose HLS.js + Fragment Interception if you control the media encoding pipeline, as it provides the cleanest buffer lifecycle management and eliminates custom network hacking in the frontend.
