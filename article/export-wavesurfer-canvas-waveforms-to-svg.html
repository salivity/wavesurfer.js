Export Wavesurfer Canvas Waveforms to SVG

This article explains how SVG export plugins convert pixel-based HTML5 canvas waveforms generated by Wavesurfer.js into clean, scalable vector graphics (SVG). While Wavesurfer.js natively renders audio visualizations using raster graphics, export plugins bridge the gap between pixels and vectors either by intercepting 2D canvas drawing commands or by regenerating vector paths directly from the underlying audio peak data.

The Challenge: Raster Canvas vs. Vector Graphics

By default, Wavesurfer.js uses the HTML5 <canvas> element to draw audio waveforms. The browser’s Web Audio API decodes the audio file into channel data, normalizes amplitude peaks, and paints them to the canvas via CanvasRenderingContext2D operations such as fillRect, lineTo, and stroke. Because the canvas is a raster surface, scaling or zooming the resulting waveform leads to pixelation.

Converting this output to an SVG requires transforming these transient drawing instructions into static XML nodes, specifically <svg>, <path>, and <rect> elements that maintain sharpness at any resolution.

Method 1: Reconstructing Paths from Peak Data

The most efficient and accurate export plugins do not parse the visual pixels on the canvas; instead, they retrieve the underlying peak data that Wavesurfer.js used to render the canvas in the first place.

  1. Extracting Amplitude Peaks: The plugin accesses Wavesurfer's internal backend (such as wavesurfer.backend.mergedPeaks or the decoded AudioBuffer). This data consists of arrays representing minimum and maximum amplitude values across set time intervals.
  2. Coordinate Transformation: The plugin maps these raw amplitude values to a user-defined SVG coordinate space. It calculates the horizontal step per peak (based on total waveform width) and the vertical deflection relative to the baseline (half of the SVG height for symmetric waveforms).
  3. Building the Path Data (d Attribute): The plugin iterates over the peaks and constructs a single SVG path string. For each time step, it appends coordinates using standard SVG path commands:
    • M (moveto) to establish the starting position.
    • V or L (lineto) to draw the vertical bar representing amplitude.
    • Z (closepath) to enclose the shape if rendering a solid, filled waveform.
  4. Assembling the SVG Node: The generated path string is inserted into a <path> element with defined fill, stroke, and stroke-width attributes, and enclosed inside an <svg> wrapper featuring an appropriate viewBox.

Method 2: Mocking the 2D Canvas Context

An alternative approach used by generic export tools (such as canvas2svg or C2S) involves context interception:

  1. Creating a Virtual Context: The plugin instantiates a JavaScript object that mimics the standard HTML5 CanvasRenderingContext2D API.
  2. Rerouting Draw Calls: When Wavesurfer.js executes its render loop, the plugin redirects drawing commands to this mock context instead of the real screen canvas.
  3. Translating Methods to XML:
    • A call to ctx.rect(x, y, w, h) creates an equivalent <rect> node.
    • Calls to ctx.beginPath(), ctx.moveTo(x, y), and ctx.lineTo(x, y) accumulate into an SVG path definition.
    • Calls to ctx.fillStyle or ctx.strokeStyle are mapped to SVG presentation attributes.
  4. Serialization: Once the draw function completes, the mock context serializes its internal DOM tree into an SVG document.

Exporting and Downloading

Once the SVG structure is compiled—whether through data reconstruction or context virtualization—the plugin serializes the XML into a text string using the browser's native XMLSerializer.

To make the graphic usable, the plugin formats this string into a standard data URL (data:image/svg+xml;utf8,...) or wraps it in a Blob with the image/svg+xml MIME type. This allows users to download the file directly, embed it inline within the DOM, or manipulate it via CSS.
