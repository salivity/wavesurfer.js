Load Saved Regions in Wavesurfer.js on Mount

This article demonstrates how to restore saved region JSON payloads into a Wavesurfer.js instance upon component or page mounting. By utilizing the official Regions plugin and synchronizing with Wavesurfer’s lifecycle events, you can seamlessly reconstruct interactive audio annotations, markers, and segments from previously persisted backend data.

Preparing the Regions Plugin

To work with regions in modern Wavesurfer.js (version 7+), you must register the RegionsPlugin. When regions are exported, they are typically saved as an array of JSON objects containing properties such as id, start, end, color, and optional metadata like content or data.

A standard serialized region payload looks like this:

[
  {
    "id": "region-1",
    "start": 1.5,
    "end": 4.2,
    "color": "rgba(255, 0, 0, 0.3)",
    "content": "Intro Segment",
    "drag": true,
    "resize": true
  },
  {
    "id": "region-2",
    "start": 6.0,
    "end": 9.8,
    "color": "rgba(0, 255, 0, 0.3)",
    "content": "Chorus Segment",
    "drag": true,
    "resize": true
  }
]

Loading Regions on Mount

To ensure the waveform dimensions and time duration are correctly mapped, load the regions either right after registering the plugin or immediately after the audio file decodes. Listening to the decode or ready event is the most reliable approach to avoid rendering issues.

Here is the implementation in modern JavaScript:

import WaveSurfer from 'wavesurfer.js';
import RegionsPlugin from 'wavesurfer.js/dist/plugins/regions.esm.js';

function initWaveSurfer(audioUrl, savedRegionsPayload) {
  // 1. Initialize Wavesurfer
  const wavesurfer = WaveSurfer.create({
    container: '#waveform',
    waveColor: '#4F4A85',
    progressColor: '#383351',
    url: audioUrl,
  });

  // 2. Initialize and register the Regions plugin
  const wsRegions = wavesurfer.registerPlugin(RegionsPlugin.create());

  // 3. Populate regions once the audio is decoded
  wavesurfer.on('decode', () => {
    savedRegionsPayload.forEach((regionData) => {
      wsRegions.addRegion({
        id: regionData.id,
        start: regionData.start,
        end: regionData.end,
        color: regionData.color || 'rgba(0, 0, 0, 0.1)',
        content: regionData.content,
        drag: regionData.drag ?? true,
        resize: regionData.resize ?? true,
      });
    });
  });

  return { wavesurfer, wsRegions };
}

Integrating with Frontend Frameworks

When integrating into frameworks like React, Vue, or Svelte, wrap the initialization inside the framework's standard mounting hook:

  • React (useEffect): Place the instantiation and region-loading logic inside a useEffect hook with an empty dependency array, and ensure you call wavesurfer.destroy() in the cleanup return function to avoid memory leaks.
  • Vue (onMounted): Call the setup function within onMounted(), storing the wsRegions reference in a component variable, and call wavesurfer.destroy() inside onUnmounted().

Using the decode event ensures that all region coordinates are rendered accurately against the total calculated duration of the audio canvas.
