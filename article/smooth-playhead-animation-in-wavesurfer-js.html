Smooth Playhead Animation in Wavesurfer.js

Achieving a continuous, fluid playhead animation across custom-styled transport bars in Wavesurfer.js requires decoupling the visual element from the browser's native audio update cycle. While default audio events like timeupdate fire intermittently—typically only 3 to 4 times per second—you can generate a seamless 60 frames-per-second animation by combining requestAnimationFrame with GPU-accelerated CSS transforms. This guide explains how to build and synchronize this smooth rendering pipeline directly with Wavesurfer's audio state.

The Problem with Native Audio Events

HTML5 audio and the standard Wavesurfer.js audioprocess event update at a low frequency (roughly every 250ms). If you bind your custom playhead's position directly to these events, the playhead will appear to jump or stutter across the timeline rather than gliding smoothly.

Step 1: Use CSS Transforms for the Playhead

To prevent browser layout reflows and ensure hardware acceleration, update the playhead's position using the CSS transform property instead of adjusting left or width.

.custom-transport-bar {
  position: relative;
  width: 100%;
  height: 8px;
  background-color: #e2e8f0;
  overflow: hidden;
}

.custom-playhead {
  position: absolute;
  top: 0;
  left: 0;
  width: 100%;
  height: 100%;
  background-color: #3b82f6;
  transform-origin: left center;
  transform: scaleX(0);
  will-change: transform;
}

Using scaleX scales the progress bar efficiently without forcing recalculations of neighboring DOM nodes.

Step 2: Implement the Animation Loop with requestAnimationFrame

Leverage requestAnimationFrame to compute the current position on every screen refresh while the audio is active. Store the animation frame ID so it can be canceled when playback stops.

const playhead = document.querySelector('.custom-playhead');
let animationFrameId = null;

function updatePlayhead() {
  if (wavesurfer.isPlaying()) {
    const currentTime = wavesurfer.getCurrentTime();
    const duration = wavesurfer.getDuration();

    if (duration > 0) {
      const progress = currentTime / duration;
      playhead.style.transform = `scaleX(${progress})`;
    }

    animationFrameId = requestAnimationFrame(updatePlayhead);
  }
}

Step 3: Bind to Wavesurfer Lifecycle Events

To maintain accuracy, start the loop on play, cancel it on pause or finish, and manually update the playhead when the user seeks or interacts with the timeline.

// Start animation loop on playback
wavesurfer.on('play', () => {
  cancelAnimationFrame(animationFrameId);
  animationFrameId = requestAnimationFrame(updatePlayhead);
});

// Stop animation loop on pause or finish
wavesurfer.on('pause', () => {
  cancelAnimationFrame(animationFrameId);
});

wavesurfer.on('finish', () => {
  cancelAnimationFrame(animationFrameId);
  playhead.style.transform = 'scaleX(1)';
});

// Instantly sync the visual position during manual seeking
wavesurfer.on('seeking', (currentTime) => {
  const duration = wavesurfer.getDuration();
  if (duration > 0) {
    const progress = currentTime / duration;
    playhead.style.transform = `scaleX(${progress})`;
  }
});

Handling Custom Pin or Indicator Playheads

If your custom transport bar uses a single moving indicator line (pin) rather than a filling bar, modify the CSS and translation calculation:

// For a pin playhead using translateX
const containerWidth = transportContainer.clientWidth;
const progress = currentTime / duration;
pinElement.style.transform = `translateX(${progress * containerWidth}px)`;

By calculating precise progress percentages inside requestAnimationFrame and rendering with hardware-accelerated transforms, the custom playhead tracks Wavesurfer.js audio playback without stuttering or latency.
