Wavesurfer.js on vs once Event Listeners

Wavesurfer.js relies on an event-driven architecture to notify developers of audio loading states, playback updates, and user interactions. While both the on and once methods are used to attach listeners to these events, the core difference between them is their lifecycle: on creates a persistent listener that triggers every time the specified event fires, whereas once creates a one-time listener that automatically removes itself after its first invocation.

The on Method: Persistent Event Handling

The on method registers a callback function that remains active indefinitely until it is explicitly unsubscribed. This makes it the standard choice for recurring events throughout the lifecycle of an audio player.

Common use cases for on include:

  • audioprocess or timeupdate: Tracking current playback time to update custom UI timers or progress bars continuously.
  • play and pause: Toggling visual playback states (such as switching play/pause icon buttons) whenever the user interacts with the controls.
  • interaction or click: Handling repeated user interactions on the waveform canvas.

In modern versions of Wavesurfer.js (v7+), the on method returns an "unlisten" function, which provides a clean mechanism to remove the event when a component unmounts:

const unsubscribe = wavesurfer.on('audioprocess', (currentTime) => {
  console.log('Current time:', currentTime);
});

// Later, to remove the listener:
unsubscribe();

The once Method: Single-Execution Handling

The once method registers a callback that executes only on the initial occurrence of the target event. Immediately after the callback finishes, Wavesurfer.js automatically detaches the listener.

Common use cases for once include:

  • ready: Executing initialization logic—such as enabling UI controls, zooming, or displaying total audio duration—as soon as the audio has decoded and the waveform finishes rendering.
  • decode: Performing an action immediately after the audio buffer is loaded, such as setting custom color parameters or reading peak data.
  • destroy: Running final cleanup logic right before the instance is torn down.

Using once avoids the overhead of manually tracking and unsubscribing from events that are only relevant during setup:

wavesurfer.once('ready', () => {
  console.log('Waveform is ready to play');
  playButton.disabled = false;
});

Key Differences at a Glance

  • Execution Count: on executes every time the event is emitted. once executes only on the first emission.
  • Memory Management: on retains the callback in memory until manually cleaned up, which can lead to memory leaks if neglected in single-page applications. once cleans up after itself automatically.
  • Appropriate Event Types: on is best suited for stream-like or cyclical events (audioprocess, seeking, finish). once is best suited for milestone or state-transition events (ready, decode).
