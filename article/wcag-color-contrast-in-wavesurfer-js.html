WCAG Color Contrast in Wavesurfer.js

Applying Web Content Accessibility Guidelines (WCAG) to Wavesurfer.js requires meeting non-text color contrast ratios for user interface components and graphical states. When configuring the waveColor (the unplayed waveform) and progressColor (the played portion), developers must ensure sufficient contrast against the container background as well as between the two waveform states. Adhering to these standards ensures that users with low vision or color vision deficiencies can discern the audio player's structure, identify the current playback progress, and navigate media effectively.

Relevant WCAG Criteria

Two primary criteria from WCAG 2.1 apply to waveform visualizations:

  • WCAG 2.1 SC 1.4.11 Non-text Contrast (Level AA): The visual presentation of user interface components and graphical objects must have a contrast ratio of at least 3:1 against adjacent colors.
  • WCAG 2.1 SC 1.4.1 Use of Color (Level A): Color should not be the only visual means of conveying information, indicating an action, prompting a response, or distinguishing a visual element.

In Wavesurfer.js, the waveform acts as an interactive progress bar and audio visualization component. Therefore, the 3:1 minimum contrast threshold applies to all adjacent visual boundaries that convey meaning.

Applying Contrast Ratios in Wavesurfer.js

When configuring waveColor and progressColor, three distinct contrast relationships must be evaluated.

1. waveColor Against the Background

The unplayed waveform visually defines the shape, amplitude, and overall duration of the audio track. To satisfy SC 1.4.11, the waveColor must maintain at least a 3:1 contrast ratio against the player's background element. If the contrast is too low, users with visual impairments will not be able to identify the component or understand audio peaks and troughs.

2. progressColor Against the Background

The progressColor represents the active, played state of the track against the player canvas. Like waveColor, it must have a minimum 3:1 contrast ratio against the background color so the played portion remains visible as an independent graphical entity.

3. progressColor Against waveColor

The boundary between the played and unplayed audio marks the current playback position. If the player does not use a physical cursor or scrubber handle, the visual distinction relies entirely on the boundary where progressColor meets waveColor.

To ensure users can perceive the playback position:

  • Maintain a 3:1 contrast ratio directly between progressColor and waveColor.
  • If a 3:1 ratio between the two colors cannot be achieved due to brand constraints, you must enable a distinct visual indicator—such as a contrasting cursorColor or a separate scrubber handle—to satisfy SC 1.4.1 (Use of Color).

Common Mistakes to Avoid

  • Using Opacity and Alpha Channels: Using rgba() values with low alpha values reduces the actual rendered contrast against the background. Measure the final rendered RGB color against the background rather than evaluating the raw hex values in isolation.
  • Complex Multi-stop Gradients: Supplying linear or canvas gradients to waveColor or progressColor can cause sections of the waveform to fall below the 3:1 threshold. If using gradients, verify that the lowest-contrast stop still meets the requirement.
  • Low-Contrast Playheads: If cursorWidth is set, ensure cursorColor achieves a 3:1 contrast ratio against both waveColor and progressColor so the indicator is consistently visible regardless of its position on the track.

Implementation Example

Below is an accessible Wavesurfer.js configuration for a light theme where the background is white (#FFFFFF).

import WaveSurfer from 'wavesurfer.js'

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  // Background: #FFFFFF
  
  // #767676 on #FFFFFF produces a 4.54:1 contrast ratio
  waveColor: '#767676', 
  
  // #005A9C on #FFFFFF produces a 7.04:1 contrast ratio
  // #005A9C against #767676 provides clear state differentiation
  progressColor: '#005A9C', 
  
  // #000000 ensures maximum visibility against both colors
  cursorColor: '#000000', 
  cursorWidth: 2,
})

By verifying these color combinations with an accessibility contrast checker before implementation, you ensure that your audio interface complies with WCAG standards and remains usable for everyone.
