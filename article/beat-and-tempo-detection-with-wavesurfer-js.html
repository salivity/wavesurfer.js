Beat and Tempo Detection with Wavesurfer.js

This article explains how to analyze audio for tempo (BPM) and transient beat locations, and subsequently map those markers onto an interactive waveform using Wavesurfer.js. Because Wavesurfer.js focuses primarily on audio visualization and playback rather than music information retrieval, integrating a dedicated client-side beat detection library such as web-audio-beat-detector or music-tempo is the standard approach for creating rhythm-aware audio players.

Understanding the Integration Workflow

Wavesurfer.js decodes audio into a native Web Audio API AudioBuffer. A beat detection library processes this raw pulse-code modulation (PCM) data to calculate the overall tempo (in beats per minute) and the exact timestamps of individual beats. Once these timestamps are computed, you use the Wavesurfer.js Regions plugin (or Markers plugin in older versions) to render visual cues directly on the waveform.

Step 1: Install and Import Required Libraries

You need Wavesurfer.js, its Regions plugin, and an analysis library. For modern web environments, web-audio-beat-detector is lightweight and uses the native Web Audio API:

npm install wavesurfer.js web-audio-beat-detector

In your JavaScript file:

import WaveSurfer from 'wavesurfer.js';
import RegionsPlugin from 'wavesurfer.js/dist/plugins/regions.esm.js';
import { analyze } from 'web-audio-beat-detector';

Step 2: Initialize Wavesurfer.js

Set up the Wavesurfer instance with the Regions plugin enabled.

const wsRegions = RegionsPlugin.create();

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: '/path-to-your-audio.mp3',
  plugins: [wsRegions],
});

Step 3: Analyze Audio and Map Beats

Wait for Wavesurfer to decode the audio. Once the decode event fires, access the internal AudioBuffer, pass it to the beat detector, and loop over the returned timestamps to insert regions.

wavesurfer.on('decode', async () => {
  // Retrieve the native AudioBuffer from Wavesurfer
  const audioBuffer = wavesurfer.getDecodedData();

  try {
    // web-audio-beat-detector extracts BPM
    const bpm = await analyze(audioBuffer);
    console.log(`Detected BPM: ${bpm}`);

    // If using a library that provides explicit beat offsets (e.g., music-tempo):
    // Map individual beat timestamps onto the waveform
    plotBeats(audioBuffer, bpm);
  } catch (error) {
    console.error('Beat detection failed:', error);
  }
});

function plotBeats(audioBuffer, bpm) {
  const secondsPerBeat = 60 / bpm;
  const duration = audioBuffer.duration;

  // Generate visual lines for each beat across the duration
  for (let time = 0; time < duration; time += secondsPerBeat) {
    wsRegions.addRegion({
      start: time,
      end: time, // Zero-length creates a single vertical line
      color: 'rgba(255, 0, 0, 0.5)',
      drag: false,
      resize: false,
    });
  }
}

Handling Irregular Tempos with Precise Peak Detection

For music with variable tempos or live drumming, a fixed BPM calculation is insufficient. Libraries like music-tempo analyze the spectral flux of the buffer and return an array of discrete timestamps (tempo.beats).

import MusicTempo from 'music-tempo';

wavesurfer.on('decode', () => {
  const buffer = wavesurfer.getDecodedData();
  
  // Downmix to mono channel data for performance
  const channelData = buffer.getChannelData(0);
  
  const calc = new MusicTempo(channelData);
  
  // calc.beats contains an array of precise timestamps in seconds
  calc.beats.forEach((timestamp) => {
    wsRegions.addRegion({
      start: timestamp,
      end: timestamp,
      color: 'rgba(0, 200, 100, 0.6)',
      drag: false,
      resize: false,
    });
  });
});

Performance Considerations

  • Web Workers: Audio analysis algorithms are computationally intensive. For longer tracks (over 3–4 minutes), execute the beat detection algorithm inside a Web Worker to prevent UI freezes on the main thread.
  • Sample Rate Reduction: Downsampling the AudioBuffer to 22,050 Hz or converting stereo tracks to mono before running analysis significantly reduces processing time without sacrificing BPM accuracy.
