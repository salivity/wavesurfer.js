Clean Up Wavesurfer.js in Single-Page Apps

Integrating Wavesurfer.js into single-page application (SPA) frameworks like React, Vue, or Angular often introduces memory leaks and audio glitches if instances are not properly dismantled. Because SPAs replace views without full page reloads, orphaned Web Audio contexts, lingering canvas elements, and unbound event listeners persist in the browser's memory. This article outlines the essential structural patterns and lifecycle strategies required to ensure Wavesurfer.js is completely and safely disposed of when a component unmounts.

The Underlying Causes of Leaks

Wavesurfer.js relies heavily on the Web Audio API, Canvas rendering, and global event bindings. When a component re-renders or unmounts, failing to properly dismantle the instance causes three primary issues:

  1. Active AudioContext Instances: Browsers enforce a strict limit on the number of concurrent AudioContext instances. Abandoned contexts consume audio hardware channels and eventually throw errors when opening new ones.
  2. Dangling Event Listeners: Event listeners attached to the window, the container element, or internal media elements prevent the garbage collector from reclaiming the component's memory.
  3. Canvas and DOM Retention: Rendered waveform canvases remain in memory if the parent reference is discarded without clearing the rendered nodes first.

The Dedicated Teardown Lifecycle Pattern

The most fundamental pattern is encapsulating the Wavesurfer instance inside a component-level lifecycle hook that guarantees a synchronous cleanup phase.

Whenever an instance is created, its corresponding destroy() method must be invoked during the unmount phase. The destroy() method handles unloading the media, clearing events, removing canvas nodes, and closing the internal AudioContext.

Implementation in React

In React, the cleanup logic belongs exclusively in the return callback of useEffect:

import { useEffect, useRef } from 'react';
import WaveSurfer from 'wavesurfer.js';

export function AudioPlayer({ audioUrl }) {
  const containerRef = useRef(null);
  const wavesurferRef = useRef(null);

  useEffect(() => {
    if (!containerRef.current) return;

    // Initialization
    wavesurferRef.current = WaveSurfer.create({
      container: containerRef.current,
      url: audioUrl,
    });

    // Cleanup phase
    return () => {
      if (wavesurferRef.current) {
        wavesurferRef.current.destroy();
        wavesurferRef.current = null;
      }
    };
  }, [audioUrl]);

  return <div ref={containerRef} />;
}

Implementation in Vue 3

In Vue 3, this is achieved using the onBeforeUnmount lifecycle hook along with a shallow reference:

<template>
  <div ref="container"></div>
</template>

<script setup>
import { ref, onMounted, onBeforeUnmount, shallowRef } from 'vue';
import WaveSurfer from 'wavesurfer.js';

const props = defineProps(['audioUrl']);
const container = ref(null);
const wavesurfer = shallowRef(null);

onMounted(() => {
  wavesurfer.value = WaveSurfer.create({
    container: container.value,
    url: props.audioUrl,
  });
});

onBeforeUnmount(() => {
  if (wavesurfer.value) {
    wavesurfer.value.destroy();
    wavesurfer.value = null;
  }
});
</script>

Note: In Vue, use shallowRef rather than ref to hold the Wavesurfer instance. Deep reactivity can interfere with Wavesurfer's internal state and audio buffers.

The Asynchronous Guard Pattern

A frequent bug occurs when an SPA unmounts a component while an audio track is still actively downloading or decoding. If wavesurfer.destroy() is called while an internal promise is resolving, race conditions can cause unhandled exceptions or incomplete teardowns.

To guard against this:

  1. Track Mount Status: Maintain a local boolean or abort controller that tracks whether the component is still actively mounted.
  2. Catch Asynchronous Initialization Errors: Ensure that decoding promises do not execute callbacks on unmounted elements.
useEffect(() => {
  let isMounted = true;

  const ws = WaveSurfer.create({
    container: containerRef.current,
  });
  
  ws.load(audioUrl)
    .then(() => {
      if (!isMounted) {
        ws.destroy();
      }
    })
    .catch((err) => {
      if (isMounted) {
        console.error('Audio loading failed:', err);
      }
    });

  wavesurferRef.current = ws;

  return () => {
    isMounted = false;
    if (wavesurferRef.current) {
      wavesurferRef.current.destroy();
      wavesurferRef.current = null;
    }
  };
}, [audioUrl]);

Shared AudioContext Management

If your application plays multiple audio clips across different components, creating a new AudioContext per waveform instance can quickly exhaust browser resources.

A reliable structural pattern is to inject a single, shared AudioContext from a global service or context provider:

  1. Pass the shared context to Wavesurfer via the audioContext option:

    WaveSurfer.create({
  container: containerRef.current,
  audioContext: globalAudioContext,
});

  2. When calling destroy(), Wavesurfer will automatically avoid closing a shared AudioContext if it was passed in externally, preventing sibling components from losing their audio output.

  3. Manage the closure of the global AudioContext at the application root level rather than at the component level.

Explicit Plugin Deregistration

Wavesurfer plugins (such as Timeline, Regions, or Minimap) attach additional event listeners to both the DOM and the parent Wavesurfer instance. While wavesurfer.destroy() is designed to cascade teardown calls to registered plugins, maintaining manual references to plugins in your state can prevent memory collection.

  • Always call destroy() on individual plugins if they are dynamically instantiated outside the primary WaveSurfer.create() configuration array.
  • Clear plugin references from your component state by setting their pointers to null immediately after triggering the parent teardown.

Reference Nullification

Simply calling .destroy() removes DOM elements and closes connections, but the JavaScript garbage collector cannot reclaim memory if references to the instance persist in component state, store subscriptions, or closures. Always follow .destroy() calls by nullifying all pointers to the Wavesurfer instance, custom events, and the DOM container ref.
