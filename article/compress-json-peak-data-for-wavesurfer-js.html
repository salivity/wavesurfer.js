Compress JSON Peak Data for Wavesurfer.js

Serving waveform peak data as raw JSON creates bloated payloads that degrade network performance and delay rendering in web audio applications. This guide demonstrates how to replace verbose JSON peak arrays with compact binary packing, dramatically reducing payload sizes by up to 80–90% and parsing binary buffers directly in the browser for rapid Wavesurfer.js rendering.

The Overhead of JSON Peaks

Waveform visualizers like Wavesurfer.js require an array of peak numbers (typically min/max pairs normalized between -1.0 and 1.0) to render audio contours without downloading the full audio file.

When serialized to JSON, floating-point numbers are represented as plain ASCII strings:

[-0.231456, 0.451239, -0.671234, 0.891245]

Each peak value consumes 8 to 12 bytes due to digits, decimal points, separators, and brackets. For a standard audio file containing 2,000 to 10,000 peak points, the resulting JSON payload can easily reach several hundred kilobytes.

The Binary Packing Solution

Because waveform rendering is purely visual, the extreme precision of 64-bit or 32-bit floating-point numbers is unnecessary. Audio peaks bounded between -1.0 and 1.0 can be mapped into a fixed-width integer format:

  • Int8 (Int8Array): Maps -1.0 to 1.0 across -128 to 127. Uses 1 byte per peak point.
  • Int16 (Int16Array): Maps -1.0 to 1.0 across -32768 to 32767. Uses 2 bytes per peak point.

For virtually all UI waveform displays, Int8 provides sufficient resolution while yielding the smallest payload.

Step 1: Pack the Peaks on the Server

To prepare the binary payload, scale the normalized float peaks to the target integer range and write them into a raw binary buffer.

Example using Node.js:

/**
 * Packs an array of normalized floats (-1.0 to 1.0) into an Int8 Buffer.
 * @param {number[]} floatPeaks
 * @returns {Buffer}
 */
function packPeaksToInt8(floatPeaks) {
  const buffer = Buffer.alloc(floatPeaks.length);

  for (let i = 0; i < floatPeaks.length; i++) {
    // Clamp values between -1.0 and 1.0
    const clamped = Math.max(-1, Math.min(1, floatPeaks[i]));
    
    // Scale to signed 8-bit integer range (-128 to 127)
    const scaled = clamped < 0 ? clamped * 128 : clamped * 127;
    buffer.writeInt8(Math.round(scaled), i);
  }

  return buffer;
}

// Serve this buffer directly with Content-Type: application/octet-stream

Step 2: Fetch and Unpack in the Browser

Wavesurfer.js accepts precomputed peaks via its peaks option or via the load() method. Instead of parsing a large JSON string with JSON.parse(), fetch the binary response as an ArrayBuffer and map it back into normalized float arrays.

Client-Side Implementation:

import WaveSurfer from 'wavesurfer.js';

async function loadPackedWaveform(audioUrl, peaksUrl, containerElement) {
  // 1. Fetch the binary peak payload
  const response = await fetch(peaksUrl);
  const arrayBuffer = await response.arrayBuffer();

  // 2. Read the binary buffer directly without string parsing
  const int8View = new Int8Array(arrayBuffer);
  const floatPeaks = new Float32Array(int8View.length);

  // 3. Normalize values back to the range [-1.0, 1.0]
  for (let i = 0; i < int8View.length; i++) {
    const val = int8View[i];
    floatPeaks[i] = val < 0 ? val / 128 : val / 127;
  }

  // 4. Initialize Wavesurfer with the unpacked peaks
  const wavesurfer = WaveSurfer.create({
    container: containerElement,
    waveColor: '#4F46E5',
    progressColor: '#818CF8',
    peaks: [floatPeaks], // Wavesurfer supports single or dual-channel peak arrays
  });

  // Load the audio resource (or render immediately with peak data)
  wavesurfer.load(audioUrl, [floatPeaks]);
  
  return wavesurfer;
}

Key Advantages

  1. Payload Reduction: A 5,000-point JSON array typically measures ~50 KB to ~80 KB uncompressed. Packed as Int8, the exact same visual data is strictly 5 KB.
  2. Eliminated JSON Parsing: Parsing multi-megabyte JSON strings blocks the browser main thread. Reading typed arrays (Int8Array / Float32Array) operates directly on memory buffers with virtually zero CPU overhead.
  3. HTTP Compression Synergy: When served with Gzip or Brotli, repetitive binary sequences achieve high compression ratios, lowering network overhead even further.
