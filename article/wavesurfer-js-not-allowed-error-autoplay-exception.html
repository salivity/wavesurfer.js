Wavesurfer.js NotAllowedError Autoplay Exception

When attempting to play audio programmatically using Wavesurfer.js before a user has interacted with the webpage, modern web browsers will block the request and raise a NotAllowedError DOMException. This overview breaks down why this exception occurs, what the console error looks like, and the direct methods developers can implement to resolve or prevent it in production applications.

The Specific Exception Thrown

Calling wavesurfer.play() without a preceding user gesture causes the browser to reject the underlying playback promise with the following exception:

DOMException: play() failed because the user didn't interact with the document first.

Depending on whether Wavesurfer.js is configured with the standard HTML5 Media backend or the Web Audio API backend, the browser console will typically display one of two messages:

  1. Media Element Backend: Uncaught (in promise) DOMException: play() failed because the user didn't interact with the document first.
  2. Web Audio Backend: The AudioContext was not allowed to start. It must be resumed (or created) after a user gesture on the page.

In both cases, the DOMException name property is set strictly to "NotAllowedError".

Why This Happens

All modern browsers—including Google Chrome, Apple Safari, Mozilla Firefox, and Microsoft Edge—enforce strict Autoplay Policies. These policies prevent websites from automatically playing unmuted audio without an explicit user gesture, such as a click, tap, or key press. Because Wavesurfer.js relies directly on the browser's native audio engines (HTMLAudioElement or AudioContext), it inherits these security and user experience restrictions directly from the browser runtime.

How to Fix and Prevent the Error

To prevent and handle this exception in Wavesurfer.js, apply one of the following approaches:

1. Require an Explicit User Interaction

The most reliable solution is to trigger wavesurfer.play() exclusively from an interactive event listener, such as a user clicking a play button.

const playButton = document.querySelector('#play-btn');

playButton.addEventListener('click', () => {
    wavesurfer.play();
});

2. Catch the Promise Rejection

Because wavesurfer.play() returns a Promise, catch the rejection gracefully to prevent an uncaught runtime error in the console and prompt the user to interact.

wavesurfer.play().catch((error) => {
    if (error.name === 'NotAllowedError') {
        console.warn('Autoplay prevented. Waiting for user interaction.');
        // Display a UI prompt for the user to click play manually
    }
});

3. Autoplay with Audio Muted

If visual playback of the waveform must begin immediately upon page load without sound, mute the audio before initiating playback. Browsers allow muted autoplay without requiring prior user gestures.

wavesurfer.setMuted(true);
wavesurfer.play();

4. Resume the AudioContext

If you are using the Web Audio backend, ensure the underlying AudioContext is properly resumed on the first user interaction:

document.addEventListener('click', () => {
    const audioContext = wavesurfer.backend.getAudioContext();
    if (audioContext && audioContext.state === 'suspended') {
        audioContext.resume();
    }
}, { once: true });
