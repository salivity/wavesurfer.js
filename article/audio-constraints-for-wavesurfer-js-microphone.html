Audio Constraints for Wavesurfer.js Microphone

Capturing live microphone input in Wavesurfer.js relies on the browser's WebRTC MediaTrackConstraints API. This article explains how to configure and pass audio constraints—such as echo cancellation, noise suppression, sample rate, and channel count—to optimize live audio capture and waveform visualization when using Wavesurfer.js.

How Wavesurfer.js Handles Microphone Constraints

Wavesurfer.js handles microphone access via dedicated plugins, primarily the Record Plugin in modern versions (v7+) or the legacy Microphone Plugin (v6). Under the hood, these plugins invoke the browser's standard navigator.mediaDevices.getUserMedia() method.

Any valid standard WebRTC MediaTrackConstraints object can be passed directly into the plugin configuration or the recording initialization method.

Available Audio Constraints

When defining constraints, you can specify exact values, ideal targets, or boolean flags for the following properties:

  • echoCancellation (boolean): Eliminates acoustic feedback between the speakers and the microphone. Set to false for high-fidelity music recording or true for voice capture.
  • noiseSuppression (boolean): Filters out background noise such as computer fans or ambient room hum.
  • autoGainControl (boolean): Automatically adjusts the microphone sensitivity to normalize speaking volume.
  • channelCount (number or { ideal: number, exact: number }): Controls whether the input is mono (1) or stereo (2). Visualizations often perform better with mono audio unless multi-channel waveforms are explicitly required.
  • sampleRate (number or { ideal: number, exact: number }): Sets the audio sample rate in Hz (e.g., 44100 or 48000).
  • sampleSize (number or { ideal: number, exact: number }): Specifies the linear PCM audio resolution, typically 16 bits.
  • latency (number): Requests a specific input latency in seconds, useful for minimizing delay during live monitoring.
  • deviceId (string or { exact: string }): Directs the browser to access a specific microphone hardware input by passing its unique ID.

Passing Constraints in Wavesurfer.js v7

In Wavesurfer.js v7, use the RecordPlugin. You can pass constraints during plugin creation or directly when starting the microphone stream:

import WaveSurfer from 'wavesurfer.js'
import RecordPlugin from 'wavesurfer.js/dist/plugins/record.esm.js'

// 1. Initialize WaveSurfer
const wavesurfer = WaveSurfer.create({
  container: '#mic-waveform',
  waveColor: 'rgb(200, 0, 200)',
  progressColor: 'rgb(100, 0, 100)',
})

// 2. Define audio constraints
const audioConstraints = {
  echoCancellation: true,
  noiseSuppression: true,
  autoGainControl: true,
  channelCount: 1,
  sampleRate: { ideal: 48000 }
}

// 3. Register the Record plugin
const record = wavesurfer.registerPlugin(
  RecordPlugin.create({
    audioConstraints: audioConstraints,
    scrollingWaveform: true,
    renderRecordedAudio: false
  })
)

// 4. Start the microphone input
record.startMic()

Alternatively, constraints can be passed directly to startMic:

record.startMic({
  audio: {
    deviceId: { exact: selectedMicrophoneId },
    echoCancellation: false
  }
})

Passing Constraints in Wavesurfer.js v6

In legacy Wavesurfer.js implementations utilizing the Microphone Plugin, constraints are passed under the constraints object:

const microphone = wavesurfer.initPlugin('microphone', {
  constraints: {
    audio: {
      echoCancellation: false,
      noiseSuppression: false,
      autoGainControl: false,
      channelCount: 2
    },
    video: false
  }
})

microphone.start()

Configuration Recommendations

  • For Voice and Dictation: Enable echoCancellation, noiseSuppression, and autoGainControl to maximize speech clarity and prevent clipping.
  • For Music and Acoustic Instruments: Disable echoCancellation, noiseSuppression, and autoGainControl to prevent WebRTC algorithms from cutting out sustained notes or dynamic range.
