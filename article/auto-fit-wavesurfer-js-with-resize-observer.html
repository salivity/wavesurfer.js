Auto-Fit Wavesurfer.js with ResizeObserver

Integrating Wavesurfer.js into responsive web applications requires dynamically redrawing audio waveforms whenever their parent containers change size. This guide demonstrates how to attach the native JavaScript ResizeObserver API to your Wavesurfer container, allowing your waveform visualizations to auto-fit fluid, flexbox, or grid layouts seamlessly without relying on unstable window-level resize events.

Why Use ResizeObserver Instead of Window Events

Wavesurfer renders audio data using HTML5 <canvas> elements. Unlike vector graphics or responsive HTML elements, a canvas does not automatically recalculate its internal pixel dimensions when its container changes size.

While listening to window.addEventListener('resize', ...) catches full browser window adjustments, it fails to detect layout changes triggered by application-specific UI events—such as collapsible sidebars, dynamic flexbox growth, tab switches, or accordion animations. The ResizeObserver API solves this by directly monitoring the specific DOM element hosting the waveform, triggering a redraw only when that exact node's bounding box changes.

Step-by-Step Implementation

To properly resize the waveform without causing rendering bottlenecks, attach a ResizeObserver to the container and debounce the re-render call.

import WaveSurfer from 'wavesurfer.js';

// 1. Select the container element
const container = document.querySelector('#waveform');

// 2. Initialize Wavesurfer.js
const wavesurfer = WaveSurfer.create({
  container: container,
  waveColor: '#4F46E5',
  progressColor: '#818CF8',
  url: '/path/to/audio.mp3',
});

// 3. Implement a debounce function to optimize performance
function debounce(func, wait = 100) {
  let timeout;
  return (...args) => {
    clearTimeout(timeout);
    timeout = setTimeout(() => func.apply(this, args), wait);
  };
}

// 4. Create the ResizeObserver instance
const resizeObserver = new ResizeObserver(
  debounce((entries) => {
    for (const entry of entries) {
      // Ensure the container is rendered and has actual width
      if (entry.contentRect.width > 0 && wavesurfer.isReady) {
        // Redraw the waveform to match new dimensions
        wavesurfer.renderer.resize();
      }
    }
  }, 100)
);

// 5. Start observing the container
resizeObserver.observe(container);

Handling Wavesurfer Version Differences

Depending on the major version of Wavesurfer.js your project utilizes, the method required to re-render the waveform varies:

  • Wavesurfer.js v7+: The renderer is exposed directly on the instance. Call wavesurfer.renderer.resize() to force the canvas layers to measure the container and recalculate their pixel ratios.
  • Wavesurfer.js v6 and older: Call wavesurfer.drawer.fireEvent('redraw') or wavesurfer.drawBuffer() to force the legacy canvas drawers to repaint based on the updated DOM width.

Managing Cleanup and Memory Leaks

Whenever the container is unmounted or removed from the DOM (such as navigating away in single-page frameworks like React, Vue, or Svelte), disconnect the observer to prevent memory leaks and unexpected callbacks on detached nodes:

function destroyPlayer() {
  resizeObserver.disconnect();
  wavesurfer.destroy();
}

By decoupling the layout trigger from the window object and debouncing observer events, your waveform stays pixel-perfect across all dynamic and fluid layout adjustments with minimal CPU overhead.
