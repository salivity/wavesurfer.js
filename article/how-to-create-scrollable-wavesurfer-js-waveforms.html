How to Create Scrollable Wavesurfer.js Waveforms

Creating a scrollable waveform in Wavesurfer.js requires a combination of targeted CSS overflow properties on the host container and appropriate JavaScript configuration. This guide outlines the essential CSS rules needed to prevent layout breakage and enable smooth horizontal scrolling, explains how the container interacts with Wavesurfer's rendering engine, and provides the exact code implementation required for seamless audio scrubbing.

Essential CSS Overflow Properties

To make a waveform scroll horizontally, the container element passed to the Wavesurfer.create({ container: ... }) option must constrain its layout and manage its content boundary. The primary required CSS rules are:

  • overflow-x: auto (or overflow-x: scroll): Enables horizontal scrolling when the rendered canvas width exceeds the container's rendered width.
  • overflow-y: hidden: Prevents vertical scrollbars or shifts caused by sub-pixel canvas rendering.
  • width: 100% (or a fixed max-width): Constrains the container to the visible viewport or parent element, preventing the wide waveform canvas from expanding the entire web page.
  • position: relative: Ensures that timeline plugins, hover overlays, and playheads render accurately relative to the waveform wrapper.
.waveform-container {
  width: 100%;
  max-width: 800px; /* Optional: limits visible width */
  overflow-x: auto;
  overflow-y: hidden;
  position: relative;
}

Why These Properties Are Necessary

Wavesurfer.js renders audio peaks inside an internal wrapper element using one or more HTML5 <canvas> elements. When zoomed in, the total width of this canvas is calculated dynamically based on the audio duration and the zoom level.

By default, an unconstrained block element allows overflowing content to push the boundaries of parent elements or spill outside its box model. Setting overflow-x: auto forces the browser to establish a scroll context specifically inside the target container, keeping the rest of the page layout intact while providing a native horizontal scrollbar.

Required Wavesurfer.js Configuration

CSS alone will not cause the waveform to scroll; the waveform canvas must be explicitly wider than its container. This is achieved by setting the minPxPerSec property during initialization or dynamically using the zoom method.

  • minPxPerSec: Defines the horizontal scale. Setting this to a value high enough (e.g., 50 to 200) ensures that long audio tracks generate a canvas significantly wider than the container element.
  • autoScroll: true: Automatically scrolls the container to follow the progress cursor during audio playback.
import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: document.querySelector('.waveform-container'),
  waveColor: '#4F46E5',
  progressColor: '#818CF8',
  minPxPerSec: 100, // Forces the waveform to stretch horizontally
  autoScroll: true,  // Keeps cursor in view during playback
  height: 128,
});

wavesurfer.load('path/to/audio.mp3');

If dynamic zoom controls are needed, call wavesurfer.zoom(pxPerSec) with the desired number of pixels per second. When the value generates a width larger than the .waveform-container, the overflow-x: auto rule will immediately activate the horizontal scrollbar.
