Docker Containers for Wavesurfer.js Waveforms

This article provides an overview of containerized waveform extraction pipelines designed to generate peak data for Wavesurfer.js frontends. Running these extraction utilities inside Docker containers standardizes the audio pre-processing pipeline, reduces server-side dependency conflicts, and offloads heavy client-side audio decoding. Below are the primary Docker containers, underlying tools, and integration methods used to generate Wavesurfer.js-compatible JSON or binary peak files.

The Standard Tool: BBC audiowaveform

The de facto standard for generating waveform data for Wavesurfer.js is audiowaveform, a C++ program developed by BBC R&D. Wavesurfer.js natively supports the JSON and binary formats produced by this utility.

Because compiling audiowaveform from source requires several dependencies (such as libsndfile, libmad, libid3tag, and boost), containerization is the preferred distribution method.

1. realies/audiowaveform

This is one of the most widely used community Docker images for audiowaveform. It packages the compiled CLI tool inside a minimal base image (usually Alpine or Ubuntu), providing a clean, single-command interface.

  • Typical Command:

    docker run --rm -v $(pwd):/data realies/audiowaveform \
  -i /data/track.mp3 \
  -o /data/track.json \
  --pixels-per-second 20 \
  --bits 8

  • Output: A JSON file containing an array of audio peak values and metadata (sample rate, channels, length) that can be passed directly to the backend: 'MediaElement' option in Wavesurfer.js via the peaks parameter.

2. Custom Alpine-Based audiowaveform Images

Many production pipelines use a custom, lightweight multi-stage Dockerfile using Alpine Linux. Because audiowaveform is available in standard package repositories or can be compiled statically:

FROM alpine:latest
RUN apk add --no-cache audiowaveform
ENTRYPOINT ["audiowaveform"]

This minimal container typically sits below 50 MB, making it ideal for ephemeral tasks in CI/CD, AWS ECS tasks, or Kubernetes Jobs.

FFmpeg-Based Docker Pipelines

When additional audio transformations (such as transcode, normalization, or downmixing) are required alongside peak extraction, standard FFmpeg containers are used.

jrottenberg/ffmpeg or linuxserver/ffmpeg

While FFmpeg does not produce the direct audiowaveform JSON format out of the box, it can extract downsampled raw PCM amplitude data using the astats or showwavespic filters, or dump raw audio to standard output for processing by lightweight scripts.

  • Pipeline Pattern: An FFmpeg container decodes the media to a 16-bit mono raw audio stream (-f s16le -ac 1) and pipes the stdout into a small Node.js, Go, or Python script that bins the samples and writes a JSON array of normalized floating-point numbers.

API Microservice Containers

For web backends requiring dynamic, on-demand waveform generation via HTTP, specialized microservice containers wrap extraction tools in web servers.

Containerized Node.js waveform-data Services

The BBC also maintains waveform-data.js. Several open-source Docker solutions run an Express or Fastify server packaging this library alongside FFmpeg:

  • Workflow: The host application sends an audio file via an HTTP POST request to the container.
  • Internal Processing: The container decodes the audio with FFmpeg and creates a WaveformData object.
  • Response: The microservice responds with a JSON payload or a .dat binary buffer structured for consumption by Wavesurfer.js.

Custom Python/FastAPI Microservices

Teams building larger media pipelines frequently use a container running Python (FastAPI or Flask) paired with librosa or scipy:

  • The container accepts audio uploads or S3 URLs.

  • The script reads the audio samples, calculates the root-mean-square (RMS) or peak amplitude per segment, normalizes the data between -1 and 1, and returns the values as a standard JSON list matching the format:

    [0.012, 0.345, 0.789, 0.456, 0.123, ...]

Configuration Tips for Wavesurfer.js Compatibility

When setting up any Docker container for this pipeline, match these flags to your frontend Wavesurfer.js configuration:

  • Resolution (--pixels-per-second or bin size): For standard responsive players, 10 to 50 samples per second of audio generally provides enough fidelity without bloating JSON file sizes.
  • Bit Depth (--bits): Set to 8 for smaller file sizes (values range from -128 to 127) or 16 for higher dynamic precision. Wavesurfer.js accepts both, provided the frontend decoding logic normalizes the peaks appropriately.
