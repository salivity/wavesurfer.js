How Custom Renderers Work in Wavesurfer.js

Modern releases of Wavesurfer.js (version 7 and later) introduced a completely rewritten, lightweight architecture that dramatically simplifies how audio waveforms are rendered to the screen. This article explains the underlying rendering pipeline in modern Wavesurfer.js, how the core engine processes audio peaks, and how developers can use the modern renderFunction API and custom canvas logic to build unique waveform visualizations.

The Modern Rendering Architecture (v7+)

In earlier versions of Wavesurfer.js, rendering relied on an abstraction called the Drawer and multiple layered canvas instances (MultiCanvas). This approach was heavy, difficult to extend, and caused performance bottlenecks on complex waveforms.

Starting with version 7, Wavesurfer.js transitioned to a streamlined TypeScript-first architecture. Rendering is now decoupled into two primary components:

  1. The Decoder / Audio Model: Decodes raw audio into an array of channel peaks (normalized min and max float values between -1 and 1).
  2. The Renderer Class: Manages the DOM wrapper, handles viewport sizing, accommodates device pixel ratios (Retina displays), manages scrolling and zoom levels, and supplies a standard HTML5 Canvas 2D rendering context.

Instead of requiring developers to subclass an internal drawing engine to change the waveform's appearance, modern Wavesurfer exposes a direct hook into the canvas drawing cycle via the renderFunction option.

Using the renderFunction Hook

The primary mechanism for custom rendering in modern Wavesurfer.js is the renderFunction configuration property. When provided during initialization, Wavesurfer delegates the visual layout of the waveform to this callback instead of its default bar-drawing routine.

The callback receives two arguments:

  • peaks: An array of arrays containing the audio channel data (e.g., peaks[0] represents channel 1 min/max points).
  • ctx: The 2D rendering context (CanvasRenderingContext2D) of the destination canvas.

Example Implementation

import WaveSurfer from 'wavesurfer.js'

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: 'violet',
  progressColor: 'purple',
  renderFunction: (peaks, ctx) => {
    const { width, height } = ctx.canvas
    const halfHeight = height / 2
    const channelData = peaks[0]
    const step = channelData.length / width

    ctx.fillStyle = '#4f46e5'
    ctx.beginPath()

    for (let i = 0; i < width; i++) {
      const index = Math.floor(i * step)
      const value = channelData[index] || 0
      const barHeight = value * halfHeight

      // Draw symmetrical bars centered vertically
      ctx.rect(i, halfHeight - barHeight, 1, barHeight * 2)
    }

    ctx.fill()
  },
})

wavesurfer.load('/path/to/audio.mp3')

How Wavesurfer Manages Context and Scaling

When writing a custom renderer, understanding the canvas lifecycle is critical:

  • DPR Scaling: Modern Wavesurfer automatically calculates window.devicePixelRatio and scales the canvas coordinate system before invoking your custom render function. This means coordinate (0, 0) is top-left and (width, height) matches CSS display pixels, ensuring sharp graphics without manual coordinate multiplication.
  • Canvas Clearing: Wavesurfer automatically clears the canvas before calling renderFunction. You do not need to call ctx.clearRect().
  • Progress Waves: Modern Wavesurfer maintains two layered canvases: the background waveform (waveColor) and the played waveform (progressColor), which is clipped dynamically according to the playback progress. The renderFunction is executed for both canvases to ensure visual consistency across both playback states.

Extending the Renderer Class for Low-Level Customization

For use cases that require an entirely different rendering paradigm—such as rendering through WebGL, SVG, or rendering custom DOM elements—you can extend or swap out the internal Renderer class.

Modern Wavesurfer exposes its internal classes directly:

import WaveSurfer from 'wavesurfer.js'
import Renderer from 'wavesurfer.js/dist/renderer.js'

class CustomRenderer extends Renderer {
  constructor(options) {
    super(options)
  }

  render(peaks) {
    // Override the default rendering cycle entirely
    super.render(peaks)
    // Custom post-processing or WebGL bindings
  }
}

By decoupling waveform data processing from drawing logic, modern Wavesurfer.js allows you to treat the waveform canvas as an open graphic pipeline, capable of rendering everything from traditional bars to rounded pill shapes, continuous curves, and frequency heatmaps.
