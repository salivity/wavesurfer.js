Handle Missing Audio 404 Errors in Wavesurfer.js

Handling HTTP 404 errors in Wavesurfer.js is essential for preventing broken interfaces and unhandled JavaScript promise rejections when an audio asset fails to load. This guide demonstrates how to listen for fetch and decoding errors using Wavesurfer's event listeners, implement user interface fallbacks, and properly clean up audio player instances when media files are missing.

Catching Errors with Event Listeners

Wavesurfer.js emits an error event whenever it fails to retrieve or decode an audio source. When a missing file triggers a 404 response, the internal fetch request fails, triggering this listener.

You should attach the error listener immediately after creating the Wavesurfer instance and before calling .load():

import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
});

// Listen for errors
wavesurfer.on('error', (error) => {
  console.error('Wavesurfer failed to load:', error);
  handleAudioError(error);
});

// Attempt to load the audio file
wavesurfer.load('/path/to/missing-audio.mp3');

Updating the UI Gracefully

When an error occurs, the waveform container remains empty, which can confuse users. To provide a smooth experience, replace the audio player container with an informative message and disable related playback controls.

function handleAudioError(error) {
  const container = document.querySelector('#waveform');
  const playButton = document.querySelector('#play-btn');

  // Disable playback controls
  if (playButton) {
    playButton.disabled = true;
    playButton.classList.add('disabled');
  }

  // Display user-friendly notification
  container.innerHTML = `
    <div class="audio-error-state">
      <p>Unable to load audio file. The file may have been moved or deleted.</p>
    </div>
  `;
}

Handling Promise Rejections in v7

In Wavesurfer.js version 7, .load() returns a Promise. This allows you to catch HTTP errors directly using standard asynchronous control flow in addition to the event listener:

async function loadAudioTrack(url) {
  try {
    await wavesurfer.load(url);
  } catch (error) {
    // Catches network errors, including 404s
    handleAudioError(error);
  }
}

loadAudioTrack('/path/to/missing-audio.mp3');

Pre-flight Verification with Fetch

If you need to inspect the HTTP status code directly to distinguish a 404 error from decoding errors, perform a fetch request before passing the data to Wavesurfer:

async function safeLoadAudio(url, wavesurferInstance) {
  try {
    const response = await fetch(url);

    if (response.status === 404) {
      throw new Error('Audio file not found (404)');
    }

    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }

    const audioBlob = await response.blob();
    await wavesurferInstance.loadBlob(audioBlob);
  } catch (error) {
    handleAudioError(error);
  }
}

Using fetch allows you to pinpoint the exact failure reason and prevent Wavesurfer from attempting to decode invalid response bodies, such as custom HTML 404 pages returned by web servers.
