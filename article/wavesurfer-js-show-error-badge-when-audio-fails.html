Wavesurfer.js: Show Error Badge When Audio Fails

When loading audio into Wavesurfer.js, network disruptions, missing files, or unsupported codecs can cause the decoding process to fail. Handling these failures gracefully requires catching the runtime error events emitted by the library and superimposing a visual error badge over the waveform container. This article explains how to configure a relative container layout, listen for the Wavesurfer.js error event, and dynamically render an accessible error badge directly over the broken waveform.

1. Set Up the Container Structure

To place a badge directly over the waveform, wrap the waveform container in a parent element set to relative positioning. This allows the error overlay to be positioned absolutely relative to the waveform's exact dimensions.

<div class="waveform-wrapper">
  <div id="waveform"></div>
  <div id="waveform-error" class="error-badge" role="alert" aria-hidden="true">
    <span>Audio failed to load</span>
  </div>
</div>

2. Style the Overlay Badge

The error badge should remain hidden by default and cover the waveform area once triggered. CSS absolute positioning ensures it sits directly on top of the canvas element generated by Wavesurfer.js.

.waveform-wrapper {
  position: relative;
  width: 100%;
  min-height: 128px;
  background-color: #f3f4f6;
  border-radius: 8px;
  overflow: hidden;
}

.error-badge {
  display: none;
  position: absolute;
  top: 0;
  left: 0;
  width: 100%;
  height: 100%;
  background: rgba(254, 242, 242, 0.9);
  color: #991b1b;
  font-family: sans-serif;
  font-size: 14px;
  font-weight: 600;
  align-items: center;
  justify-content: center;
  gap: 8px;
  border: 1px solid #f87171;
  border-radius: 8px;
  z-index: 10;
}

.error-badge.visible {
  display: flex;
}

3. Handle Errors in Wavesurfer.js

Wavesurfer.js emits an error event whenever fetching the audio fails or the browser's Web Audio API cannot decode the file. Attach a listener to this event during initialization to reveal the badge and update its contents with the relevant failure message.

import WaveSurfer from 'wavesurfer.js';

const errorBadge = document.getElementById('waveform-error');

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: 'https://example.com/audio-file-that-does-not-exist.mp3',
});

// Listen for loading or decoding errors
wavesurfer.on('error', (error) => {
  displayWaveformError(error);
});

function displayWaveformError(error) {
  if (!errorBadge) return;

  // Update badge visibility and accessibility attributes
  errorBadge.classList.add('visible');
  errorBadge.setAttribute('aria-hidden', 'false');

  // Provide user-friendly feedback
  errorBadge.innerHTML = `
    <svg width="18" height="18" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2">
      <circle cx="12" cy="12" r="10"></circle>
      <line x1="12" y1="8" x2="12" y2="12"></line>
      <line x1="12" y1="16" x2="12.01" y2="16"></line>
    </svg>
    <span>Failed to load audio: ${error.message || 'Media source error'}</span>
  `;
}

4. Resetting State on Dynamic Reloads

If the application supports switching tracks or retrying failed audio sources, reset the badge prior to loading a new source:

function loadNewTrack(url) {
  // Hide error state before attempting to load
  errorBadge.classList.remove('visible');
  errorBadge.setAttribute('aria-hidden', 'true');

  wavesurfer.load(url);
}

This decoupled approach ensures that users receive immediate visual feedback whenever an audio stream is unreachable, while maintaining layout stability across varying playback states.
