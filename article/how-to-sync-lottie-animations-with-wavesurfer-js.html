How to Sync Lottie Animations with Wavesurfer.js

Integrating Lottie animations with Wavesurfer.js allows you to build engaging, audio-reactive interfaces by driving vector animations directly from audio playback events. This guide covers how to set up both libraries, wire Wavesurfer playback lifecycle events to Lottie controls, and achieve frame-accurate animation synchronization based on the audio track's current time.

Core Architecture

The synchronization relies on two main components: an audio decoder/player (Wavesurfer.js) and a vector animation renderer (lottie-web). To ensure the animation matches the audio precisely, Lottie should not run on its own internal clock. Instead, its playback should be manually scrubbed using Lottie’s goToAndStop() method, mapped directly to Wavesurfer's playback timeline.

Step 1: Initializing the Instances

First, instantiate both the Wavesurfer player and the Lottie animation. Ensure that Lottie’s autoplay setting is set to false so it remains paused until driven by Wavesurfer.

import WaveSurfer from 'wavesurfer.js';
import lottie from 'lottie-web';

// Initialize Wavesurfer
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: '/path/to/audio.mp3',
});

// Initialize Lottie
const lottieContainer = document.getElementById('lottie-player');
const animation = lottie.loadAnimation({
  container: lottieContainer,
  renderer: 'svg',
  loop: false,
  autoplay: false,
  path: '/path/to/animation.json',
});

Step 2: Mapping Audio Progress to Animation Frames

To map the timeline accurately, determine the total number of frames in the Lottie file and update the frame position whenever the audio time updates.

The formula to calculate the current frame is:

\[\text{Current Frame} = \left(\frac{\text{Current Time}}{\text{Total Duration}}\right) \times \text{Total Animation Frames}\]

Listen to the timeupdate (or audioprocess in older versions) and seeking events provided by Wavesurfer:

animation.addEventListener('DOMLoaded', () => {
  const totalFrames = animation.totalFrames;

  const syncAnimation = () => {
    const duration = wavesurfer.getDuration();
    if (!duration) return;

    const currentTime = wavesurfer.getCurrentTime();
    const progress = currentTime / duration;
    const targetFrame = progress * totalFrames;

    // Set the animation to the mapped frame (second argument set to true indicates frames, not time)
    animation.goToAndStop(targetFrame, true);
  };

  // Sync continuously during playback
  wavesurfer.on('timeupdate', syncAnimation);

  // Sync when user scrubs or clicks on the waveform
  wavesurfer.on('seeking', syncAnimation);
});

Step 3: Handling Playback State Changes

If your animation contains continuous background motion rather than fixed scrubbing, you can alternate between playing and pausing the animation using state listeners:

wavesurfer.on('play', () => {
  animation.play();
});

wavesurfer.on('pause', () => {
  animation.pause();
});

wavesurfer.on('finish', () => {
  animation.stop();
});

Performance Optimization

When scrubbing high-complexity animations via the timeupdate event, frequent DOM re-renders can cause performance bottlenecks. Wrap the frame updates in requestAnimationFrame to ensure updates occur only as fast as the display can refresh:

let animationFrameId = null;

wavesurfer.on('timeupdate', () => {
  if (animationFrameId) return;

  animationFrameId = requestAnimationFrame(() => {
    const duration = wavesurfer.getDuration();
    if (duration > 0) {
      const currentFrame = (wavesurfer.getCurrentTime() / duration) * animation.totalFrames;
      animation.goToAndStop(currentFrame, true);
    }
    animationFrameId = null;
  });
});

Using this decoupled render pattern guarantees that the visual animation stays locked to the waveform cursor without overloading the main browser thread.
