Configure CSP worker-src for Wavesurfer.js

This guide explains how to properly configure the Content Security Policy (CSP) worker-src directive to allow Wavesurfer.js to run without security violations. You will learn why Wavesurfer.js triggers CSP errors, the exact directives required to resolve them, and how to implement the policy via HTTP headers or HTML meta tags.

Why Wavesurfer.js Triggers CSP Violations

Wavesurfer.js relies on Web Workers to process and render audio waveforms asynchronously without freezing the user interface. By default, Wavesurfer.js and its related plugins often construct these workers on the fly using inline Blob objects generated via URL.createObjectURL().

When a strict CSP is present, modern browsers block these inline background threads unless the blob: scheme is explicitly permitted. Without this permission, the browser console will display an error similar to:

Refused to create a worker from 'blob:https://example.com/...' because it violates the following Content Security Policy directive: "worker-src 'self'".

The Required worker-src Configuration

To permit Wavesurfer.js to instantiate its background threads, you must add the blob: source expression to your worker-src directive alongside 'self'.

worker-src 'self' blob:;

If your application hosts the Wavesurfer script or dedicated worker files on an external Content Delivery Network (CDN), include the CDN host as well:

worker-src 'self' blob: https://cdnjs.cloudflare.com;

Implementation Methods

Depending on your web server stack, implement the updated CSP using one of the following methods.

1. HTTP Response Header (Recommended)

Configuring CSP through your web server or application framework provides the most robust security.

Nginx Configuration:

add_header Content-Security-Policy "default-src 'self'; worker-src 'self' blob:; media-src 'self' blob:; connect-src 'self';";

Apache Configuration:

Header set Content-Security-Policy "default-src 'self'; worker-src 'self' blob:; media-src 'self' blob:; connect-src 'self';"

Node.js (Express with Helmet):

app.use(
  helmet.contentSecurityPolicy({
    directives: {
      defaultSrc: ["'self'"],
      workerSrc: ["'self'", "blob:"],
      mediaSrc: ["'self'", "blob:"],
      connectSrc: ["'self'"],
    },
  })
);

2. HTML Meta Tag

If you cannot modify server headers, insert the policy directly into the <head> of your HTML document:

<meta 
  http-equiv="Content-Security-Policy" 
  content="default-src 'self'; worker-src 'self' blob:; media-src 'self' blob:;"
>

Supporting Legacy Browsers with child-src

The worker-src directive is defined in CSP Level 3. Older browsers (such as older versions of Safari or Chrome) look to the child-src or script-src directives to govern Web Workers.

To ensure complete cross-browser compatibility, define child-src identically to worker-src:

Content-Security-Policy: worker-src 'self' blob:; child-src 'self' blob:;

Modern browsers that support worker-src will ignore child-src for workers, while older browsers will fall back to child-src and allow the audio rendering thread to execute.
