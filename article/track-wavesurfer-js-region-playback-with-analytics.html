Track Wavesurfer.js Region Playback with Analytics

Tracking user engagement with specific audio segments provides critical insights into which portions of your media capture the most attention. This article demonstrates how to detect playback across defined timestamps using the Wavesurfer.js Regions plugin and trigger analytics events to platforms like Google Analytics, Mixpanel, or a custom backend. You will learn the setup process, the specific event listeners required, and how to prevent duplicate event firing during audio scrubbing or looping.

1. Set Up Wavesurfer.js with the Regions Plugin

To monitor specific audio sections, you must register the RegionsPlugin with your Wavesurfer instance and define regions using unique identifiers and custom metadata.

import WaveSurfer from 'wavesurfer.js';
import RegionsPlugin from 'wavesurfer.js/dist/plugins/regions.esm.js';

// Initialize WaveSurfer
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: '/path/to/audio.mp3',
});

// Initialize and register the Regions plugin
const wsRegions = wavesurfer.registerPlugin(RegionsPlugin.create());

// Add designated tracking regions once audio loads
wavesurfer.on('ready', () => {
  wsRegions.addRegion({
    id: 'chorus_segment',
    start: 30,
    end: 45,
    color: 'rgba(0, 255, 0, 0.1)',
    data: {
      title: 'Main Chorus',
      category: 'Key Moments',
    },
  });
});

2. Capture Region Entry Events

The Regions plugin emits a region-in event the moment the playback head enters a region boundary. This event passes the target region object, allowing you to extract its ID, start and end times, and custom data attributes.

wsRegions.on('region-in', (region) => {
  logRegionPlayback(region, 'started');
});

wsRegions.on('region-out', (region) => {
  logRegionPlayback(region, 'completed');
});

3. Send Payload to Your Analytics Provider

Create a centralized logging function to format the data and transmit it to your analytics service (e.g., Google Analytics 4, Mixpanel, or an internal API endpoint).

function logRegionPlayback(region, status) {
  const payload = {
    event: 'audio_region_playback',
    region_id: region.id,
    region_title: region.data?.title || 'Unknown',
    start_time: region.start,
    end_time: region.end,
    action: status,
  };

  // Example: Google Analytics 4 (gtag)
  if (typeof gtag === 'function') {
    gtag('event', 'audio_region_playback', payload);
  }

  // Example: Custom Analytics API
  fetch('/api/analytics/audio', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(payload),
  }).catch((err) => console.error('Failed to log analytics:', err));
}

4. Prevent Duplicate Logging

Audio scrubbing, seeking, or rapid pausing can trigger region-in repeatedly. To ensure accurate metrics, implement a deduplication check that verifies the audio is actively playing and restricts firing to once per complete playback pass.

const playedRegions = new Set();

wsRegions.on('region-in', (region) => {
  // Only log if audio is actively playing and hasn't been logged this cycle
  if (wavesurfer.isPlaying() && !playedRegions.has(region.id)) {
    logRegionPlayback(region, 'started');
    playedRegions.add(region.id);
  }
});

// Reset tracked regions when the track restarts or finishes
wavesurfer.on('finish', () => {
  playedRegions.clear();
});

wavesurfer.on('seek', () => {
  // Optional: clear state on manual seek if you want re-triggers
  playedRegions.clear();
});
