How to Use Pre-Decoded Peak Data in Wavesurfer.js

Pre-decoded peak data allows web applications to render audio waveforms instantly without requiring the browser to download and decode the full audio file. This article explains what pre-decoded peak data is, why it is essential for web performance, and the exact steps to generate and pass this data into Wavesurfer.js for fast waveform rendering.

What is Pre-Decoded Peak Data?

By default, Wavesurfer.js fetches an entire audio file and decodes it using the browser's Web Audio API (AudioContext.decodeAudioData). It then analyzes the uncompressed audio buffer to extract the minimum and maximum amplitude values across set time intervals to draw the waveform. For long files or low-power mobile devices, this decoding step consumes significant CPU, memory, and time.

Pre-decoded peak data is a pre-calculated array of numbers representing the minimum and maximum volume peaks of an audio file. By extracting these values ahead of time on a server or build step, you can send a lightweight JSON array (often just a few kilobytes) directly to the client. This allows Wavesurfer.js to skip the decoding process and draw the canvas immediately.

Formats for Peak Data

Peak data in Wavesurfer.js typically takes one of two structures:

  1. Merged/Single Channel Array: A single array of normalized floating-point numbers (between -1 and 1) or integer values representing alternate min/max amplitudes or absolute peaks.
  2. Multi-Channel Array: An array of arrays, where each sub-array represents a distinct audio channel containing paired values (e.g., [[min1, max1, min2, max2], ...]).

Pre-computed peaks are commonly generated on the server using command-line tools like BBC's audiowaveform utility or ffmpeg.

Passing Peak Data into Wavesurfer.js

In Wavesurfer.js (v7+), pre-decoded peaks can be passed directly during initialization or dynamically loaded with the audio source.

Method 1: Passing Peaks During Initialization

If you already have the peaks and audio source ready, pass both the url and peaks properties directly to WaveSurfer.create():

import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F46E5',
  progressColor: '#818CF8',
  url: '/audio/track.mp3',
  peaks: [
    [0.01, -0.02, 0.45, -0.42, 0.88, -0.85, 0.22, -0.19]
  ],
  duration: 180 // Explicit duration in seconds prevents layout shifts
});

Method 2: Supplying Peaks via the load() Method

If you fetch peak data asynchronously from an API before or alongside loading the track, pass the peaks and duration as arguments to the load method:

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#10B981',
  progressColor: '#059669',
});

async function loadTrackWithPeaks() {
  // Fetch pre-computed peaks from your API or JSON file
  const response = await fetch('/api/peaks/track-123.json');
  const data = await response.json(); 

  // data.peaks contains the array of peak values
  // data.duration contains the audio length in seconds
  wavesurfer.load('/audio/track-123.mp3', data.peaks, data.duration);
}

loadTrackWithPeaks();

Best Practices

  • Always Include Duration: When providing pre-decoded peaks, always specify the duration parameter. Without it, Wavesurfer.js cannot calculate playback positions or render the progress timeline correctly until the audio file metadata finishes loading.
  • Normalize Peak Values: Ensure peaks are normalized consistently (typically within the range of -1 to 1 for floating-point arrays). Out-of-bounds numbers can cause visual clipping or distorted waveform heights.
  • Match Resolution to Width: Generating roughly 800 to 1600 peak points per audio track provides enough visual fidelity for standard responsive web layouts without inflating payload sizes.
