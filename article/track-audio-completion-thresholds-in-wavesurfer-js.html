Track Audio Completion Thresholds in Wavesurfer.js

Measuring audio completion metrics—specifically quartile milestones at 25%, 50%, 75%, and 100%—is critical for understanding listener retention and reporting accurate media analytics. This guide demonstrates how to calculate these playback thresholds in Wavesurfer.js using core events, manage trigger states to prevent duplicate analytics calls, and handle edge cases like scrubbing and track resets.

Understanding the Tracking Strategy

Audio players fire continuous playback events, often multiple times per second. To accurately track milestone percentages without spamming your analytics provider (such as Google Analytics, Segment, or a custom backend), you need to:

  1. Obtain the total duration once the audio decodes.
  2. Monitor playback progress via the timeupdate event.
  3. Calculate the current completion percentage.
  4. Flag reached milestones in an internal state object so each milestone fires only once per continuous listen.

Implementation

The following implementation is compatible with modern Wavesurfer.js (version 7+).

import WaveSurfer from 'wavesurfer.js';

// 1. Initialize Wavesurfer
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#violet',
  progressColor: '#purple',
  url: '/path/to/audio.mp3',
});

// 2. Define milestone states
const milestones = {
  25: false,
  50: false,
  75: false,
  100: false,
};

// Helper function to dispatch analytics
function trackMilestone(percentage) {
  console.log(`Audio reached ${percentage}% completion`);
  // Example: analytics.track('Audio Quartile Reached', { quartile: percentage });
}

// 3. Listen for time updates during playback
wavesurfer.on('timeupdate', (currentTime) => {
  const duration = wavesurfer.getDuration();
  if (!duration) return;

  const currentPercent = (currentTime / duration) * 100;

  // Check thresholds sequentially
  [25, 50, 75].forEach((threshold) => {
    if (currentPercent >= threshold && !milestones[threshold]) {
      milestones[threshold] = true;
      trackMilestone(threshold);
    }
  });
});

// 4. Capture the 100% threshold using the 'finish' event
wavesurfer.on('finish', () => {
  if (!milestones[100]) {
    milestones[100] = true;
    trackMilestone(100);
  }
});

Handling Seeking and Resets

Listeners frequently scrub backward or replay tracks. Depending on your analytics requirements, you may want to reset thresholds when a user seeks backward or restarts the audio.

To reset thresholds when the track is replayed from the beginning:

// Reset thresholds if user seeks back to the start or a new track loads
wavesurfer.on('seeking', (currentTime) => {
  // If the user seeks back before the 25% mark, reset milestones for re-evaluation
  const duration = wavesurfer.getDuration();
  const currentPercent = (currentTime / duration) * 100;

  Object.keys(milestones).forEach((key) => {
    const threshold = Number(key);
    if (currentPercent < threshold) {
      milestones[threshold] = false;
    }
  });
});

Using the timeupdate event combined with a threshold cache guarantees accurate quartile reporting while preventing redundant network requests.
