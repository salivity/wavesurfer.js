Configure FFT Size in Wavesurfer Spectrogram

Configuring the Fast Fourier Transform (FFT) size in the Wavesurfer.js spectrogram plugin controls the balance between time resolution and frequency resolution in your audio visualization. This guide demonstrates how to set the FFT size using the plugin's configuration options, provides a complete implementation example, and explains how different values affect the output.

The fftSamples Property

In Wavesurfer.js, the FFT size is defined using the fftSamples option within the spectrogram plugin configuration. Although standard Web Audio API nodes refer to this parameter as fftSize, the Wavesurfer.js spectrogram plugin maps this setting to fftSamples.

The value must be a power of two (such as 256, 512, 1024, 2048, or 4096). The default value is typically 512.

Implementation Example

To set the FFT size, pass fftSamples inside the options object when initializing the spectrogram plugin:

import WaveSurfer from 'wavesurfer.js';
import Spectrogram from 'wavesurfer.js/dist/plugins/spectrogram.esm.js';

// Initialize Wavesurfer with the Spectrogram plugin
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: '/path/to/audio.mp3',
  plugins: [
    Spectrogram.create({
      container: '#spectrogram',
      fftSamples: 1024, // Configures the FFT size
      labels: true,
      splitChannels: false
    })
  ]
});

If you are using an older version of Wavesurfer.js via a script tag, the structure remains the same within the plugin registration:

WaveSurfer.spectrogram.create({
  container: '#spectrogram',
  fftSamples: 1024
});

Choosing the Right FFT Size

Adjusting fftSamples alters the trade-off between time precision and frequency precision:

  • Smaller Values (256 or 512): Provide higher time resolution but lower frequency resolution. Fast transients, drum hits, and rapid speech changes are sharper along the horizontal time axis, but individual frequency pitches appear blurred vertically. Lower values also reduce CPU usage.
  • Standard Value (1024): Offers a balanced trade-off suitable for most music and speech analysis tasks.
  • Larger Values (2048 or 4096): Provide high frequency resolution at the expense of time resolution. Narrow frequency bands and harmonics are distinct and sharp, but transient events are smeared horizontally across time. Higher values require more processing power during rendering.
