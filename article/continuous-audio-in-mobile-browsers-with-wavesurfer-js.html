Continuous Audio in Mobile Browsers with Wavesurfer.js

Enabling continuous, uninterrupted audio playback on mobile browsers using Wavesurfer.js presents unique challenges due to strict mobile operating system policies regarding autoplay, resource management, and background media. Mobile browsers like iOS Safari and Android Chrome routinely suspend the Web Audio API when a user locks their screen or switches tabs. This guide provides a straightforward method to configure Wavesurfer.js for continuous mobile playback by utilizing the HTML5 media element backend, handling user-gesture requirements, and integrating the Media Session API.

1. Switch to the MediaElement Backend

By default, Wavesurfer.js often relies on the Web Audio API (backend: 'WebAudio'). Mobile devices aggressively suspend Web Audio contexts to save battery as soon as the browser loses focus or the screen turns off.

To bypass this restriction, configure Wavesurfer to use the native HTML5 <audio> element backend. Mobile operating systems allow continuous background streaming through native audio elements:

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  backend: 'MediaElement', // Crucial for mobile background playback
});

2. Unlock Audio with a Single User Gesture

Mobile browsers forbid unprompted audio playback. Audio must be initiated by an explicit user gesture (such as a click or touchend event). Once unlocked, you can load subsequent tracks programmatically without re-triggering restrictions, provided you reuse the same media instance.

const playButton = document.getElementById('play-btn');

playButton.addEventListener('click', () => {
  if (!wavesurfer.isPlaying()) {
    wavesurfer.play();
  } else {
    wavesurfer.pause();
  }
});

3. Handle Playlist Transitions Seamlessly

To achieve continuous playback across multiple tracks, listen for the finish event and load the next track immediately into the existing player pipeline. Reusing the underlying media element keeps the browser's playback permissions active.

const playlist = ['track1.mp3', 'track2.mp3', 'track3.mp3'];
let currentTrackIndex = 0;

wavesurfer.on('finish', () => {
  currentTrackIndex++;
  
  if (currentTrackIndex < playlist.length) {
    // Load and play the next track immediately within the active session
    wavesurfer.load(playlist[currentTrackIndex]);
    wavesurfer.once('ready', () => {
      wavesurfer.play();
    });
  }
});

4. Implement the Media Session API

The Media Session API informs the mobile operating system that an active playback session is running. This enables lock-screen controls, prevents the operating system from terminating the browser audio thread, and supports continuous playback even when the display is off.

function updateMediaSession(trackTitle, artistName) {
  if ('mediaSession' in navigator) {
    navigator.mediaSession.metadata = new MediaMetadata({
      title: trackTitle,
      artist: artistName,
    });

    navigator.mediaSession.setActionHandler('play', () => wavesurfer.play());
    navigator.mediaSession.setActionHandler('pause', () => wavesurfer.pause());
    navigator.mediaSession.setActionHandler('nexttrack', () => playNextTrack());
    navigator.mediaSession.setActionHandler('previoustrack', () => playPreviousTrack());
  }
}

wavesurfer.on('play', () => {
  updateMediaSession('Current Track Title', 'Artist Name');
});

Summary of Requirements

  • Always use backend: 'MediaElement': Avoid pure Web Audio on mobile if background or continuous playback is needed.
  • Initialize via user touch: Ensure the initial play call originates from a real user interaction.
  • Maintain the audio context: Chain sequential tracks via the finish event instead of destroying and recreating the Wavesurfer instance.
  • Sync with navigator.mediaSession: Keep the native OS media service active to prevent background throttling.
