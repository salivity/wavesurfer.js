Disconnecting Web Audio Nodes in Wavesurfer.js

Integrating custom Web Audio API nodes with Wavesurfer.js allows for advanced audio processing such as equalization, dynamic compression, and custom routing. However, calling wavesurfer.destroy() does not automatically sever the connections between custom nodes or release them from the underlying AudioContext, which can cause memory leaks and lingering audio artifacts. This article details the exact steps required to cleanly disconnect Web Audio nodes and release system resources when destroying a Wavesurfer instance.

The Problem with Default Destruction

When you create a custom audio pipeline using nodes like BiquadFilterNode, GainNode, or AnalyserNode and connect them to the Wavesurfer backend or its internal HTMLMediaElement, these nodes remain registered within the active AudioContext. Calling wavesurfer.destroy() disposes of Wavesurfer’s internal event listeners, renderer, and canvas elements, but your custom nodes may stay chained together in memory if they still hold references or remain connected to an active AudioDestinationNode.

Step 1: Retain Node References

To disconnect nodes manually, keep track of every node you instantiate and connect. Store them in an array or an accessible object rather than relying on anonymous references inside initialization blocks.

const audioContext = new (window.AudioContext || window.webkitAudioContext)();
const filterNode = audioContext.createBiquadFilter();
const gainNode = audioContext.createGain();

const customNodes = [filterNode, gainNode];

Step 2: Hook into the Destruction Lifecycle

You can ensure your cleanup logic runs at the correct moment by listening to Wavesurfer's built-in destroy event, or by wrapping the destruction call within a dedicated cleanup function.

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: 'violet',
  progressColor: 'purple',
  audioContext: audioContext
});

// Hook into the destroy event
wavesurfer.on('destroy', () => {
  cleanupAudioNodes(customNodes);
});

Step 3: Implement Clean Disconnection

Iterate through your custom nodes and call the native disconnect() method on each one. Calling node.disconnect() with no arguments severs all outgoing connections from that node, preventing them from feeding audio downstream.

function cleanupAudioNodes(nodes) {
  nodes.forEach(node => {
    if (node && typeof node.disconnect === 'function') {
      try {
        node.disconnect();
      } catch (error) {
        console.warn('Error disconnecting node:', error);
      }
    }
  });

  // Empty the array to remove references
  nodes.length = 0;
}

Step 4: Handle the AudioContext and Media Element

If you passed a custom AudioContext to Wavesurfer that will not be reused by other components on the page, close or suspend it to free underlying hardware channels. Additionally, if you attached a MediaElementAudioSourceNode to an existing HTML5 audio element, ensure that source node is disconnected as well.

function destroyWavesurferCleanly(wavesurfer, customNodes, audioContext) {
  // 1. Destroy the Wavesurfer instance (triggers 'destroy' events)
  if (wavesurfer) {
    wavesurfer.destroy();
  }

  // 2. Disconnect custom audio nodes
  cleanupAudioNodes(customNodes);

  // 3. Close the AudioContext if it is no longer needed
  if (audioContext && audioContext.state !== 'closed') {
    audioContext.close();
  }

  // 4. Nullify variables to allow garbage collection
  wavesurfer = null;
  audioContext = null;
}

Following this pattern ensures that audio routing chains are fully dismantled, native browser threads stop processing inactive audio buffers, and memory is promptly reclaimed by the garbage collector.
