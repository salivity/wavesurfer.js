Load a Blob or File Directly into Wavesurfer.js

This guide explains how to render audio waveforms from local Blob or File objects directly in Wavesurfer.js without uploading the files to a remote server. By using native browser APIs like URL.createObjectURL() or the built-in loader methods, you can quickly pass client-side audio data straight into your Wavesurfer instance for immediate playback and visualization.

Method 1: Using URL.createObjectURL() (Recommended)

The most reliable and standard method across modern versions of Wavesurfer.js (including version 7+) is to convert your File or Blob into a temporary DOMString URL using URL.createObjectURL().

import WaveSurfer from 'wavesurfer.js';

// 1. Initialize Wavesurfer
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
});

// 2. Handle a File input or Blob object
const fileInput = document.querySelector('input[type="file"]');

fileInput.addEventListener('change', (event) => {
  const file = event.target.files[0];

  if (file) {
    // Generate a temporary local URL for the Blob/File
    const audioUrl = URL.createObjectURL(file);

    // Load the URL directly into Wavesurfer
    wavesurfer.load(audioUrl);

    // Free memory when the audio is loaded or component unmounts
    wavesurfer.on('ready', () => {
      URL.revokeObjectURL(audioUrl);
    });
  }
});

Method 2: Using the loadBlob Method (Legacy / v6)

If you are using Wavesurfer.js version 6 or older, the library provides a direct loadBlob method that handles the Blob or File object natively without manually generating an object URL.

const fileInput = document.querySelector('input[type="file"]');

fileInput.addEventListener('change', (event) => {
  const file = event.target.files[0];

  if (file) {
    // Directly pass the File or Blob instance
    wavesurfer.loadBlob(file);
  }
});

Key Considerations

  • Memory Management: When using URL.createObjectURL(), always call URL.revokeObjectURL(url) once the waveform has finished decoding (via the ready or decode event) to prevent memory leaks in single-page applications.
  • Audio Types: Ensure the Blob or File object represents a valid audio MIME type (such as audio/mp3, audio/wav, or audio/ogg) supported by the user's browser HTML5 audio element or Web Audio API.
