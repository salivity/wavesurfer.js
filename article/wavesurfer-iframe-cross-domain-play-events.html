Wavesurfer Iframe Cross-Domain Play Events

Cross-domain communication between an embedded Wavesurfer.js instance inside an iframe and its host page relies on the HTML5 postMessage API. Because the browser's Same-Origin Policy prevents host windows and embedded child frames from accessing each other's DOM or JavaScript contexts directly across different domains, postMessage acts as a secure data bridge. This article explains how to capture audio playback events within Wavesurfer.js, serialize them into messages, transmit them across origins, and handle them inside the parent window.

The Mechanism: The window.postMessage API

When Wavesurfer.js runs on domain-a.com inside an iframe and the parent application runs on domain-b.com, direct function calls between the two windows are blocked by the browser. The window.postMessage() method allows one window to dispatch a message event to another window regardless of origin, while providing built-in verification mechanisms to ensure communication remains secure.

Sending Play Events from the Iframe

Inside the iframe containing Wavesurfer.js, you attach an event listener to the Wavesurfer instance using its native event system. When a user triggers playback, Wavesurfer emits a play event. The iframe script catches this event and invokes window.parent.postMessage() to pass the state up to the host container.

// Inside the iframe (child window)
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: '/audio-track.mp3'
});

// Listen to Wavesurfer's play event
wavesurfer.on('play', () => {
  const payload = {
    type: 'WAVESURFER_PLAY',
    currentTime: wavesurfer.getCurrentTime(),
    duration: wavesurfer.getDuration()
  };

  // Replace 'https://host-domain.com' with the parent's actual origin for security
  window.parent.postMessage(payload, 'https://host-domain.com');
});

// Optionally notify on pause
wavesurfer.on('pause', () => {
  window.parent.postMessage({ type: 'WAVESURFER_PAUSE' }, 'https://host-domain.com');
});

Receiving and Processing Events in the Host Page

The host window registers a global listener for the message event. To prevent Cross-Site Scripting (XSS) and unauthorized data ingestion, the host must first verify the origin property of the incoming event against the allowed domain of the iframe.

// Inside the host page (parent window)
window.addEventListener('message', (event) => {
  // 1. Verify the sender origin
  if (event.origin !== 'https://iframe-domain.com') {
    return;
  }

  // 2. Parse and handle the specific event
  const { type, currentTime, duration } = event.data;

  switch (type) {
    case 'WAVESURFER_PLAY':
      console.log(`Audio started playing at ${currentTime}s of ${duration}s`);
      // Perform host actions, such as pausing other media players or updating external UI
      break;

    case 'WAVESURFER_PAUSE':
      console.log('Audio playback paused');
      break;
  }
});

Bidirectional Control: Controlling Wavesurfer from the Host

Cross-domain messaging also works in reverse. If the parent page needs to control playback inside the iframe (for instance, a master "Pause All" button), the host dispatches a message to the iframe's contentWindow:

  1. Host sends command:

    const iframe = document.getElementById('wavesurfer-frame');
iframe.contentWindow.postMessage({ action: 'PAUSE' }, 'https://iframe-domain.com');

  2. Iframe receives and executes:

    window.addEventListener('message', (event) => {
  if (event.origin !== 'https://host-domain.com') return;

  if (event.data.action === 'PAUSE') {
    wavesurfer.pause();
  } else if (event.data.action === 'PLAY') {
    wavesurfer.play();
  }
});

Security Considerations

  • Avoid Wildcard Origins: Always supply a specific target origin (such as 'https://example.com') instead of '*' in the second parameter of postMessage. This ensures sensitive playback metadata is not broadcast to unintended domains.
  • Validate Sender Origins: The listener must always check event.origin before executing any state changes or DOM updates based on event.data.
  • Sanitize Payloads: Ensure any dynamic parameters passed through the message payload are validated prior to execution in the receiving window.
