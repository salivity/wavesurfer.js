Web Audio Time Stretching in Wavesurfer.js

This article explains how to configure Web Audio nodes to achieve pitch-preserving time stretching in Wavesurfer.js. While the native Web Audio API alters both pitch and speed when modifying playback rates, integrating a MediaElementAudioSourceNode with HTML5 media properties or inserting an AudioWorkletNode running a time-domain pitch-synchronous overlap-add (TD-PSOLA) algorithm allows tempo adjustments independent of pitch.

The Limitation of Native Web Audio Nodes

By default, the Web Audio API's AudioBufferSourceNode handles playback rate changes by resampling the audio buffer. Increasing the playbackRate causes the familiar "chipmunk" pitch-shift effect, while lowering it drops the pitch. There is no native built-in DSP node in standard Web Audio specifications dedicated strictly to independent time-scale modification.

Configuration 1: The MediaElementAudioSourceNode Approach

The most reliable, browser-optimized configuration for Wavesurfer.js relies on routing an HTML5 <audio> element through Web Audio. Modern browsers include native, hardware-accelerated time stretching within the media element engine.

  1. Backend Initialization: Initialize Wavesurfer.js using the MediaElement backend instead of the default Web Audio buffer:

    const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  backend: 'MediaElement',
  // additional settings
});

  2. Web Audio Node Chain: When Wavesurfer or your custom configuration connects the media element to an AudioContext, it uses a MediaElementAudioSourceNode:

    HTMLMediaElement \(\rightarrow\) MediaElementAudioSourceNode \(\rightarrow\) [Optional Effects / Analyser Nodes] \(\rightarrow\) AudioDestinationNode

  3. Enabling Pitch Preservation: Access the underlying HTML5 media element from Wavesurfer.js and ensure pitch preservation is enabled:

    const mediaElement = wavesurfer.getMediaElement();
mediaElement.preservesPitch = true;

When calling wavesurfer.setPlaybackRate(speed), the media element updates its internal playbackRate while maintaining the root pitch using the browser's internal time-stretching algorithm.

Configuration 2: AudioWorkletNode with Custom DSP

If your application requires raw AudioBuffer manipulation without an HTML5 <audio> element, you must place an AudioWorkletNode running a phase vocoder or WSOLA (Waveform Similarity Overlap-Add) algorithm into the node graph.

  1. Node Chain Setup: AudioBufferSourceNode \(\rightarrow\) AudioWorkletNode (Time Stretch Processor) \(\rightarrow\) AudioDestinationNode

  2. Processor Implementation: The AudioWorkletProcessor receives audio frames in real-time from the buffer, computes overlapping windows via algorithms like SoundTouch (WSOLA), and outputs time-stretched audio chunks to the destination without changing the pitch.

For most production deployments of Wavesurfer.js, the MediaElementAudioSourceNode method is preferred because it requires minimal CPU overhead and avoids the complexity of loading custom DSP worklet modules.
