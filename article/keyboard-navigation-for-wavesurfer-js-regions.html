Keyboard Navigation for Wavesurfer.js Regions

Wavesurfer.js is a popular library for interactive audio visualization, but its regions plugin is primarily designed around mouse and touch interactions by default. To make regions accessible to keyboard users, developers must explicitly implement focus management, ARIA attributes, and keyboard event listeners. This article explains how to make waveform regions focusable, cycle between them using standard navigation keys, and trigger playback using the keyboard.

Making Regions Focusable

By default, the DOM elements generated by the Wavesurfer.js Regions Plugin do not receive keyboard focus. To allow users to navigate to a region using the Tab key, you must assign a tabindex to each region's DOM element upon creation.

When listening to the region-created event, update the underlying element:

wsRegions.on('region-created', (region) => {
  const element = region.element;
  element.setAttribute('tabindex', '0');
  element.setAttribute('role', 'region');
  element.setAttribute('aria-label', region.id || 'Audio Region');
});

Setting tabindex="0" inserts the region into the standard browser tab sequence, allowing keyboard users to reach it naturally.

Implementing Keyboard Listeners for Navigation

While the Tab key handles basic sequential navigation, standard accessibility patterns often use the arrow keys to cycle between related UI elements. You can listen for keydown events globally or on the container wrapper to switch between active regions.

  1. Maintain an index of regions: Fetch all active regions using wsRegions.getRegions().
  2. Track the currently focused region: Determine which region currently has focus or is active.
  3. Handle Arrow Keys: Listen for ArrowRight (or ArrowDown) to advance to the next region, and ArrowLeft (or ArrowUp) to move to the previous region.

Here is a practical implementation:

document.addEventListener('keydown', (e) => {
  const regions = wsRegions.getRegions();
  if (!regions.length) return;

  const focusedElement = document.activeElement;
  const currentIndex = regions.findIndex(r => r.element === focusedElement);

  if (e.key === 'ArrowRight' || e.key === 'ArrowDown') {
    e.preventDefault();
    const nextIndex = (currentIndex + 1) % regions.length;
    regions[nextIndex].element.focus();
  } else if (e.key === 'ArrowLeft' || e.key === 'ArrowUp') {
    e.preventDefault();
    const prevIndex = (currentIndex - 1 + regions.length) % regions.length;
    regions[prevIndex].element.focus();
  }
});

Triggering Region Playback

Focusing on a region visually indicates its selection, but users also need a way to play the selected segment without using a mouse. The standard accessibility behavior uses the Enter or Space key to activate an element.

Attach a keydown listener directly to the region element when it is created:

wsRegions.on('region-created', (region) => {
  region.element.setAttribute('tabindex', '0');

  region.element.addEventListener('keydown', (e) => {
    if (e.key === 'Enter' || e.key === ' ') {
      e.preventDefault();
      region.play();
    }
  });
});

Visual Focus Indicators

Ensure your CSS includes distinct focus indicators for the region elements. Wavesurfer.js allows custom styling via CSS classes or inline styles. Add a high-contrast focus outline to ensure keyboard users know which region is currently selected:

.wavesurfer-region:focus {
  outline: 2px solid #005fcc;
  outline-offset: 2px;
}

By combining focusable DOM elements, arrow-key event delegation, playback shortcuts, and distinct styling, keyboard users can efficiently navigate and interact with regions in Wavesurfer.js.
