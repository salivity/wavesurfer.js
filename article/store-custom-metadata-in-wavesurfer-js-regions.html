Store Custom Metadata in Wavesurfer.js Regions

This guide explains how to store, access, and update custom user key-value metadata within Wavesurfer.js region objects. By leveraging the built-in data property in the Wavesurfer.js Regions plugin, you can attach arbitrary application-specific information—such as tags, user IDs, or notes—directly to audio segments for easy retrieval and state management.

Storing Metadata During Region Creation

The cleanest way to attach custom metadata in Wavesurfer.js (version 7 and later) is by using the data property within the options object passed to addRegion. This property accepts any standard JavaScript object.

import WaveSurfer from 'wavesurfer.js';
import RegionsPlugin from 'wavesurfer.js/dist/plugins/regions.esm.js';

const ws = WaveSurfer.create({
  container: '#waveform',
  waveColor: 'rgb(200, 0, 200)',
  progressColor: 'rgb(100, 0, 100)',
  url: '/audio.mp3',
});

const wsRegions = ws.registerPlugin(RegionsPlugin.create());

// Add a region with custom key-value metadata
const region = wsRegions.addRegion({
  start: 2,
  end: 6,
  content: 'Chorus',
  color: 'rgba(0, 255, 0, 0.1)',
  data: {
    userId: 'usr_84920',
    tag: 'vocals',
    confidenceScore: 0.95,
    notes: 'Needs pitch correction'
  }
});

Accessing Custom Metadata

You can retrieve the custom key-value pairs at any time by accessing the data property on the region instance. This is typically done during user interactions or event callbacks:

// Access metadata when a user clicks a region
wsRegions.on('region-clicked', (region, e) => {
  e.stopPropagation();
  console.log('Region Metadata:', region.data);
  console.log('Tag:', region.data.tag);
  console.log('User ID:', region.data.userId);
});

// Access metadata across all active regions
const allRegions = wsRegions.getRegions();
allRegions.forEach((reg) => {
  if (reg.data && reg.data.tag === 'vocals') {
    console.log(`Vocal region found from ${reg.start} to ${reg.end}`);
  }
});

Updating Metadata Dynamically

To modify or append custom properties after a region has already been instantiated, use the setOptions method. When doing this, merge the existing properties to avoid overwriting previous values:

// Update existing metadata
region.setOptions({
  data: {
    ...region.data,
    notes: 'Pitch correction completed',
    approved: true
  }
});

Direct mutation of the data object (such as region.data.approved = true;) is also technically possible, but calling setOptions ensures that changes propagate cleanly through Wavesurfer's internal state cycles and triggers the appropriate update events.

Serializing Metadata for Backend Storage

When persisting your regions to a database or JSON file, you can map over the region list to serialize both the native properties and your custom metadata:

function exportRegions() {
  return wsRegions.getRegions().map(region => ({
    id: region.id,
    start: region.start,
    end: region.end,
    content: region.content?.innerText || region.content,
    data: region.data || {}
  }));
}

This structure makes it straightforward to save your segments to an API and re-instantiate them with their associated metadata during future user sessions.
