How to Attach MediaStream to Wavesurfer.js

Visualizing live audio with Wavesurfer.js requires capturing an active MediaStream—such as input from a user's microphone or a WebRTC stream—and rendering its frequency or time-domain data dynamically. This guide explains how to connect a live MediaStream to Wavesurfer.js using both the official Record plugin in Wavesurfer v7 and a custom Web Audio API integration.

Method 1: Using the Wavesurfer Record Plugin (Recommended)

In modern Wavesurfer.js (v7+), real-time stream rendering is handled natively through the official Record Plugin. This plugin abstracts the Web Audio API connection and handles drawing scrolling waveforms directly from a microphone stream.

1. Install or Import Dependencies

npm install wavesurfer.js

Or import via ESM:

import WaveSurfer from 'wavesurfer.js';
import RecordPlugin from 'wavesurfer.js/dist/plugins/record.esm.js';

2. Initialize Wavesurfer and the Plugin

Set up your target HTML container and instantiate Wavesurfer with the Record plugin attached:

<div id="waveform"></div>
<button id="start-btn">Start Stream</button>
<button id="stop-btn">Stop Stream</button>
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F46E5',
  progressColor: '#312E81',
  cursorWidth: 0,
});

// Register the record plugin
const record = wavesurfer.registerPlugin(
  RecordPlugin.create({
    scrollingWaveform: true,
    renderRecordedAudio: false, // Prevents auto-drawing final waveform on stop
  })
);

3. Start the Live Stream

Call startMic() to capture the MediaStream and immediately begin real-time visualization:

const startBtn = document.getElementById('start-btn');
const stopBtn = document.getElementById('stop-btn');

startBtn.addEventListener('click', async () => {
  // Requests microphone access and routes the MediaStream into Wavesurfer
  await record.startMic();
});

stopBtn.addEventListener('click', () => {
  record.stopMic();
});

Method 2: Attaching an Existing MediaStream Manually

If you already have a MediaStream instance (for example, from a WebRTC connection or an existing getUserMedia call), you can route the stream into Wavesurfer's internal audio context using standard Web Audio API nodes.

1. Setup Wavesurfer and Web Audio Nodes

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#10B981',
  interact: false,
  cursorWidth: 0,
});

// Extract Wavesurfer's internal or create a shared AudioContext
const audioContext = new (window.AudioContext || window.webkitAudioContext)();
const analyser = audioContext.createAnalyser();
analyser.fftSize = 512;

2. Connect the MediaStream to the Analyser

Pass your active MediaStream to the context using createMediaStreamSource:

async function attachStreamToWaveform(mediaStream) {
  // Ensure AudioContext is running
  if (audioContext.state === 'suspended') {
    await audioContext.resume();
  }

  // Create source from the MediaStream
  const source = audioContext.createMediaStreamSource(mediaStream);
  source.connect(analyser);

  // Buffer to hold waveform data
  const bufferLength = analyser.frequencyBinCount;
  const dataArray = new Float32Array(bufferLength);

  // Animation loop to draw continuous updates
  function draw() {
    requestAnimationFrame(draw);

    analyser.getFloatTimeDomainData(dataArray);

    // Load peaks into Wavesurfer for instant visualization
    wavesurfer.load('', [Array.from(dataArray)]);
  }

  draw();
}

// Example usage with navigator.mediaDevices
navigator.mediaDevices.getUserMedia({ audio: true })
  .then((stream) => {
    attachStreamToWaveform(stream);
  })
  .catch((err) => {
    console.error('Error accessing MediaStream:', err);
  });

Key Considerations

  • Browser Autoplay Policies: An AudioContext requires a direct user gesture (such as a button click) before it can capture or process live audio streams.
  • Stream Cleanup: Always call stream.getTracks().forEach(track => track.stop()) when destroying or navigating away from the page to release the microphone device.
