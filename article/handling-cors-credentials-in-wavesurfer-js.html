Handling CORS Credentials in Wavesurfer.js

Managing Cross-Origin Resource Sharing (CORS) credentials is essential when fetching protected audio files across different domains in Wavesurfer.js. This article explains which attributes control CORS credentials in both modern and legacy versions of Wavesurfer.js, detailing how to pass cookies and authorization headers with your audio requests.

The Short Answer

The specific attribute used to handle CORS credentials depends on whether you are using the modern version (v7+) or a legacy version (v6 or older) of Wavesurfer.js:

  • In Wavesurfer.js v7+: CORS credentials for data fetches are controlled by the fetchParams object using standard Fetch API options: credentials: 'include'. If you are mounting or streaming via an HTML media element directly, you use the crossOrigin option set to 'use-credentials'.
  • In Wavesurfer.js v6 and older: CORS credentials are handled via the xhr configuration object by setting withCredentials: true.

Wavesurfer.js v7+ Implementation

In version 7, Wavesurfer.js switched from XMLHttpRequest to the standard fetch API for requesting audio data.

Using fetchParams for Fetched Audio

When Wavesurfer.js downloads audio data (such as an ArrayBuffer to render the Web Audio waveform), pass the credentials property inside fetchParams:

import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: 'https://api.example.com/audio/sample.mp3',
  fetchParams: {
    credentials: 'include', // Sends cookies and authorization headers cross-origin
    headers: {
      'Authorization': 'Bearer YOUR_TOKEN'
    }
  }
});

The valid values for the credentials attribute are:

  • 'include': Always sends user credentials (cookies, HTTP basic auth) even on cross-origin calls.
  • 'same-origin': Sends credentials only when requests target the same origin (default in standard fetch).
  • 'omit': Never sends credentials.

Using crossOrigin with Media Elements

If you are using direct media streaming with an audio element (via the media option), use the crossOrigin attribute:

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  url: 'https://api.example.com/audio/stream.mp3',
  crossOrigin: 'use-credentials' // Sets the HTMLMediaElement crossOrigin property
});

The 'use-credentials' value instructs the browser to send credentials when loading the resource from a different domain.

Wavesurfer.js v6 and Earlier Implementation

Earlier releases relied on the browser's XMLHttpRequest (XHR) implementation under the hood. To send authentication cookies or headers, configure the xhr object with the withCredentials boolean:

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  backend: 'WebAudio',
  xhr: {
    withCredentials: true
  }
});

wavesurfer.load('https://api.example.com/audio/sample.mp3');

Server-Side CORS Requirements

Client-side configuration alone is insufficient if the server does not allow credentials. When sending credentials from Wavesurfer.js, ensure your server responds with:

  1. Access-Control-Allow-Credentials: true
  2. An explicit origin in Access-Control-Allow-Origin (e.g., https://yourdomain.com). A wildcard (*) cannot be used when credentials are enabled.
