Position Overlays in Zoomed Wavesurfer.js

Managing custom overlay user interfaces—such as custom playheads, cue markers, selection ranges, or floating toolbars—on a zoomed-in Wavesurfer.js instance requires synchronizing absolute time coordinates with dynamic scroll offsets. When an audio waveform is zoomed using wavesurfer.zoom(pxPerSec), the underlying canvas expands horizontally inside a scrollable wrapper (overflow-x: auto). The optimal strategy to manage UI overlays relies on dividing overlays into content-relative elements (anchored directly to audio timestamps) and viewport-relative elements (fixed inside the visible window), then driving their positions through container injection, passive scroll synchronization, and hardware-accelerated transforms.

Content-Relative Overlays: Injecting into the Scroll Wrapper

For UI components that must remain attached to a precise audio timestamp (such as custom annotations or event markers), the most effective approach is mounting the overlay DOM elements directly inside Wavesurfer’s scroll container rather than an external parent container.

  1. Target the Scroll Element: Retrieve the internal scroll container via wavesurfer.getWrapper().
  2. Calculate Absolute Pixel Positions: Compute the horizontal offset using the current zoom level: \[\text{Left Offset (px)} = \text{Audio Time (seconds)} \times \text{pixelsPerSecond}\]
  3. Apply CSS Absolute Positioning: Set the overlay's CSS to position: absolute with top: 0 and left: [calculated_px]px.

Because the overlay resides inside the scrollable container, the browser handles position updates natively during user scrolling via the GPU. This eliminates visual jitter, scroll lag, and synchronization drift without requiring JavaScript scroll listeners.

Viewport-Relative Overlays: Synchronizing with Scroll Events

Certain overlay elements—such as a fixed-center playhead, sticky timecode headers, or floating audio editing controls—must remain visible within the user's viewport while the waveform scrolls beneath them.

Managing these elements requires tracking the scroll container’s visible bounds:

  1. Attach Passive Scroll Listeners: Bind a scroll event listener to the wrapper returned by wavesurfer.getWrapper():

    const scrollContainer = wavesurfer.getWrapper();
scrollContainer.addEventListener('scroll', handleScroll, { passive: true });

  2. Read Bounds via scrollLeft: Read scrollContainer.scrollLeft to determine the current visible time window: \[\text{Start Time} = \frac{\text{scrollLeft}}{\text{pixelsPerSecond}}\] \[\text{End Time} = \frac{\text{scrollLeft} + \text{clientWidth}}{\text{pixelsPerSecond}}\]

  3. Update with requestAnimationFrame: To prevent layout thrashing and maintain 60/120 FPS performance, read scroll values and update overlay styles inside a requestAnimationFrame callback.

  4. Use Transforms Instead of Offsets: Position sticky or viewport-constrained elements using transform: translate3d(x, y, 0) rather than adjusting left or margin-left. This keeps operations on the compositor thread.

Handling Dynamic Zoom and Resize Events

Zooming modifies the horizontal scale factor, invalidating previously calculated pixel coordinates. A complete overlay strategy requires subscribing to lifecycle events:

  • The zoom Event: Listen for wavesurfer.on('zoom', (pxPerSec) => { ... }). Recompute the pixel offsets of all content-relative overlays using the new pxPerSec multiplier.
  • The redraw Event: Whenever audio data or waveform dimensions change, trigger a layout recalculation for elements tied to waveform boundaries.
  • Resize Observer: Attach a ResizeObserver to the main Wavesurfer container to recalculate visible limits when the browser window or container dimensions change.

Coordinate Mapping Pattern

Store all overlay locations in application state as raw audio seconds rather than pixel values. Treat audio time as the single source of truth:

function syncOverlayPosition(overlayElement, timestampInSeconds, pxPerSec) {
  const pixelPosition = timestampInSeconds * pxPerSec;
  overlayElement.style.transform = `translate3d(${pixelPosition}px, 0, 0)`;
}

By decoupling the underlying time data from the pixel representations, you ensure that zooming, horizontal scrolling, and responsive container resizing can instantly project overlays to their correct positions without cumulative drift.
