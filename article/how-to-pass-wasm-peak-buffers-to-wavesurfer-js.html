How to Pass WASM Peak Buffers to Wavesurfer.js

Precomputing audio waveform peaks using WebAssembly (WASM) drastically reduces CPU overhead and avoids UI thread freezing when rendering large audio files in the browser. Instead of relying on Wavesurfer.js to decode raw audio and calculate peak points internally, you can feed an externally generated peak array directly into the player. This guide details how to extract typed peak arrays from WASM linear memory and supply them properly to Wavesurfer.js.

1. Expected Peak Data Format in Wavesurfer.js

Wavesurfer.js accepts precomputed waveform data through the peaks property in its configuration or via the load() method. The peaks option expects an array of arrays representing the channels (e.g., [channel1Peaks, channel2Peaks]), or an array of numbers representing a single mono channel. The values must be floating-point numbers normalized between -1.0 and 1.0 (or 0.0 and 1.0 if using absolute values).

2. Extracting the Buffer from WASM Memory

When a WASM module calculates waveform peaks, it stores the results in its linear memory buffer (WebAssembly.Memory). The WASM function typically returns a memory pointer (offset) and the length of the computed float array.

To read this in JavaScript without unnecessary data copying, create a Float32Array view over the module's memory:

// Assume wasmInstance is your instantiated WebAssembly module
// and it returns a pointer and length for the calculated peaks
const pointer = wasmInstance.exports.get_peaks_pointer();
const length = wasmInstance.exports.get_peaks_length();

// Create a view into WASM memory
const wasmMemoryBuffer = wasmInstance.exports.memory.buffer;
const rawPeaksView = new Float32Array(wasmMemoryBuffer, pointer, length);

// Clone the data if the WASM memory might grow or be freed
const peaksData = new Float32Array(rawPeaksView);

// Free the allocated WASM memory if your module requires manual deallocation
wasmInstance.exports.free_peaks_buffer(pointer, length);

3. Formatting Multi-Channel Peaks

If your WASM function calculates interleaved or multi-channel data, you must format it according to Wavesurfer's channel requirements before passing it to the configuration:

// For Mono: Wrap the Float32Array in an array
const monoPeaks = [peaksData];

// For Stereo: De-interleave or split the buffer into two distinct channels
const channel1 = new Float32Array(length / 2);
const channel2 = new Float32Array(length / 2);

for (let i = 0, j = 0; i < length; i += 2, j++) {
  channel1[j] = peaksData[i];
  channel2[j] = peaksData[i + 1];
}

const stereoPeaks = [channel1, channel2];

4. Passing Peaks into Wavesurfer.js

When supplying precomputed peaks, you should also provide the total duration of the audio file in seconds. This prevents Wavesurfer from attempting to fetch or decode the audio file solely to calculate timeline scaling.

Initialization Option

Pass the peaks directly during instance creation:

import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F46E5',
  progressColor: '#818CF8',
  url: '/path/to/audio.mp3',
  peaks: monoPeaks,     // Your extracted WASM peak data
  duration: 240.5,      // Audio duration in seconds
});

Dynamic Load Option

Alternatively, you can initialize the player empty and provide both the audio source and the WASM peaks simultaneously using load():

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F46E5',
  progressColor: '#818CF8',
});

// Load audio along with WASM-computed peaks
wavesurfer.load('/path/to/audio.mp3', monoPeaks, 240.5);

Using this approach completely bypasses the browser's Web Audio API decoding step for visualization, allowing the waveform to render instantaneously even on low-powered devices.
