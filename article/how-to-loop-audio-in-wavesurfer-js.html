How to Loop Audio in Wavesurfer.js

This guide explains how to enable continuous looping of the main audio track in Wavesurfer.js. While Wavesurfer.js does not include a standalone loop: true option in its core configuration object, endless playback is controlled directly via the standard HTMLMediaElement loop property or by binding to Wavesurfer playback lifecycle events.

The Primary Parameter: The HTML5 loop Property

Wavesurfer.js (particularly version 7 and later) relies on the browser's native HTMLMediaElement for decoding and playing audio tracks. The exact parameter that controls endless looping is the HTML5 audio loop property.

To enable looping on the active track, access the media element from the Wavesurfer instance and set its loop boolean property to true:

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: '/path/to/audio.mp3',
});

// Enable endless looping via the underlying media element
wavesurfer.getMediaElement().loop = true;

When set to true, the browser seamlessly restarts audio playback from the beginning as soon as the track reaches the end without any audible gap.

Passing a Looped Element via the media Parameter

You can also configure looping during initialization by passing an existing HTML <audio> element that already has the loop attribute set into Wavesurfer's media initialization parameter:

<audio id="my-audio" src="/path/to/audio.mp3" loop></audio>
<div id="waveform"></div>

<script>
  const audioElement = document.getElementById('my-audio');

  const wavesurfer = WaveSurfer.create({
    container: '#waveform',
    media: audioElement, // Wavesurfer uses this pre-configured looped element
  });
</script>

Alternative Method: Listening to the finish Event

If you prefer programmatic control without directly altering the media element's properties, you can listen for the finish event and restart playback manually:

wavesurfer.on('finish', () => {
  wavesurfer.play();
});

Using wavesurfer.getMediaElement().loop = true remains the recommended approach, as native browser looping avoids the minor latency or stutter that can occasionally occur when restarting via JavaScript event callbacks.
