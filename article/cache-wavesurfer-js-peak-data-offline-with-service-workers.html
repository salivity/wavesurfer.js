Cache Wavesurfer.js Peak Data Offline with Service Workers

Rendering audio waveforms offline with Wavesurfer.js requires instant access to waveform data without re-decoding massive audio files on the client. By precomputing peak data into lightweight JSON or array structures, web applications can leverage tailored Service Worker caching strategies—principally Cache First and Stale-While-Revalidate—to deliver zero-latency waveform displays even when disconnected from the network.

The Role of Precomputed Peaks

Wavesurfer.js normally generates waveforms by fetching an entire audio buffer and decoding it via the Web Audio API. This process consumes substantial CPU and memory, making offline re-renders slow.

Passing precalculated arrays via the peaks option bypasses audio decoding:

WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F46E5',
  backend: 'MediaElement',
  peaks: cachedPeaksArray,
  url: 'audio.mp3'
});

To make this instant offline, the Service Worker must store and serve these peak files independently of the underlying audio files.

Strategy 1: Cache First (Best for Static Audio Peaks)

When audio tracks are immutable, their corresponding peak data is also static. The Cache First (or Cache Falling Back to Network) strategy is the fastest choice.

The Service Worker checks the Cache Storage API immediately upon receiving a request for peak data. If the entry exists, it resolves instantly without touching the network:

self.addEventListener('fetch', (event) => {
  const url = new URL(event.request.url);

  if (url.pathname.endsWith('-peaks.json')) {
    event.respondWith(
      caches.open('wavesurfer-peaks-v1').then(async (cache) => {
        const cachedResponse = await cache.match(event.request);
        if (cachedResponse) {
          return cachedResponse;
        }

        const networkResponse = await fetch(event.request);
        cache.put(event.request, networkResponse.clone());
        return networkResponse;
      })
    );
  }
});

Because JSON peak files generally range from 10 KB to 50 KB, they load in milliseconds from cache, letting Wavesurfer.js render the waveform immediately.

Strategy 2: Stale-While-Revalidate (Best for Dynamic Peak Formats)

If peak resolutions or audio normalizations are periodically updated on the server, the Stale-While-Revalidate strategy serves the cached peak data instantly while silently fetching an updated version in the background.

import { registerRoute } from 'workbox-routing';
import { StaleWhileRevalidate } from 'workbox-strategies';
import { CacheableResponsePlugin } from 'workbox-cacheable-response';

registerRoute(
  ({ url }) => url.pathname.includes('/api/peaks/'),
  new StaleWhileRevalidate({
    cacheName: 'dynamic-peaks-cache',
    plugins: [
      new CacheableResponsePlugin({
        statuses: [0, 200],
      }),
    ],
  })
);

On the initial render, the user gets an instant waveform from the local cache. If the background fetch discovers updated peak data, the worker stores it for the subsequent view or fires an update event to redraw the canvas.

Strategy 3: Precaching During Installation

For default or featured tracks in an offline application, precaching guarantees that peak data is available on the user's first offline session:

const PEAK_ASSETS = [
  '/peaks/intro-track.json',
  '/peaks/sample-audio.json'
];

self.addEventListener('install', (event) => {
  event.waitUntil(
    caches.open('static-peaks-v1').then((cache) => {
      return cache.addAll(PEAK_ASSETS);
    })
  );
});

Separating Peak Caching from Audio Streams

Audio files (.mp3, .wav) require HTTP Range Requests (Status 206) for streaming, which can complicate Service Worker caching logic. Storing precomputed peak arrays as standalone .json files completely isolates waveform visualization from media delivery. Wavesurfer.js can visually render the full track timeline from the Service Worker cache immediately, even while the audio element buffers the media stream asynchronously.
