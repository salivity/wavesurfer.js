Sync Video Playback with Wavesurfer.js

Synchronizing HTML5 video playback with a Wavesurfer.js audio waveform allows you to build rich media editors, transcription tools, and interactive video players. This guide explains how to tie a native video element directly to Wavesurfer.js, ensuring that playback, pausing, and seeking remain frame-accurate and fully synchronized across both components.

1. HTML Structure

Create a standard HTML5 <video> element alongside a <div> container where Wavesurfer will render the waveform:

<div class="player-container">
  <video id="video-element" width="640" height="360" controls>
    <source src="video.mp4" type="video/mp4" />
    Your browser does not support the video tag.
  </video>
  <div id="waveform"></div>
</div>

2. Direct Media Binding (Wavesurfer.js v7+)

In modern versions of Wavesurfer.js (v7 and newer), the simplest and most performant way to synchronize video is by passing the <video> DOM element directly to the media configuration parameter.

When you assign the video element as the media target, Wavesurfer automatically binds to its internal playback events (play, pause, seeking, and timeupdate), eliminating manual synchronization logic:

import WaveSurfer from 'wavesurfer.js';

const video = document.getElementById('video-element');

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  media: video, // Binds Wavesurfer directly to the video element
});

Because the video element acts as the master media controller, pressing play on the native video player or interacting with the waveform immediately updates both elements in real time.

3. Manual Synchronization (Custom Implementations or v6)

If you are using an older version of Wavesurfer.js, or need custom sync handling (such as rendering the waveform from a separate, high-quality audio track), you can manage the state using native event listeners.

Master: Video Element

When the video plays, pauses, or seeks, mirror that state to Wavesurfer:

const video = document.getElementById('video-element');
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: 'audio-track.mp3', // Separate audio source
});

// Sync play/pause
video.addEventListener('play', () => wavesurfer.play());
video.addEventListener('pause', () => wavesurfer.pause());

// Sync seeking
video.addEventListener('seeked', () => {
  const progress = video.currentTime / video.duration;
  wavesurfer.seekTo(progress);
});

Master: Waveform Seeking

To allow users to scrub the video by clicking on the waveform, update the video's currentTime when Wavesurfer detects an interaction:

wavesurfer.on('interaction', (newProgress) => {
  video.currentTime = newProgress * video.duration;
});

4. Performance and Audio Extraction

Decoding large video files on the client side to generate waveform data can cause significant browser lag. For optimal performance:

  1. Pre-extract Audio: Generate an .mp3 or .wav file on your server during upload, and point Wavesurfer to that audio file while keeping the video muted or synced.
  2. Pre-compute Waveform Peaks: Generate peak data on the backend using tools like audiowaveform and pass the JSON array into Wavesurfer via the peaks configuration option. This allows the waveform to render instantly without downloading or decoding the entire media file first.
