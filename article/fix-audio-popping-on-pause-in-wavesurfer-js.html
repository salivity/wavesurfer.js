Fix Audio Popping on Pause in Wavesurfer.js

Audio popping or clicking sounds during playback pause in Wavesurfer.js typically occur because playback is interrupted abruptly at a non-zero amplitude in the audio waveform. This sudden drop to silence creates a transient audio click that is noticeable and jarring to listeners. This article explains why this artifact happens and how to resolve it by applying a rapid micro-fade using the Web Audio API's gain controls before halting playback.

Why the Pop Occurs

Digital audio relies on continuous waveforms. When you abruptly pause playback via wavesurfer.pause(), the audio stream stops immediately. If the waveform happens to be at a peak or trough rather than at the zero-crossing point, the speaker cone abruptly jumps back to its resting position. This sudden instantaneous change in voltage produces a mechanical pop or click.

The Solution: Implement a Micro-Fade

The standard method to prevent audio clicking is to smoothly ramp the volume down to zero over 10 to 25 milliseconds before issuing the pause command. This duration is imperceptible as a fade to human ears, but it provides enough time to eliminate the instantaneous drop in amplitude.

Implementation with Web Audio API

Wavesurfer.js uses the Web Audio API backend by default, granting direct access to its AudioContext and dynamic gain manipulation. You can wrap the default pause functionality with a custom method that automates this micro-fade.

// Function to safely pause without audio clicks
function safePause(wavesurfer) {
  // Check if audio is currently playing
  if (!wavesurfer.isPlaying()) return;

  // Access the audio context and backend
  const audioContext = wavesurfer.backend.ac;
  const gainNode = wavesurfer.backend.gainNode;
  const currentTime = audioContext.currentTime;
  const fadeDuration = 0.015; // 15 milliseconds

  // Cancel any scheduled audio parameter changes
  gainNode.gain.cancelScheduledValues(currentTime);

  // Set the current value explicitly to avoid abrupt transitions
  gainNode.gain.setValueAtTime(gainNode.gain.value, currentTime);

  // Ramp down to zero smoothly
  gainNode.gain.linearRampToValueAtTime(0, currentTime + fadeDuration);

  // Pause the playback after the ramp finishes and reset the gain
  setTimeout(() => {
    wavesurfer.pause();
    // Restore the gain level for the next playback start
    gainNode.gain.setValueAtTime(1, audioContext.currentTime);
  }, fadeDuration * 1000);
}

Implementing a Soft Play Resume

To fully eliminate audio artifacts, the same principle should be applied when playback resumes. Starting playback mid-waveform can also cause a click if the waveform does not begin at zero:

function safePlay(wavesurfer) {
  const audioContext = wavesurfer.backend.ac;
  const gainNode = wavesurfer.backend.gainNode;
  const currentTime = audioContext.currentTime;
  const fadeDuration = 0.015;

  // Initialize gain to zero before starting
  gainNode.gain.setValueAtTime(0, currentTime);

  wavesurfer.play();

  // Ramp up to normal volume
  gainNode.gain.linearRampToValueAtTime(1, currentTime + fadeDuration);
}

Handling the MediaElement Backend

If your Wavesurfer instance is configured with backend: 'MediaElement', parameter scheduling via AudioContext might not be directly available. In this scenario, either initialize an AudioContext node connected to the media element using createMediaElementSource, or rapidly step down wavesurfer.setVolume() via a short JavaScript interval before invoking wavesurfer.pause(). Switching to the default WebAudio backend is generally recommended for superior timing precision and native ramp functions.
