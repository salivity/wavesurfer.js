Purging Off-Screen Regions in Wavesurfer.js

Managing thousands of annotations in large Wavesurfer.js projects can degrade rendering performance, cause dropped frames, and exhaust browser memory due to excessive Document Object Model (DOM) nodes. This article explains how to systematically purge off-screen region elements using dynamic DOM virtualization, ensuring only currently visible regions remain mounted in the DOM during playback, scrolling, and zooming.

The DOM Overhead of Regions

By default, the Wavesurfer.js Regions plugin instantiates physical DOM elements for every region added to the waveform. In projects with extensive audio files containing hundreds or thousands of tagged segments, all region elements remain inside the container node regardless of whether they fall inside the visible viewport. This causes severe layout thrashing and sluggish scroll performance.

Wavesurfer.js does not include an automatic native cull method (such as an internal purgeOffscreen() function), meaning developers must implement a viewport virtualization pattern to unmount off-screen region nodes and remount them as they scroll into view.

The Virtualization Technique

Purging off-screen regions requires separating region data from region rendering. Store your region definitions in a lightweight JavaScript array or state store rather than relying on the plugin instance as your data source of truth.

The purging workflow consists of three steps:

  1. Calculate the Visible Time Window: Determine the start and end timestamps currently visible in the container.
  2. Purge Out-of-Bounds Regions: Call region.remove() on instantiated regions whose boundaries fall outside the visible window.
  3. Mount In-Bounds Regions: Call regionsPlugin.addRegion() exclusively for regions that intersect the visible window.

Calculating the Viewport Range

To determine which regions to purge and which to keep, listen to the scroll event of the Wavesurfer wrapper element:

const container = wavesurfer.getWrapper();
const duration = wavesurfer.getDuration();
const scrollWidth = container.scrollWidth;

function getVisibleTimeRange(bufferSeconds = 2) {
  const scrollLeft = container.scrollLeft;
  const clientWidth = container.clientWidth;

  const startTime = Math.max(0, (scrollLeft / scrollWidth) * duration - bufferSeconds);
  const endTime = Math.min(duration, ((scrollLeft + clientWidth) / scrollWidth) * duration + bufferSeconds);

  return { startTime, endTime };
}

Adding a buffer prevents visual popping by keeping elements just outside the edges rendered during rapid scrolling.

Executing the Purge and Re-render Cycle

Maintain a reference to currently rendered region instances via a Map. When updating, identify active regions that have moved off-screen, call remove(), and delete them from the active map:

const activeRegions = new Map(); // key: regionId, value: Region instance

function updateVisibleRegions(allRegionData) {
  const { startTime, endTime } = getVisibleTimeRange();

  // 1. Purge off-screen regions
  activeRegions.forEach((regionInstance, id) => {
    if (regionInstance.end < startTime || regionInstance.start > endTime) {
      regionInstance.remove();
      activeRegions.delete(id);
    }
  });

  // 2. Mount newly visible regions
  allRegionData.forEach((data) => {
    const isVisible = data.end >= startTime && data.start <= endTime;
    if (isVisible && !activeRegions.has(data.id)) {
      const newRegion = regionsPlugin.addRegion(data);
      activeRegions.set(data.id, newRegion);
    }
  });
}

Event Binding and Optimization

Attach the update function to Wavesurfer's lifecycle events:

  • scroll on the container element to detect user navigation.
  • zoom to recalculate visible bounds when the pixel-per-second ratio changes.
  • audioprocess or timeupdate if auto-scrolling is enabled during playback.

Wrap the scroll listener with requestAnimationFrame or a micro-debounce to avoid running the purge cycle multiple times per frame, keeping DOM mutations smooth even on lower-powered devices.
