Anchor Overlays to Timestamps in Wavesurfer.js

This article explains how to keep absolute positioned overlay elements precisely aligned with specific audio timestamps in Wavesurfer.js. When building custom markers, flags, or annotations, changes in waveform zoom levels, container resizing, and scrolling can displace HTML elements. By understanding the mathematical relationship between audio duration and container width, leveraging Wavesurfer’s coordinate systems, and listening to key lifecycle events, you can ensure custom overlay elements remain perfectly anchored at their designated timestamps.

The Underlying Coordinate Math

Audio in Wavesurfer.js is plotted sequentially along the horizontal X-axis. To anchor an overlay element to a specific timestamp, you must convert that timestamp (in seconds) into a pixel offset relative to the waveform canvas container.

The formula used to derive the horizontal position depends on whether fixed widths or zoom levels (minPxPerSec) are active:

  • Standard View (Fit to Container): \[\text{Position (px)} = \left(\frac{\text{Target Time (s)}}{\text{Total Duration (s)}}\right) \times \text{Total Container Width (px)}\]

  • Zoomed View (Using minPxPerSec): \[\text{Position (px)} = \text{Target Time (s)} \times \text{minPxPerSec}\]

Parent Container Context

For CSS absolute positioning (position: absolute; left: Xpx;) to work seamlessly, the overlay elements must be appended to the correct parent node inside the Wavesurfer DOM tree.

Wavesurfer.js creates an internal wrapper structure: an outer host element, a scroll container, and an inner wrapper that hosts the rendered canvas. Your custom overlay elements should be appended to the inner wrapper container (or an overlay container that shares the exact width and height of the waveform canvas). The parent container must have position: relative or position: absolute so that left: 0 aligns with timestamp 00:00.

Dynamic Event Handling and Position Updates

Because container widths change during window resizing and pixel-per-second ratios change during zooming, static positioning will fail. To keep overlays anchored, you must recalculate their pixel positions when the waveform layout updates.

Listen to the following Wavesurfer.js events to trigger position recalculations:

  1. ready / decode: Wait until the audio is fully decoded before calculating initial positions, as the total duration (wavesurfer.getDuration()) is required.
  2. zoom: Whenever wavesurfer.zoom(pxPerSec) is called, the horizontal scale changes. Recompute the left style property of each overlay element using the updated zoom ratio.
  3. redraw: Fired when the waveform redraws, such as during container resize events.

Implementation Pattern

Below is the standard programmatic pattern for keeping an array of marker overlays synchronized with Wavesurfer:

const markers = [
  { time: 12.5, element: document.getElementById('marker-1') },
  { time: 45.0, element: document.getElementById('marker-2') }
];

function updateOverlayPositions() {
  const duration = wavesurfer.getDuration();
  if (!duration) return;

  // Obtain the rendered width of the waveform wrapper
  const wrapper = wavesurfer.getWrapper();
  const totalWidth = wrapper.scrollWidth;

  markers.forEach(marker => {
    const positionPx = (marker.time / duration) * totalWidth;
    marker.element.style.position = 'absolute';
    marker.element.style.left = `${positionPx}px`;
    marker.element.style.transform = 'translateX(-50%)'; // Centers the marker on the timestamp
  });
}

// Lifecycle listeners
wavesurfer.on('ready', updateOverlayPositions);
wavesurfer.on('zoom', updateOverlayPositions);
wavesurfer.on('redraw', updateOverlayPositions);

Alternative: Using the Regions Plugin

If manual DOM management and coordinate calculations are not strictly necessary for your architecture, the official Regions Plugin (wavesurfer.js/plugins/regions) handles this anchoring automatically. A single-point region (where start equals end) renders a dedicated DOM element that Wavesurfer internally synchronizes across zooms, resizes, and audio decoding cycles.
