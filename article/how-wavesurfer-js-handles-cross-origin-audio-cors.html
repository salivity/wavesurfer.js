How Wavesurfer.js Handles Cross-Origin Audio (CORS)

This article provides an overview of how Wavesurfer.js interacts with cross-origin audio files and explains the mechanisms required to prevent CORS-related playback and rendering failures. It covers the underlying browser security models governing the Web Audio API and HTML5 canvas, the specific client-side parameters available in Wavesurfer.js, and the necessary server-side header configurations needed to seamlessly load remote audio assets.

Why CORS Affects Wavesurfer.js

Wavesurfer.js does not merely play audio; it visualizes the audio waveform. To render waveforms, the library must decode raw audio data using the browser's Web Audio API (AudioContext.decodeAudioData) and draw the visual representation onto an HTML5 <canvas> element.

Browsers enforce Cross-Origin Resource Sharing (CORS) policies to protect users. If an audio file is hosted on a different domain, protocol, or port than the web application hosting Wavesurfer.js, the browser restricts access to the underlying binary data unless the remote server explicitly permits it. If cross-origin restrictions are violated, Wavesurfer.js will fail to fetch the audio data, throwing errors such as DOMException: The element has no supported sources or failing to decode audio entirely.

Client-Side Configuration in Wavesurfer.js

Wavesurfer.js handles audio loading differently depending on the configured backend and initialization options.

1. Standard Fetch and WebAudio (Default)

By default, Wavesurfer.js fetches audio files as binary data using the standard fetch API before passing the ArrayBuffer to decodeAudioData. When using the url parameter or wavesurfer.load(url):

  • The request automatically follows standard CORS fetch rules.
  • If customized authentication or credentials are required, developers can pass custom fetch options into the fetchParams property during initialization:
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: 'https://example-cdn.com/audio/sample.mp3',
  fetchParams: {
    mode: 'cors',
    credentials: 'omit', // or 'include' if cookies/auth headers are required
  },
});

2. MediaElement Backend

When working with long audio files or streaming sources, developers often use the MediaElement backend (backend: 'MediaElement'). In this mode, Wavesurfer.js wraps an HTML5 <audio> element.

To analyze audio from an external <audio> element with Web Audio and draw it on a canvas, the element must declare a cross-origin attribute. In Wavesurfer.js, you can specify this behavior by passing an existing audio element or configuring the media element options:

const audioElement = new Audio();
audioElement.crossOrigin = 'anonymous';
audioElement.src = 'https://example-cdn.com/audio/sample.mp3';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  media: audioElement,
});

Setting crossOrigin = 'anonymous' ensures the browser requests the file with standard CORS headers, allowing the Web Audio API to process the stream without tainting the canvas.

Required Server-Side Headers

Client-side configurations alone cannot resolve CORS restrictions. The server or Content Delivery Network (CDN) hosting the audio files must include specific HTTP response headers.

The minimum required header is:

Access-Control-Allow-Origin: *

(Replace * with your specific domain in production environments requiring restricted access).

If credentials such as cookies or authorization headers are sent via fetchParams, the server must also return:

Access-Control-Allow-Credentials: true
Access-Control-Allow-Origin: https://yourdomain.com

Additionally, because browsers may initiate an OPTIONS preflight check before downloading the resource, the hosting server must respond to HTTP OPTIONS requests with:

Access-Control-Allow-Methods: GET, HEAD, OPTIONS
Access-Control-Allow-Headers: Range, Content-Type, Authorization

Handling the Range header is essential, as modern browsers often fetch audio using partial content requests (206 Partial Content).

Bypassing Audio Decoding via Precomputed Peaks

If configuring CORS on a third-party server is impossible, Wavesurfer.js provides a workaround: precomputed peaks.

By generating waveform data (an array of floating-point numbers) on a server beforehand, you can supply this data directly to Wavesurfer.js using the peaks option alongside the MediaElement backend:

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  url: 'https://external-domain.com/audio.mp3',
  peaks: [[0.01, 0.5, 0.2, -0.4], [0.02, 0.45, 0.18, -0.38]], // Pre-generated peak data
});

Because Wavesurfer.js does not need to read the raw binary data to generate the waveform when peaks are pre-supplied, it bypasses the need for Web Audio decoding, eliminating CORS canvas restrictions while allowing the underlying media element to handle standard playback.
