Wavesurfer.js Audio Buffer Slicing for Scrubbing

This article examines how Web Audio buffer slicing enables responsive audio snippet playback during scrubbing in Wavesurfer.js. It details the underlying Web Audio API mechanics—specifically utilizing playback offset scheduling on an AudioBufferSourceNode alongside channel-level PCM data slicing—to produce smooth, low-latency micro-previews as a user interacts with the waveform display.

Virtual Buffer Slicing via AudioBufferSourceNode

In most Wavesurfer.js implementations, snippet playback during scrubbing does not require physically splitting or copying the underlying AudioBuffer. Instead, non-destructive, virtual buffer slicing is achieved using the playback parameters of the Web Audio API's native AudioBufferSourceNode.start() method:

sourceNode.start(when, offset, duration);

When a user drags across the waveform:

  1. offset marks the exact timestamp (in seconds) corresponding to the cursor position on the timeline.
  2. duration defines the length of the preview snippet (typically between 30ms and 100ms).
  3. when is set to audioContext.currentTime for immediate execution.

By pointing directly to the master AudioBuffer already stored in memory, this technique creates instantaneous audio slices on the fly with zero memory allocation overhead.

Physical Buffer Slicing with Float32Array Subarrays

When physical extraction of a slice is required—such as caching micro-buffers for granular synthesis or custom export tasks—Web Audio channels must be sliced at the PCM data level. Because an AudioBuffer does not feature a native .slice() method, slicing is handled via Float32Array.prototype.subarray() or AudioBuffer.copyFromChannel().

To create an isolated snippet buffer:

  1. Allocate a destination buffer using audioContext.createBuffer() with the exact sample count matching the desired snippet duration (durationInSeconds * sampleRate).
  2. Read the source samples from each channel using sourceAudioBuffer.getChannelData(channelIndex).
  3. Extract the slice using .subarray(startSample, endSample).
  4. Write the sliced array into the new buffer using destinationAudioBuffer.copyToChannel().

Handling Scrubbing Artifacts and Concurrency

Rapid scrubbing fires multiple pointer events per second. Playing unmanaged slices can lead to browser CPU exhaustion and harsh audio popping. To maintain smooth playback:

  • Node Management: Previous AudioBufferSourceNode instances must be disconnected and stopped immediately before instantiating a new one.
  • Micro-Fades: An active snippet should be routed through a GainNode configured with short linear or exponential gain ramps (1ms to 5ms) at the start and end of the slice to eliminate DC offset clicks.
  • Throttling: Scrub event listeners should be throttled or debounced using requestAnimationFrame to match the display refresh rate and prevent redundant audio buffer instantiations.
