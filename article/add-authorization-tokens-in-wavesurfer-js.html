Add Authorization Tokens in Wavesurfer.js

Securing audio assets often requires attaching authorization headers, such as Bearer tokens, to incoming HTTP requests. Because Wavesurfer.js relies on fetching audio files to decode audio buffers and generate visual waveforms, standard public URLs are insufficient for protected endpoints. This article outlines the primary methods for passing authentication tokens to audio requests in Wavesurfer.js, covering native fetch options, pre-fetching via Blobs, and handling HTML5 media elements.

Method 1: Using Native fetchParams (Wavesurfer.js v7+)

Modern versions of Wavesurfer.js (v7 and newer) use the Fetch API under the hood to download audio data. You can pass standard fetch configuration options directly through the fetchParams property when initializing the instance or when calling the load method.

Setting Headers at Initialization

import WaveSurfer from 'wavesurfer.js';

const token = 'YOUR_AUTH_TOKEN';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: 'https://example.com/api/audio/track-123.mp3',
  fetchParams: {
    headers: {
      'Authorization': `Bearer ${token}`,
      'Accept': 'audio/*'
    }
  }
});

Passing Headers Dynamically with load

If your token changes or you load audio files dynamically after initialization:

wavesurfer.load('https://example.com/api/audio/track-456.mp3', null, null);
// Or pass custom fetch options if calling fetch directly before passing to wavesurfer

Method 2: Fetching the Audio as a Blob (Universal Approach)

When you need precise control over error handling, token refresh flows, or older Wavesurfer.js compatibility, the most reliable approach is to retrieve the audio file using the standard JavaScript fetch API, convert the response into a Blob, and pass that Blob to Wavesurfer.

async function loadProtectedAudio(audioUrl, token) {
  try {
    const response = await fetch(audioUrl, {
      method: 'GET',
      headers: {
        'Authorization': `Bearer ${token}`
      }
    });

    if (!response.ok) {
      throw new Error(`HTTP error! status: ${response.status}`);
    }

    const audioBlob = await response.blob();
    
    // For Wavesurfer.js v7:
    wavesurfer.load(URL.createObjectURL(audioBlob));

    // For Wavesurfer.js v6 and below:
    // wavesurfer.loadBlob(audioBlob);
  } catch (error) {
    console.error('Failed to load protected audio:', error);
  }
}

loadProtectedAudio('https://example.com/api/audio/stream', 'YOUR_AUTH_TOKEN');

This method ensures that any authentication challenge, such as an expired token triggering a 401 Unauthorized, can be intercepted and handled prior to waveform rendering.

Method 3: MediaElement Backend and Token Considerations

Standard HTML5 <audio> elements cannot accept custom HTTP request headers like Authorization: Bearer .... If you configure Wavesurfer.js to stream using the native browser media element (by setting backend: 'MediaElement'), header-based authorization will fail.

For streaming via native media elements, use alternative authorization strategies:

  1. Signed URLs: Generate a temporary, pre-signed URL on your server (commonly used with cloud storage like AWS S3 or Google Cloud Storage) containing the authentication signature as query parameters.
  2. Cookie-Based Sessions: Use secure, HttpOnly session cookies. When using cookies, ensure CORS credentials are enabled in fetchParams:
const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  url: 'https://example.com/api/audio/track-123.mp3',
  fetchParams: {
    credentials: 'include'
  }
});
