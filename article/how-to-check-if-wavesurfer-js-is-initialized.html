How to Check If Wavesurfer.js Is Initialized

Interacting with Wavesurfer.js before it has finished decoding audio and drawing the waveform often leads to runtime errors or ignored commands. Because audio loading and waveform rendering are asynchronous, you must verify that the instance is ready before calling playback, zooming, or manipulation methods. This guide covers how to safely check the initialization status of Wavesurfer.js using event listeners, Promises, and state flags.

1. Using the ready Event Listener (Recommended for All Versions)

The most standard and reliable way to execute code once Wavesurfer.js is ready is by subscribing to its ready event. This event fires after the audio file has been downloaded, decoded, and rendered into the canvas.

import WaveSurfer from 'wavesurfer.js';

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#4F4A85',
  progressColor: '#383351',
  url: '/audio.mp3'
});

// Listen for the ready event
wavesurfer.on('ready', () => {
  console.log('WaveSurfer is fully initialized.');
  wavesurfer.play();
});

Using wavesurfer.once('ready', callback) is also an option if you only want the handler to execute the first time the audio becomes ready.

2. Using Promises with load() (Wavesurfer.js v7+)

In Wavesurfer.js v7 and newer, the load() method returns a Promise that resolves once the audio is loaded and decoded. This allows you to use modern async/await syntax to ensure the instance is ready before executing methods.

const wavesurfer = WaveSurfer.create({
  container: '#waveform',
  waveColor: '#violet',
  progressColor: '#purple'
});

async function initializeAudio() {
  try {
    await wavesurfer.load('/audio.mp3');
    // Code here runs only after the audio is ready
    console.log('Audio loaded successfully');
    wavesurfer.setTime(10);
  } catch (error) {
    console.error('Error loading audio:', error);
  }
}

initializeAudio();

3. Checking the State Flag Programmatically

If you are invoking a method from an external trigger—such as a custom UI button click—the ready event may have already fired in the past. To handle this, track the readiness state using an internal variable or check the underlying media element.

Custom State Tracking

let isWaveSurferReady = false;

wavesurfer.on('ready', () => {
  isWaveSurferReady = true;
});

function handlePlayButtonClick() {
  if (!isWaveSurferReady) {
    console.warn('Wavesurfer is not ready yet.');
    return;
  }
  wavesurfer.playPause();
}

Checking the Decoded Duration or Buffer

In earlier versions (v6 and below), you can inspect the instance directly. If the audio is decoded, wavesurfer.isReady returns a boolean (in v4/v5), or wavesurfer.getDuration() will return a value greater than zero:

function isReady(ws) {
  // Returns true if audio duration is available and valid
  return ws.getDuration() > 0;
}

if (isReady(wavesurfer)) {
  wavesurfer.play();
} else {
  wavesurfer.once('ready', () => wavesurfer.play());
}

In Wavesurfer.js v7, you can also inspect wavesurfer.getMediaElement().readyState to check the HTMLMediaElement's standard readiness level (where readyState >= 3 or 4 indicates sufficient data to play).
