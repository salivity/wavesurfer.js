Fix Wavesurfer.js Audio Clicks with Gain Fade-Out

Abrupt playback interruptions, jumps, and custom seeking operations in Wavesurfer.js frequently produce audible clicks or pops due to instantaneous amplitude drops. This article outlines the root cause of these waveform discontinuities and demonstrates how to implement Web Audio API gain fade-out techniques—such as linear ramps and exponential target curves—within custom Wavesurfer.js playhead logic to ensure smooth, artifact-free audio playback.

The Cause of Playhead Clicks

Audible clicks occur when an audio waveform is instantly cut off at a non-zero amplitude point. When a user seeks, pauses, or dynamically repositions a custom playhead, terminating or repositioning the playback instantly forces the signal to jump from its current value directly to zero (or to a different phase value). The digital-to-analog converter interprets this vertical edge as a wideband impulse, resulting in a distinct pop. To eliminate this artifact, the amplitude must be transitioned smoothly to zero before the playhead position changes.

Intercepting the Wavesurfer.js Gain Graph

Wavesurfer.js relies on the Web Audio API backend by default. To apply custom fade-out logic, access the underlying AudioContext and insert or control a GainNode before executing seek or reposition commands:

const audioContext = wavesurfer.backend.getAudioContext();
// Alternatively, connect a custom GainNode via wavesurfer.backend.setFilter()
const gainNode = audioContext.createGain();
wavesurfer.backend.setFilter(gainNode);

Technique 1: Linear Ramp Down (linearRampToValueAtTime)

A fast linear ramp is one of the most reliable methods for silencing audio right before a playhead jump. A fade-out duration between 3 to 15 milliseconds is ideal; it is brief enough to feel instantaneous to the user, yet sufficiently gradual to prevent high-frequency transients.

function smoothSeek(targetProgress) {
  const now = audioContext.currentTime;
  const fadeDuration = 0.005; // 5 milliseconds

  // Cancel any previously scheduled changes to prevent race conditions
  gainNode.gain.cancelScheduledValues(now);

  // Anchor the current gain value
  gainNode.gain.setValueAtTime(gainNode.gain.value, now);

  // Ramp down to zero
  gainNode.gain.linearRampToValueAtTime(0, now + fadeDuration);

  // Perform the seek once the ramp completes
  setTimeout(() => {
    wavesurfer.seekTo(targetProgress);

    // Ramp back up to full volume
    const resumeTime = audioContext.currentTime;
    gainNode.gain.setValueAtTime(0, resumeTime);
    gainNode.gain.linearRampToValueAtTime(1, resumeTime + fadeDuration);
  }, fadeDuration * 1000);
}

Technique 2: Exponential Smoothing (setTargetAtTime)

While linear ramps are predictable, exponential curves model natural acoustic decay more closely and avoid mathematical discontinuities at the start of the fade. The setTargetAtTime method provides smooth exponential decay toward zero without requiring manual recalculation of current gain levels.

function fadeAndPause() {
  const now = audioContext.currentTime;
  const timeConstant = 0.003; // Time constant determines steepness

  gainNode.gain.cancelScheduledValues(now);
  gainNode.gain.setTargetAtTime(0, now, timeConstant);

  // Wait for the decay to drop below audible thresholds (~3 to 4 time constants)
  setTimeout(() => {
    wavesurfer.pause();
    gainNode.gain.setValueAtTime(1, audioContext.currentTime);
  }, timeConstant * 4 * 1000);
}

Handling Rapid Scrubbing and Edge Cases

When users drag a custom playhead rapidly, multiple seek commands fire in quick succession. To avoid overlapping and corrupted audio ramps:

  • Always call cancelScheduledValues: Clearing the queue ensures that incoming fade commands immediately take over from the instantaneous gain level rather than conflicting with previous ramps.
  • Debounce high-frequency playhead updates: When implementing continuous dragging, throttle or debounce the seekTo triggers while maintaining an active fade-out until dragging ceases.
  • Anchor the gain value: Always declare setValueAtTime(gainNode.gain.value, audioContext.currentTime) before scheduling any ramp, which sets an explicit starting point and prevents browsers from defaulting to the last scheduled point in the past.
