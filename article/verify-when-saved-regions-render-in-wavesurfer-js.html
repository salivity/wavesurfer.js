Verify When Saved Regions Render in Wavesurfer.js

This article explains how to determine when saved audio regions have completely rendered on a Wavesurfer.js waveform. It covers the core lifecycle events in Wavesurfer.js, clarifies why no native single event exists for bulk region rendering, and provides the standard implementation pattern to reliably confirm that all saved regions have been drawn to the DOM.

The Short Answer: No Single Native Event

Wavesurfer.js and its official Regions plugin do not provide a dedicated, single event such as regions-rendered or regions-ready to signal that an entire array of saved regions has finished rendering.

Instead, confirming that all saved regions are rendered requires combining the Wavesurfer instance's ready event with the Regions plugin's region-created event counter or an asynchronous execution frame.

The Foundation: The ready Event

Before any region can be calculated and placed accurately, the waveform itself must decode the audio and render the visual canvas. Attempting to add regions before this stage results in incorrect pixel positioning because the container's duration and width are not yet finalized.

The ready event verifies that the waveform is fully drawn and ready for DOM manipulation:

wavesurfer.on('ready', () => {
    // Waveform is ready; safe to render saved regions
    loadSavedRegions(savedRegionsData);
});

Verifying Completion with the region-created Event

The Regions plugin emits the region-created event synchronously as each individual region is created and appended to the DOM.

To verify that all saved regions have completed rendering, track the number of emitted region-created events against the total count of regions in your saved dataset:

import WaveSurfer from 'wavesurfer.js';
import RegionsPlugin from 'wavesurfer.js/dist/plugins/regions.js';

const ws = WaveSurfer.create({
    container: '#waveform',
    waveColor: '#violet',
    progressColor: '#purple',
    url: '/path/to/audio.mp3',
});

const wsRegions = ws.registerPlugin(RegionsPlugin.create());

const savedRegions = [
    { start: 1, end: 3, content: 'Intro' },
    { start: 5, end: 9, content: 'Verse' },
    { start: 12, end: 16, content: 'Chorus' }
];

ws.on('ready', () => {
    let renderedCount = 0;
    const totalRegions = savedRegions.length;

    if (totalRegions === 0) {
        onAllRegionsRendered();
        return;
    }

    // Subscribe to each individual creation event
    const unsubscribe = wsRegions.on('region-created', (region) => {
        renderedCount++;
        
        if (renderedCount === totalRegions) {
            // All saved regions are now created and rendered in the DOM
            onAllRegionsRendered();
            unsubscribe(); // Clean up listener if no longer needed
        }
    });

    // Add the saved regions
    savedRegions.forEach((data) => {
        wsRegions.addRegion(data);
    });
});

function onAllRegionsRendered() {
    console.log('All saved regions have completely rendered.');
}

Ensuring DOM Paint with requestAnimationFrame

While region-created fires when the region object is initialized and inserted into the document tree, browser rendering pipelines might defer painting for a frame.

To guarantee that visual layout and painting are complete on screen:

ws.on('ready', () => {
    savedRegions.forEach((regionData) => wsRegions.addRegion(regionData));

    // Wait for the next browser paint cycle
    requestAnimationFrame(() => {
        requestAnimationFrame(() => {
            console.log('All regions are visually painted to the screen.');
        });
    });
});

Summary

  1. Wait for the wavesurfer.on('ready') event to ensure the audio is decoded and the waveform dimensions are established.
  2. Listen to wsRegions.on('region-created') and increment a counter against your saved dataset length to programmatically verify that every region has finished loading.
  3. Use requestAnimationFrame if your application requires confirmation that the browser has fully painted the elements to the display.
