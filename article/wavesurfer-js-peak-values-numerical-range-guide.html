Wavesurfer.js Peak Values Numerical Range Guide

This guide explains the numerical ranges used for peak values inside Wavesurfer.js array parameters, helping developers properly render pre-computed waveforms. You will learn the default floating-point bounds expected by the library, how single and multi-channel peak arrays are structured, and how to normalize peak data originating from third-party generation tools.

The Default Float Range: -1.0 to 1.0

Under standard operation, Wavesurfer.js expects peak values to be normalized floating-point numbers ranging from -1.0 to 1.0.

This range directly corresponds to the standard output of the Web Audio API's AudioBuffer.getChannelData() method, which outputs raw PCM audio data as 32-bit floats. Within this spectrum:

  • 0.0 represents absolute silence (the zero-crossing baseline of the audio signal).
  • 1.0 represents the maximum positive amplitude (the crest of the wave).
  • -1.0 represents the maximum negative amplitude (the trough of the wave).

Absolute Range: 0.0 to 1.0

Wavesurfer.js can also accept peak arrays containing only positive numbers ranging from 0.0 to 1.0.

When only non-negative numbers are supplied, Wavesurfer.js interprets them as absolute peak values (rectified audio). The rendering engine automatically mirrors these values across the horizontal center line to draw a symmetrical waveform.

Array Structures for Peaks

Wavesurfer.js supports multiple array formats for passing peaks via the peaks configuration option or the load() method:

  1. Interleaved 1D Array: A single array alternating between minimum (negative) and maximum (positive) values: [-0.8, 0.85, -0.4, 0.42, -0.9, 0.95]
  2. Normalized 2D Array: An array containing separate sub-arrays for each audio channel: [ [-0.8, 0.85, -0.4, 0.42], [-0.75, 0.8, -0.35, 0.4] ]
  3. Single-Value 1D Array: A simple array of magnitudes that the library mirrors: [0.85, 0.42, 0.95, 0.12]

Handling Third-Party Pre-computed Peaks

External command-line utilities (such as the BBC's audiowaveform) typically export peak data in integer formats rather than normalized floats. Common integer ranges include:

  • 8-bit Signed Integers: -128 to 127
  • 16-bit Signed Integers: -32,768 to 32,767

Wavesurfer.js does not automatically downscale integer arrays. If integers outside the -1.0 to 1.0 range are passed directly to Wavesurfer.js, the visual waveform will clip and distort beyond the bounds of the canvas. You must map these integer arrays to normalized floating-point numbers prior to initialization by dividing each value by its absolute integer maximum (e.g., dividing 8-bit values by 128 or 16-bit values by 32768).
