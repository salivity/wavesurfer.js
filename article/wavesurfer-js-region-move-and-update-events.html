Wavesurfer.js Region Move and Update Events

When using the Regions plugin in Wavesurfer.js, detecting when a user moves, drags, or resizes a region is essential for syncing your application's state or saving changes. The specific event that fires depends on the version of Wavesurfer.js you are using and whether you need to capture real-time movements or wait until the user has finished dragging. The primary events responsible for these interactions are region-updated (at the plugin level) and update or update-end (at the individual region level).

Wavesurfer.js v7 Events

In Wavesurfer.js v7 and newer, events can be handled either globally through the RegionsPlugin instance or directly on an individual Region object.

1. The Global Plugin Event: region-updated

The RegionsPlugin emits a single unified event when a region is modified:

  • region-updated: Fires when a region is actively dragged, resized, or updated programmatically.
const wsRegions = wavesurfer.registerPlugin(RegionsPlugin.create());

wsRegions.on('region-updated', (region) => {
  console.log(`Region ${region.id} was modified:`, region.start, region.end);
});

2. Individual Region Events: update and update-end

If you need finer control over the drag lifecycle—distinguishing between continuous movement and the final drop action—listen directly to the individual region instance:

  • update: Emitted repeatedly in real time while the region is actively being dragged or resized.
  • update-end: Emitted once when the user releases the mouse button, completing the move or resize action.
wsRegions.on('region-created', (region) => {
  // Real-time tracking during drag/resize
  region.on('update', () => {
    console.log('Dragging or resizing:', region.start, region.end);
  });

  // Action completed
  region.on('update-end', () => {
    console.log('Finished updating region:', region.start, region.end);
    // Ideal place to save changes to a database
  });
});

Wavesurfer.js v6 (Legacy) Events

In Wavesurfer.js v6 and older, the event names on the main wavesurfer instance followed a different naming convention:

  • region-updated: Fired continuously as the region was being dragged or resized.
  • region-update-end: Fired once the drag or resize action was completed.
// Legacy syntax (v6 and earlier)
wavesurfer.on('region-update-end', (region) => {
  console.log('Region modification complete:', region);
});

Which Event Should You Use?

  • Use continuous events (update / region-updated): When you need to update visual UI elements in real time, such as displaying live start/end timestamps in an input box.
  • Use completion events (update-end): When triggering expensive operations, such as making an API call, persisting region boundaries to a backend, or pushing an action to an undo/redo stack.
